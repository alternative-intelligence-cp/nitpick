proposals, each with a recommendation. Four carried questions that were the

## P-3 (D-201, proposed) — the builtin surface typed from one generated table

**The problem, restated from the survey.** 54 bare-name builtins; 13 have
bespoke typing arms; the other 41 type UNKNOWN ("no signature yet"), so an
argument-shape or `?|`-default mistake surfaces at llc or at runtime — the
`unwrap_unknown.npk` draft passed a `string` where `write_file` wants a
`cstring` and the kernel refused with the error swallowed. Meanwhile the
emitter carries a THIRD copy of the floor (`ir_runtime.npk`'s 45-entry
`rt_sig`), whose argument coercion is signedness-blind (always `zext` —
the exact bug class D-192 fixed for `sys`), and BUILTIN_REFERENCE is a
fourth copy nothing diffs. One fact, four representations — the recurring
defect of Phase A, at the language's floor.

**The design:**

1. **BUILTIN_REFERENCE.md's marked regions become the single authority.**
   The Signature column is normalized to one parseable syntax (§3's table
   gains the column it lacks; `read`/`write`'s untyped `ptr` becomes
   `wild int8->`; the U+2192 arrow, optional parameter names, and the
   `move` prefix are kept and specified). The generator — which already
   scrapes these regions for names and never-fails, and already hard-fails
   on a missing Fails column — grows a strict signature parser that
   hard-fails on any row it cannot read.
2. **The generator emits the signature table as committed source**, the
   `builtins.npk` precedent: `builtin_sig_*` accessors (param count, param
   type text at i, return type text, never-fails) beside the existing
   `is_builtin_name`/`builtin_never_fails` — and `is_builtin_name` itself
   is derived from the same rows, so the name list and the signature list
   cannot disagree.
3. **The checker types every regular builtin call through the shared
   argument path** — arity, per-argument fits, `move` where the signature
   says so, spread refusal — by interning the table's type texts at check
   time. The nine genuinely irregular builtins keep their bespoke arms
   (`sys` variadic; `atomic_from_ptr`'s turbofish; the seven
   annotation-directed constructors `channel`/`mutex`/`rwlock`/`condvar`/
   `barrier`/`arena_make`/`shared_arena_make`), and the table marks them
   `special` — so a builtin with neither a signature nor a special arm
   fails generation, and the completeness question is closed by
   construction. (`check_args` wraps unconditionally today, so the shared
   path is its pieces re-used, not the function called blind.)
4. **The typing rule** (**USER** — see below): never-fails builtins type as
   **bare T**; may-fail builtins as `Result<T>`. This generalizes the
   settled 13-arm convention (`own_fd`, `buffer_new`, `arena_make` bare;
   `channel`, `mutex`, `open` wrapped) to the whole surface. The floor's
   ABI is untouched — symbols keep answering in the envelope, and the
   emitter extracts the value half at the site, the 1.3.7 `buffer_new`
   mechanism made general.
5. **The emitter's parallel authority retires.** With real types recorded
   at every builtin call: the UNKNOWN-operand fallbacks go
   (`result_ll_value_half` and both its `?|`/`?!` consumers, the typer's
   `t == 0` bails, `emit_raw`'s wrapped/inner fallback, `call_param_want`'s
   0-means-skip); the signedness-blind coercion loop goes (the checker now
   refuses what it papered over, and the remaining language-type→symbol-type
   adaptations — `memset`'s `int64` value vs `i32` symbol — become explicit
   per-row ABI notes in the same generated table, signedness-correct);
   `rt_sig` keeps only its honest job, name→symbol+LLVM-ABI, and is
   GENERATED from the same rows, collapsing the third and fourth copies
   into the reference. `check_runtime_sigs_agree` then diffs npkrt.ll
   against the reference-derived table — the spec finally in the loop.
6. **A bare name not in the table refuses at type time** (new TYPE code).
   Nothing is left legitimately UNKNOWN: `type_call`'s `pass 0i32`
   fall-through becomes an internal defect, and REACH/locks/statement-rule
   sites drop their unknown-tolerance arms.
7. **The migration is three steps inside one subcycle (1.4.2), fixpoint
   green at each**: (a) land the table and typing with a transitional rule
   — `raw`/`drop` on a now-bare never-fails builtin call is accepted as the
   identity; (b) the tree-wide re-spell (`src/` ~1,700 `raw` sheds, `lib/`,
   `tests/`), with the seed's `check.BUILTINS` wrapped-flags flipped and
   its emitter taught the same extract-at-site in the same commit (the
   seed still builds `src/` until 1.4.6); (c) the transitional rule
   removed — `raw` on a non-Result operand refuses, as everywhere else.
   New rejection suite `builtin_args.npk` on the `sys_args.npk` model;
   `buffer_rules.npk`/`raw_unlicensed.npk`/`unwrap_unknown.npk` updated to
   assert the typed world.

**USER — the typing rule.** Two candidates:

- **(a) Everything wraps**: every builtin call types `Result<T>`, `raw`
  stays at never-fails sites (licensed by the table), the 13 bare-T arms
  are REVERSED (`buffer:b = raw buffer_new(16i64);`). One rule shared with
  user functions — but it re-wraps seven surfaces settled bare across
  1.1–1.3, and it blankets ~1,700 provably-cannot-fail `string_concat`
  sites in `raw`, diluting the acknowledgement `raw` exists to be: when
  the opt-out appears on every third line, it stops marking anything.
- **(b) Never-fails builtins are bare** (recommended): the type system
  states the truth the contract already proves — `buffer_new` cannot fail,
  so its type IS `buffer` — and `raw` remains what D-163 made it: the
  spelling at sites where an ENVELOPE is being removed on the strength of
  a contract. Builtins are the floor, not user functions; the direction of
  travel across three cycles (D-185, D-200, the CLAUDE.md-recorded
  precedent "checker-typed builtins are called WITHOUT `raw`") chose this
  deliberately, seven times. The cost is the one-time re-spell sweep and
  the seed flip, both mechanical, both fixpoint-checked.

**Recommendation: (b).** Safety and correctness are equal under both — the
checker refuses bad arguments either way — so the tiebreak is which rule
keeps `raw` meaningful as a signal, and that is (b) decisively. (a)'s
uniformity argument is real but points at the wrong uniformity: the
uniform rule worth having is "`raw` appears exactly where a contract is
being leaned on", not "every call yields an envelope".

## C-10 (D-202, proposed) — the fixpoint criterion restated

**The finding, sharpened**: the harness has measured the right thing since
0.8.1 — the seed-built compiler's emission of `src/main.npk` versus stage
1's re-emission, byte for byte, two `.ll` texts from the same
`src/backend`. The unsatisfiable sentence lives only in the docs:
BUILD_REFERENCE:188 ("Stage 1 and stage 2 must be byte-identical"), carried
verbatim from superseded D-079:5443 into D-085's records at :5798/:5825/
:5883. (OPEN_DECISIONS' citation "D-085:5747" is off — 5747 is inside
D-084; the operative lines are those four.)

**The restated criterion (normative text for BUILD_REFERENCE §6):**

> Self-hosting is the fixpoint of the compiler's emission of itself: **the
> first stage built from the current source, and the next stage built by
> it, must emit the compiler byte-identically.** Binaries are then
> identical from that emission onward. Before the 1.4.6 switch the first
> such stage is the seed-built compiler; after it, the snapshot-built one.
> When the builder snapshot is older than the source, the comparison is
> stage-N vs stage-N+1 where stage N is the first CURRENT-source compiler
> — the three-pass shape §6.2 already describes for ABI changes.

D-085's records get a dated annotation pointing here (archives are not
rewritten; the annotation rule is the house convention). The harness
comment's stale "the 1.2 fixpoint" is corrected in the same pass.

**Recommendation: adopt as written.** No code change; the spec stops
telling an implementer self-hosting is broken.

## C-11 (D-203, proposed) — the committed IR, the survival map, and what the floor IS

Three interlocked pieces:

1. **What gets committed, and when.** `bootstrap/seed/stage1.ll` — the name
   LAYOUT and `npkseed.py` have always used — holding the **fixpoint
   emission of the real compiler**, committed at the 1.4.6 switch (the
   first moment the artifact is the permanent one; committing the seed's
   emission now would be an 11 MB file superseded within the same cycle).
   Beside it, `bootstrap/seed/STAMP`: the source commit it was emitted
   from, the toolchain version, and the sha256 of the `.ll` — the build
   INPUT record reproducibility needs (the artifact itself stays free of
   paths/times/env per D-078). Rebuild-from-LLVM-alone is then:
   `llc stage1.ll`, `llc npkrt.ll`, `ld.lld -static` → npkc, which rebuilds
   itself from `src/` and must close the fixpoint against the committed
   text. **The snapshot is a pinned artifact, not a tracking one**: it
   refreshes at cycle closes (with the push), never per-commit — the
   from-scratch audit path for any historical state is the generator plus
   the pre-switch commits, the standard trusting-trust answer D-085
   already records.
2. **The `bootstrap/` survival map** (LAYOUT §5 amended): `seed/` (the
   committed IR + STAMP) and `generator/` (the regeneration tool — needed
   to regenerate tables and the historical seed, never to build) survive
   indefinitely; `harness/` survives until `npkg` parity is proven and its
   retirement executes under `meta/SWITCH.md`, not this cycle; the blanket
   "all of it is deleted once self-hosting closes" is struck.
3. **`npkrt.ll` is re-homed and D-015 gets its disposition** (**USER**).
   The floor is in every artifact ever linked, including the one that will
   ship — it is not bootstrap material, and its THROWAWAY header is false.
   Proposal: move it to top-level `runtime/npkrt.ll` at 1.4.6 (with its
   tests), and settle D-015's "replaced at a later rung" as: **the floor's
   permanent form is reviewed, hand-written LLVM IR** — D-015's own "later"
   row already names "tuned IR" as an accepted end state. A Nitpick rewrite
   of the floor is decided OUT: it would churn the single most
   safety-critical layer immediately before verification, for uniformity's
   sake, against a floor that is line-reviewed, exercised by the runtime
   stage, diffed three ways by `check_runtime_sigs_agree`, and scanned for
   dependencies on every run. If C-19's answer (Astrée's input format)
   forces a C rendering of the floor, that is 1.5's question and reopens
   this row with the constraint on the table — recorded here so the
   interaction is not lost.

**Recommendation: all three as written.**

## C-12 (D-204, proposed) — byte-reproducibility defined and checked

The claim D-078 makes becomes three checked facts:

1. **The toolchain is a pinned input.** `nitpick.toml` gains
   `[toolchain] llvm = "20.1.2"` plus the exact flag sets (llc:
   `-O0 -filetype=obj -relocation-model=static` — and the opt-O2 leg's
   pair; ld.lld: `-static`); the harness (and later `npkg`) verifies
   `llvm-config --version` against it and refuses a mismatch loudly.
   BUILD_REFERENCE §5 records that the pin is part of the reproducibility
   statement: "same inputs" includes the tools.
2. **The seed emission is path-independent on every path.** The harness
   path already is (`module_id="test"`, relative paths, zero absolute
   paths in 11.2 MB); `npkseed.py:65` stops embedding its argv as the
   ModuleID (fixed to the same `"test"`). The real compiler already emits
   no ModuleID at all.
3. **A `repro` harness stage builds twice from different cwds** and
   compares the emissions byte-for-byte — turning "byte-identical in one
   process on one machine" into the actual claim. After 1.4.6 the same
   stage also asserts the committed `stage1.ll` still matches a fresh
   fixpoint emission and its STAMP sha256 — the snapshot cannot silently
   rot.

**Recommendation: adopt; land the mechanics at 1.4.5** (the stage exists
and runs green BEFORE the switch commits the snapshot it will then guard).

## C-13 (D-205, proposed) — the builder rule and the switch

The rule that has been obeyed by discipline since 0.9, named three
different switch cycles, and never landed as a sentence, becomes normative
(SUBSET_1 §4, BUILD_REFERENCE §6):

> **`src/` may not use any construct its current builder cannot compile.**
> Until 1.4.6 the builder is the regenerated Python seed, and `src/` is
> subset 1. At 1.4.6 the builder becomes the committed
> `bootstrap/seed/stage1.ll`, and the constraint becomes: a language
> feature `src/` wants to use must already be in the snapshot — new
> features enter `src/` only after a snapshot refresh, and the snapshot
> refreshes at cycle closes.

SUBSET_1 §4's adoption table is corrected to the truth the survey
measured: no adoption happened at 0.9–1.2 (the constraint overruled the
table); adoption happens at 1.4.7, once, under D-209's scope. §4's stale
"(1.3)" is fixed in the same pass. The seed's retirement is the switch
itself: after 1.4.6 it is never the builder again; its two coupled
harness instruments re-base (`check_ll_types_agree` retires WITH the seed
— its question, "do the two emitters agree", ends when there is one
emitter; `check_runtime_sigs_agree` drops to the two-way diff that P-3
already sharpened).

**Recommendation: adopt as written.**

## B-4 (D-206, proposed) — `npkg`, the spawn primitive, the closed-world link

**Scope for 1.4 (subcycle 1.4.8): `npkg build` and `npkg test`, minimal
and real.** `npkg update` has nothing to resolve in a single-repo world
and stubs to a named refusal; `npkg verify` refuses naming 1.5 (the rung
style) until the z3 pipeline exists to be driven.

1. **The spawn primitive.** A new floor entry, `npk_spawn`, generalizing
   `driver_clone_exec`'s proven shape — same fork-shape `CLONE_PIDFD`
   clone, same allocation-free child discipline (the copied-futex rule),
   same PDEATHSIG + NO_NEW_PRIVS, same 16-slot registry so the trap route
   kills outstanding tool children and a clean exit with a live child
   refuses (the D-151/D-188 exit discipline extends to build tools) — with
   the one generalization the survey shows is needed: the block carries
   caller-directed stdio targets (stdout to a pipe or file fd instead of
   hardcoded `/dev/null`; the fd-3 control channel optional and absent for
   tools). The Bridge's `spawn_driver` becomes a caller of the same
   primitive with its driver-specific block. Waiting stays `sys(WAITID)`
   from Nitpick, the nbridge pattern. The new builtin enters
   BUILTIN_REFERENCE's marked region and P-3's table from birth.
2. **Directory listing** needs no floor addition: `sys(SYS_GETDENTS64)`
   over an owned buffer, the dirent records parsed in Nitpick —
   `lib/nfs.npk`, `dir_list(Path) → Result<…>`, library-owned like
   ntensor's bounds. The suite discovery the harness does with `glob`
   becomes this.
3. **`npkg` is written in full Nitpick against the compiler's own
   modules** — it `use`s the real frontend for its source-scanning
   instruments rather than reimplementing them as regexes, which is the
   self-hosting dividend and retires the Python checks' regex fragility.
4. **The closed-world link is `npkg`'s law, not a flag**: only
   npkc-produced objects plus the audited runtime allowlist may appear in
   a link line, with no relaxing option — D-011's scan written into
   BUILD_REFERENCE §4 as a permanent pipeline step, which makes
   "in-process FFI does not exist" structural for every user program.
5. **Succession, not replacement**: `npkg test` runs the suites and every
   whole-suite instrument; parity is proven by running BOTH runners and
   comparing verdicts run-for-run; the Python harness retires under
   `meta/SWITCH.md`'s coordinated operation, not in 1.4 — never a gap
   where neither runs. The §7.1 self-check obligation (the harness is
   itself tested) transfers to `npkg` explicitly — and 1.4.1 first wires
   the EXISTING `selfcheck.py` into the Python run, so the property is
   continuously held on both sides of the succession.

**Recommendation: adopt; the spawn primitive's block layout is settled at
1.4.8 with the code in front of us** (its shape is constrained by the
allocation-free child rule, not by taste).

## C-22 (D-207, proposed) — per-scope joins

The machinery: `join_head` becomes per-scope, threaded through the 1.2
scope-exit walk that already owns drop flags — a scope's exit joins the
tasks that scope spawned (relaying the first child error per D-163 rule
4), then reclaims that scope's channels and releases its shared arenas,
in that order. What it lifts:

- `channel()` inside a loop (per-iteration reclaim at the body's exit);
- **`shared_arena` teardown** — the managed-lowering hole this row has
  been excusing: `TY_SHARED_ARENA` leaves `type_drops`' excuse table and
  drops for real, joined-before-freed;
- the workaround guidance (create the channel outside the loop) remains
  the PERFORMANCE advice, no longer a language rule.

**USER — the third tenant stays refused.** `dyn` channel elements: erased
content can hide a borrow, and no join ordering cures a type-level
invisibility — BORROW-004's spawn-crossing question cannot be asked of a
value whose type is erased. Proposal: the refusal becomes permanent (a
decision that it is not going in, not a deferral), recorded with this
reasoning.

**Recommendation: build the machinery at 1.4.4; ratify the permanent
`dyn`-element refusal.**

## S-2 (D-208, proposed) — loop-carried moved-from states

The 0.5 move analysis gains loop-header merge states: a binding moved
anywhere in a loop body is moved-from at the body's head unless reassigned
on every path that reaches the back edge — the same fixed-point shape the
read-before-assign analysis has run since 0.5, extended, not invented.
`modmap_members`' double-free class (one `move` re-executed by iteration)
becomes a refusal with its own code and rejection case; the acceptance
side proves reassign-then-move-again loops still pass (0.5's lesson:
these analyses fail closed, so over-refusal is the likelier defect —
the acceptance case is not optional). Expect the first run over `src/` to
find latent instances of exactly this shape; they are repairs, not
regressions.

**Recommendation: adopt at 1.4.3, before the adoption sweep enlarges the
code the analysis must be right about.**

## D-209 (proposed) — the adoption scope

What `src/` adopts at 1.4.7, decided as a list rather than an ambition
(**USER** — this is what "self-hosting" makes the compiler's own source
look like):

**In (recommended):**
- **Generics where duplication is real**: the concrete collection copies
  (the `TokenList`-shape families) become the generic containers the
  language has had since 1.0 — the single largest mechanical
  simplification available, and the strongest exercise generics get
  before verification;
- **`dyn Writer` diagnostics** (D-075's stated design, deferred since
  0.0): the compiler's own diagnostics through the trait, which is also
  what `npkg test`'s capture-and-compare expects;
- **The unwrap forms and `for`/`till`** where they replace hand-rolled
  index loops and match-shaped unwraps — judicious, file-by-file, each
  step fixpoint-green.

**Out, by decision (not deferral):**
- **A mass `&{ }` re-spell of the ~1,700 diagnostic concatenations** —
  comfort-only churn of working, tested code; `&{ }` is the idiom for NEW
  code (P-3's sweep already touches those lines once; touching them twice
  for spelling buys no safety);
- **async in the pipeline** — the driver is sequential by design; async
  adoption for its own sake adds verification surface with no consumer;
- **macro/comptime adoption in `src/`** — same reasoning.

**Recommendation: the list as written**, with the standing rule that any
adoption step that would change EMITTED IR (not just source spelling) is
its own commit with the fixpoint and the 172-program suite between it and
the next.
