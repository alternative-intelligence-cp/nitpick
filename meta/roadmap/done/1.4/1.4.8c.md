## Execution record (2026-09-02)

**Decisions taken on contact, each with the reason:**

- **Module-scope names are checked against `Error` only.** The prelude clash is
  `bind_prelude_into`'s report already, so a second RESOLVE-001 for a
  `struct:Duration` would have been D-240's own violation inside D-239's code.
  Associated types and generic parameters are checked against both owners,
  because nothing else sees them.
- **Members and the value namespace are outside the rule**, stated in the
  decision: a field, a variant or a method is reached through its owner and
  shadows nothing (an `enum:Outcome = { Ok, Error }` is ordinary code); a local
  `int32:x` cannot make a type mean less. The rule is about names a TYPE lookup
  can find.
- **`tools/resolve_check.npk` gets the call too.** The module-rejection suite
  is that tool's, and the rule is the loader's — so the loader's tool reports
  it. (Observed, not acted on: `resolve_check` never called
  `graph_check_dup_members`, which is why member duplicates are tested in the
  `types` suite rather than `modules`; the pipeline runs both after resolution.
  A candidate for the close's doc pass, not a defect.)
- **Which of `drop`'s two reports stays.** `type_unwrap`'s TYPE-007 ("`drop`
  needs a `Result`, and this is `NIL`") is the true sentence for a never-fails
  builtin's bare value; rule 4's TYPE-042 ("discards a VALUE") is true only of a
  `Result` carrying a value, which is the case `raw_unlicensed.npk`'s seventh
  refusal pins and which still reports. An untyped operand (`dt == 0`) is
  treated the same way — refused where it failed to type — since the licensed
  branch is reached only for a known never-fails callee.
- **The old-blanket probe restores the resolver's generics itself** and is
  called from inside `impl_collect`'s own generic window (nesting a save/restore
  of the same value), so both callers read the target under the impl's
  parameters exactly as before; `resolve_trait_type` reports nothing for a
  non-trait target, which is what made the inline probe safe and makes the
  shared one safe.
- **A spread argument is still typed**, only the fit against the register it
  cannot become is skipped — a mistake inside the collection expression is not
  hidden behind the spread refusal.
- **The compiler caught the one slip in the new code**: a one-argument
  `string_concat` in the `Error` message, TYPE-054 at the build of
  `tools/check.npk` (the D-201 table checking the compiler's own source). The
  `pid` local I first wrote (a keyword, D-042) was caught by reading before it
  cost a build.
