## The work, in order

1. **`nitpick.toml` gains `[toolchain]`** — the pinned facts as data:

   ```toml
   [toolchain]
   # D-204: the toolchain is a BUILD INPUT. Exact patch release — r4's
   # strongest directive: "pinning to a minor version is insufficient
   # for strict byte-identity"; any update, patch included, is a
   # breaking change that regenerates expected hashes.
   llvm      = "20.1.2"
   llc-flags = ["-O0", "-filetype=obj", "-relocation-model=static"]
   opt-flags = ["-O2", "-S"]          # the harness's opt leg (1.3.8)
   lld-flags = ["-static"]
   ```

   NOT added: `-mcpu` pinning — the .ll embeds `target triple` and we
   emit no `-mcpu`, so llc uses the triple's generic CPU; r4 recommends
   explicit `-mcpu` when hosts vary, but pinning a specific
   microarchitecture would change today's byte-identical output. Record
   the question in the file as a comment: if cross-machine divergence is
   ever observed, `-mcpu=x86-64` (the generic tune) is the fix, applied
   everywhere at once with hashes regenerated. No `--build-id` (we pass
   none; `uuid` is the entropy-injecting form to never use).

2. **The harness verifies the pin**: at startup (once, where llc/lld are
   first invoked), run `llvm-config --version` (or `llc --version`) and
   `ld.lld --version`; mismatch against `[toolchain] llvm` **fails the
   run loudly** with the versions shown. Parse nitpick.toml with tomllib
   (already imported). ~15 lines beside `RUNTIME_LL`.

3. **`npkseed.py` stops embedding its argv path**: line ~65,
   `module_id=mods[0]._path` → `module_id="test"` (the harness path's
   constant — one spelling both paths share). One-line change plus its
   comment.

4. **The `repro` stage** (new, in the whole-suite block's family, after
   selfhost):
   - Build the compiler's emission twice **from two different working
     directories** (copy nothing — invoke the seed-built `ec` binary
     with cwd set to the repo root and then to a temp dir, absolute
     paths for inputs) and byte-compare the two IR outputs. This
     exercises H9-class path leakage AND (run-to-run) the H1 ASLR class.
   - Assemble one of them with llc TWICE and byte-compare the two `.o`
     files (the pure-llc determinism check — H1 on the backend side).
   - After 1.4.6 exists: also assert `bootstrap/seed/stage1.ll` matches
     the current fixpoint emission byte-for-byte AND its `STAMP` sha256
     — the snapshot cannot silently rot. (Guard the assertion on the
     file existing so the stage runs green before the switch.)
   - Print in the harness's stage style; failures name which comparison
     diverged and the first differing byte offset.
   Cost: one extra emission + two llc runs ≈ tens of seconds. Not
   gated behind `--only` filtering exemptions — it IS a whole-suite
   check.

5. **BUILD_REFERENCE §5** already carries D-204's bullet (landed at

# Execution record

## Step 3's diagnosis was wrong, in an instructive direction

The plan says npkseed.py "stops embedding its argv path", `mods[0]._path` →
a constant. It never embedded the argv path. `Module` is built as
`S.Module(items, path)`, so the file path lands in the node's `path` FIELD,
while `_path` is the `Node` base's LOCATION attribute and `_at()` is never
called on a module node — so it evaluated to the class default `"?"` on every
invocation, and the seed's output was already invocation-independent.

Reproducible **by accident**, and one character from the opposite: a
well-meaning reader fixing what looks like a typo would have written
`mods[0].path` and leaked the argv path into the IR. So the change still
landed, for the reason the plan wanted rather than the one it gave — the
constant is now explicit, is the SAME constant the harness passes
(`"test"`, one spelling for the emitter's two entry points), and the comment
records the trap so the typo cannot be "fixed" back into a defect.

## The flags are pinned AND read, not pinned and described

The plan's `[toolchain]` table states flag sets. A table nothing consumes is
the next stale document, and this project has been bitten by that class
repeatedly (§26 of TYPE_REFERENCE promising a `fixed` rule enforced nowhere;
`check_runtime_sigs_agree`'s derived-inner leg that had never run). So every
`llc`/`opt`/`ld.lld` invocation in the harness is now BUILT from the
manifest's lists — the same shape BUILTIN_REFERENCE's marked regions have had
since 1.4.2. Fifteen call sites, one authority.

`llc-opt-flags` is a fourth key the plan did not list: the 1.3.8 instrument
re-runs every program through `opt -O2` + `llc -O2`, and those llc flags are
NOT the build's. Naming them separately keeps "what the build does" and "what
the check does" distinguishable instead of deriving one from the other by
string substitution.

`llvm-config` is not used for the version probe, though the plan offered it:
it ships in a -dev package the build does not otherwise need, and asking the
tools we already require (`llc`, `opt`, `ld.lld`) for their own versions is
both fewer dependencies and the more honest question — the version that
matters is the one that will run.

## What the repro stage measures, and what it cost

Measured before writing the stage, on this machine, with the seed-built
compiler over `src/main.npk` (15,292,234 bytes of IR):

| | |
|---|---|
| emission 1, cwd = repo root | 3m05.1s |
| emission 2, same cwd, same binary | 3m05.9s — **identical bytes** |
| emission 3, cwd = elsewhere, absolute inputs | 3m05.0s — **identical bytes** |

So both hazard classes are clean today: H1 (ASLR / hash iteration order,
which has no controlling flag and can only be tested) and H9 (the build path
leaking into the artifact — not hypothetical for us, since D-179's
origin-chain site tables embed source paths for real).

The stage costs ONE extra emission (~3 min) plus one extra `llc` on the
compiler's own IR, against a ~25-minute run. That is the honest price of
making reproducibility a tested property rather than a claim, and the
fixpoint cannot substitute: it compares two DIFFERENT binaries, so
"byte-identical" there means they agree, not that either is deterministic.

Peak RSS for one emission is ~10 GB. Not acted on — it is the status quo the
harness has always paid — but written down, because it is a number worth
knowing before anyone runs this on a smaller machine.

## The pin's failure path is held, not just demonstrated

The plan called a `selfcheck.py` case a nice-to-have. It is cheap and it is
the same argument that file exists for: a check only ever seen to PASS is a
check nobody has tested. `selfcheck.py` now moves the PIN (the only half of
the comparison it can move) and asserts three things — a mismatched version
fails, an absent pin fails, and the real installed toolchain passes.
