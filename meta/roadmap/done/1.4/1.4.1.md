# 1.4.1 — The instruments: B-7's walkers-total check, the orphan wiring, and what the first run found

**The deliverable**: `check_type_walkers_total` — the companion B-7 asked
for, generalizing `check_drops_total`'s shape to TEN walkers, each with an
excuse table where a kind's default is a reviewed claim instead of an
accident. Plus the two standalone instruments that were wired to nothing
(`selfcheck.py`, `spec_coverage.py` — both now run in the whole-suite
block as subprocesses), and `check_allocas_hoisted` on stage 1 — the one
module big enough to overflow (D-173's own defect was the seed-built npkc
segfaulting on `src/`, yet the pin never ran there).

The walkers: `type_drops` (absorbed from `check_drops_total`, its excuse
table kept verbatim), `type_contains_borrow`, `type_contains_channel`,
`type_holds_pointer` (escape), `field_holds_ptr` (layout), `type_subst`,
`type_mentions_param`, `ll_type`, `type_display`, and `emit_one_drop` —
the backend half of `type_drops`' claim.

## The first run: 195 findings, classified one by one

`ll_type` and `type_drops` came back clean. The rest produced the house
pattern — every instrument's first run has found something — and this one
found a real miscompile-class defect plus a laundering hole:

1. **`emit_one_drop` had no `TY_ENUM` arm, and its default emitted a
   VALID EMPTY BODY.** An enum owning a payload registered a drop, scope
   exit called `@"npk.drop.<tid>"`, and the body was bare `ret void` — the
   payload leaked at every scope exit since 1.2, green throughout because
   a managed-heap leak shows up in no counter a program can read (the
   probe's `wild_live_count` stayed 0 through the leak). `src/`'s own
   enums are payload-less kind tags, so the compiler itself never leaked —
   which is also why the fixpoint never noticed. **Fixed**: the arm is a
   tag switch to the live variant, its owning payloads dropped in reverse
   payload order; tags come from `variant_tag_of` and offsets from
   `variant_payload_slot_at` — cores extracted from the `ExprEmitter`
   functions so construction, `pick` binding, and the drop read ONE walk.
   The default now pushes `EMIT_INTERNAL` (a silent leak was wearing a
   completed compile). `enum_drop.npk`: 2000 descriptor-owning enum drops
   (EMFILE proves release), the multi-payload offset pin, the
   struct-field path.
2. **The contains-walkers answered `false` for owned containers.**
   `type_contains_channel(Mutex<Channel<…>>)` was false — so a function
   creating a channel and returning it inside a mutex, rwlock, arena,
   shared arena, or atomic laundered the endpoint past D-183's `gives`
   rule (creation registers reclaim at the creator, the endpoint rides
   out, `StaleHandle` waits at the caller). **Fixed**: the owned
   containers recurse into their element — a mutex owns its cell and the
   cell holds the element, so the element answers, not the wrapper; the
   pointee-exclusion stays for PLAIN pointers (a borrowed pointee stays
   where it is). With the truthful answer the `gives` demand fires and
   the SHAPE rule then refuses (a channel behind a nesting level the
   stash cannot name) — the correct end state. Two rejection cases in
   `gives_rules.npk`. `type_contains_borrow` got the same recursion
   (`Mutex<int32[]>` crossing a spawn carried a frame view nothing could
   see).
3. **`TY_FLOAT` and `TY_OWNEDFD` fell to the conservative-TRUE tails of
   both pointer walkers** — a float local was "address-holding" to the
   escape analysis, an OwnedFd-holding struct was pointer-bearing: the
   exact over-refusal class the `field_holds_ptr` comment records having
   refused D-182's own actor example. **Fixed** with stated lines (plus
   `TY_RANGE` recursing its element, `TY_FUNC` stated false in escape —
   a code address cannot point into a frame).
4. **Two mention/subst asymmetries**: `type_subst` never rebuilt
   `TY_RANGE` though `type_mentions_param` counts a range's element (an
   unsubstituted parameter handed to the emitter — loud, but wrong); and
   `type_mentions_param` covered `TY_FUNC` but not `TY_FUNC_VARIADIC`
   (the 1.1.10-D3 zero-size class waiting for a variadic fn type). Both
   fixed via the shared predicates.
5. **`type_display` could not name `OwnedFd`** (a nameless interned
   singleton the named-type tail cannot answer for). Fixed.

Everything else was excused with its true reason — scalars, tier kinds,
code addresses, the stated conservative tails, the post-substitution
askers — 100+ rows, each a claim the instrument now diffs forever.

## Raised for the user (recorded in OPEN_DECISIONS §2e)

- **S-4 — `dyn` coercion of a channel-carrying concrete.** The one
  laundering path the walker fix cannot close without a new rule: an
  endpoint-holding struct coerced to `dyn` and returned from its
  channel's creator. `contains_channel(DYN)` answering `true` would
  demand `gives` of every dyn-returning creator (a claim about channels
  most such returns do not carry), so the precise fix is refusing the
  COERCION of a channel-carrying concrete — D-207's reasoning completed.
  The residual today ends in a deterministic runtime `StaleHandle`, never
  a dangling address. Recommendation: refuse the coercion, landing with
  D-207's subcycle (1.4.4).
- **S-5 — an owning enum payload cannot be read back out.** TYPE-046
  correctly refuses a `pick` arm binding an owning payload (the binding
  is a copy; two owners). But no move-binding form exists in patterns, so
  an enum with an owning payload is construct-and-drop-only — a
  write-only container. The missing form is a consuming destructure
  (a `pick` over `move(v)` whose arms RECEIVE ownership). Needs a
  decision on the spelling; natural home beside S-2's move work (1.4.3)
  or its own slot.
