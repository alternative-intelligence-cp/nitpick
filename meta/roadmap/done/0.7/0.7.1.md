# 0.7.1 — The IR writer

**Cycle 0.7 — IR emission core.**

## Goal

The module every later subcycle writes through: a growable output, deterministic
temporary and label naming, and symbol mangling that matches the seed exactly.

No semantics. This subcycle produces no IR that means anything — it produces the
thing that will.

## What it is

`src/backend/ir/ir_writer.npk`, the first module of the backend.

**Text, not a structure.** The output is LLVM IR as characters, which is what `llc`
takes and what a person reads during bootstrap. There is no intermediate object
graph, because there is one consumer and the text *is* the artifact.

## The three properties, and why each is not a free choice

### Determinism (D-078)

**Identical input must produce byte-identical output** — not equivalent IR,
identical bytes — because D-085's stage-1/stage-2 fixpoint compares two compilers'
output for equality.

So: temporaries are numbered sequentially from a counter, labels likewise, and
**every counter resets at each function**. That last part is not about determinism —
it is so that a one-function change produces a one-function diff, which is what makes
the fixpoint check's output readable when it fails.

`irw_temp` is the **only** source of a value name. Two schemes numbering into one
space is how a `%3` comes to mean two things.

### Symbol naming is the seed's decision, not this module's

`@main` keeps its name so the linker finds it; everything else is `@npk_<name>` so a
Nitpick name cannot collide with a runtime symbol.

**This matches `bootstrap/generator/emit.py` exactly and had to.** Stage 1 is built
by the seed and calls into the same runtime; a different prefix would be two
compilers emitting calls to two different symbols, and nothing would catch it until
the link failed.

### The sink grows now, and that was a change to shared code

`sink_to_buffer` had a fixed capacity and **dropped whatever did not fit** — "full;
drop the rest". That is a defensible answer for a diagnostic renderer, whose total is
already bounded by `diaglist`'s own cap. It is the wrong answer for an emitter:

> **IR that is silently truncated is a program that compiles to something other than
> what was written, with nothing anywhere reporting it.**

The alternative was a second buffer mechanism for the backend, which the blueprint
philosophy argues against — two things doing one job means remembering which applies
where. So the sink grows, and **the bound stays where it belongs**: on the diagnostic
list, which is what the fixed cap was protecting.

## What the test asserts, and what it deliberately does not

`tests/backend/ir_writer.npk` — the first backend test, registered as a new
**positive** suite in `nitpick.toml`.

It does not assert "IR came out". It asserts the two properties the cycle rests on:

- **The same program twice is the same bytes.** Built by calling one `build`
  function against two writers and comparing byte for byte.
- **Symbol naming matches the seed** — `@main`, `@npk_alloc`, `@npk_f`.

Plus that temporaries are sequential and per-function, and that the sink grows rather
than truncating — written far past the initial capacity, with the expected length
**computed from the string's own length rather than counted by hand.** A
hand-counted constant is a number that is wrong once and then asserted forever; the
first version of that line said 28 where the answer was 27.

**A backend test cannot be a rejection case**, which is why the suite is positive:
the thing being checked is the IR, and IR that is wrong in a way that still assembles
produces no diagnostic at all. That is the same argument 0.6 made for asserting on
expansion output rather than on diagnostics.

## Done when

- A writer produces byte-identical output for identical calls.
- Temporaries and labels are sequential and reset per function.
- `ir_symbol` agrees with the seed for `main` and for everything else.
- The buffer grows instead of dropping, and a test writes past its initial capacity.
