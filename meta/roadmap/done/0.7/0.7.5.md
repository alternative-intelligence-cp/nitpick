# 0.7.5 — Expressions: arithmetic, comparison, casts, calls

**Cycle 0.7 — IR emission core.**

## Goal

`src/backend/ir/ir_expr.npk` — literals, names, unary and binary operators,
short-circuit `&&`/`||`, scalar casts, calls to user functions and to the runtime
floor, and `raw`. Plus `src/backend/ir/ir_runtime.npk`, whose existence this
subcycle had to argue for.

## The frontend's answer is the type; the emitter never types anything

The checker recorded every expression's type in `ExprTypes` (0.4.2), and
`check_kinds_typed` holds the line that every kind is covered. So the emitter reads
`exprtypes_get` where the seed rebuilds a checker scope per node and asks again —
and asking again is two typings of one expression, which is two chances to
disagree.

It also kills the seed's argument-coercion machinery outright: D-092 has no
implicit widening, so the checker already made every argument **exactly** its
parameter's type, and the emitter passes values as themselves.

## Why `ir_runtime.npk` exists — the third copy of one fact, diffed

The one place `ExprTypes` is silent is a bare-name builtin call, typed UNKNOWN **on
purpose** (`type_expr.npk`: *"a bare-name builtin resolves to no symbol and that is
correct; its signature arrives with call checking"*). So the emitter must know the
floor the way the seed does — which makes a third copy of what `npkrt.ll` defines:
the runtime **defines**, the seed declares for stage 1, the compiler declares for
stage 2.

None of the three is removable, so `check_runtime_sigs_agree` diffs all three on
every full run — parsing the `define` lines out of `npkrt.ll` itself, through
balanced parentheses, because the first draft was line-anchored and two multi-line
defines came back "missing". Negative-controlled: one byte changed in the table is
one failure reported.

`RtSig` stores `wrapped` and `inner` rather than deriving them from the return
text, because sniffing "is this a Result" out of text makes `cstring`'s
`{ ptr, i64 }` one brace away from a wrong answer — the slot-that-means-two-things
class, avoided by storing the fact.

## Two deliberate departures from the seed

- **No `nsw`, no `nuw`, ever** (D-037: overflow is defined wrapping). The seed also
  omits them; here it is stated as a rule with the reasoning attached: the flag is
  the license for LLVM to delete exactly the guard a safety language adds, and the
  prototype's workaround — disabling optimisation for affected types — put a
  guarantee in a build flag, where verification (which analyses optimised output)
  never sees it. The test pins `%t4 = add i32 %t2, %t3` as bytes.
- **Extension follows the source's signedness, not the target's.** The seed
  sign-extends whenever the *target* is signed, so `uint32 => int64` of a value
  with the high bit set goes NEGATIVE — breaking D-021's no-loss promise in a
  corner its one program never exercises. Here: signed source `sext`, unsigned
  source `zext` (`bool` and `char8` are unsigned — neither has negative values),
  truncation truncates. The test pins `zext i32 … to i64` for the uint32 case
  beside `sext` for the int32 one.

One more that is smaller but of the same kind: **comparisons default unsigned**,
and only a signed integer opts into `slt`-family predicates — because `char8`
orders by code point, and `slt` would sort the upper half of every encoding below
NUL. The seed compares chars signed; its one program never compares a byte past
127.

## What deliberately does not lower here

- **`relay`** — it branches and runs `defer`; it is control flow in expression
  position and lands in 0.7.6 with the rest. Until then it refuses with the cycle
  that lowers it.
- **Places** — `@x`, `<-p`, member access, indexing — belong with assignment
  (0.7.6), which is what needs an address rather than a value.
- An unclassified kind fails closed (`LL_BROKEN`), never guesses.

## Also fixed on the way

`cat3`/`cat4`/`cat5` were private in two backend modules; the seed compiles the
group as one namespace and refused the duplicate — so they are `pub` in
`ir_writer.npk`, once. The seed's arity check (D-127's gift) then caught four
`cat5` calls passing six arguments, one by one, at compile time — the exact class
of error that cost two days when nothing checked it.

## Done when

- Every emitted shape byte-matches its pin, and every pin assembles under `llc`
  (verified with completed bodies).
- The three-way runtime signature diff runs green on every full run and fails on a
  one-byte perturbation.
- `raw` extracts from a wrapped call, passes a bare one through, and `Result<NIL>`
  yields its `i32 0`.
