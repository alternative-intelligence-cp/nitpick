# 0.2.2 — Types

**Cycle 0.2 — AST and parser.**

## Goal

`TypeNode` parsing in full, and the `>>` split.

## Work

1. Named types, generic arguments, `Result<T>`.
2. Pointers `T->`, slices `T[]`, arrays `T[N]`, qualifiers (`wild`, `stack`,
   `fixed`, …).
3. Generic parameter lists on declarations — `<T>`, `<T: A & B>` with `&`
   combining (D-029), and `<comptime int32:LEVEL>` value parameters (D-064).

## The `>>` split

The lexer emits `>>` as one token because a type position is not lexically
detectable (0.1.5). When the parser needs a `>` to close a type-argument list and
finds `OpShr`, it calls `tokenlist_split_shr` and consumes the first half.

`Handle<Node<int64>>` must parse; `x >> 2i32` must stay a shift. Both get tests,
because the failure mode is silent -- a wrong split produces a valid parse of a
different program.

## Done when

- Every type form in `TYPE_REFERENCE.md` parses.
- Nested generics close correctly, and shifts are untouched.
