# 1.0.9c — The value and pattern lowerings

**Cycle 1.0, the tail's third part.** The rows of the disposition table that
are backend work with no decision behind them, plus D-169 at the checker and
the one builtin D-061 named and nobody wrote.

## What it builds

- **Multi-payload variants**: construction (`Ev.Move(1i32, 2i32)`) and the
  destructuring binding (`(Ev.Move(x, y))`) — the payload is a `{ … }` of the
  payloads, laid out as the enum's interned layout already says; the
  exhaustiveness analysis (0.5) already speaks for the arms.
- **Struct destructuring in `pick`** — the pattern tail 0.9.7 scheduled.
- **A call through a function-valued member** (`s.f(x)` where `f` is a field
  of function type, and `(s.f)(x)`): the checker distinguishes it from a UFCS
  method today; it lowers as an indirect call with one more step to fetch the
  callee.
- **`comptime(…)` in a runtime position** — the folder already produced the
  constant at 0.6; emit it.
- **The pipe** — "a call written the other way round" (`type_pipe`); lowers
  as the call.
- **Non-scalar casts enumerated**: every pair `cast_class` admits for a
  non-scalar (`=>`/`=>!`) is listed, then lowered or refused at the checker by
  name — none left to the rung.
- **The remaining builtins enumerated** against BUILTIN_REFERENCE: each is
  lowered or re-pointed by name at the cycle that consumes it.
- **D-169 at the checker**: `==`/`!=` on a struct, array, `Result`, two
  non-`NIL` `Optional`s, `string` or `dyn` refused with `TYPE_NOT_COMPARABLE`
  and the spelling that works; the 1.0.7 rung retires and
  `nonscalar_compare.npk` moves to the types suite.
- **`#unreachable()`** (D-061): a builtin that traps through D-142's route;
  the `(!)` message's advice becomes true.

## Tests

One executed program per lowered row; one rejection per checker refusal; the

## Done when

## Outcome

**Every value and pattern lowering landed, D-169 moved to the checker, and
`#unreachable()` exists — nine rows, each an executed program or a named
refusal, no generic rung left behind.**

### The lowerings

- **`comptime(…)` in a value position** emits the FOLDED constant (`fold_const`
  in the emitter), not the runtime evaluation — the point of writing `comptime`
  where a value goes, and the only way `comptime(GLOBAL)` yields a value before
  module-level bindings lower (1.0.9d).
- **The pipe** `x |> g` lowers as `g(x)` — a named function directly, a function
  value through the pointer. Fixing the lowering surfaced a latent `type_pipe`
  bug: it returned the bare success type where a call returns `Result<T>`, so
  `x |> g` and `g(x)` had been two different types for one operation, caught by
  nothing because nothing had lowered it. It wraps in `Result` now, like a call.
- **A call through a function-valued member** — `(s.f)(x)` and `s.f(x)` where `f`
  is a field of function type — lowers as an indirect call, the field loaded
  first. The field is the more specific reading of `.f` than a UFCS free
  function, tried first on both checker and emitter by the same rule. The "a
  call through a member" rung retires for this shape.
- **Multi-payload variants** construct and destructure: a variant's payloads are
  laid out as a struct (the layout sized the area by the largest variant's SUM,
  not the largest single field, which is why it was a rung), and one
  `variant_payload_slot` gives construction and binding the same offset and type
  per payload so they cannot drift.
- **Struct destructuring in `pick`**: an irrefutable arm that binds the struct's
  fields by name. It covers the selector like a wildcard (a struct has no `==`,
  D-169), and the selector being an aggregate is exactly why a struct pick takes
  the compare chain, not the switch. The checker now types the bindings — a
  per-binding types-window on the pattern, read back by name — which also closed
  a latent hole where MULTI-payload enum bindings typed as unknown.
- **Non-scalar casts** are enumerated: every pair `cast_class` admits lowers
  (an enum's tag is read, a `tbb` takes the matrix, a pointer is a no-op, a
  kernel id is scalar), and the one it admitted that could not lower — an integer
  forging a payload-carrying enum — is refused at the checker by name
  (`TYPE_NO_CAST`). The generic "a cast between non-scalar types" rung is retired.
- **The remaining builtins** are enumerated by construction: `call_builtin`
  lowers a bare-name builtin to its runtime call or refuses it BY NAME (`the
  builtin \`x\``), and `emit_builtin` fails closed — no builtin falls through to
  a generic rung.

### D-169 and `#unreachable`

- **D-169** moved `==`/`!=` on an aggregate from a backend rung to a checker
  refusal (`TYPE_NOT_COMPARABLE`, TYPE-034): a struct, array, `Result`, `string`,
  `dyn`, two non-`NIL` `Optional`s or a payload-carrying enum has no built-in
  equality, and the message names `Eq`. `x == NIL` stays — found on the AST, since
  an unsuffixed `NIL` takes the `Optional`'s type before the comparison is typed.
  `nonscalar_compare.npk` moved from the rung suite to the type-rejection suite.
- **`#unreachable()`** (D-061) is the builtin that replaced the removed `(!)`: it
  traps through D-142's route (`UNREACHABLE`, −4102) if control ever reaches it,
  so a wrong exclusion is a controlled stop, not undefined behaviour. As an
  expression it takes the type its position expects; reaching it runs the trap
  and hands back an `undef` in a fresh dead block. The `pick` `(!)` message now
  points at it directly.

### Tests

Seven executed programs (`comptime_runtime`, `pipe`, `fn_field_call`,
`unreachable_arm`, `multi_payload`, `struct_pick`, `enum_int_cast`) and two
checker rejections (`cast_payload_enum` → TYPE-032, `nonscalar_compare` →

### A generator hazard found and avoided

`bootstrap/generator/gen_tables.py` is STALE — the committed generated files
(`ast_kind.npk`, `builtin_types.npk`, `num_width.npk`, `builtins.npk`) are hand-
maintained ahead of it, so re-running it REGRESSED them (dropped D-164's
`TypeProjection`, the arena/handle type mappings, the char widths, and half the
bare-name builtins). `#unreachable` was added to `is_hash_builtin` by hand and to
`BUILTIN_REFERENCE.md` for a future, corrected run; the generated files were
reverted to HEAD. This is worth a decision: either the generator is retired, or
it is brought back in sync — running it as-is corrupts the build.

### What the self-host check caught

The seed's checker is looser than the real one, and the difference surfaced on
the first full run: `pass (raw PayloadSlot{ … })` in `variant_payload_slot`
applied `raw` to a struct literal, which the seed accepted and npkc — checking
ITSELF — refused with `NITPICK-TYPE-007` ("`raw` needs a `Result`"). `raw`
discards a `Result`; a struct value is not one, and `pass` wraps it. Fixed to
`pass (PayloadSlot{ … })`. This is the self-host check doing exactly its job —
holding the compiler to the standard it holds every other program to.

The second full run was green: stage 1 rebuilt itself byte-identically, 80
real-backend programs ran, the rung suite shrank by two.
