# 1.0.9d — The library-facing decisions, and the cycle closes

**Cycle 1.0, the tail's last part.** The four decisions that build library
surface — each is what the concrete collections and the compiler's own
diagnostics will use when 1.2 switches the builder.

## What it builds

- **D-165 — module-level bindings.** A constant initialiser lowers to an LLVM
  `constant`/`global` under D-156's symbol; a call in one is refused
  (`TYPE_GLOBAL_NOT_CONSTANT`); `a module-level binding` and `a name that is
  not a local` retire.
- **D-168 — `&{ }` through `ToString`.** The prelude's `impl:…:ToString` for
  every builtin scalar over floor conversions (`npk_int_to_string` and
  siblings, one per family); the template lowers to a `string_concat` chain;
  a type with no impl is refused at the checker (`TYPE_NOT_STRINGABLE`);
  `a template literal` retires.
- **D-166 — `for` over an `Iterator`.** `Self->` admitted as a receiver in a
  trait signature (`check_signature` substitutes through the receiver's
  wrapper; object safety treats it as a receiver); the prelude's `Iterator`;
  the loop lowering (`next(@it)` until `NIL`); the binding's type must equal
  `Item`. `a `for` over this iterable` retires.
- **D-123's two generators**: `#[derive(Hash)]` (FNV-1a over every field, a
  `string` through its bytes) and `#[derive(Ord)]` on an enum (the tag
  through `=>! int32`); `DERIVE_NOT_GENERATED` retires with them.

## Closing the cycle

`rg '"1\.0"' src/backend` returns nothing; `check_rung_names_open_cycle`
passes with `1.0/` moved under `done/`; the README row is struck; the roadmap's
cycle map marks 1.0 DONE with the cycle's findings summarised the way
0.9's are. Then the push, per the convention.

## Done when

All four land with their specs current; the fixpoint holds; cycle 1.0 is in
`done/`.

## Outcome

The four decisions landed as four commits — D-165 (module-level bindings lower
to LLVM `constant`/`global` under D-156's symbol; a non-constant initialiser is
`TYPE_GLOBAL_NOT_CONSTANT`), D-168 (`&{ }` renders through `ToString`, the
prelude supplying impls for every exact scalar family; `char`/`flt` scheduled
post-1.0, OPEN_DECISIONS §6b), D-166 (`for` over an `Iterator` with a `Self->`
receiver), and D-123 (`#[derive(Hash)]` via FNV-1a, `#[derive(Ord)]` on an enum
by its tag). Each held the fixpoint byte-identical.

### The cycle closed: the last six "1.0" rungs

Closing the cycle meant driving `rg '"1.0"' src/backend` to nothing. Six sites
remained; the disposition table's verdict for each was verified against the
frontend before the string was removed:

- **`a `for` over this iterable`** (`ir_stmt`) → `iv_broken`. `check_for`
  (D-166) admits exactly range, slice, array, pointer, and an `Iterator`
  implementor — the five arms the backend already handles — and refuses
  everything else with `TYPE_NOT_ITERABLE`. The fallthrough is unreachable.
- **`the defaults operator`** (`ir_expr`) → `iv_broken`. `?|` is struck at parse
  (D-167, `PARSE-009`); a clean program never reaches the backend guard.
- **`the builtin `name``** (`ir_expr`) → `iv_broken`. Every `is_builtin_name`
  either lowers inline (`string_byte_length`, `string_is_empty`,
  `shared_arena_make`, `arena_make`), is `sys`, or has an `rt_sig` entry — the
  resolver admits no other name, so the catch-all is unreachable.
- **`a call through a member`** (`ir_expr`, ×2) → `iv_broken`. `emit_call` routes
  a function-valued member to `emit_indirect_call`; `emit_enum_ctor`/`emit_ctor`
  are entered only for a checker-confirmed enum constructor.
- **`a postfix operator`** (`ir_expr`) → **struck, D-174**. `++`/`--` was the one
  shape left, and it had no owner cycle anywhere in the roadmap — evidence it was
  never a planned feature, only an unremoved prototype inheritance. It is struck
  the way `?|` was: redundant with `x += 1`, and its value form hides a write
  inside an expression, which the blueprint philosophy forbids. The parser
  refuses `a++`/`a--` by name (`PARSE_INCDEC_REMOVED`, `NITPICK-PARSE-010`) with
  the replacement; the backend guard becomes a defensive `iv_broken`.

`check_rung_names_open_cycle` now enforces the close: with `1.0/` under `done/`,
any `iv_rung` still naming "1.0" fails the harness. The surviving "1.1" and
"1.3" rungs (async, verification) name cycles still open, as intended.

### KIND_STATUS corrected

The two struck operators (`ExprPostfixExpr`, `ExprDefaultsExpr`) moved to
`inert` with the reason stated; four kinds that 1.0.9b/c/d actually lowered
(`ExprTemplateLiteral`, `ExprPipeExpr`, `ExprComptimeExpr`, `ExprDynCastExpr`)
had stale `rung` labels corrected to `lowered` — the check tolerated them
(`lowered` and `rung` both require only a mention) but the table is the
description the backend is diffed against, and it now reads true.
