# 1.0.2 — Monomorphization lowering

**Cycle 1.0.** With names settled (1.0.0), instantiate-dedup-emit becomes real:
a generic used at a concrete type lowers to a specialized definition under its
D-156 symbol. Gated on C-1 (done).

## What it builds

- **Instantiation lowering** — emit the specialized struct/function body with type
  parameters substituted, once per distinct mangled name (D-108 dedup already keys
  the frontend table; the backend emits each once).
- **The depth-cap diagnostic prints the instantiation stack** (D-064 §6, currently
  one sentence — grammar #12): exceeding depth 64 names the chain that reached it,
  not just the limit.

## Tests

`Container<int32>` and `Container<int64>` emit distinct specialized types and run; a
nested instantiation (`Box<Container<int32>>`) references the inner instance's own
symbol; dedup proven by a repeated instantiation emitting one definition (grep the
IR); the depth cap prints the instantiation chain.

## Done when

Generic TYPES lower and run; dedup emits one definition per mangled name; the
depth-cap diagnostic prints the stack; the fixpoint holds.

## Outcome (recorded at close)

**Generic types lower; generic FUNCTIONS are split to 1.0.2b.** The two are
different work and the split is worth stating: a generic type needs one
`%"npk.mod.Container<int32>" = type { … }` per instantiation, which is a
substituted body walk — done here. A generic *function* needs one BODY per
argument set, which needs the call site to record which instantiation it wants
and the emitter to walk instantiation requests rather than declarations; the
`iv_rung("a generic function"/"a generic call", "1.0")` refusals stay until it
lands, and `tests/rejection/generics.npk` stays as their inversion.

What landed: `ll_named`/`ll_enum` render an instance's mangled name (legal now
that D-156 quotes every symbol — that was the whole reason they refused);
`ll_struct_body` substitutes, pushing `r.generics` from the declaration's
parameter window bound to the instance's arguments and re-homing the scope, the
same two moves `type_layout` (0.8.1) makes for the same reason (a struct's
parameters are declared into no scope, so `T` resolves through
`generic_lookup`, never a scope lookup); `emit_type_headers` walks the interned
TYPE TABLE for instances, which is why dedup needed no new mechanism — D-108
already keys an instantiation by mangled name, so the table holds each exactly
once and the emission order is the interning order (deterministic, which the
fixpoint requires). A generic declaration itself emits nothing: it is a
template, and resolving its fields would resolve `T` with nothing bound — the
removed `args_count > 0` rung had been masking that, and skipping generic
declarations in the header walk is the honest form.

The depth cap now carries the chain (D-064 §6's "the instantiation stack",
which was one sentence): the resolver holds a 64-entry name array pushed and
popped with `depth`, and the message reads `A -> B -> A`. (Named `inst_chain`,
not `stack` — `stack` is a reserved memory qualifier.)
