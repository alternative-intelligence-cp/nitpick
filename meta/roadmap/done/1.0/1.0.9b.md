# 1.0.9b — The trait and grammar decisions land

**Cycle 1.0, the tail's second part.** Three decisions settled at 1.0.9's
opening are spellings, and spellings are parser work plus everything
downstream of it — which is why they are one subcycle rather than three lines
in 1.0.9.

## What it builds

- **D-170 — `(` Type `)`.** One production in `p_parse_type`: a parenthesised
  type is its inner type with the suffixes applied to the group. No new node
  kind. `(dyn Speaks)[2]`, `(dyn A & B)->`, `(dyn Speaks)?` become spellable;
  `dyn_slots.npk`'s array case is rewritten to the direct spelling, and the
  `Pair<dyn Speaks>` route stays as the substitution case it also is.
- **D-171 — every impl names its target.** `p_parse_impl` reads
  `impl:<params>:Target(:Trait)?`; the blanket impls in `tests/` and the specs
  become `impl:<T: P>:T:Trait`; `collect_impls` classifies by slot 1 (a bare
  parameter → blanket, an instantiation mentioning the parameters → family,
  otherwise per-instance) — no segment counted, no shape heuristic. The
  inherent family impl (`impl:<T>:List<T> = { … }`) resolves, checks,
  dispatches and emits through the family machinery with trait 0;
  `generic_list.npk` gains a `push` METHOD beside the free function, which
  needs D-166's `Self->` receiver only for a trait — an inherent method on
  `List<T>` may take `List<T>->:self` today.
- **D-172 — `Trait.method(recv, …)`.** `namespace_member` gains the trait
  case; the call resolves the method for the receiver's type through
  `find_method` with the trait fixed, fits the receiver as parameter 0, and
  lowers through the existing method-call path (the "a call through a member"
  rung retires for this shape; the function-valued-field shape is 1.0.9c's).
  The ambiguity diagnostic names the form.
- **The `dyn` cast** (`x => dyn Speaks`, `DynCastExpr`) lowers as the
  explicit spelling of the slot widening: `emit_fit` with the cast's target.
- **A `dyn` over a family instance:** a vtable per recorded family
  instantiation, emitted beside its methods, so `dyn Sized:s = List<int32>`
  dispatches; the rung retires.
- **The bare-trait rung** (`TY_TRAIT` in `ll_type`) is converted to
  `LL_BROKEN` once the checker is shown to refuse a trait in every value
  position (a probe per position).

## Tests

A program per decision: `type_group.npk` (an array, a pointer and an
`Optional` of a `dyn`, dispatched through), `impl_target.npk` (a blanket impl
in the new spelling, an inherent family impl with a mutating method, a
per-instance impl beside a family one still refused as overlap), and
`trait_qualified.npk` (two traits supplying one name, each reached by its
qualified form, and the unqualified call still refused by name). Rejection
cases for the old blanket spelling (refused with the new form in the message),
for a qualified call on a type that does not implement the trait, and for a
`dyn` cast to a trait the value does not implement.

## Done when

The three decisions are implemented and their specs read as current (the
TRAITS_REFERENCE §2.4 note from 1.0.7 is struck); the `dyn` cast and family
`dyn` rungs are gone; the fixpoint holds.

## Outcome

**All three decisions, both `dyn` rungs, and the two stale diagnostics landed;
the specs read as current and the fixpoint holds.**

### The three decisions

- **D-170 — `(` Type `)`.** One production in `p_parse_type`; `p_looks_like_decl`
  learned that a leading `(` opens a type group so a statement can begin with
  one. `type_group.npk` builds an array, a pointer and an `Optional` of a `dyn`
  and dispatches through each (exit 42).
- **D-171 — every impl names its target.** `p_parse_impl` reads
  `impl:<params>:Target(:Trait)?`; `collect_impls` classifies by slot 1 —
  `impl_is_blanket` tests whether the target is a bare argument-less parameter,
  which separates a blanket (`impl:<T: P>:T:Trait`) from a family
  (`impl:<T>:Box<T>:Trait`) with no segment count and no shape heuristic. The
  inherent family impl (`impl:<T>:Box<T> = { … }`) resolves, checks, dispatches
  and emits through the family machinery with trait 0, and one of its methods
  mutates through a `Box<T>->:self` receiver. `impl_target.npk` proves the
  blanket and the mutating inherent family method together (exit 42).
- **D-172 — `Trait.method(recv, …)`.** A trait name in expression position is a
  namespace; the call resolves the method for the receiver's type with the trait
  fixed, fits the receiver as parameter 0, and lowers as a direct call
  (`emit_qualified_call`), so the "a call through a member" rung retires for this
  shape. `trait_qualified.npk` reaches two same-named methods, each by its trait
  (exit 42).

### The two `dyn` rungs

- **The `dyn` cast** (`x => dyn Speaks`, `DynCastExpr`) lowers as `emit_fit` to
  the cast's target — the same fat-pointer build a `dyn` slot triggers
  implicitly, so the explicit and implicit forms cannot drift. Its trait
  operands resolve through `resolve_trait_type`, not the value-type path D-171
  refuses.
- **A `dyn` over a family instance.** A family impl's vtable is per
  instantiation, so it is registered and emitted by a pre-pass in `emit_all`,
  before the function loop where `emit_dyn_from` reads the table — the same
  timing `build_vtmap` gives a per-instance impl. It is built only when every
  slot has a recorded method (`family_vtable_ready`), and a `dyn` coercion is
  what records them: `fits`, on accepting a value into a `dyn` slot, calls
  `record_dyn_family_methods`, which records every one of the trait's methods for
  that instantiation. `dynfam.npk` builds a `dyn` from a `Box<int32>` never
  called directly and dispatches (exit 42). The old rung message ("enabled by
  cycle 1.0") became a fail-closed `iv_broken`, since a missing table now means
  the checker accepted a `dyn` the emitter could not build.

### The bare-trait rung and two stale diagnostics

The `TY_TRAIT` case in `ll_type` is `LL_BROKEN`, confirmed by a probe per value
position (local, parameter, return, field, array, pointer, optional) — the
checker refuses each with `NITPICK-TYPE-002`, so the backend case is unreachable
for a valid program. Two diagnostics the audit had left pointing at the old
world were corrected: the method-name ambiguity (`TYPE-020`) now names the
`Trait.method(recv, …)` form as the fix rather than "no call spelling names one
of the two yet", and an OLD blanket spelling (`impl:<T: Bound>:Trait`) is caught
by name (`TYPE-012`) with the new form in the message rather than the generic
"is a trait, not a value type".

### Tests and specs

Three accept programs (`type_group`, `impl_target`, `trait_qualified`) and three
rejection cases (`impl_old_blanket`, `trait_qualified_call` covering both the
non-implementor and the still-ambiguous unqualified call, `dyn_cast`). Every
old-spelling blanket in the suite was rewritten to `impl:<T: P>:T:Trait`
(`coherence.npk`, `whole_grammar.npk`, the `type_generic.npk` and
`type_access.npk` unit strings). TRAITS_REFERENCE's §2.4 T-7 note is struck and
replaced with what D-171 settled; §2.6's blanket form and the UFCS section carry
the new spellings and the qualified call; DECISIONS.md marks D-031 amended and
D-161 superseded by D-171.

### What the whole-suite checks caught

A full run over the first draft failed three ways, each a check doing its job,
none found by a test:

- **`check_slot_sites_agree`** — `emit_qualified_call` calls `emit_fit` and no
  row paired it. D-172's receiver-and-args fit is checked by `check_args`, so
  that row now claims the emitter; the check forces every new coercion site to
  declare its checker partner.
- **The real-parser sweep** — `too_deep.npk` (a macro-depth rejection) stopped
  parsing. D-170's leading-`(` made `p_looks_like_decl` scan a 512-token nested
  expression and hit the "cannot tell a declaration from an expression" error
  instead of the macro-depth refusal. A parenthesised TYPE caps near 200 tokens
  (D-064), so a leading `(` that has not resolved in budget is a long
  expression, not a broken type — it falls back to the expression parser now,
  which is what it did before D-170.
- **The self-host check** — `npkc` could not compile itself: the family-vtable
  pre-pass reached its resolver through a LOCAL emitter, a borrow the escape
  analysis cannot name (BORROW-009). Extracted into `emit_family_vtable`, where
  the emitter is a parameter — the same shape `emit_family_instance` already
  had, and the reason it self-hosted while the inline draft did not.

The second full run was green and stage 1 rebuilt itself byte-identically.
