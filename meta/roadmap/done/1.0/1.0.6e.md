# 1.0.6e — A `dyn` is built at every slot, not only at a declaration

**Cycle 1.0.** Found at 1.0.7's opening, by reading the CALLERS of
`emit_dyn_from` before adding the `Optional` wrap beside it: there is exactly
one, the declaration initialiser. **A concrete value meets a `dyn` slot at
sixteen places in the checker and is built at one in the emitter.** Scheduled
ahead of 1.0.7 rather than folded into it, on 1.0.5b's precedent: a defect with
a segfault in it gets its own record, its own test, and its own commit.

## What was measured

`fits` (`type_expr.npk`) admits a concrete value into a `dyn` slot wherever a
value meets a slot — a declaration's initialiser, an assignment, a call
argument, `pass`, a `Result{…}` or struct-literal field, an array element, a
`pick` arm's `give`, an unwrap's default. The emitter widens at the first of
those and stores the raw value at the rest. Three probes, each a program the
checker accepts without a diagnostic:

| Slot | What the emitter did | What happened |
|---|---|---|
| call argument `speak(d)` | passed `%Dog` where `{ ptr, ptr }` is declared | `llc` rejected — fails closed, not by name |
| `pass d;` from a `dyn`-returning function | returned `%Dog` as `{ ptr, ptr }` | `llc` rejected — fails closed, not by name |
| assignment `q = c;` into an existing `dyn` | **stored the 4-byte `Cat` over the 16-byte slot** | compiled, linked, ran, **segfaulted** (exit −11) |

The third is the one this subcycle exists for. With opaque pointers a `store`
checks nothing against the pointee, so the emitted IR is legal:

```llvm
  store { ptr, ptr } %t9, ptr %t5             ; the dyn built at the declaration
  %t10 = load %"npk.dyn_assign.Cat", ptr %t3
  store %"npk.dyn_assign.Cat" %t10, ptr %t5   ; the assignment: 4 bytes over the data word
  %t11 = load { ptr, ptr }, ptr %t5
  %t12 = extractvalue { ptr, ptr } %t11, 0    ; data word: Cat's bytes, vtable word: still Dog's
  …
  %t16 = call { i32, i32 } %t15(ptr %t12)     ; Dog's thunk, through a garbage pointer
```

The data word now holds the `Cat`'s field bytes and the vtable word still names
`Dog`'s table. This run read through address zero and died; a `Cat` whose
field held a plausible address would have returned an answer instead. **An
uncontrolled crash from a program the checker accepted** is the event this
language exists to make impossible, and it is reachable from one assignment.

## Why it was never caught

`dyn_vtable.npk` covers construction at a declaration and dispatch through it,
thoroughly. No test has ever put a concrete value into a `dyn` slot any other
way. Same finding as 1.0.6b's: bound, call and impl each had coverage and the
combination had none — here, `dyn` and each slot kind each have coverage and
`dyn` × slot has one of sixteen. 1.0.5c's own comment on the declaration site
says why the construction mattered ("stored 4 bytes into a 16-byte slot") and
then built it at the one site its test reached.

## What it builds

- **One slot helper in the emitter, `emit_fit`**, the backend's half of `fits`:
  given the slot's type and the value in hand, it returns the value or the
  widened/rebuilt `dyn` — and nothing else, because `fits` licenses nothing
  else (D-092, D-099's wrap is 1.0.7's and lands in this same function). The
  declaration site's inline `dyn` block moves into it; the assignment, `pass`,
  call-argument (named, method, indirect, enum-constructor, arena), literal-
  field, array-element, `give` and unwrap-default sites call it. **One
  function, every site** — the same shape as `fits` on the checker's side, so
  that the two lists can be read against each other.
- **`check_slot_sites_agree`**, a whole-tree check: every `fits(` site in the
  frontend has a named `emit_fit(` counterpart in the backend, by a table in
  the check that pairs them. The list is small and closed; a new `fits` site
  without a partner fails the harness. It is the instrument 1.0.6b said did not
  exist for its combination gap — here the combination is enumerable, so it
  does.

## Tests

`tests/backend/programs/dyn_slots.npk`: a concrete value reaching a `dyn` slot
through every slot kind — argument, `pass`, assignment, struct field, array
element, `Result{…}` field, `give`, `?` default — each dispatched through
afterwards and each checked for the answer the OTHER implementor would not give.
The assignment case is the regression; the rest are the coverage 1.0.5c owed.

## Done when

Every probe above compiles, links and runs to its expected exit; `emit_fit` is
the only place a `dyn` is built or widened; `check_slot_sites_agree` runs on
every harness invocation and pairs every `fits` site; the fixpoint holds.

## Outcome

**Landed as planned, with one finding the plan did not have and one grammar
gap it could not close.**

**`emit_fit` is the one place a value is built into a slot.** Fourteen backend
sites call it — the declaration (where the inline `dyn` block used to be),
assignment (the segfault), `pass`, the three call forms (named, indirect,
method — argument `i` fit to parameter `i + skip`, the checker's own rule), the
variant constructor's payload, the arena and shared-arena value slots, the
struct, array and `Result{…}` literals, `?`'s default, and a `pick` arm's
`give`. The pick frame gained the slot's type so `give` could ask; the variant
payload resolves in the enum's home scope, as `check_ctor_args` resolves it.

**The signature travels on the call.** `check_args` measures arguments against a
function type that, for a generic or family-impl call, is the SUBSTITUTED one
computed under a binding only the checker held — so the emitter cannot
re-derive the parameter an argument is fit to. `callee_ft` is recorded beside
`callee`/`callee_sym`/`callee_trait`, the same mechanism for the same reason.

**The finding: `fninst_for_call` matched by argument types, and a fitted
argument would have matched nothing.** 1.0.2b found a generic call's
specialization by comparing each argument's recorded type with the
instantiation's parameter type — exact only while the two are equal. A `Cat`
arriving where `dyn Speaks` is declared (or, from 1.0.7, an `int32` where
`int32?` is) would have matched no instantiation and called the template's
symbol, which does not exist. It now matches `callee_ft` against the
instantiation's signature structurally (`tt_func` interns a fresh parameter
window per computation, so two computations of one signature are two ids — the
artifact `types_agree` already exists for). `twice::<int32>(0i32, c)` in the test
is the case.

**Every value leaves `emit_expr` carrying its recorded type.** The kind walk
returned `iv("i8", …, 0i32)` for comparisons and `bool` literals because
nothing downstream asked; `emit_fit` asks. One wrapper stamps the type where the
walk left it empty — the `type_of_expr` shape, for the same reason.

**The grammar gap.** The test's array case was written `dyn Speaks[2]:arr`, and
the checker refused it: the `dyn` production parses each operand with the full
type grammar and takes no suffix of its own, so `dyn Speaks[2]` is
`dyn (Speaks[2])` — an array is not a trait — and **no spelling exists for an
array, pointer or `Optional` OF a `dyn`**. `dyn Speaks->` and `dyn Speaks?` are
the same shape. The slot is reached in the test through a generic field
(`Pair<dyn Speaks>`'s `T[2]:items`), which is a real program and tests the same
emitter path; the spelling is a grammar question and therefore the user's —
raised at 1.0.9 as **T-6** with a recommendation (a parenthesised type,
`(dyn A & B)[2]`: explicit grouping, no precedence rule to remember, the
expression grammar's own answer).

**Two harness additions.** `check_slot_sites_agree` pairs the sixteen `fits`
sites with their `emit_fit` partners by a table, and a `refused:` row must still
find its rung string — so lowering `??` at 1.0.7 is forced to write its pairing
rather than forget it. Verified by making it fail three ways before it was
trusted. And `bootstrap/harness/quickemit.py` (1.0.5b's backend twin of
`quickcheck.py`) now runs the harness's two per-program scans — duplicate
symbols in the IR, undefined symbols in the object — and takes `--keep`; every
probe in this subcycle ran through it. **Recorded against myself:** I
overwrote that file without having read it, and only `git status` showed me it
already existed; its automatic rebuild-when-stale rule was better than the
manual `--no-build` flag I had written, and is what survived the merge.

**Reserved-word cost, recorded because CLAUDE.md asks for it:** `tid` as a
parameter name cost one build (it is a kernel identifier type).
