# 0.3.6 — Diagnostics, suites, and closing

**Cycle 0.3 — Modules, symbols, visibility.**

## Goal

Every failure this cycle can produce has a code, a span, and a test.

## Work

1. Codes centralised as in 0.1.6 and 0.2.1 — a mistyped literal at a call site
   silently invents a new code, and the test asserting the old one then fails for
   an unrelated reason.
2. The catalogue: unresolved name, duplicate declaration, private access,
   ambiguous path, missing file, unresolvable cycle, missing import target,
   wildcard shadowing.
3. A multi-file suite. `tests/` has been single-file throughout; a module system
   cannot be tested that way.
4. Extend the reachability habit: the "every Ident binds or diagnoses" check from
   0.3.5 joins `check_kinds_reachable` in the harness.
5. Close the cycle — `done/0.3/`, ROADMAP, push.

## Watch for

**The rejection suite gets a second job.** `tests/rejection/` currently asserts
that a construct outside subset 1 parses and is refused by the checker. Module
errors are refused *earlier*, by the loader, and a file that fails to resolve
never reaches the checker at all. Those need to be a distinct group, or the two
kinds of "correctly refused" become indistinguishable.

## Done when

- Every diagnostic in the catalogue has a code and a test.
- A multi-file test suite runs.
- The cycle is archived and pushed.
