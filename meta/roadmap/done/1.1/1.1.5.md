# 1.1.5 — `Error` is a type: declarations, retyping, and the great renaming (D-179)

**Cycle 1.1.** The foundation of the typed-error system, deliberately BEFORE
the executor (now 1.1.8): the executor mints deadline/windup/parking
failures, and built after this change it is built once.

## Stages

- **A — the declaration and the type.** `error:Name;` parses (a new decl
  kind — a language change, ratified with D-179); the `Error` type joins the
  type table as a nominal 4-byte non-number (no arithmetic, no ordering, no
  casts; equality and `pick` only; values exist only by naming a declared
  constant — the `bool`/`char` doctrine applied). The prelude declares the
  SYSTEM family carrying D-142's fixed codes (`HeapIntegrity` −4102,
  `DeadlineExceeded` −4107, …; npkrt.ll's hardcoded values are the
  stability constraint); user constants get deterministic positive codes in
  module-graph order. User code cannot declare into the system domain.
- **B — the retyping.** `Result<T>`'s error half, `fail`'s operand, `?!`'s
  operand and `failsafe`'s parameter all become `Error`. A tbb literal in
  error position becomes a type error — the loud migration edge. The seed
  learns the decl form and the (unchanged-width) lowering.
- **C — the sweep.** Every `fail Ntbb32` / `?! Ntbb32` in `src/`, `lib/`
  and `tests/` flips to a named constant. The compiler's own conventions
  get real names at last (`?! 9tbb32` → `TestAbort`-family, `?! 5tbb32` →
  `ProvenSlice`, `?! 25tbb32` → `Rederivation` — final names chosen in the
  sweep with a naming table recorded here). Sweep tooling per the 1.1.2
  pattern: propose, audit every site, full harness between rounds.

## Done when

`src/` compiles with zero numeric error literals; every test names its
errors; the system family round-trips through npkrt.ll unchanged; full
harness green; fixpoint holds.

## Stages A0/A/B/C outcome

**A0** renamed `Result.error` to `.err` ahead of the keyword (its own green
landing). **A** landed the declaration, the type, hash-derived codes (the
generated-tables discipline moved the keyword into LEXICAL_REFERENCE and
the node kind into AST_REFERENCE §1; mid-build the numbering was amended
from walk-order to FNV-of-`module.Name` so the seed and stage 1 agree
without a shared order — and a second amendment made the FILE BASENAME the
name authority after src's mod-less files all hashed under an empty name),
the prelude system family, and the refusal surface free from the
kind-based predicates.

**B** retyped `fail`, `?!`, `!!!` (which gained a checker arm it never
had), `Result{…}` literals, `.err`, and `failsafe`'s signature (TYPE-044 —
the convention became a rule). **C** renamed everything: src declares its
own defects file-locally (`BoundsId`, `ProvenSlice`, `Rederived`,
`FileUnknown` — zero numeric error literals remain, zero import churn),
59 test files carry named constants, 190 failsafe signatures retyped,
and the runtime-trap tests compare prelude names (`DivByZero`,
`DivOverflow`, `OutOfBounds` joined the family when the sweep found the
−409x codes the first table missed; `IoEof` covers the io floor's
marker, and "any kernel error" assertions became `is_error`).

The fix-loop's own finds: selfhost caught a signedness bug in the new
basename helper; the escape and layout analyses needed explicit
`TY_ERROR`-is-a-word arms (conservative defaults had it pointer-ish); and
two sweep regexes were caught mangling fixtures (a duplicate-field case,
and decls prepended to expression fragments) — each restored by hand.
`.is_error` beside `is_err(x)` remains the noted two-spellings candidate.
Full harness green; stage 1 rebuilt itself byte-identically. 1.1.6 (the
origin chain) is next.
