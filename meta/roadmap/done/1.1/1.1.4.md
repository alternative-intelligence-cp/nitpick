# 1.1.4 — Coroutine lowering: switched-resume state machines (D-177)

**Cycle 1.1.** The machines themselves — frames, resume functions, await
composition, the spawn and its join — over D-153's frame allocator, per
D-177's lowering. The run queue and futex parking are 1.1.5; here `async
main` drives through an entry shim and the join drives children directly.

## Stages (each lands compiling, harness-gated)

- **B — the checker's async rules.** `await` only inside an `async` function
  (`TYPE-043`, the spec's long-promised rule); `await`'s operand is a call to
  an `async` callee; the spawn form (`drop` of an un-awaited `async` call)
  only inside an `async` function (the join must have a frame to live in).
  The liveness-across-await walk: for each async function, which locals'
  live ranges cross a suspension point, recorded for the backend — C-8's
  future surface.
- **C — the minimal machine.** An async function with no crossing locals
  lowers to `[header | args]` frame + resume switch; direct `await`
  allocates the callee frame, drives it, copies the result slot at DONE,
  frees; `async main` runs via the entry shim. First async program runs.
- **D — crossing locals.** Frame-resident locals via the layout machinery;
  every read/write through the frame pointer in the segments after their
  first suspension.
- **E — spawn + join + wind-up.** `drop work()` links the child onto the
  scope's join list and (until 1.1.5) the join drives it at scope exit:
  every exit path joins under the executor deadline; first child error
  relays verbatim after all finish; deadline expiry sets `windup` and a
  still-unfinished child traps −4107. Await segments poll `windup` first.

## Done when

Async programs run under the real backend: an awaited chain returns its
value; a spawned child's error reaches the join and relays; wind-up unwinds
through `defer`; the fixpoint holds; the async rungs retire.

## Stage C design (settled during build)

- **Every `ret` flows through one seam.** `fnem_ret_pass`/`fnem_ret_fail`
  already centralise pass/fail (relay's error path calls `fnem_ret_fail`);
  `emit_exit`/`emit_return` and the close fall-through get the same treatment
  via a new `fnem_ret_agg` ("return this fully-built value"): sync = `ret`,
  async = store to the frame's result slot + `ret i8 0`.
- **Params are frame-resident from the start.** The caller stored them; the
  resume fn binds each param name to an entry-block GEP instead of an alloca
  copy, so a param used after a suspension just works. Only true LOCALS can
  cross, and stage C rungs those (stage D frame-slots them).
- **The switch rides the alloca stream.** The writer's three streams
  (module/allocas/body, 1.0.9a) place the entry block's tail: allocas and
  param GEPs accumulate during body emission, and `fnem_close` appends the
  state load + `switch` last, so it lands after every hoisted alloca and
  before the body. Switch default is a −4102 defensive block (D-061): a
  resume state nobody assigned is a defect, not a branch.
- **Frame size is the GEP-null idiom** — `ptrtoint (getelementptr %F, ptr
  null, i32 1) to i64` — a link-time constant, so the compiler's idea of the
  size and LLVM's cannot drift. `@npk_alloc`/`@npk_dalloc` allocate and free
  frames; no new runtime symbols.
- **Frame slot indices are fixed**: 0 resume_fn, 1 state, 2 windup,
  3 result (bare `i32` for `async main`), 4 join_head, 5 sibling,
  6 awaitee, 7+i = param i. The awaiter derives the callee's frame type
  name and resume symbol from the callee's mangled symbol
  (`%"npk.frame.<bare>"`, `@"npk.resume.<bare>"`) — cross-references are
  derivable, never carried.
- **The await site polls-and-propagates**: seg.K loads its own windup, on
  nonzero stores it into the awaitee's windup word, then drives. No skip
  path — a wound-up child unwinds through its own defers and answers
  through its result slot like any other completion (D-062). Nobody sets
  windup until stage E; the shape is complete now.
- **The suspend `ret i8 1` runs no defers** — suspension is not scope exit.
- **`async main`'s shim** is the emitted `@main`: allocate main's frame,
  store argv, drive once; DONE → return the bare i32 result; SUSPENDED →
  −4102 (nothing can legally suspend before 1.1.5's executor exists).
- **Checker rules added with the walk** (both TYPE-043): `await`/spawn
  inside `defer` (defers are cleanup and cleanup is synchronous — the join,
  not a defer, is where child-related blocking belongs, D-062), and `async`
  on `failsafe` (the crash path must not depend on an executor).
- **The walk** (`analysis/suspend.npk`, D-177's checker-side commitment):
  source-position liveness per async fn — a local crosses if a suspension
  point sits between its declaration and last use, where a suspension
  inside a loop extends to the loop's whole extent for locals declared
  outside it, a defer-body use counts at scope end, and an address-taken
  local in a suspending fn is conservatively crossing. Params exempt
  (frame-resident). Result recorded as a symbol flag the backend reads.
- **Stage-C backend rungs** (each retired by D/E): a crossing local; a
  suspension inside a `for` body (the hidden iterator slot crosses) or a
  value-`pick` (the hidden result slot crosses); `await` of a generic,
  method, or indirect call; the spawn form (stage E).

## Stage B+C outcome

Stages B and C landed together. The checker: `TYPE-043` covers await-in-sync,
spawn-in-sync, await/spawn-in-defer, `async failsafe`, and the bare call to
an `async` callee (recorded in D-177's checker-rules section); `await` types
as its operand's `Result<T>` (the suspension is WHEN, not WHAT), and the
D-163 licence already rules `raw await` out. The suspend walk
(`analysis/suspend.npk`) marks crossing locals on `ExprTypes` by var-decl
stmt index; positions ride a walk-order CURSOR because statement spans are
first-token spans — a binder registers past everything its initialiser
touched, a suspension past its operand's argument uses.

The backend: `async` functions emit as `i8 npk.resume.…(ptr %fr)` machines
per the D-177 frame; parameters are frame-resident GEP bindings; every exit
flows through `fnem_ret_agg` (store result + `ret i8 0`); the entry switch
rides the alloca stream; `@main` is the entry shim. `tests/backend/programs/`
`async_chain.npk` runs the composed machines to exit 42 — chain, error
relay through two frames, param-resident `while` awaits.

**One rung added beyond the plan: the first-evaluation rule.** An `await`
whose statement already minted a non-alloca temp refuses
(`an await after other evaluation in its statement`) — an SSA value from
before the suspension would not dominate its post-resume use. Stage D's
frame spill lifts it alongside the crossing-local, `for`-body and `pick`
rungs (`tests/rejection/async{,_crossing,_await_nested,_await_for,`
`_await_pick}.npk`; the old `async.npk` now exercises the spawn rung, which
stage E retires).

## Stage D notes (pre-drafted during C)

The frame type is FIXED at `fnem_open`, so stage D opens with a pre-scan of
the body before the type line is written: (a) every crossing-marked var-decl,
its type resolved the same way `emit_vardecl` resolves it, becomes slot
`7 + pcount + j`, GEP-cut in the entry block, bound at its declaration site
through the ordinary scope stack (shadowing costs nothing — slots key by
stmt index); (b) a `for` containing a suspension reserves its hidden
iterator slots in the frame; (c) a value-`pick` containing one reserves its
result slot — and the suspend walk gains eager registration for arm pattern
bindings and `for` elements at the same time (the lazy-registration residue
the walk's header confesses).

**A decision the user owes stage D** (raised at the 1.1.4-C report): the
first-evaluation rung — `x = v + await f(v)` refused because `v`'s SSA value
would not survive the resume — can be retired two ways. (1) Make it a
LANGUAGE rule: an `await` stands first in its statement's evaluation (or is
bound alone: `int32:t = relay await f(v); x = v + t;` — `t` is a crossing
local, which stage D makes frame-resident, so the workaround is always one
line). Suspension points stay statement-visible; no mid-expression re-entry
state exists for a verifier to model. (2) Build per-temp SSA spill — the
compiler tracks which statement temps are live across the suspension and
spills them to synthetic frame slots; evaluation order stays untouched, at
the cost of exactly the liveness machinery D-177 declined to inherit from
LLVM's CoroSplit (hand-built here, so verifiable, but the largest single
piece of new analysis in the backend). Recommendation: (1), as a D-17x
amendment — it is the blueprint-shaped answer and strictly simpler to
verify; (2) remains available later without breaking (1)-conforming code.

## Stage D1 outcome (crossing var-decl locals)

Landed as pre-drafted: `scan_crossing` walks statement positions under the
instantiation binding before `fnem_open` fixes the frame type; marked
var-decls become slots `7 + pcount + j`, GEP-cut at entry; the declaration
site binds the name to its slot and the alloca never exists. A marked decl
the scan cannot reach (inside a value-`pick`'s arms) refuses at the
declaration — refusal, never a dead slot. `async_locals.npk` runs scalars,
a struct written between suspensions, an address-taken local mutated
through a borrow across an await, and a defer on the post-resume error
path, to exit 42. The crossing rung and its rejection test retired.

Still open here: D2 (`for`-iterator state into the frame), D3 (value-`pick`
slots and arm pattern bindings, plus the walk's eager registration), the
first-evaluation decision (language rule vs temp spill — user's call,
drafted above), and stage E.

## Stage D2+D3 outcome

**D2 — loop state is frame-resident in a coroutine, uniformly** (whether or
not the body suspends, so no detector exists for the emitter's needs to
drift from): the counted loop's counter/limit/step/direction (the audit here
found `loop`/`till` were never guarded in stage C — a latent hole, closed by
framing), the range `for`'s hi and binding, the indexed `for`'s
base/len/idx/binding, the iterator `for`'s receiver, and the `when` tracking
flag. Roles 1–6 on the loop's stmt index; `loop_slot`/`loop_stash`/
`loop_reread` are the one seam. `async_loops.npk` runs all four kinds with
awaits inside to exit 42 (and documents that ranges are INCLUSIVE — the
first probe's arithmetic was wrong, not the emitter). The `for` rung and its
rejection test retired.

**D3 — pick arms suspend**: arm pattern bindings are frame-resident (role
7+ordinal on the ARM's stmt index; the scan mirrors `bind_payload`'s own
field/payload resolution and the emitter fails closed on any drift), and
`scan_expr` follows expressions into value-`pick` arms so their var-decls
and binds register too. The `give` slot needs no framing — written and read
in the same activation, always after the arm's last suspension. The ONE
position that still refuses is an `await` inside a `where` guard: the
compare chain re-reads the selector after a failed guard, and no frame slot
can save an SSA selector the next arm's test needs. `async_pick.npk` (exit
42) covers single/multi payload binds read after suspension, a struct
destructure, guards, and a value pick declaring a local across an await;
`async_await_pick.npk` now pins the guard rung.

Remaining in 1.1.4 after D2+D3: stage E, and the first-evaluation
decision — settled below.

## Stage E outcome (spawn + join; wind-up shape held for 1.1.5)

The spawn: `drop f(…)` on an `async` callee builds the child frame through
the same helper `await` uses and links it — `child.sibling = join_head;
join_head = child` — with no yield. The checker gained the rule the join's
layout depends on: a spawned callee declares `NIL` (TYPE-043; D-177's
checker-rules section), which fixes every spawnable child's error at header
slot 3 `{ i32 }`, so ONE join walks a heterogeneous list through the
generic `%"npk.frame.hdr"` type, dispatching through the resume slot — the
slot earning its place. The join rides the one return seam: every exit
stores its result and falls into `npk.join`, which drives each child to
DONE (a SUSPENDED child before 1.1.5's executor is the −4102 defect the
shim already traps), frees it, and lets the FIRST child error stand unless
the function's own error already does; `async main`'s childrens' errors
route through `failsafe` (D-013). Wind-up (deadline expiry setting the
windup word, −4107) is executor policy and lands with 1.1.5's run loop —
the poll-and-propagate shape has been in every await site since stage C.

`async_spawn.npk` (exit 42): loop spawns, child-error relay, own-error
precedence, and a relay exit that still joins; `async_spawn_mainerr.npk`
(exit 33) pins the failsafe route. The spawn rung retired;
`tests/rejection/async.npk` now pins the generic-await rung.

## The first-evaluation decision — RATIFIED as D-178

The user chose the language rule over the spill: **a statement suspends at
most once, before anything else it computes** — with the spill explicitly
available later if deemed necessary (it cannot break conforming code).
Enforced by the checker as `NITPICK-SUSPEND-002` from the suspend walk
(prefix must be bare literals; the await's own arguments are exempt; an
assignment whose value suspends takes a bare-name target; a value-`pick`
that suspends counts as the suspension), pinned by
`tests/analysis/rejection/await_first.npk` with the legal shapes in the
same file. The backend's temp-count guard stays as the defensive backstop;
its rung test retired with it (no legal program reaches it). Every
existing async test already conformed — bind-first was the natural idiom
throughout.

**1.1.4 is complete.** The machines, their frames, the composition, the
spawn and its join are all real; what waits on 1.1.5 is the executor —
parking, the run queue, the windup setter, and the deadline that makes
−4107 reachable.
