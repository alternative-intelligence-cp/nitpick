v3 §15's still-open questions get settled IN this subcycle (D-187):
`#ptr_add<T>` is ELEMENT-scaled (it lowers to gep; byte math is `T = int8`);
`atomic_from_ptr` is **wild-context-only** (aliasing foreign memory is wild
business — the TOS-signed zone — which also disposes of the storability
question: a wild local, used in place); **a `defer` may not `await`**
(cleanup is bounded and synchronous — v3's reap/close split is the blessed
shape, and the drop system is synchronous by construction); fabricated
pointers are tracked by REGISTRIES, not the leak checker (v3 §4.5, adopted).

## a — primitives, spawn, teardown, the registry — DONE (D-187/D-188)

**Landed:** `#ptr_add<T>` — element-scaled (D-187), gep lowering, `ptr_add.npk`.
`atomic_from_ptr` — D-187 settled as option A (user's call), and it needed
NO grammar change: the turbofish (`::<T>`, D-064) already parses on a
bare-name callee, so `atomic_from_ptr::<int64>(p).load()` works with only
typer + emitter wiring. Fused-only (never stored — TYPE-007), the emitter
dispatches through the pointer. `atomic_alias.npk` / `atomic_alias_rules.npk`.
The two ring primitives are done; **b** is unblocked.

### a (continued) — the data plane's shared memory — DONE

`lib/nbridge.npk` begins: `Shm` (a sealed memfd both processes map) with
`shm_create_sealed` (create → ftruncate → seal SHRINK|GROW|SEAL → mmap, the
plan's §4.3 step-2 order) and `shm_unmap`. The seal is the architecture's
load-bearing line — without it a driver `ftruncate(fd, 0)` SIGBUS-bombs the
runtime through the data plane. `shm_sealed.npk` proves BOTH directions
(poc test 1's shape): the mapping reads and writes, and a hostile shrink is
refused — `sys` maps the negative kernel return into `Result.err`, so the
refusal shows as `is_error`, the seal doing its job. Surfaced two backend
robustness gaps, recorded as OPEN_DECISIONS S-3 (sys non-integer arg emits
invalid IR; `?\|` over a pointer-arg sys call EMIT-002s where `?!` is fine).

### a (continued) — spawn, teardown, the registry — DONE (D-188)

All landed; `driver_spawn.npk` / `driver_spawn_fail.npk` / `driver_leak.npk`
prove the paths (stress 40, and by hand 500+ under parallel load, zero
orphans):

- nlibc constants + helpers (`lib/nbridge.npk`): socketpair (+NONBLOCK, ours),
  the stderr pipe, /dev/null, `fd_above_std` (every child-bound fd ≥ 4 so the
  dup3 shuffle cannot clobber a source), sendmsg/recvmsg + MSG_NOSIGNAL +
  SCM_RIGHTS (`send_fd`/`recv_fd` — msghdr/iovec/cmsg exist only there, as
  struct views over one wild allocation).
- The allocation-free child path in npkrt: `npk_driver_clone_exec` — CAS-claim,
  publish-BEFORE-clone (CLONE_PIDFD writes the pidfd INTO the slot), fork-shape
  clone, then PDEATHSIG → recorded-parent check → NO_NEW_PRIVS → dup3 ×4 →
  execve(constructed argv/empty envp) → exit_group(127). Surface: two
  bare-name builtins (`driver_clone_exec` wrapped, `driver_retire` void).
- `Bridge` (OwnedFd where v3 predates it; move-only by TYPE-046), `spawn_driver`
  (all eight steps; INIT_REQ carries the sealed memfd via SCM_RIGHTS;
  INIT_ACK validated under the deadline; every failure path releases
  everything and retires the slot — proven by the failure test's clean
  exit-0 under both exit checks), `bridge_reap` (sync, bounded, `never
  fails` — the defer-safe backstop), errors as a D-179 family (EDriverSpawn/
  Protocol/Fault/Deadline, ERingFull, EBridgePoisoned).
- **The registry**: 16-entry preallocated table; `npk_driver_kill_all` on the
  TRAP PATH before user `failsafe`; **and (D-188, user-ratified direction) a
  clean exit 0 with a live driver refuses — trap −4109 `DriverLeak`**, the
  D-151 exit rule extended to the second registry.
- Fallout fixed on the way: `?!` is unwrap-or-TRAP (v3 §4.2 bars it from the
  Bridge; the library tier now binds-and-fails everywhere — an EPIPE
  schedule found the misuse), the `// stress:` loop was dead in the
  real-backend harness stage (restored in `check_emitted_program`), and the
  harness gained `tests/backend/fixtures/` + `// argv:` substitution
  (`mock_driver.npk` — the Nitpick mock; the C reference driver replaces it
  at stage c).

## b — dispatch, the ring, close, stderr — DONE (D-189)

All landed; `driver_dispatch` / `driver_deadline` / `driver_fault` /
`driver_close_ladder` pin the paths (six round trips over a four-slot ring
so the indices wrap; deadline → kill + poison; fault → stderr tail; wrong
seq → protocol kill; the SIGTERM rung on a deaf driver):

- The §6.1 ring header, written in `spawn_driver` step 2b (magic
  "NPKDRV03", abi_version, POWER-OF-TWO capacity — a parameter now,
  enforced at spawn — bulk offsets); head/tail ride the mapping's zero
  fill.
- `io_watch(fd, events)` builtin — register-only, TWO args (no deadline: a
  registration carries none; the park that follows owns it); prelude
  `io_ready2`; dispatch composes the TRIPLE wait (ctrl, pidfd, stderr).
- Ring access as wild locals over `#ptr_add` + `atomic_from_ptr::<int64>`;
  the [UNTRUSTED] validations: tail ∈ [head−cap, head] or the driver dies
  EDriverProtocol; the reply's opcode/length/seq likewise.
- `dispatch` (§4.4): fresh seq, descriptor before the SeqCst head publish,
  EXEC_NOTIFY, the triple wait, kill-on-protocol, KILL-ON-DEADLINE (D-055
  rule 1 taken literally — the §5.4 graceful ladder is close's alone),
  poisoning — every later dispatch answers EBridgePoisoned until respawn.
- `bridge_close`: the ladder (SHUTDOWN + SHUT_WR → half → SIGTERM →
  quarter → SIGKILL), every rung ended by DEATH-OR-BUDGET (never by a wait
  merely returning — `close_wait_dead`'s check/wait/re-check), the
  release phase synchronous and single-shot behind `closed`.
- The stderr drain WOVEN into dispatch/teardown (D-180 bars a borrowing
  drain task; none is needed — the wait wakes on stderr pressure), 8 KiB
  drop-oldest, `bridge_stderr_tail` returns the owned tail (D-179 errors
  carry no payload, so the report reads the bridge).
- Two runtime defects flushed out and fixed: the executor's SPENT-WAKE
  stamp was never consumed at resume (every once-woken task busy-polled
  all later waits — a year latent behind retry loops; one cmpxchg at the
  resume site), and D-186's slice copy allocated from the wild-TRACKED
  entry (a sliced string alive at `exit 0` was a phantom WildLeak).
