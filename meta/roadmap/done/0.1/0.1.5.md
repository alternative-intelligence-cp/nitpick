# 0.1.5 — Operators, and the three interaction rules

**Cycle 0.1 — Lexer.**

## Goal

The full operator and punctuation set (§5), and the three places where lexing
depends on more than the next character.

## The three rules

**1. `>>` splitting.** `>>` is right-shift *and* the closing pair of a nested
generic. It splits into two `>` tokens **only inside a type-argument context**,
which is opened by a type position or by `::<` and nowhere else (D-064). Outside
one it is a shift, with no lookahead and no speculative parse.

**2. Positional `!`** (D-046). Leading is negation — `!x`, `!=`. Trailing or
repeated is unchecked or emphatic — `?!`, `=>!`, `_!`, `!!!`. A reader can tell
which from the token alone, and so can the lexer.

**3. The `#` sigil** (D-020). `#` followed by `[` is an attribute; followed by an
identifier it is a builtin. It is **not** a value operator, and it is no longer
the pin operator — pinning is obsolete without a collector.

## Work

1. Longest-match over the operator table, `<=>` beating `<=`, `..*` beating `..`.
2. The three rules above.
3. The range and spread family — `..`, `...`, `..*`, `..^` — which share a dot
   prefix because they are one family (§5.1).

## Done when

- Every operator in §5 lexes.
- `x >> 2i32` is one shift token; `Handle<Node<int64>>` splits.
- Rejection cases cover `!!` , which no longer exists.
