# 0.1.1 — Token representation

**Cycle 0.1 — Lexer.**

## Goal

The token kind enum, `Token`, and a growable `TokenList`.

## Shape

`Token` is `{ kind, Span span, int64 payload }`. **The payload is one machine
word** (`SUBSET_1.md` §1.2): an intern index for an identifier or keyword, the
value for an integer literal, an index into a side table for a string. That is
what keeps the token 24 bytes and the AST pointer-free.

The kind enum covers **every** token in `LEXICAL_REFERENCE.md` §4 and §5 —
including keywords for constructs no rung can lower yet. They still lex.

## Work

1. `src/frontend/token.npk` — the kind enum, `Token`, constructors.
2. `TokenList`, growable over `alloc` / `ralloc` and `#size_of<Token>`.
3. A name-of-kind function, for diagnostics and for debugging output.

## Done when

- Every keyword and operator in `LEXICAL_REFERENCE.md` has a kind.
- `TokenList` grows past its initial capacity without losing tokens.

## Not in this subcycle

Still no lexing. This is the shape the lexer will fill.
