# 0.1.2 — Whitespace, comments, identifiers, keywords

**Cycle 0.1 — Lexer.**

## Goal

The first bytes actually consumed: whitespace, comments, identifiers, and the
keyword table.

## Work

1. The scanner core — a cursor over the source bytes, tracking line and column.
2. Whitespace and comments. **Block comments do not nest**
   (`LEXICAL_REFERENCE.md` §2), which is a decision to preserve rather than a
   limitation to fix.
3. Identifiers: `[a-zA-Z_][a-zA-Z0-9_]*`, ASCII-bounded.
4. The keyword table — every category in §4. Keywords are recognised **after**
   an identifier is scanned, not by prefix matching, so `iffy` is an identifier.

## The rule that is easy to get wrong

`_?`, `_!`, `_~` and `_^` are **operators**, resolved *before* identifiers that
begin with an underscore (§3). An identifier scanner that runs first will happily
eat `_` and leave `?` stranded.

## Done when

- Identifiers, keywords and comments lex, with correct spans.
- `_^ x` lexes as the relay operator, not as an identifier.
