# 0.5.0 — The substrate

**Cycle 0.5 — Static analyses.**

## Goal

An expression's type recorded once, and the walk every analysis shares.

## Why a substrate subcycle at all

0.4.0 built the type representation before anything used it, for the same reason:
every later subcycle asks the same two questions, and answering them twice is how
two answers start to disagree.

The two questions here are **"what type is this expression"** and **"what is the
state of this binding along this path"**. Neither has an owner today.

## Work

1. **An expression-type side table**, indexed by `ExprId`, written by the checker
   as it types each expression and read by every analysis. `type_of_expr` computes
   and discards today.
2. **The analysis walk** — a per-function traversal that visits every statement
   and expression, with the enclosing declaration's context in hand, driven from
   `check_module` so there is one order and not several.
3. **A borrow classifier** — does this expression yield a borrow? `@x`, `$$i x`,
   `$$m x`, a parameter declared `borrow_imm`/`borrow_mut`, and anything derived
   from one by field access or indexing. Nothing else.
4. The mechanical completeness check this cycle gets: **every expression the
   checker typed has exactly one recorded type, and it is the one the checker
   computed.**

## Recording rather than recomputing

Two computations of one fact is the shape that has cost this compiler defects
repeatedly — `is_error` beside `error` (D-069), `expr_shape` read two ways, a type
name read as a token kind (D-104). An analysis that recomputes types agrees with
the checker only while both are maintained together. One that reads what the
checker recorded agrees **by construction**.

It also makes the completeness check possible: a recomputing analysis has nothing
to compare against.

## Watch for

**The table must be written on every path the checker types**, including the ones
that report an error and return the invalid type. An expression with no recorded
type is indistinguishable from one the analysis has not reached yet, and that is
the ambiguity `FieldInfo` and `MethodFind` were both restructured to remove — say
"typed as invalid" out loud rather than leaving a hole.

**A borrow derived from a borrow is still a borrow.** `$$m rec.field` and
`$$m arr[i]` are borrows of the same frame as `$$m rec`; a classifier that only
recognised the operator itself would let one field access launder second-class
into first-class.

## Done when

- Every expression the checker types has a recorded type, checked mechanically.
- The borrow classifier answers for each of the five forms, with a test per form.
- The walk reaches every statement kind, proven the way `stmt_is_classified` is.
