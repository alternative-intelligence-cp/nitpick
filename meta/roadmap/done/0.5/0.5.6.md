# 0.5.6 — Lock levels

**Cycle 0.5 — Static analyses.**

## Goal

Acquisition strictly increases, so circular wait is impossible by construction
(D-056).

## Why this decision exists at all

`--verify-concurrency` was documented as verifying "data race **and deadlock**
freedom", and **deadlock freedom had no mechanism anywhere**. A flag promising a
safety property nothing delivered is worse than promising nothing, because it
invites reliance.

The root cause was type erasure: a lock was an `int64` handle, so at `lock(h)`
nothing in the program text said *which* lock was being acquired. The fix is the
one taken for `printf` and `ioctl` — **put the information in the type.**

## The rule

`Mutex<T, LEVEL>` — the mutex owns its data, so "forgot to take the lock" is
unrepresentable; `LEVEL` is a compile-time constant, so at every acquisition the
compiler knows the rank; **a thread holding level N may acquire only levels > N.**

**Every blocking primitive is levelled**, not just `mutex`. `rwlock`, `condvar`,
`channel`, `barrier` and any future one participate — two tasks blocked on each
other's bounded channel are deadlocked just as thoroughly, and a rule covering
only mutexes would look like a proof without being one.

## Work

1. The acquisition set per function, **transitively through the call graph**.
   This is the cycle's only whole-program analysis, which is affordable because
   verification is whole-program anyway.
2. The possibly-held set at each acquisition site, from the same graph.
3. Reject any path that can acquire `L' ≤ L` while holding `L`.
4. **The dynamic-dispatch declaration** — see below.
5. A recursion bound on the call-graph walk, for the same reason every other walk
   in this compiler has one: the graph is a program's, so it can contain a cycle.

## The decision this subcycle cannot start without

**D-056 requires a spelling that does not exist.** A call through a trait object
can reach anything, so its acquisition set is unbounded, and the decision says a
dynamically dispatched call *"declares its maximum acquisition level as part of
the trait method's contract, and implementations are checked against it. An
undeclared method may not acquire at all."*

`VERIFICATION_REFERENCE.md` §248 restates it. **No document gives the syntax**, and
the frontend is built once — so this is settled before the parser is finished, not
after. The cycle README carries the recommendation: a third contract kind,
`acquires <= N`, beside `requires` and `ensures`.

## What is not here, and is said so it is not looked for

The blocking primitives themselves are the **concurrency stdlib**, carried in
`OPEN_DECISIONS.md` §3 and not built yet. So this analysis is written against the
shape D-056 specifies and tested against fixtures that declare their own
`Mutex<T, comptime int32:LEVEL>`. The stdlib types are then checked for free when
they arrive — which is the right order, because the analysis is what tells us the
shape is checkable.

**Deadlines are the other half and are not static.** Every blocking operation
takes a deadline and returns `Result`, so a residual deadlock becomes a timeout
error at a known point rather than a wedged process. That is containment, not
proof, and it is why the flag claims lock-order freedom rather than deadlock
freedom.

## Done when

- Acquiring downward is refused, naming both levels.
- A transitive acquisition through a call is caught.
- An undeclared dynamically dispatched method may not acquire, and one that
  declares a bound is checked against its implementations.

## What this found

**D-113 settled the bound and not the fact.** It gives `acquires <= N` for a trait
method and says the whole-program analysis computes acquisition sets — but nothing
said how the analysis knows an acquisition happened at all. The same shape of gap
D-113 itself was, found the same way: by trying to build against it.

Settled as **D-122**: `acquires N` states a fact, `acquires <= N` states a bound.
One keyword, two forms, and the analysis knows nothing about what a `Mutex` is.

**The prototype confirmed the diagnosis.** `stdlib/mutex.npk` still reads
`func:lock = int32(int64:handle)` — the erased API D-056 identified as the root
cause, unchanged. So the stdlib genuinely has to be rewritten and there was nothing
to pattern-match against, which is the right order: the analysis is what tells us
the shape is checkable.

**The keyword went in through the spec.** `acquires` was added to
`LEXICAL_REFERENCE.md`'s `VerificationKeyword` production and `gen_tables.py`
regenerated every token table plus the seed's keyword list. Nothing hand-edited,
including the renumbering a new keyword forces on every token after it.

## The design question this subcycle actually turned on

**When is a lock released, when there is no release to look at?** D-056's model is
that the guard's lifetime is the critical section. So:

- a level is held for the rest of the block that **bound** it;
- a **bare call** leaves nothing held, because the helper's guard was scoped inside
  it;
- a function's **own declared level** is held throughout its body.

Getting the second one wrong refuses every second call to an ordinary helper, which
is why the acceptance suite has a case for it — and why breaking the rule refuses
that case rather than adding a finding.

## Done when — all three met

- Acquiring downward is refused, naming both levels. ✓
- A transitive acquisition through a call is caught. ✓
- An undeclared dynamically dispatched method may not acquire, and one that
  declares a bound is checked against its implementations. ✓ *(and the
  implementation inherits the bound without repeating it — requiring the repetition
  would make the promise opt-in at the one place it has to be kept)*

Verified by making it fail, three times: equal levels permitted (5 findings, not
6), transitive widening removed (**3, not 6** — half the findings are the
whole-program half), and the release rule broken, which refuses correct code in the
acceptance suite rather than losing a finding.

## What is still owed, and by whom

The **concurrency stdlib** — `Mutex<T, LEVEL>` and the rest — is
`OPEN_DECISIONS.md` §3 and not built. When it arrives it is checked for free: its
`acquire` writes `acquires LEVEL` and this analysis already knows what to do with
it.
