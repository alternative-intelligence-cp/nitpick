# 0.9.8 — Borrow-analysis repairs and the doc-sync pass

**Cycle 0.9.** Two clean-ups that belong at the end of the cycle: the confirmed
borrow-checker soundness holes (the live ones must land before the constructs that
make them dangerous multiply), and the doc-sync pass that drains
`check_decisions_current`'s first-run worklist.

## Part 1 — borrow-analysis repairs

All six were verified against the live checker in the deep dive
([../audit-0.8-close/deep_dive_borrow_checker.md](../audit-0.8-close/deep_dive_borrow_checker.md); probes in
[../audit-0.8-close/probes/](../audit-0.8-close/probes/)). The analyses are well-built; these are the
"wrong-after-a-merge" residue the 0.5 retrospective predicted would recur. Land the
**live** ones (F-1, F-4, F-6) here; the latent ones (F-2, F-3, F-5) are gated to the
rungs that make them reachable and are ticketed accordingly.

### F-1 (live, HIGH) — rule B's single-borrow exemption

`escape_call_like` triggers rule B only at `borrowed >= 2`, but a borrow can escape
through a single call when the *destination* is a non-borrow pointer whose pointee
holds a pointer (`stash(cell, @x)` with `cell: Cell->`). **Proven:** two borrows →
refused; one borrow + one pointer dest → accepted (probes `a1`/`a2`). Fix: count
pointer-typed arguments whose pointee can carry a pointer (borrow or not, receiver
included) as destinations; rule B applies when `borrows ≥ 1 ∧ destinations ≥ 1`
(excluding the borrow when it is the only pointer). `tt_intern(@t, k)` stays exempt.
**Revalidate against the full acceptance suite + a self-compile**, exactly as
D-138's relaxations were — the compiler's own constructor idioms must still pass.

### F-4 (live, MED-HIGH) — the taint doesn't track param- or field-rooted Results

`check_value_read`/`binding_slot` require a `SYM_STMT` local root and collapse member
paths to the root, so `t.b.value` through a parameter is never tracked, and checking
`t.a` licenses reading `t.b.value`. Fix: track `(root-slot, interned field path)`
pairs (the `checked` set becomes a short per-function list, not a bitmap); for param
roots, either track param slots the same way or refuse `.value` through a param root
as "cannot be shown checked" (conservative, matching the untracked-binding posture).
Note the `moved`/`freed` root-collapse is *conservative* (safe) — only `checked`
collapses unsafely; comment the asymmetry where they share `binding_slot`.

### F-6 (live, MED, precision) — pick arms leak state into siblings

`assign_pick` absorbs each arm's `may`/`moved`/`freed` into the walk state before the
next arm copies it, so exclusive arms see each other's effects — wrongly refusing
per-case `fixed` init (probe `b`). Fix: copy every arm from the pristine pre-pick
state (as `if` does); accumulate `may`/`moved`/`freed` in a side accumulator; apply
once after the loop. `must` already works this way — the asymmetry was the bug.

### Ticketed to later rungs (write the tests now as `expect-accept`/latent)

- **F-2** (expression-`pick` `give` launders a borrow) → **before pick-expression
  lowering** (0.9.7 makes it reachable; land the fix with it or immediately after).
- **F-3** (inner-block borrow deref'd after scope) → **before any lifetime-intrinsic/
  stack-coloring work**; record a gate on that future item. Needs scope-depth
  tracking per binding.
- **F-5** (defer-named binding moved/freed after registration) → **with 0.10's real
  allocator**, when `dalloc` stops being a no-op and the double-free becomes real.

Each ships its probe as the rejection/acceptance case (probes A/C/E/F → rejections;
B's pick half → acceptance; D's pd1/pd2 → rejections, pd3 the control).

## Outcome (recorded at close)

All three live repairs landed, plus F-2 (its gate — pick-expression lowering
— arrived in 0.9.7, so the ticket came due in the same cycle): D-146 records
the four shapes. The F-1 repair went through three refinements against the
compiler's own source — the self-compile is the acceptance test the deep dive
demanded, and it drove the rule from "any pointer destination" to
"LOCAL-rooted borrow beside a destination whose pointee can hold THAT
borrow's type", with Escape gaining the checker's resolver to walk struct
fields. Four new suite cases (borrow_dest, pickexpr_borrow, taint_paths
rejections; the per-case-`fixed` acceptance) hold the lines.

The doc-sync drained `check_decisions_current` to CLEAN (D-129, D-114,
D-028 annotated) and swept the load-bearing Theme-F passages: the 3-field
Result IR example, the tryte trit-count (Part Q's 6→10), the `int32<Meters>`
remnant, the misaligned enum §9.3 example (now teaching the 0.9.2 slot
shape + D-140's cast rules), D-008's removed `ok(x)` row struck through with
its story, OP_REFERENCE's `?`-family note pinned to D-099/D-144, and the
checker's own `#ptr_add` prose corrected to the `@p[i]` spelling.
