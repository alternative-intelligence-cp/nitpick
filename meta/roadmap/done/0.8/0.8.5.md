# 0.8.5 — Line-discipline IO (D-050) and the diagnostics writer over it

## What landed

**The fd quartet on the floor** (D-141): `open`/`close`/`read`/`write`, one
syscall each, `Result`-wrapped, `fd`-typed per D-042. Plus `write_all` — the
retry loop — in IR only because pointer stepping (`#ptr_add`) is a 0.9 rung; it
graduates to the library then. `write_raw` is gone (bare return, pre-D-075
shape, second spelling for one job).

**The error-code convention repaired.** D-005's `Result` layout has always said
"< 0 system, > 0 user"; 0.8.3's floor negated errno to positive. Now the error
slot carries the kernel's return as delivered (ENOENT −2), floor-detected
conditions reuse the vocabulary negatively (interior NUL −22, range −34), and
**E_EOF = −4096** — first code past MAX_ERRNO, collision-impossible; end-of-
input is an error code at the floor exactly as D-075 specifies for the trait.
`read_stdin` also stopped flattening every read failure to 5 (EIO).

**`lib/nio.npk`** — D-050 as code: `nio_normalize` / `nio_read_text` /
`nio_stdin_text` on the read side (CRLF/CR → LF, fast path returns the input
untouched); `NioW` on the write side — ending a creation parameter (`NioEnding`,
the greppable opt-in), buffering fixed per D-076 (stdout line, stderr
unbuffered, file full with a 64K threshold), `int32 =>! fd` manufacture confined
here. `Sink` lost its fd arm — a write_raw-era mode tag, D-072's rejected
pattern — and is now purely the capture buffer.

**stdout is the product; stderr is the report.** main and all three tools emit
diagnostics through the unbuffered nio stderr writer: they survive a trap
(D-076's reason) and survive a redirect — `npkc bad.npk > out.ll` shows its
errors now. The harness and quickcheck parse stderr. The compiler's own report
path runs through the library tier, which makes nio load-bearing from birth.

## What the new floor found (two latent bugs, both fixed)

1. **The seed dropped `pass (relay f(...))` for `Result<NIL>` callees** —
   `emit_return_ok` saw a NIL return and emitted ok WITHOUT evaluating the
   expression: the call never ran and the callee's error came back as success.
   Every diagnostic line lost its newline to the first half; the whole report
   went silent to the second. Fixed in the seed;
   `tests/conformance/09_pass_relay_nil.npk` locks both halves (effect runs,
   error propagates with the same code) under both compilers.

2. **`tbb32` widened by zext** — the type interned unsigned and the emitter's
   widener only consulted TY_INT, so `(err => int64)` turned −9 into four
   billion. Balanced ternary is symmetric about zero and INT32_MIN is its ERR
   sentinel: the carrier is signed by construction. Fixed in `tt_tbb` (b = 1)
   and the widener (a TY_TBB arm). Found by fd_io's write-after-close, the
   first negative code any test ever pushed through a cast.

## Tests

- `tests/backend/programs/fd_io.npk` — quartet roundtrip; EBADF negative after
  close; **E_EOF pinned numerically**; zero-length read is ok(0), not EOF.
- `tests/backend/programs/line_discipline.npk` — byte path plants exact mixed
  endings, text read normalizes them; Lf writer emits `\n`, CrLf writer
  translates every logical `\n` including interior ones.
- `tests/conformance/09_pass_relay_nil.npk` — the seed miscompile, locked.
- Every rejection suite now exercises the stderr contract on every run.
