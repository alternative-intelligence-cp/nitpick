# 0.8.3 — File output: `write_file`, and `npkc -o`

**Cycle 0.8.**

## The floor grows one routine, not three symbols

`npk_write_file(cstring, string) → Result<NIL>` — `read_file`'s mirror: a whole
buffer to a path, replacing what was there. `openat`/`write`/`close` live
**inside** it as one auditable hand-written-IR body rather than as three exposed
symbols; the fd-granular primitives arrive with D-050's line discipline (0.8.5),
where a held-open descriptor is the point. Two rules the body states:

- **A short write is not failure.** `write(2)` may accept fewer bytes than
  offered, so the loop advances by what was accepted; only a negative return is
  an error. Treating a short write as success is the classic way to truncate a
  file and report victory.
- **A failed close is a failed write.** Kernel-buffered errors surface at
  `close(2)`, and reporting success past one is reporting bytes that may not
  exist.

The signature crossed all three authorities in one motion — the seed's tables,
`BUILTIN_REFERENCE.md` §2b (regenerated into the resolver), and
`ir_runtime.npk` — with `check_runtime_sigs_agree` green across the trio, and the
new symbol lands inside the 0.8.2 allowlist automatically because the allowlist
is parsed from the runtime's defines.

## `npkc -o`

```
npkc <root.npk>              IR on stdout
npkc <root.npk> -o <out.ll>  IR written to the file, stdout silent
```

One flag, parsed positionally — one flag does not justify an argument scanner;
the day there are two, this becomes the driver's argument table. A write failure
is exit 2 with a message on stderr, through the same floor routine, because an
`.ll` that silently lost its tail would be a program that assembles to something
other than what was compiled.

**The selfhost stage now exercises the flag as its standing coverage**: stage 1
is emitted through `-o` (stdout must stay silent — one delivery, not two), stage
2 through stdout, and the two are compared byte-for-byte as before.

## The test

`tests/backend/programs/file_io.npk` round-trips through the real filesystem:
write, read back, compare byte-for-byte — **twice, with a shorter second body**,
because `O_TRUNC` leaving a stale tail is the classic way "replaced" quietly
means "prefixed". A path that cannot be created answers through the `Result`,
never a crash. Droppings land in `.internal/`, which is gitignored — a test's
leftovers must never be able to show up in `git status`.

## What wiring the flag flushed out

The harness's `-o` selfhost run **timed out at ten minutes**, and the trail led
somewhere much older than the flag:

- **`direct_named_type` read a token kind as an intern index** — the exact
  two-meanings slot `resolve_named` had to learn in 0.4, unlearned here since
  0.3.3. Every `int32:` field grew a containment edge to whatever identifier sat
  at intern index ~85–175: garbage edges in the struct-containment graph.
- **`struct_reaches_self` was a bare DFS**, exponential in the sharing of the
  graph it walks. The garbage edges fed it fanout for four cycles without anyone
  noticing, because no real program had a hub — until `Front` arrived with ten
  aggregate fields all containing the same table structs, and the self-compile
  fell off the cliff. Memoised per query (`seen` over intern indices), which is
  correctness-neutral for a reachability question.

The two compounded: the garbage powered the blowup, and the fuel the blowup
burned was **masking the garbage** — once memoisation let the walk run deep, the
fake edges manufactured "cycles" between structs made of plain integers, which
is what finally exposed the misread. Self-compile: **>600 s → 5.6 s.**

- Stage 1 arrives via `-o`, silent on stdout, and the fixpoint still closes.
- The three-way signature diff and the zero-dependency scan both know the new
