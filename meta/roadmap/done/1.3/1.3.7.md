# 1.3.7 — the library tier: `lib/nvec.npk`, `lib/ntensor.npk` (D-200)

The tier's LIBRARY half: `vec2/3/4` as structs over `simd<flt64, N>` with
`.x/.y/.z/.w`, `dot`/`cross`/`length`; `vec9` as nine named `flt64` fields
(`m00`…`m22` — matrix semantics, not a lane vector); `matrix<T>`
`{cells, rows, cols}` and `tensor<T>` with RANK CAPPED AT 9 and dims
INLINE; `tmatrix`/`ttensor` as the same containers over `tryte`. All four
containers OWN their heap cell — the 1.2 managed regime drops them.
Dimensions are `int64`.

## Design points, fixed at open (inside D-200's ratified frame)

1. **`buffer` lands MINIMALLY as the managed owning cell** — the
   mechanism D-200's "the managed regime drops them" presumes, and the
   language does not otherwise have: no library-reachable owned heap
   exists (strings own bytes but are not mutable storage; arenas are
   handle-shaped; `buffer` has been a keyword since Phase A with §23
   specifying exactly the string-twin layout `{ptr, i64 len, i64 cap}`).
   What lands: `TY_BUFFER`, the bare type (it was mis-filed as generic),
   the floor's `buffer_new(i64) → Result<buffer>` (managed allocation,
   `len = cap = n`, zeroed), members `.ptr/.len/.cap` (the string trio),
   and the SCOPE-EXIT DROP — the string's own cap-gated drop body,
   shared because the layout is shared. §23's typed read/write verb
   family, `buffer_free`, and `resize` do NOT land: under 1.2 the drop
   is automatic (manual free is the wild regime's spelling), and typed
   access is the general `#ptr_add` + dereference mechanism the Bridge
   already exercises — a per-width verb family would be a second copy of
   it. §23 is synced to say so.
2. **`#sqrt` joins the builtins** (flt32/flt64 → `llvm.sqrt`, the
   declares already in the fixed block): `length` is ratified, the
   square root is an instruction on this target, and the alternative — a
   prelude Newton iteration — computes a subtly DIFFERENT number than
   the instruction, which is exactly the drift this language exists to
   refuse.
3. **`lib/nvec.npk`**: `vec2/3/4` each `{ simd<flt64, N>:v }` with
   constructor FUNCTIONS `vec2_of/vec3_of/vec4_of` (D-185's rule — no
   static methods; the bare names are the structs'), impl methods
   `.x()/.y()/.z()/.w()` (lane places), `.dot(o)` (the elementwise
   product's `.sum()` — the 1.3.1 reduction), `.length2()`, `.length()`
   (`#sqrt`), and `.cross(o)` on `vec3` alone. `vec9` is nine `flt64`
   FIELDS `m00…m22` — real fields on a real struct, plus `vec9_id()`
   (identity) and `.mul(o)` (3×3 product, the one operation its
   semantics name).
4. **`lib/ntensor.npk`**: `struct:matrix<T> = { buffer:cells;
   int64:rows; int64:cols; }` with `mat_of::<T>(rows, cols)` (zeroed),
   `.get(r, c)`/`.set(r, c, v)` — bounds-checked in the LIBRARY (a
   refusal-shaped `fail` on a bad index; the buffer's own body is
   in-bounds by construction), addressed via `#ptr_add<T>` over
   `.cells.ptr`. `tensor<T>` `{ buffer:cells; int64:ndims;
   int64[9]:dims; }` — ONE allocation, rank ≤ 9 enforced at
   `tensor_of`, row-major strides computed on access.
   `tmatrix`/`ttensor` are NOT new types: they are `matrix<tryte>` /
   `tensor<tryte>` — D-200's own words, "the same containers over
   `tryte`" — documented and tested as instances.
5. **The drops are free**: a generic struct holding a `buffer` field
   drops it through the 1.2 field walk — the library adds nothing, and
   the exit-time leak registry proves it in every test that exits 0.

## Close-out — LANDED

Everything above landed as planned; the full harness is green and stage 1
rebuilds itself byte-identically. The record of what the subcycle changed
beyond the plan's own text:

- **`buffer` registration ran the full B-7 walker sweep**: `type_drops`
  (true — the point), `type_contains_borrow` (false — owns its body, moves
  whole), channel elements (rides whole, like a string), escape's
  `type_holds_pointer`/`carries_pointer` (true), `field_holds_ptr` (true
  via the stated tail), `equatable` (false — the trio would compare the
  ADDRESS), `type_display` ("buffer"), `ll_type` (`{ ptr, i64, i64 }`),
  the member emit gates (both, next to the string's), and the shared
  drop body (`TY_STRING || TY_BUFFER` strlike).
- **A real miscompile found and fixed**: a checker-typed `never fails`
  builtin (the call typed as its BARE value — no `raw` needed) returning
  through the floor's `{ T, i32 }` envelope was passed out unextracted, so
  `buffer:b = buffer_new(16i64)` stored 32 bytes into a 24-byte alloca.
  The generic rt path now extracts the value half at the call site when
  the recorded type is non-Result. `buffer_new` is the FIRST builtin in
  that class — every earlier wrapped builtin is either typed `Result` by
  its arm or left untyped for `raw`/`?!` to unwrap — so nothing existing
  was affected; the class is now safe for whatever joins it.
- **Two spelling facts the libraries taught**: a generic struct literal in
  a generic factory is the BARE name (`matrix{ … }` — the prelude's own
  `TextWriter{}` idiom; `matrix<T>{ … }` does not parse), and
  checker-typed builtins are called WITHOUT `raw` (`own_fd`'s precedent —
  the arm's type IS the value type).
- **Contract fix during write-up**: the first ntensor draft declared
  `get`/`set` `never fails` while `fail`ing `BadIndex` — refused by the
  checker exactly as designed; the methods now fail honestly and
  `tensor_offset`'s failure `relay`s through `get`/`set`.
- `is_hash_builtin`/`is_builtin_name` come from BUILTIN_REFERENCE.md via
  gen_tables.py — the `#sqrt` and `buffer_new` rows were added THERE (a
  hand edit to builtins.npk is erased on the next regen).
- Tests: `buffer_basic` (trio, zeroed birth, `#ptr_add` writes at byte and
  int64 width, empty-buffer answers, inner-scope drop, move),
  `nvec_basic` (exact 3-4-5/1-2-2 values, cross anticommutes into
  perpendicularity checks, vec9 identity and a permutation product),
  `ntensor_basic` (matrix round trips and refusals, `matrix<tryte>` with
  the twisted ERR visible through the container, tensor ranks 1/3/9,
  row-major offset pinned against a raw `#ptr_add` write, rank-0/10 and
  zero-extent and wrong-arity refusals), `buffer_rules` (9 rejection rows:
  `buffer_new` arity/int64, buffer move-only TYPE-046, buffer `==`
  TYPE-034, `#sqrt` non-float/tfp/turbofish/arity).
