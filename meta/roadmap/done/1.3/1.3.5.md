# 1.3.5 — `frac8/16/32/64`: the exact rationals (D-198)

The tier's first NON-SCALAR family: invariant-normalized mixed numbers
`{whole: iN, num: iN, denom: uN}`, value = whole + num/denom, exact or
ERR — never rounded. The five invariants hold after every operation:
denom > 0; num ≥ 0 when whole ≠ 0; num < denom; gcd(num, denom) = 1;
the sign rides whole (or num when whole = 0).

## Design points, fixed at open (inside D-198's ratified frame)

1. **The algorithms live in the PRELUDE, in Nitpick, in `int256`.** One
   generic core — `gcd`, `normalize`, `add/sub/mul/div`, `cmp` — working
   on components as plain wide integers with the width's bounds as
   parameters, returning a `FracParts` struct whose `ok` flag says
   whether the reduced form fits the width. The emitter lowers a frac
   operator to extract-components → widen → `call @"npk.prelude.…"` →
   check `ok` → narrow-or-ERR → rebuild. Grounds: every prelude function
   emits into every program under a deterministic symbol (verified:
   `@"npk.prelude.tfp_render"` is in a minimal program's IR), so the
   synthesized call always links; the D-193 precedent put exactly this
   kind of careful arithmetic in the prelude; hand-written npkrt IR with
   loops is verification-hostile; and inline per-site expansion of a gcd
   loop is not reviewable. `int256` because frac64's cross-products
   reach 2^127 and their SUM overflows i128 — 256 holds everything with
   headroom, and "exact or ERR" chose correctness over cycles at
   ratification. ONE implementation, four widths — the one-mechanism
   rule; performance inlining is LLVM's problem later.
2. **The prototype's all-signed layout is corrected to D-198's**: denom
   is `uN`. The canonical ERR triple is `{minN, minN, 0}`; `is_err` is
   the disjunction the decision names — whole or num at the width's
   most-negative, or denom 0 — so a partially-forged state reads as ERR
   too, not only the canonical one.
3. **Read-only members `.whole` / `.num` / `.denom`** (intN, intN,
   uintN). Unlike `tfp` — whose raw bits are an encoding and stay hidden
   — a frac's components ARE the spec's own value model, `ToString`
   renders them, and the prelude needs to read them from Nitpick. They
   are VALUES, not places (the string `.len` mechanism), so assignment
   through them cannot break the invariants.
4. **No frac literals.** `int => frac` is the lossless entry (D-198);
   a ratio is division. An unsuffixed literal in a frac slot refuses
   with the cast named — the tbb posture, not the ternary one, because
   a bare integer is not a mixed number's spelling.
5. **No `pick` on a frac selector**, refused by name: a frac has no
   enumerable cases beyond ERR, `is_err` is the look, and comparisons
   are the decisions. (The scalar pick machinery compares one register;
   an aggregate selector would need its own lowering for a construct
   with no use.) `ERR` as a frac literal-by-context, `is_err`, and the
   compare-trap discipline all extend — the family joins the taint
   quartet everywhere except the selector position.
6. **Operators are `+ - * /` and the comparisons** — no `%` (D-198's
   list is exact; a mixed-number remainder has no ratified meaning) and
   no bitwise, both refused by name (TYPE-052, the family's own code).
   Comparisons run through the exact core (`cmp` by cross-multiplied
   difference in `int256`) after the twisted ERR-trap; equality is
   admitted (a frac is a VALUE with exact equality — the aggregate
   `==`-refusal list does not gain this kind).
7. **Casts**: `int => frac` lossless where the range fits (the width's
   whole must hold it; the minN forge-edge takes the tbb entering
   discipline — trap under `=>`, absorb as ERR under `=>!`); frac
   widths widen `=>` (components extend; the reduced form always fits a
   wider width), narrow `=>!` only (components range-check, out-of-fit
   absorbs as ERR); `frac =>! flt64` rounds (the acknowledged form,
   correcting §20) and `frac => flt` refuses; `frac =>! intN` truncates
   toward zero — whole plus one when whole is negative and num nonzero,
   the mixed-number form's own edge — with ERR trapping under BOTH
   spellings on any exit (D-144 as amended). Cross-twisted-family is
   IMPOSSIBLE — through the plain integer, one rule.
8. **`ToString`** is a prelude impl per width over the members:
   "3 1/3", "-2 5/8", "0", "ERR" — exact by construction (D-198's own
   strings).
9. **Layout**: `{iN, iN, uN}` — sizes 3/6/12/24, component alignment.
   The LL struct text is load-bearing at the emitter's synthesized call
   (`FracParts` = `{ i8, i256, i256, i256 }` inside the Result wrapper);
   a `// ll:` marker pins it under `check_ll_types_agree`.

## The work

1. **Generator/types**: the four names (a `FRAC` dict), `TY_FRAC` (=44),
   `tt_frac`, predicates (drops/ordered/escape/layout/equatable),
   `type_range` rows (whole's magnitude, the overclaim-safe posture).
2. **Prelude**: `FracParts`, `npk_gcd256`, `npk_frac_norm`,
   `npk_frac_add/sub/mul/div/cmp` in `int256`; four `ToString` impls
   over the members.
3. **Checker**: members, the operator arm (op gate + same-type;
   TYPE-052), compare admission + equality, `ERR`/`is_err`/sentinel
   context, the pick-selector refusal, the cast matrix, no-literal
   refusal.
4. **Emitter**: the frac arm in `emit_arith_value` (unpack → widen →
   call → repack-or-ERR), the compare path (trap then core), `is_err`
   and the ERR constant as aggregates, member extraction, the cast
   family, `ll_type` → the struct.
5. **Tests**: `frac_basic.npk` (construction by cast, the four
   operators against hand-computed exact answers, normalization
   visible through the members, stickiness, div-by-zero → ERR,
   overflow-in-reduction → ERR, comparisons and equality, width
   widen/narrow, the flt64 and int exits, ToString via `&{}`),
   `frac_cmp_err.npk` (−4100), rejection rows (`%`, bitwise, mixing,
   literal-in-slot, pick selector, `frac => flt64` without the bang,
   cross-family), exhaust — N/A by design point 5.
6. **Docs**: D-198 implementation record, TYPE_REFERENCE §20 sync,
   CLAUDE.md status.

## Close-out: what landed, and the found defects

Everything above landed as designed; the implementation record is on
D-198 in DECISIONS.md. Tests: `frac_basic.npk` (hand-computed exact
answers end to end — construction, the four operators, normalization
visible through the members, negation under the sign convention,
div-zero → ERR, stickiness, EXACT comparisons including `2/4 == 1/2`,
width widen/narrow-absorb, the flt64 and truncate-toward-zero exits,
compound assigns through the shared core, ToString "5 1/3"),
`frac_cmp_err.npk` (the −4100), eleven refusal rows in
`frac_rules.npk`.

**Found defect — D-169's non-scalar comparison belt.** The emitter's
fail-closed belt ("a comparison on a non-scalar is a DEFECT, not a
rung") was right for everything the checker refuses — and frac is the
first aggregate the checker ADMITS to comparison, so the belt called a
legal `f < g` a compiler defect. The frac compare arm now precedes the
belt. The shape to remember: a fail-closed belt written when a category
was empty becomes a refusal of the category's first legitimate member,
and nothing announces it until that member exists.

Two build-time finds of the session's own class: `tid` and `fd` used as
locals in the new emitter code — the CLAUDE.md reserved-words table's
own rows — caught only by npkc's parse (the seed's checker never builds
backend files), plus six `cat5` arity slips the seed cannot see either.
The self-compile-before-harness step (the 1.3.3 lesson) caught all of
them before any full run.
