# 1.3.8 — the cycle close: pins, the rung retirement, the optimiser leg

The close-out row from the cycle README: whole-tier `// ll:` markers, the
`check_kinds_lowered_or_refused` retirement of the G-3 rungs, the
optimised-output check (the pinned LLVM-optimiser lesson), and doc sync.

## What landed

1. **The tier's lowering, pinned** (`tests/backend/ir_types.npk`): fifteen
   new `ll_is` assertions — `simd<flt64,4>`/`simd<int32,8>`, `tfp64`/
   `tfp256`, `dim256` (erased to `i256`; and `tt_dim(0)` IS `tfp256`, the
   zero-vector rule asserted at the type-table level), the ternary four
   (`i8`/`i16` carriers), `frac32`/`frac64` triples, `complex<flt64>`/
   `complex<tfp64>` pairs, and `buffer`. NO `// ll:` markers — the Optional
   precedent: every one of these is OUT_OF_SUBSET for the seed, so there is
   no second lowering to diff; the pin is the real compiler asserting its
   own text, which is what stops a representation drifting under a later
   edit. Two seed-invisible resolution defects surfaced while probing the
   fixture under npkc (imports for `source.npk` and `type_trait.npk` error
   names its failsafe already spelled) and were fixed; the fixture's
   remaining npkc-strictness gaps (D-065 moves in seed-era helper code) are
   the seed suite's by design and stay.
2. **The G-3 rung retired** (`ir_expr.npk`, the `emit_binary` tail): every
   kind the checker admits to arithmetic now has its arm, so the last
   `iv_rung("arithmetic on this type", "1.3 (G-3)")` became the defect
   confession (`iv_broken`) — the TYPE-029 transition, again. This is also
   what `check_rung_names_open_cycle` requires before the folder moves to
   `done/`: a refusal may not name a closed cycle.
3. **The opt-O2 leg** (`check_optimised_program`, harness): EVERY
   real-backend program now runs twice — the emitted IR through `opt -O2`
   then `llc -O2`, linked and executed with the same expectations,
   including the `// stress:` loop. A changed answer fails with a message
   naming the optimiser; a missing `opt` fails LOUDLY (a silent skip is
   how an optimiser defect ships). The zero-dependency scan runs on the
   optimised object too, because `opt` is licensed to MINT libcalls — a
   vectorised loop becoming `memcpy` is a new undefined symbol the -O0
   scan never saw. This is the pinned prototype lesson made a standing
   instrument rather than a one-off audit.
4. **Doc sync**: the ROADMAP 1.3 row marked done with the cycle's record,
   CLAUDE.md's status and instrument paragraphs updated, this file, and
   the folder moved to `meta/roadmap/done/1.3/`.

## What the opt-O2 leg found on its FIRST full run

Eleven programs — the whole Bridge/driver suite, both pipe tests,
`io_ready_basic` — failed DETERMINISTICALLY under `-O2` while `-O0` stayed
green. The bisect (per-pass, then per-function by `optnone`) said three
independent passes each sufficed (sroa, early-cse, gvn) and named MAIN's
resume as a culprit — while the misbehaving answer came from the CHILD,
which was UNOPTIMISED in the bisect build. That shape is the signature of
a stack resurrection, and the probe confirmed it:

**The suspend walk recorded no suspension point for the bare suspension
primitives.** `suspend_io`/`suspend_until` park the machine exactly as an
`await` does — their lowering ends the segment with a resume — but the
liveness-across-suspension walk (D-177, 1.1.4) only knew `await` nodes,
so `io_ready`'s `give_up` deadline, written before the park and read
after it, stayed an ALLOCA. Re-entry is a NEW invocation with a FRESH
alloca; at `-O0` the load found the OLD BYTES anyway — same call path,
same stack depth, nothing between — so every run since 1.1.12 passed on
a stack-layout coincidence. The first optimised build shrank the
caller's frame, the coincidence broke, and the child read garbage as its
deadline: `DeadlineExceeded` at 40ms of a 1000ms wait, one hundred runs
in one hundred.

The fix is in the WALK, not the programs: a call to `suspend_io` or
`suspend_until` now records a suspension point past its arguments (the
`await` rule — arguments evaluate before the machine can yield), which
required handing the walk the intern table to recognise the two names.
`give_up` moved into the coroutine frame (`io_ready`'s frame grew its
16th slot) and all eleven programs answer identically at both levels.
This is the SECOND hole in the same analysis — D-191's close fixed
`fn_end` reading a span that covers only the block's opening — and it is
precisely the class the pinned optimiser lesson predicted: the -O0
answer was never the language's answer, only the stack's.
