# 1.3.3 — `dim256<Unit>`: dimensional analysis in the checker (D-036/D-196)

The semantic-intent showcase of the tier: units as exponent vectors over the
seven SI base dimensions, checked through arithmetic, ERASED before lowering
— `dim256<U>` IS `tfp256` at the IR level, and every D-195 rule applies.

## Design points, fixed at open (inside D-196's ratified frame)

1. **A unit is a packed vector.** Seven signed exponents (mass, length,
   time, current, temperature, amount, luminous intensity), `i8` each,
   packed into the one `int64` payload slot of an interned `TY_DIM` type —
   same vector, same type id, so unit equality IS type-id equality and the
   checker's existing same-type discipline does the enforcement. An
   exponent past ±127 refuses (no physics has one; a refusal beats a wrap).
2. **The ZERO vector IS `tfp256`** — dimensionless `dim256` interns as the
   `tfp256` type id itself, not as a distinct kind. `dist / dist` is bare
   `tfp256` by construction; scaling (`dim * tfp256`) falls out of the
   total algebra with no special case; and there is exactly ONE spelling
   for a dimensionless quantity. Consequently the BARE forms refuse: a
   `dim256` annotation or `1.5dim256` literal without `<U>` names the
   dimensionless type by its wrong name, and the message says to write
   `tfp256` (or add the unit). One meaning, one spelling.
3. **Annotations take a single unit NAME.** `dim256<Meters>`,
   `1000.0dim256<Joules>` — never an inline expression. Unit ALGEBRA is
   spelled in one place only: the `unit:` declaration. A compound an author
   wants is a name away (`unit:MetersPerSecond = Meters / Seconds;`), and
   the annotation stays flat, greppable, and NAMED — the semantic-intent
   lever D-196 ratified the grammar change for.
4. **`unit:Name = expr;` joins the grammar** (D-196, user-ratified):
   `pub`-able, module-scoped like every declaration, RHS over unit names,
   `1`, `*`, `/` and parentheses, evaluated to a vector at collection —
   anything else in it refuses by name. `unit` becomes a reserved word
   (documented in CLAUDE.md's table: it reads like an ordinary local).
5. **The seven SI base units are compiler-declared in the root scope**
   (`Kilograms`, `Meters`, `Seconds`, `Amperes`, `Kelvin`, `Moles`,
   `Candela`); the derived set is PRELUDE `unit:` declarations — the
   ratified examples (`Newtons`, `Joules`, `MetersPerSecond`, `Hertz`)
   plus the standard SI derived names (`Radians = 1`, `Steradians = 1`,
   `Pascals`, `Watts`, `Coulombs`, `Volts`, `Farads`, `Ohms`, `Siemens`,
   `Webers`, `Teslas`, `Henries`, `Lumens`, `Lux`, `Becquerels`, `Grays`,
   `Sieverts`, `Katals`, `MetersPerSecondSquared`). One mechanism: the
   prelude exercises the same declaration a user writes. Names are names
   for vectors (D-196) — `Hertz` and `Becquerels` naming the same vector
   is physics, not a conflict; diagnostics render the BASE-product form
   (`Meters·Seconds⁻¹`), never a guessed name.
6. **Arithmetic**: `*`/`/` add/subtract vectors between any two 256-bit
   twisted operands (the result's vector interns on the fly — the algebra
   is TOTAL, no "if registered"); `+ - %` and every comparison require the
   SAME vector, refusing with both units shown in base form; ordering is
   full within a vector (a dim is a number, D-195 rule 5); `is_err`, the
   `ERR` sentinel, the `pick` ERR arm, `.floor()`/`.trunc()` (unit kept)
   all extend; division by zero yields ERR (D-007's twisted row).
7. **Casts — exactly one boundary.** `dim256<U> => tfp256` drops the unit
   (always safe); `tfp256 =>! dim256<U>` asserts one and REFUSES without
   the bang (a silent unit-gain is how unit bugs are born — D-196
   dissolves §5a's "warning" row). Both are IR no-ops and ERR RIDES —
   relabeling never leaves the twisted family, so the D-144-as-amended
   leaving trap does not apply; the sentinel is the same bit pattern on
   both sides. Everything else (`dim<U> ⇄ dim<V>`, dim ⇄ int/flt/narrower
   tfp) is CAST_IMPOSSIBLE with a message naming the two-step through
   `tfp256` — a relabel spells BOTH halves, the drop and the assertion.
8. **Erasure at the backend boundary, per-site.** `ll_type` says `i256`,
   layout says 32/16, and every emitter site that dispatches on `TY_TFP`
   admits `TY_DIM` as tfp256 — enumerated up front, the 1.3.1 B-7 sweep
   discipline. Mangling: `%dim256` plus seven signed exponents (D-156
   reversibility). `DeclUnit` lowers to NOTHING and is confessed as
   erased to `check_kinds_lowered_or_refused`.
9. **No `ToString` on a dimensioned value — by design, not deferral.**
   Rendering drops the unit, and this language makes drops explicit: the
   spelling is `&{x => tfp256}`. A dimensioned value never silently
   becomes its bare number, in text or anywhere else.

## The work

1. **Grammar**: the `unit` keyword (LEXICAL_REFERENCE table + regenerate),
   `DeclUnit` through parser/AST/every walker (the instruments enumerate),
   the literal's `<UnitName>` tail (bounded lookahead `< Ident >` after a
   `dim256`-suffixed literal — the struct-literal precedent), and the
   `whole_grammar.npk` rows.
2. **Collection/resolution**: the unit symbol kind, base units seeded in
   the root scope, `unit:` RHS evaluation (names/`1`/`*`//`/parens` →
   vector, everything else refused), the prelude's derived set,
   `dim256<Name>` resolution through the unit table, `TY_DIM` interning
   with the packed vector, zero-vector → `t_tfp256` identity, bare-form
   refusals.
3. **Checker**: the §6 arithmetic rules on `TY_DIM` (extending the twisted
   arms), base-form unit display in diagnostics, the cast matrix row, the
   literal path (D-195 fold + vector type), methods, REACH/failsafe
   (TbbErr arms — same family).
4. **Emitter**: the TY_TFP-site sweep admitting TY_DIM at 256 bits, the
   two no-op casts, mangling, layout.
5. **Tests**: `dim_basic.npk` (algebra end to end: compose, cancel to
   tfp256, scale, floor/trunc, both casts, ERR ride, compare), a compare-
   on-ERR trap program, rejection rows (mismatched add/compare with the
   both-units message, silent unit-gain `=>`, `dim<U> => dim<V>`, unknown
   unit, bad `unit:` RHS, exponent overflow, bare `dim256` annotation and
   literal), frontend `cx` rows for the vector algebra, the grammar rows.
6. **Docs**: TYPE_REFERENCE §5a rewritten against D-196 (the "if
   registered" and "warning" rows die; the rules table gets the cast
   spellings), the reserved-words row for `unit`, CLAUDE.md status.

## Close-out: what landed, and the two found defects

Everything above landed as designed; the implementation record is on
D-196 in DECISIONS.md. The messages came out with the algebra visible:
`dim256<Meters/Seconds>` in the mismatch refusals, `dim256<Meters^2>` in
the compound-assign one, `dim256<Kilograms*Meters^2/Seconds^2>` for
Joules. Tests: `dim_basic.npk` (compose, cancel-to-tfp256, scale, `%`,
ordering, Newtons×Meters=Joules, a user unit combining with `Meters`,
floor, negation, div-zero→ERR riding the drop cast, the `pick` ERR arm,
compound assigns), `dim_cmp_err.npk` (the −4100 on a tainted compare),
twelve refusal rows in `types/rejection/dim_rules.npk`, two exhaust rows,
and the grammar corpus rows (both literal forms, `pub unit:`, parens).

**Found defect 1 — the `pick` ERR-arm demand had never extended past
`tbb`.** A `pick` on a `tfp` selector lowered fine at 1.3.2 with NO
ERR-arm requirement — `(*)` swallowed the taint, the exact D-008 hole the
tbb arm exists to close. All three twisted kinds now take the demand;
`exhaustiveness.npk` pins tfp and dim rows.

**Found defect 2 — compound assignment was a SECOND implementation of the
operators, and it had drifted** (0.9.5, latent — nothing ever exercised a
non-plain-int compound assign; found by `dim_basic`'s first `*=`). The
stmt emitter's own `arith_name` tail meant: twisted `+=` wrapped instead
of saturating, twisted `/=` by zero reached the hardware divider instead
of yielding ERR, plain `/=` skipped the D-007/D-142 division guards, and
float `+=` emitted an integer `add` on a double. The fix is the house
shape — the arithmetic value core extracted as `emit_arith_value`, both
spellings routing through it; `tbb.npk` and `float.npk` grew the compound
rows that would have caught it. REACH learned that a compound `/=`/`%=`
arms the trap identities (with the twisted suppression), since the walk
had never read the statement's own operator.

**Found defect 3 — `bridge_stubs.npk` compared token kinds by HARDCODED
NUMBER** (`92i64 // KwInt32`) — a hand copy of a GENERATED enum, the
"one fact, two representations" defect in its purest form. The `unit`
keyword's insertion renumbered every kind after 80, and the extern wire
vocabulary silently began refusing legal `int64` returns (EXTERN-001 on
`extern_stub`/`extern_c_driver`). Compared symbolically now
(`bs_kind_is` over `TokenKind`), and the harness grew
`check_no_kind_literals` — the grep that would have named it: an integer
literal annotated with a `// Kw…` comment outside the generated table is
a copy of it.

The selfhost stage also caught two of this subcycle's own slips the seed
is too loose to see — `emit_arith_value` missing `pub` across the
module boundary, and two D-065 move-discipline violations in the
extracted body (a `move` of a lent parameter's field; a double-move of
one root) — the fixpoint earning its keep again.
