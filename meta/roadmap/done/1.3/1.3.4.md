# 1.3.4 — `trit`/`tryte`/`nit`/`nyte`: the ternary/nonary bases (D-197)

The tier that exists because ternary/nonary HARDWARE is a planned target:
balanced-base values with the D-144 sticky-ERR discipline, checked as
ternary in the frontend, EMULATED by the binary rung — and the emulation
is the rung's choice, never the type's identity (§7's load-bearing
caveat).

## Design points, fixed at open (inside D-197's ratified frame)

1. **The binary rung stores the VALUE, not packed digits.** One `TY_TERN`
   kind: `a` = carrier bits (8/16 — `type_int_bits` stays uniform, the
   dim lesson), `b` = base (3 or 9 — nonzero, so `type_is_signed` answers
   true for free), `c` = digit count (1/10/5); the balanced bound derives
   as (base^digits − 1)/2 → ±1, ±29524, ±4, ±29524. The PROTOTYPE packs
   trits into LUT-driven split bytes with ripple-carry loops — the exact
   emulation-as-identity §7 warns against, plus runtime LUT state a
   verifier would have to carry. The value representation makes balanced
   order NUMERIC order, arithmetic native with one bound check, and the
   ERR sentinels (−128/−32768) COINCIDE with the tbb carrier minimums —
   `tbb_min_decimal` serves a third family, and `tbb_divlike` runs
   verbatim (a quotient's magnitude never exceeds its dividend's).
2. **Overflow → ERR at every width — the prototype's `trit_add` clamp is
   OVERRULED.** The oracle saturates a trit sum to ±1 while its own
   multiply errs on overflow; D-197's text ("sticky, D-144 discipline;
   overflow → ERR") is uniform and outranks it. `1trit + 1trit` is ERR,
   exactly as `MAX + 1` is on tbb.
3. **Ops per D-197**: `+ - *` at all four; `/ %` at `tryte`/`nyte` ONLY
   (a three-state division is not an operation anyone writes — refused
   with its own code, TYPE-051); comparisons at all four (balanced order
   IS numeric order under the value representation, so the twisted
   compare-trap discipline applies unchanged); negation is `0 - x`,
   total under balance; division by zero yields ERR (D-007's twisted
   row — REACH suppresses the trap arms).
4. **Kleene logic rides `&` and `|` on the single digits** (`trit`/`nit`,
   the user-ratified spelling): AND = min, OR = max, True=1, Unknown=0,
   False=−1, ERR sticky; NOT is `0 - x`, which in balanced ternary IS
   logical negation — no new spellings. On `tryte`/`nyte` the operators
   stay refused (the bitwise refusal's own message).
5. **Digit access**: `.trit(i)` / `.nit(i)` — bounds-checked index
   (OutOfBounds trap), result typed `trit`/`nit`, an ERR receiver yields
   an ERR digit (sticky through extraction). Computed from the value by
   the offset trick — `(v + bound)` is 0..base^digits−1 unsigned, digit
   i = that / base^i mod base − (base−1)/2 — with base^i a branch-free
   select over the ≤10 constants. `.len` is the digit count (10/5/1),
   an `int64` like every other `.len`.
6. **Literals are contextual, both spellings.** A ternary-typed slot
   takes an unsuffixed integer literal — decimal (`tryte:t = 42;`) or
   balanced-sequence (`1T0T1t`, `2An`; D-147 folds the digits to the
   value at scan) — range-checked against the EXACT balanced bound in a
   dedicated literal arm (`ValueRange`'s power-of-two magnitudes cannot
   spell ±29524). `ERR` takes the slot's type; `is_err` and the `pick`
   ERR arm extend (the fourth twisted kind joins the exhaust demand).
7. **Casts**: the four types are ONE family within themselves — value-
   preserving, sentinel maps, widening-or-equal `=>` (`trit => tryte`,
   `trit => nit`, `tryte => nyte` and back — same 59049 values), value-
   narrowing `=>!` saturates to ERR (`tryte =>! trit`), the tbb⇄tbb
   discipline. Leaving to int/float: the D-144-as-amended rule — ERR
   traps under BOTH spellings, the value range-classified (`type_range`
   rows overclaim to the enclosing power of two — ±4 reads as ±7 — which
   is the SAFE direction: it can only make a leaving cast stricter).
   Entering from int/float: check-or-saturate, the tbb entering arms.
   Cross-twisted-family (⇄ tbb/tfp/dim): CAST_IMPOSSIBLE, through the
   plain integer — the D-195 amendment-4 precedent, one rule.
8. **`ToString`**: "ERR" or the decimal value (D-168's shape, the tbb
   impls' twin) — the value IS a number; balanced-digit rendering is
   what the digit methods are for. Four prelude impls, `is_err`-guarded.
9. **REACH**: the family arms `TbbErr` (one taint, one name — D-195);
   its division arms no DivByZero/DivOverflow; the exhaust demand and
   every twisted predicate gain the fourth kind — the enumerated sweep,
   third run of the playbook.

## The work

1. **Generator/types**: the four names leave known:false (a `TERNARY`
   dict beside `KERNEL`/`SIMPLE`: name → base, digits from base+bits);
   `TY_TERN` (=43), `tt_tern`, the bound helper, predicate arms
   (drops/ordered/escape/layout), `type_range` rows.
2. **Checker**: the literal arm (exact bound), ERR/`is_err`/pick, the
   arithmetic arm (same-type; the `/ %` gate at digits>1; TYPE-051),
   the Kleene intercept on `&`/`|` for digits==1, negation, compare
   admission, the cast matrix, digit methods + `.len`, mixing refusals.
3. **Emitter**: the TERN arithmetic arm in `emit_arith_value` (sticky
   checks; native add/sub with the balanced-bound select; mul through
   i32; `tbb_divlike` for `/ %`), Kleene min/max selects, negation via
   the twneg shape, casts (family-internal maps; the tbb-shaped
   entering/leaving arms with the balanced bounds), digit extraction and
   `.len`, `ll_type` → i8/i16, literal emission (the folded value).
4. **Prelude**: four `ToString` impls.
5. **Tests**: `tern_basic.npk` (all four types: arithmetic, overflow→ERR
   — including the trit clamp departure — stickiness, div/mod at
   tryte/nyte, div-zero→ERR, Kleene truth table, digits of positive and
   negative values, `.len`, both literal spellings, family casts,
   leaving/entering casts, negation, ordering, pick ERR arm),

6. **Docs**: D-197 implementation record (the representation decision

   Kleene, digits, casts), CLAUDE.md status.

## Close-out: what landed, and the found defect

Everything above landed as designed; the implementation record is on
D-197 in DECISIONS.md. Two mechanics fell out during the build: `trit`
and `nit` joined the after-dot keyword interning (the D-056 `acquire`
mechanism — the type keywords carry no intern, and the digit extraction
is their one legal home after a `.`), and the digit power `base^i` is a
branch-free select chain over the ≤10 constants rather than a loop — no
phi, and on a ternary target the whole extraction is one instruction
anyway. Tests: `tern_basic.npk` (48 assertions — both literal spellings,
overflow→ERR including the overruled trit clamp, stickiness, `/ %` at
the multi-digit pair, div-zero→ERR, the Kleene truth table, digits of
positive AND negative values plus the ERR receiver, `.len`, every family
cast direction, saturating entry, pick, compound assigns through the
shared core), `tern_cmp_err.npk` (the −4100), `tern_digit_oob.npk` (the
D-070 bounds trap on a digit index), eight refusal rows in
`tern_rules.npk`, the exhaust row.

**Found defect — the same-text early-out defeated the tbb cast matrix at
SAME-WIDTH crossings.** Placing the tern cast intercept demanded an
answer to where the early-out sits, and the answer exposed tbb:
`tbb32` and `int32` share the carrier text `i32`, and `emit_cast`'s
early-out sat ABOVE the tbb intercept — so the same-width crossings
(`tbb32 ⇄ int32`, `tbb64 ⇄ int64/uint64`, …) rode through with NO
sentinel check. That is the audit's Theme-A hole D-144's own text says
0.9.5 closed. Its tests passed by COINCIDENCE: the only int32 value
outside tbb32's valid range is INT_MIN, whose bit pattern IS the
sentinel — the unchecked forge produced exactly the "saturation" the
test asserted — and the leaving direction quietly read ERR out as a
number, the laundering 1.3.2b closed at every OTHER width. The tbb
intercept now precedes the early-out (as tfp's has since 1.3.2, and
tern's does from birth), with a same-TYPE short-circuit keeping the true
no-op; `tbb.npk` pins the same-width crossings in both directions.
