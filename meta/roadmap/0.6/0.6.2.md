# 0.6.2 — Hygiene

**Cycle 0.6 — Macros and comptime.**

## Goal

An identifier in a macro body means what it meant where the macro was **written**,
and `#caller(NAME)` is the only way to mean anything else.

## The rule, and why it is a flip

The prototype resolves a macro-body identifier in the defining scope, notices when
the call site disagrees, emits `NITPICK-061 MACRO_HYGIENE_VIOLATION` — and **keeps
the caller's binding anyway.** `bug603` states the intent outright: "the macro
doesn't use `#caller()`, so the back-compat path keeps the caller-scope binding
while NITPICK-061 surfaces the hazard."

D-057 calls that what it is:

> A back-compat path, not a design. And it is precisely the failure the blueprint
> philosophy exists to prevent: **the macro means something different depending on
> where it is invoked**, with a warning as the only guard. A warning is not a
> mechanism; it is a request that someone be paying attention.

Flipped, in four parts:

1. An identifier in a macro body resolves in the **defining scope**. Always.
2. If it does not resolve there, that is a **compile error** — never a silent
   fallback to the caller's scope.
3. **`#caller(NAME)`** is the sole way to reach the call site.
4. **`NITPICK-061` disappears as a warning**, because the hazard is structurally
   absent rather than detected.

## Work

1. Resolve macro bodies in their defining scope, which means the expansion pass
   has to carry that scope with each body it instantiates.
2. Refuse an unresolved identifier, naming the defining scope it was looked for in.
3. **`#caller(NAME)`** — and note that `caller` is **not currently a builtin**:
   `builtins.npk` does not list it, so a program writing `#caller(x)` today gets
   "unknown name" from the resolver. The sigil is right (D-020, D-046); the entry
   is missing.
4. Delete `NITPICK-061` rather than leaving it unreachable. A warning whose hazard
   cannot arise is a code a reader will eventually try to trigger.

## Watch for

**This is the one subcycle where the prototype is not the oracle.** Everywhere
else in this project the prototype's behaviour is what to check against; here it
is explicitly what to replace, and its 49 tests encode the old rule. A test
recovered from the corpus that asserts the caller's binding wins is asserting the
thing D-057 removed.

**`#caller` is an escape hatch, so it must be greppable and it must be checked.**
Naming something through it that does not exist at the call site is the same error
as failing to resolve in the defining scope, and it needs its own diagnostic —
otherwise the opt-out is the one path with no rule.

## Done when

- A macro body naming something from its defining scope resolves there, even where
  the call site has a different binding of that name.
- A macro body naming something absent from its defining scope is refused.
- `#caller(NAME)` reaches the call site, and is refused when the name is not there.
- `NITPICK-061` no longer exists.
