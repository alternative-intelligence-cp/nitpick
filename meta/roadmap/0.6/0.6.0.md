# 0.6.0 — The macro semantics, recovered and written down

**Cycle 0.6 — Macros and comptime.**

## Goal

`meta/specs/MACRO_REFERENCE.md` exists, and every later subcycle is built against
it rather than against 31 test files.

## Why this is a subcycle and not a preliminary

D-057's finding is that the macro system **is** specified — in the wrong artifact:

> 49 `.npk` files under `nitpick/tests/`, carrying the semantics in comments keyed
> to decision codes (`MACRO2-DEC-001…007`, `COMPTIME-006/007`). No user code in
> `stdlib`, `ARCHIVE`, or the examples declares a macro; the entire corpus is
> tests.

Building against that corpus directly is exactly how cycle 0.4 lost five defects:
each was a construct that parsed, was recorded faithfully, and was never read
downstream — and each survived because the test that should have caught it was
written from what was convenient rather than from the specification's own example.
**There is no specification's own example here to write from.** So one gets written.

It is also a deliverable. `meta/specs/` becomes the contents of `nitpick-docs` at
the switch (`meta/SWITCH.md`), and a language whose macro system is documented only
by its own regression tests is not one anybody outside the project can use.

## Work

1. **Read the corpus and extract the rules.** 31 files carry `MACRO2-DEC` or
   `COMPTIME-` codes; the named ones D-057 cites are `bug591`–`bug603`,
   `MACRO2-DEC-001…007` and `COMPTIME-006/007`.
2. **Write `MACRO_REFERENCE.md`** — declaration form, invocation form, parameter
   substitution, hygiene, what may be emitted, expansion order, and the bounds.
3. **Record what the corpus leaves open**, rather than inventing it. A rule nobody
   wrote down and no test exercises is not a rule; it is a decision waiting.
4. **Settle what `#[derive]` generates** — see below. It is frontend-blocking and
   belongs here, not in 0.6.5.

## What is already settled and must be written as settled

Three things D-057 decided, which the corpus does **not** say — so the reference
records the decision, not the prototype's behaviour:

- **Hygiene resolves in the defining scope, always**, and failure to resolve there
  is a compile error. The prototype keeps the caller's binding and warns; that is
  a back-compat path, and `NITPICK-061` disappears with it.
- **Expansion is bounded.** The prototype does not terminate on
  `macro:m = () { m!(); };`.
- **`MacroPattern` in `pick` is gone**, not respelled — macros expand to a fixed
  point before semantic analysis, so no invocation survives for a pattern to match.
  `AST_REFERENCE.md` already records this; the macro reference should not
  reintroduce it.

## The decision this subcycle owes 0.6.5

**What `#[derive]` may derive, and what each one generates.**
`TRAITS_REFERENCE.md` §131 lists eight — `Default`, `PartialOrd`, `ToString`,
`Eq`, `Hash`, `Clone`, `Debug`, `Ord` — and **what they generate is nowhere.**

Several are not mechanical:

- **`Ord` / `PartialOrd`** need a field order. Declaration order is the obvious
  answer and it is a decision, because it makes reordering fields a semantic change.
- **`Hash`** needs a combining function, which is a cryptographic-adjacent choice
  in a language whose crypto library is a separate audited artifact.
- **`Debug` / `ToString`** need a format, and D-053 moved formatting to `&{ }`
  interpolation — so what these generate is a function returning `string`, not a
  format string.
- **`Default`** needs a default per field type, and Nitpick has **no implicit
  default value** (D-010). That is not a small wrinkle: `Default` may be
  underivable for exactly the reason definite assignment exists.

Frontend-blocking in the same way D-113 was: derive generates declarations, so the
frontend has to accept whatever shape they take, and the frontend is built once.

## Watch for

**The corpus is the prototype's behaviour, not the language's design.** Where the
two differ, D-057 already picked — and the reference records the decision with the
prototype's behaviour noted as what it replaced. Writing down what the tests do,
where a decision says otherwise, would be documenting a bug.

**No user code declares a macro.** Every example in the reference has to be
written, and — per the lesson 0.4 paid for — every later test should be written
from those examples rather than from whatever is convenient.

## Done when

- `meta/specs/MACRO_REFERENCE.md` covers declaration, invocation, substitution,
  hygiene, emission, expansion order and bounds.
- Everything the corpus leaves open is listed as open, not guessed.
- What `#[derive]` generates is settled, per trait, with `Default`'s interaction
  with D-010 resolved either way.
