# 0.4.5 — Member access, calls, and UFCS

**Cycle 0.4 — Type system and checking.**

## Goal

Everything 0.3.5 deliberately left alone.

## Work

1. `p.x` — a struct field, **auto-dereferencing** through pointers (D-006). `.`
   is the only member operator; `->` is type-position only.
2. `p?.x` — the same, short-circuiting on absence.
3. `Net.Disconnect` — an enum variant. Identical in the AST to `math.sqrt`, and
   told apart **here**, by what the base resolved to in 0.3.5.
4. `math.sqrt` — through a module alias.
5. Calls: arity, argument types, and the variadic `..*T[]` (D-070).
6. **UFCS** — `p.magnitude()` resolves to `Point_magnitude(p)` (D-006). The
   receiver is already apart from the callee in the AST (0.2.8), which is what
   makes this a lookup rather than a rewrite.
7. Index: bounds-checked, on arrays, slices and pointers.

## Watch for

**Auto-dereference must not hide a level.** `pp.x` where `pp` is `Point->->` is
either an error or two dereferences, and whichever it is has to be the same
everywhere. Decide it once, here, and write it down.

## Done when

- A field, an enum variant and a module member all resolve, and each says
  something useful when it does not exist.
- UFCS resolves, and a method that does not exist names the type it was sought on.
- Calling with the wrong arity names both counts.

---

## Outcome

`src/frontend/type_layout.npk` — struct layout, field lookup, enum variants.
`src/frontend/type_access.npk` — member access, indexing, calls, UFCS.

**D-098** answers the question the plan flagged: **auto-dereference is one level
only.** `pp.x` on a `Point->->` is an error naming `<-`, and the same rule
applies to UFCS, because a method call that peeled differently from a field
access would make `.` mean two things one character apart.

### Struct layout was a placeholder

0.4.1 interned a named type from its declaration and left the size at zero —
"computed once every field's type is known". Field types become known here, and
the debt was worth tracking: a `Result<Point>` built from a zero-sized `Point` is
four bytes where it should be twelve, and nothing downstream would have said so.
The layout walk and the field lookup are **the same walk**, because splitting
them would mean two traversals that have to agree about padding.

### An enum variant and a module member are the same node

Told apart by what the base resolved to, exactly as 0.3.5 deferred. Two things
this needed:

- **The namespace question has to be asked before the base is typed as a value.**
  `Net` is an enum name, and typing it as an expression reports "`Net` is a type,
  not a value" — right in general, wrong where a type name is exactly what belongs.
- **A `Scope` records its parent, not its owner**, so a module's members were
  unreachable from its name. `Symbol.inner` now carries the scope a namespace
  name opens; walking the tree for a child scope would have found every sibling
  block too.

### Three defects, one shape between them

**`namespace_member` returned a type id and used zero for "not a namespace".** So
a variant that did not exist reported its own error, returned zero, fell through
to the value path, and reported a second, misleading one. Split into `handled`
and `type_id` — the same *whether* versus *which* fix as `expr_shape` and
`num_width_kind`, now the fourth time.

**`expr_generic_count` reads the payload, and a method call's payload is the
method NAME.** Asking a `MethodCallExpr` for a generic count returns an intern
index and slices the argument window by it. The accessor is only meaningful on
`CallExpr` and `BuiltinExpr`; that is now written where it is defined.

**The test built its values with `NULL`.** `NULL` is valid only where a pointer
is expected, so a `NULL`-initialised slice is an error in its own right and every
case built on one was measuring that instead of what it meant to. The values come
in as parameters now.

### Still owed

`Optional` construction — nothing builds one, so `??` and the `?.` positive case
have no value to test against. Now that declarations carry types this is a test
to write once something constructs an `Optional`, which is a language question
rather than a checker one: `Result` has `Result{…}` and `Optional` has no
counterpart in any spec I can find. **Worth raising before 0.4.6.**

Variadic `..*T[]` argument checking (plan item 5) is not done — `fn_type` does
not carry the variadic spec, so a variadic call currently checks as fixed arity.
