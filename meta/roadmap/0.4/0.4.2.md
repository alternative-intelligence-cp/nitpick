# 0.4.2 — Expression typing

**Cycle 0.4 — Type system and checking.**

## Goal

Every expression has a type, and the operators enforce the semantic-type rules.

## The rules that matter more than the mechanism

**`bool` and `char8` are not integers.** They are one byte each, they are
representationally identical to `uint8`, and none of that makes them numbers.
`true + 1i32` does not typecheck. `'a' * 2i32` does not typecheck. There is no
implicit conversion in either direction.

**`tbb32` is an error-code type, not a number.** Comparison and assignment;
arithmetic drags in ERR, stickiness and saturation (D-008), and those belong to
the type's own operations rather than to `+`.

**`fd`, `pid`, `tid`, `uid`, `gid` compare and do not add** (D-042). An `fd` plus
one is not an `fd`, and the type system is the only thing that will say so.

Each of these is a place where the machine representation and the language
disagree, deliberately. This subcycle is where the language wins.

## Work

1. Literals — including the width suffix, which is **required** in expression
   position, and the base forms (`FFhex`, `1T0t`, `2An`).
2. Arithmetic, comparison, logical and bitwise operators, each with the operand
   types it actually accepts.
3. Integer promotion rules: what `int32 + int64` is, and whether it is legal.
4. `&&` and `||` take `bool` and nothing else — no truthiness.
5. Unary `-`, `~`, `!`, `@` (a second-class borrow, D-004), `<-`, `$$i`, `$$m`.
6. Ranges, the ternary, `defaults`.
7. `$` inside `loop`/`till`, which has a type and no declaration.

## Done when

- `true + 1i32`, `'a' * 2i32` and `err_code + 1i32` are all refused, each naming
  the type that made it wrong.
- Every operator in `OP_REFERENCE.md` §0 types its operands.
- A `bool` condition is required where the grammar takes one.

---

## Outcome

`src/frontend/type_expr.npk` — `ExprTyper`, the operator rules, and the
diagnostics that say *why* a familiar-looking type is not a number.
`tests/frontend/type_expr.npk` covers every operator in `OP_REFERENCE.md` §0 that
this subcycle owns. **47 tests pass.**

Two decisions were forced and are recorded: **D-092** (unsuffixed literals take
their type from context; implicit widening only within one signedness) and
**D-093** (a range is a typed value; ordering is narrower than equality).

### What the operators accept

| Family | Accepts | Refuses, and says why |
|---|---|---|
| `+ - * / %` | integers, floats | `bool`, `char`, `tbb`, kernel ids, pointers |
| `& \| ^ << >>` | integers | floats, `bool` — and points at `&&` |
| `== !=` | any type with equality | operands with no common type |
| `< <= > >= <=>` | integers, floats, **chars** | `bool`, `tbb`, kernel ids (D-093) |
| `&& \|\| !` | `bool` and nothing else | everything — there is no truthiness |
| unary `-` | signed numbers | unsigned: negation has no answer there |
| unary `~` | integers | everything else |
| `++ --` | numbers | `char8` especially |
| `..` `...` | ordered endpoints | anything with no ordering |
| `is (c):a:b` | `bool` condition, arms agreeing | either half failing |
| `?\|` / `defaults` | both sides agreeing | a fallback of another type |
| `@` `$$i` `$$m` | anything | — |
| `<-` | pointers | non-pointers, and `any->` (cast first) |

### What this cost, and what it bought

The width suffix was being **discarded by the parser**, so `42i32` and `42` were
the same node and D-092's rule could not be applied to either. Fixing that put
the width in slot `a`, which was free on a literal — and that broke the compiler
in a way nothing detected.

`resolve_expr` walked slot `a` as a child on every kind it did not name. A
`42i32` began resolving whatever node sat at index `WI32`. No crash, no
diagnostic; a name in a different file stopped binding, and the only trace was
`tests/frontend/resolve.npk` exiting 100.

**D-094** is the result: slots hold node references, never scalars; `expr_shape`
states every kind's shape once; both walkers are driven by it; and
`EXPR_KIND_MAX`, generated from `AST_REFERENCE.md`, makes a missing entry a test
failure that names the kind. Verified by making it fail.

Fixing it also found the same assumption **copied into `init_reaches`**, the
global-initialiser cycle check, with its own partial list of window kinds — three
named, four missed. A self-reference through a template literal or a method
call's arguments went unseen. One table, two callers, both correct now.

### The transferable part

This is the third completeness check in the compiler, and all three were found
the same way: **two lists that had to agree, with nothing making them agree.**
Spec node tables versus generated kinds (0.2). Walked constructs versus bound
identifiers (0.3.5). Node kinds versus the shapes a walker knows (here).

The tell is a comment asserting a fact about *all* of something. `"slot a is an
operand on every node that has one"` was true when written, was never checked,
and stopped being true two cycles later. When a comment quantifies over a list,
that is a check waiting to be written.

One more, smaller: the test's `errs()` counted only **type** diagnostics, so a
positive case whose expression failed to parse passed for the wrong reason — node
0 types instantly and reports nothing. Parse failures now count against the same
total.
