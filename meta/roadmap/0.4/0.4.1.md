# 0.4.1 — Type resolution

**Cycle 0.4 — Type system and checking.**

## Goal

Every `TypeNode` in the AST becomes a `Type`, or a diagnostic.

## Work

1. `NamedType` → the symbol it names, then that symbol's type. A name that is not
   a type — a function, a global — is an error saying **what it is instead**.
2. The builtin scalar names, from the generated table rather than a second list.
3. `PointerType`, `OptionalType`, `ArrayType` (fixed **and** slice — the same node
   discriminated by whether a size is present, D-070).
4. **`cstring`, `any` and `FuncType`** — the three corners 0.2.8 made reachable.
   `any` is legal **only under `->`** (`TYPE_REFERENCE.md` §27), and the message
   the spec already writes is the one to emit.
5. `dyn A & B` → a trait-object type over a set of traits, checked for object
   safety in 0.4.6.
6. `Self`, valid only inside a `trait` or `impl` body (D-030).
7. An array size is a **constant expression**: evaluate it, and a non-constant one
   is an error naming what it depends on.

## Watch for

**A bare `any` must not be silently promoted to `any->`.** The spec's message
says a bare one is not a valid type; a checker that helpfully fixed it would make
`any` mean two different things depending on where it was written.

## Done when

- Every type spelling in `tests/grammar/whole_grammar.npk` resolves or diagnoses.
- Bare `any` is refused, `any->` is not.
- A name that is not a type says what it is.
