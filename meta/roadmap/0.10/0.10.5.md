# 0.10.5 — The `wildx` W^X state machine

**Cycle 0.10.** Executable memory for the JIT, with the lifecycle enforced as
verifiable obligations. D-035 settled that `wildx` is retained and specified *what*
must be provable; this subcycle builds the *how* — the analysis and runtime that
make the W^X invariant structural rather than hoped-for. It is last in the cycle
because it is the most specialized and has the fewest dependents.

## What D-035 requires, and what is missing

D-035's three deliverables are all open at 0.8-close (total_audit B-1):

1. **State the verification boundary** — `wildx`-generated code is outside both Z3
   and any static analysis (no AST exists for it), exactly like the FFI barrier.
   The guarantee `wildx` delivers is *containment*: the JIT cannot corrupt host
   memory safety.
2. **Specify the lifecycle as verifiable obligations** — and this is the gap: the
   `alloc → write → seal → execute → free` state machine, with seal-before-execute,
   no-write-after-seal, no-double-free, and no-live-pages-at-exit. `bindings.npk`
   tracks `move`/`free` but has **no notion of the seal transition**.
3. **`--extra-picky=no-wildx`** — a rule separate from `no-wild`, since manual
   memory and runtime code generation are very different risks.

## What it builds

- **The runtime**: `wildx_alloc` (a W^X page with a guard page and ASLR — the
  prototype's `wildx_alloc.cpp` design, rewritten C-free), `wildx_seal` (the
  **one-way** RW→RX transition that makes the invariant structural — a page is never
  simultaneously writable and executable), and `wildx_free`. Pages join the
  `<wild-live>` registry (0.10.1) so a live `wildx` page at `exit` traps.
- **The state-machine analysis** — an extension in the analysis layer (alongside the
  0.5 move/free machinery it resembles) tracking each `wildx` binding's state:
  writing after seal is refused, executing before seal is refused, double-free and
  use-after-free fall out of the existing move machinery (a seal/free is a state
  transition the walk already knows how to thread). This is the machinery D-035 said
  "should reject statically" the class of bug it found.
- **`--extra-picky=no-wildx`** — rejects `wildx` independently of `no-wild`.

## The regression test D-035 hand-delivered

D-035 found a **use-after-free in the prototype's `jit.npk`**: it frees the page on
write failure and then seals the freed page, with no early return. That exact shape
is the acceptance test for the state machine — the analysis must refuse it
(seal-after-free), and a corrected version (early return on write failure) must pass.
Port the corrected `jit.npk` compile-a-function example C-free as the positive test.

## Certification note (state, do not resolve)

A program containing `wildx` will not reach the highest DO-178C/IEC 61508/ISO 26262
levels (they require structural coverage over code that exists before execution) —
that is a property of the *program*, not the language, and `--extra-picky=no-wildx`
gives a high-assurance build mode that excludes it. State this in the spec where the
verification boundary is stated; it is not a gap to close, it is a boundary to
document.

## Tests

`tests/analysis/rejection/wildx.npk`: seal-after-free (the `jit.npk` bug),
write-after-seal, execute-before-seal, double-free, each refused with its own code;
an acceptance case of the correct `alloc→write→seal→execute→free` sequence. A runtime
program (executed) that JITs and calls a trivial function, proving the W^X
transition works and the page is freed before exit (empty live-set).

## Done when

`wildx` alloc/seal/free lower with W^X, guard pages, and ASLR; the state-machine
analysis refuses every out-of-order transition (the `jit.npk` bug among them) and
accepts the correct sequence; live `wildx` pages at `exit` trap via the 0.10.1
registry; `--extra-picky=no-wildx` exists; the verification boundary and
certification note are written into the spec. **Cycle 0.10 closes** — the real
allocator, the leak guarantee, both arena types, the frame allocator, and the JIT
lifecycle all exist, and 1.1 has the substrate it needs.

## Outcome (recorded at close)

Landed as D-155, closing D-035's three deliverables and cycle 0.10. The
design's best move was recognising how LITTLE new analysis the state machine
needed: seal-after-free (the jit.npk bug), double-free, and use-after-free
all fall out of the existing move machinery (a free is a move, D-065), and
no-live-at-exit falls out of 0.10.1's registry. Only two transitions were
genuinely new — write-after-seal and execute-before-seal — and they took two
seal columns in the binding state, because the prohibitions merge oppositely
(sealed-on-any forbids writing; sealed-on-all permits executing; the
one-armed seal is refused for both, correctly).

The runtime is real W^X: three-page guarded mappings, one-way RW→RX
mprotect, kernel-placed (ASLR), secret-keyed headers. wildx_jit.npk writes
`mov eax, 42; ret` and runs it end to end. --extra-picky=no-wildx is a real
parsed build mode scanning the tree for any wildx and refusing it
(WILDX-003), with the verification boundary and certification note written
into VERIFICATION_REFERENCE §6.4.

Two small course-corrections in flight: place_root stops at `<-` (a deref
yields the pointee value, D-004), so the write-after-seal check peels the
deref to reach the pointer binding; and byte patterns like 0xB8/0xC3 exceed
int8 (D-148), so JIT pages are `wildx uint8->`. Both were caught by the
probes before the harness.

**Cycle 0.10 closes.** The real allocator, the leak guarantee, both arena
types, the frame allocator, and the wildx lifecycle all exist and run; 1.1
has its substrate.
