# 0.10.2 — `arena<T>` and `Handle<T>`

**Cycle 0.10.** The single-threaded arena and its generation-counted handle — the
mechanism D-003 made load-bearing, since it is how Nitpick handles graph-shaped and
cyclic data without a collector (allocate the graph, drop the arena wholesale).
These parse as keywords today and lower nowhere (their refusal names no cycle — a
gap this subcycle also closes).

## What it provides

- **`arena<T>`** — a slab of `T` slots (`MEMORY_REFERENCE §4`), with `alloc`, `get`,
  `free`, `reset`, `destroy`. Growth may reallocate the slab (single-threaded, so no
  concurrent `get` can dangle). **Reconcile the operation set (allocator dive §5.4):**
  PROTOTYPE_DELTA dropped `reset`/`destroy` and chained access, but D-017's operation
  table (which postdates the delta and is authoritative) keeps them for `arena<T>` —
  so `reset`/`destroy` are IN. Chained access through arenas embedded in structs
  (`app.my_arena.alloc()`, MEMORY_REFERENCE §4.2) is UFCS, which is a 1.0 rung — so
  the arena *type* lowers here and the *chained-UFCS sugar* waits for 1.0 (state this
  so the boundary is not a surprise).
- **`Handle<T>`** — the 16-byte `{i64 index, i32 generation}` (MEMORY_REFERENCE §4.1).
  Handles are **indices, not pointers**, which is what makes them safe across arena
  growth and able to express cycles. `get(h)` checks the generation; a stale handle
  fails through `Result` (`get` returns `Result<T>`, the `?`-with-default idiom the
  spec shows), never dangles. `free(h)` increments the slot's generation, retiring
  every outstanding handle to it.

## The keyword-refusal gap it closes

`arena`, `Handle`, `shared_arena` currently resolve to "not available at this rung
yet" with **no cycle named** (`resolve_type.npk:1392-1399`) — violating the D-085
standard the backend refusals meet (total_audit B-3). As each lands here, its
refusal is replaced by lowering; until 0.10.3/0.10.4 land the others, amend their
refusals to name **0.10** so the message is honest.

## Interaction with the borrow checker

`get()` returning a second-class borrow (D-004) was left open by D-017. Decide here:
**proposed yes** — `get(h)` yields a borrow that cannot escape the checking scope,
which composes with the escape analysis already built and prevents a returned `T&`
from outliving a `reset`. This is small and it closes the open sub-item D-017 left.

## Tests

`tests/backend/programs/arena.npk`: allocate a cyclic graph in an arena (two nodes
holding each other's handles), traverse it, drop the arena wholesale (no per-node
free, no leak — the live-set from 0.10.1 confirms empty at exit); a stale handle
(freed slot, reused generation) failing `get` through `Result` rather than reading
the new occupant; a `reset` invalidating all handles.

## Done when

`arena<T>` and `Handle<T>` lower and run; the generation check turns a
use-after-free into a `Result` error, demonstrated by an executed program; the
operation set matches D-017 (reset/destroy in); `get`'s borrow status is decided;
the keyword refusals name 0.10 until the siblings land.

## Outcome (recorded at close)

Landed as D-152. The plan's open items resolved: `get`'s borrow status is
NO — a borrow-returning `get` is a returned borrow, which BORROW-001
already refuses language-wide, so `get` copies and `put` (new, amending
D-017's table) writes back; `reset`/`destroy` are in per D-017; the
spec's `arena<int64>.alloc(1000)` creator — one name for two operations —
is corrected to the type-directed `arena_make` builtin. Chained access
through struct-embedded arenas turned out to need NO UFCS machinery at
all: the receiver is an ordinary member place, proven in the program test.

The runtime is stride-erased (the compiler computes element stride) with a
generation PARITY discipline — live even, freed odd, handles only ever
carry even — so a stale handle cannot match a freed slot even in
principle, and a slot retiring at 0xFFFFFFFE means the counter never
wraps. Slab and generation array are wild-role blocks: the leak check
counts an un-destroyed arena, making D-003's "drop it wholesale" a
mechanical contract. `destroy` is a typed move in the binding analysis
(receiver-type-gated, never name-matched). The keyword-refusal gap closed:
`shared_arena` names 0.10.4, `atomic` names 1.1.

`arena.npk` runs the whole story — cycle, growth relocation, staleness,
reuse-under-new-generation, lazy `?` fallback, reset, chaining, wholesale
drop through the exit check; the two rejection files lock wrong-element,
non-operation, no-context, cycle-naming, and both destroy moves.
