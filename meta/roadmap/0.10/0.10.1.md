# 0.10.1 — The leak registry and the exit-time check

**Cycle 0.10.** Make the K-semantics leak guarantee real. Today it is vacuous —
`<wild-live>` tracks nothing because nothing frees, so `exit` with a leaked `wild`
allocation succeeds silently. This subcycle wires real allocation into a live-set
and enforces the exit precondition the whole leak story rests on.

## Why this is a safety subcycle, not bookkeeping

The reason arenas could replace a tracing collector without losing safety (D-003) is
that **a leak is a detected, controlled condition** here rather than silent
corruption: the K-semantics rule routes `exit` with live `wild`/`wildx` memory to
`failsafe` instead of returning (CONTROL_REFERENCE §4.6, SAFETY_ARCHITECTURE). That
is a promise about this subcycle's code. Until it exists, the promise is unbacked —
a program can leak a device handle or a mapped region and exit clean, which for the
robotics path is a resource left live at shutdown.

## What it builds

- **The `<wild-live>` registry** — a runtime structure recording every live `wild`
  allocation (and, via 0.10.5, every `wildx` page). `alloc` adds; `dalloc` removes;
  `ralloc` swaps. Preallocated and reachable from `failsafe` (it must be walkable in
  a degraded state, so it cannot grow during a trap — same discipline as the driver
  registry in the extern-driver work and the stream registry IO_REFERENCE §10 owes).
- **The exit-time check** — `exit` (legal only in `main`/`failsafe`, D-013) completes
  only when the live-set is empty; a non-empty set routes to `failsafe`, which may
  then clean up and exit (the two-layer shape D-062 and the driver registry both
  use). This is emitted at the `exit` lowering site, extending 0.9's `emit_exit`.
- **Registry unification (the audit's recurring ask).** The allocation registry, the
  stream registry (IO_REFERENCE §10, open, told to share the allocation registry's
  structure), and the driver registry (extern-driver work) are one mechanism with
  three client tables. Build the mechanism once here — preallocated, fixed-capacity,
  failsafe-walkable — so 1.1's streams and the eventual driver support are clients,
  not re-inventions.

## OOM → failsafe, allocation-free (fixes total_audit C-3)

The floor exits 70 on OOM with a comment that the real runtime must trap. Wire it:
OOM routes to `failsafe` (OOM is a listed trigger, SAFETY_ARCHITECTURE). **State the
allocator's own obligation** the spec omits: OOM handling runs *when allocation just
failed*, so its path must be allocation-free — the failsafe-reachable state is
preallocated, the D-014 discipline applied at the allocator boundary specifically.
Record this in SAFETY_ARCHITECTURE where OOM is listed.

## Tests

`tests/backend/programs/leak.npk`: a program that allocates `wild`, frees it, and
exits clean (empty set → normal exit); one that allocates and *forgets* to free,
asserting the process routes to `failsafe` at `exit` with the leak trap code rather
than exiting 0; one whose `failsafe` cleans up the registry and exits positive. A
program that exhausts memory, asserting the OOM trap rather than a silent exit 70.

## Done when

Every real allocation is in the live-set; `exit` with a non-empty set traps to
`failsafe`; the leak guarantee is demonstrated by an executed program (not just
asserted in a doc); OOM routes to `failsafe` allocation-free; the one registry
mechanism exists with the allocation table as its first client and the stream/driver
tables specified as the next two.
