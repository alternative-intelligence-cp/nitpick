# 0.1.6 — Lexical diagnostics, and the suites

**Cycle 0.1 — Lexer.**

## Goal

Every lexical error produces a diagnostic with a stable code and an accurate
span, and the cycle's suites are complete.

## Work

1. Assign codes to every lexical error and record them.
2. **Error recovery**: a lexer that stops at the first bad byte reports one
   problem per run. Recover to the next plausible token boundary and keep going,
   so a file with three bad literals reports three.
3. Complete the conformance suite — every construct in
   `LEXICAL_REFERENCE.md` lexes.
4. Complete the rejection suite — and remember these are the cases that pin the
   specification. D-057, D-064 and D-066 were all recovered from error cases in
   the prototype, not from prose.

## Done when

- Every lexical error has a code, and a rejection test asserting it.
- A file with several errors reports several, not one.
- The suite passes, and closing the cycle pushes it.
