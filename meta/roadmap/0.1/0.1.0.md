# 0.1.0 — Source manager, intern table, and `#size_of<T>`

**Cycle 0.1 — Lexer.** Storage first: the lexer reads from one of these and
writes into the other, so neither can wait.

## Goal

`SourceManager` (the file table a `Span.file` indexes into), `InternTable`
(identifier text → `int32`), and the `#size_of<T>` builtin that any manual
container needs.

## Why `#size_of<T>` is in scope here

Subset 1 has no generics, so every growable container is hand-written over
`alloc` / `ralloc` — and growing one means knowing an element's size. The
alternative is writing `48i64` for a two-string struct and hoping nobody adds a
field, which is a silent-corruption bug waiting on a refactor.

So `#size_of<T>` joins subset 1. It is already specified
(`BUILTIN_REFERENCE.md`), and it is the first `#`-sigil construct the seed has to
handle — `#name<T>(...)` keeps bare brackets because the sigil is itself the
disambiguator (D-064).

**It must not compute layout by hand.** The seed asks LLVM instead:

```llvm
%p = getelementptr %T, ptr null, i32 1
%n = ptrtoint ptr %p to i64
```

A hand-rolled size that disagrees with the one LLVM lays out is exactly the kind
of mismatch that survives testing and corrupts memory later. Asking the authority
costs two instructions that `opt` folds away.

## Work

**1. `#size_of<T>`** — parse, check, lower. The seed's first `#` builtin.

**2. `src/frontend/source.npk`.** `SourceFile { path, text }` and a
`SourceManager` holding them, growable over `alloc`/`ralloc`. `Span.file` is an
index into it, which is why spans stay five `int32`s rather than carrying a
string.

**3. `src/frontend/intern.npk`.** Identifier text is interned to an `int32`, so a
token payload fits in one machine word — the restriction `SUBSET_1.md` §1.2
records, and the reason the AST needs no pointers. Includes `string_eq`, written
in Nitpick over `.ptr` / `.len` rather than added to the runtime floor.

**4. Tests.** Round-tripping, deduplication (interning the same text twice yields
the same index), and bounds.

## Done when

- `#size_of<T>` lowers, and its result matches what `llc` lays out.
- Both tables round-trip and dedupe.
- The whole suite still passes.

## Not in this subcycle

No lexing. Nothing reads a byte of Nitpick source yet.
