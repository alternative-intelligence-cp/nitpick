# 0.5.4 — Exhaustiveness

**Cycle 0.5 — Static analyses.**

## Goal

A `pick` covers every case, and a tainted value never steers a branch.

## The rules

**`pick` must be exhaustive** — every value covered, or `(*)` supplied
(`SPEC_GAPS` §4, `CONTROL_REFERENCE` §1.2.2).

**A `tbb` selector additionally requires an explicit `ERR:` arm**, and `(*)` may
**not** absorb it (D-008 §5.1). That exception is the whole point of the rule: ERR
is the case a wildcard would swallow, and swallowing it is a tainted value
steering a branch — the one thing `tbb`'s sticky ERR exists to prevent.

**`(!)` is removed** (D-061). An arm the author believes cannot occur is an
ordinary arm whose body is `#unreachable()` — explicit, greppable, and it traps
rather than silently proceeding. The marker it replaced let an arm be *elided from
exhaustiveness*, and the arm most likely to be elided was the ERR one.

## Work

1. Enum exhaustiveness — every variant covered, or `(*)`. The variants come from
   the selector's type, which is why this needs 0.5.0's recorded types.
2. `bool` exhaustiveness — both values, or `(*)`.
3. The `tbb` ERR arm, and the refusal of `(*)` standing in for it.
4. **Which cases are missing, named.** "This `pick` is not exhaustive" makes the
   reader enumerate the variants themselves, which is the one thing the compiler
   already did.
5. Unreachable arms — a variant matched twice, or an arm after `(*)`.

## Watch for

**An integer selector cannot be exhaustive without `(*)`**, and saying so plainly
beats reporting the same "not exhaustive" as an enum with one variant missing. The
fix differs: one needs an arm, the other needs a wildcard.

**Guards do not count toward coverage.** `where` makes an arm conditional, so a
guarded arm covers nothing — a `pick` whose only `ERR:` arm carries a guard has no
unconditional ERR arm and must be refused, or the guard becomes a way to elide the
case D-061 removed the marker for.

## Done when

- A `pick` missing a variant is refused, naming the variant.
- A `tbb` selector with no `ERR:` arm is refused, and one where `(*)` stands in
  for it is refused too.
- A guarded `ERR:` arm does not satisfy the rule.
