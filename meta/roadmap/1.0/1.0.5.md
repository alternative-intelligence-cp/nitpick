# 1.0.5 — `dyn`: object safety, dispatch, ABI (D-157/D-158/D-159)

**Cycle 1.0.** The three `dyn` decisions land together because they are one
boundary. Decided: `D-157` (object safety), `D-158` (dispatch + vtables), `D-159`
(multi-bound ABI).

## What it builds

- **D-163 hook:** `find_method`'s `TY_DYN` path returns the TRAIT's declaration,
  never a concrete impl's — so 1.1's licence reads the trait's `never fails`
  contract for a `dyn` call (the vtable hides which impl runs, D-163 rule 5).

- **Object safety, extended (D-157):** `check_object_safe` walks the full type tree
  of every parameter and the return, refusing `Self` anywhere but the receiver, and
  rule 3 (no generic methods) unified. This is a **safety fix** — the current check
  reads only the return node.
- **Vtables (D-158):** per (impl, trait), entries in trait-declaration order, each a
  per-impl adapter thunk (caller passes data ptr + args; thunk loads the by-value
  receiver and calls the real method). `find_method` gains its `TY_DYN` path: own
  methods of the named traits only, ambiguity across bounds refused.
- **Multi-bound ABI (D-159):** `dyn` over N traits interns as `{data, vt_1…vt_N}`,
  bounds canonically ordered so slots are static; widening (`dyn A & B → dyn A`) is a
  value rebuild. Fixes `types.npk`'s flat 16-byte interning.

## Tests

A `dyn Trait` constructed from a concrete value and a method called through it; a
supertrait method NOT reachable through the subtrait's `dyn` (refused); an ambiguous
method across two bounds refused; `dyn A & B` widened to `dyn A` and dispatched; a
trait with `Self` in a non-receiver position refused object-unsafe; `dyn` of an
assoc-mentioning trait refused.

## Done when

Object safety refuses every non-receiver `Self`; `dyn` construction and dispatch run;
multi-bound layout and widening work; the vtable is declaration-indexed and
thunk-backed; the fixpoint holds.
