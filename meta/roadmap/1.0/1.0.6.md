# 1.0.6 — Associated types (D-160)

**Cycle 1.0.** Associated types become referenceable — the C-5 resolution, not the
descope. Decided: `D-160`.

## What it builds

- **`TY_ASSOC`** — a type kind carrying (trait decl, name); a bare assoc name inside
  a trait body resolves to it as `Self` does.
- **Impl binding substitutes** — `assoc:Item = int32;` binds the projection for that
  impl; the trait's method checks substitute bindings the way `Self` substitution
  works; defaults (`assoc:Error = string;`) inherited unless overridden.
- **External projection** — `T.Item` in generic code bounded by the trait, resolved
  through the existing dotted-path type grammar (settled against the parser as it
  stands in 1.0.5; no new token/node beyond the type kind).
- **Object-safety interaction** (from D-157): an assoc-mentioning signature makes the
  trait not object-safe.

## Tests

`Iterator`/`next → Item` typechecks (TRAITS_REFERENCE's flagship, which does not
today); an impl binding `Item` and a call resolving through it; a default assoc type
inherited; `T.Item` in a generic function; `dyn Iterator` refused.

## Done when

Associated types resolve in-trait, bind per-impl, and project externally; the spec's
own `Iterator` typechecks; assoc-mentioning traits are object-unsafe; the fixpoint
holds.

**Met except external projection**, which turned out to rest on a false premise
and is now C-20, gated on 1.0.6b. Everything else landed.

## What landed

**`TY_ASSOC`** carries the pair `(declaring trait, name)` — not the name alone,
because two traits may each declare `Item` and merging them would let an impl of
one satisfy the other.

**A bare assoc name resolves inside its trait**, the way `Self` does and in the
same place: after the generic-parameter lookup and before the scope, so the
nearer binding wins and a module-level `Item` is not what the trait body meant.
This needed `self_trait` on the resolver — `etyper_resolver`'s comment warns that
a field the constructor forgets gives "a resolver that is subtly not this
checker's", and this is exactly such a field.

**An impl's binding substitutes into signature comparison**, one level, the same
level `Self` gets and for the same stated reason: `Item` is a whole type where it
appears, and `Item->` would need the substitution to rebuild the wrapper. The
three values that comparison needs — target, impl, scope — became `SigCtx`
rather than three more parameters through four functions.

**A trait DEFAULT is inherited** by an impl that omits the binding (D-028's
surviving half), and **an assoc-mentioning signature makes the trait
object-unsafe** — D-157's erasure argument exactly, asked by the SAME walk
rather than a second one over the same tree.

**`trait:Iterator { assoc:Item; func:next = Item(Self:self); }` typechecks**,
which the plan noted it did not.

## Two smaller things

**`assoc` is a reserved word**, and it cost the edit-build-fail cycle
`CLAUDE.md`'s table is written about — `bool:assoc;` is not a field. Added to
that table.

**A missing binding was reported twice**: once correctly, naming the associated
type the impl failed to bind, and once as a downstream signature mismatch
pointing at the METHOD rather than at the `assoc:Item = …;` that was omitted.
The completeness walk already refuses a required assoc an impl does not bind,
and that is exactly the case that reaches the comparison with no binding — so
the second line is suppressed. Same judgment as D-157's rules 1 and 2, which do
not both fire for one mistake.

## What did not land, and why it is not a deferral

**External projection.** D-160 says `T.Item` "rides the EXISTING dotted-path type
grammar **if the parser already admits it**" — it does not, measured, six
`NITPICK-PARSE-001` — and the fallback it names, `Iterator.Item`, is dotted too.
Neither the spec (§2.3 shows declaration and binding only) nor the prototype
(`AssociatedTypeDecl`/`AssociatedTypeBinding`, and no projection node anywhere)
has ever had one.

Deciding it needs the alternative to work first: if a generic trait can be a
generic function's bound, projection is a convenience rather than a necessity.
**It cannot** — 1.0.6b's defect, verified pre-existing. So the question is
**C-20**, gated on **C-21**, both with rows and owners rather than a sentence
here.

- A missing binding with no default: one diagnostic, naming the associated type.
- Full harness green: `types` 23 → 24, `grammar` 289 → 290, and stage 1 rebuilt
  itself byte-identically.
