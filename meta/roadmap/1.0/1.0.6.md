# 1.0.6 — `Optional<T>` and the generic stdlib

**Cycle 1.0, closing.** With generics lowering (1.0.1) and traits/assoc types real
(1.0.3/1.0.5), the parameterized library types become buildable — `Optional<T>`
first (grammar #13's refusal names 1.0). No new decision.

## What it builds

- **`Optional<T>` as a library type** where D-099 left a compiler-known one, now that
  a generic can carry it — reconciled with the postfix `T?` sugar (one type, two
  spellings, the D-099 rule).
- **The first generic collections** expressible as library types (not yet adopted in
  `src/` — C-13), proving the machinery end to end: a generic container with methods,
  an impl, maybe a derived trait.

## Tests

`Optional<int32>` built, matched, unwrapped via the existing `?`/`?!` idioms; a
generic container type with an inherent method and a trait impl, instantiated at two
element types and run.

## Done when

`Optional<T>` lowers as a library type consistent with `T?`; a generic collection
with methods and an impl runs at multiple instantiations; **cycle 1.0 closes** —
generics, traits, and `dyn` all lower, and the concrete collections are ready to
retire when 1.2 switches the builder.
