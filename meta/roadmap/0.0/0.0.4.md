# 0.0.4 — Seed: runtime floor and linking

**Cycle 0.0 — Foundations.** Last of three seed subcycles; the point where
Nitpick first *runs*.

## Goal

The handful of symbols the emitted IR calls into, hand-written as LLVM IR, plus
linking — so a conformance file becomes a binary that executes and returns a
code.

## The runtime floor

D-015 already settles the approach: runtime symbols start as **hand-written LLVM
IR** and are replaced at a later rung. This is that rung.

| Symbol | Seed implementation |
|---|---|
| `alloc` | **a bump allocator that never frees** |
| `dalloc` | a no-op |
| `open` / `read` / `close` / `write` | raw syscalls |
| `exit` | raw syscall |
| `memcpy` / `memset` | the symbols LLVM emits calls to |
| `string_concat` / `int_to_string` | enough to build a diagnostic message |

**Never freeing is correct, not a shortcut.** The compiler is a process that runs
once and exits, so reclamation buys nothing — and an allocator is exactly the kind
of subtle code that must not live in the least-audited artifact. Real allocation
arrives with `nlibc` in cycle 0.8.

**`dalloc` as a no-op is safe but must be honest.** Our sources still write
`defer { dalloc(p); }`, so they stay correct when real allocation lands. What the
seed must not do is let a *leak* look like a success: the K-semantics rule that
`exit` requires no live `wild` allocations is **not** implemented here, and
`SUBSET_1.md` records that as one of the checks stage 1 owns.

## `failsafe`

Every executable must define one (D-013), and the seed must route to it. At this
rung "trap" means: call `failsafe(code)`, then `exit` with its return value.

The three checkable requirements (D-014) — it exists, its body is non-empty, it
returns a positive value — are **stage 1's** to enforce. The seed only needs the
call path.

## Work

1. Write the runtime IR module.
2. Link: `llc` each `.ll` to an object, then `ld.lld`. Per D-067 these are
   **subprocesses**, and a nonzero exit is an error the driver reports rather than
   continues past.
3. Run the conformance suite end to end.

## Done when

- Every file in `tests/conformance/` compiles, links, runs, and exits `0`.
- A deliberate `fail` path reaches `failsafe` and exits with its positive code.
- The whole pipeline is reproducible — same sources, byte-identical objects.

## Closing the seed

At this point Nitpick compiles and runs, and everything after it is written **in
Nitpick**. The seed is finished and, apart from bug fixes, is never touched again
until it is deleted at self-hosting.
