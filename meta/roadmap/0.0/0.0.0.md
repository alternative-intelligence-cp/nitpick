# 0.0.0 — Repository skeleton and manifest

**Cycle 0.0 — Foundations.** First subcycle. Nothing here compiles Nitpick; it
establishes where things live and how the project describes itself.

## Goal

A directory tree and a `nitpick.toml` that match the specification set, so that
every later subcycle has an unambiguous place to put its files.

## Why first

`BUILD_REFERENCE.md` §3 makes module resolution depend on the layout — a
dependency named `nfs` at `../nfs` roots at `../nfs/src/`, and `use "nfs/x.npk"`
resolves against that. If the layout is decided ad hoc later, every `use` in the
repository changes when it is corrected.

## Work

**1. Directory layout.** `CLAUDE.md`'s scaffold is `src/`, `src/inc/`, `tests/`.
Extend it to the frontend decomposition `../npkc-native/MAPPING.md` documents as
a reasonable starting point — `lexer`, `parser`, `type_system`, `type_checker_*`,
`symbol_table`, `module_{table,resolver,loader}`, `diagnostics`,
`source_location` — with two deliberate departures:

- **no `backend/ffi_bridge`** and nothing resembling it. That bridge is the thing
  this project exists to eliminate.
- **`borrow_checker` is not a separate stage.** D-004 makes borrows
  second-class, so the check is escape analysis in the type checker rather than a
  standalone pass over a lifetime graph.

**2. `nitpick.toml`.** Per D-077: `[project]`, `[build]`, `[dependencies]`,
`[verify]`. `target = "executable"`, `entry` under `[build]`, **no `edition`
key**. `[dependencies]` is empty and stays empty for a long while — the compiler
depends on nothing until `nlibc` exists in 0.8.

**3. `nitpick.lock`.** Empty but present and committed, so the "a build reads the
lock and never writes it" rule (D-078) is true from the first build rather than
becoming true later.

**4. `.gitignore`.** Build outputs, and `.internal/` — which `CLAUDE.md` marks
gitignored scratch that must never be committed.

## Done when

- The tree exists with a `.gitkeep` in every empty directory.
- `nitpick.toml` validates against D-077's schema by inspection.
- A written note in the repo records **why** the layout departs from
  `npkc-native` in the two places above, so it is not "corrected" back later.

## Not in this subcycle

No source files, no build driver, no tests. Layout only.
