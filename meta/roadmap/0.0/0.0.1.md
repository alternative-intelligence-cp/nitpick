# 0.0.1 — The bootstrap language subset

**Cycle 0.0 — Foundations.** The most important subcycle in the cycle, and the
one most likely to be skipped and regretted.

## Goal

A written, tested definition of the language subset this repository's own sources
may use, for as long as stage 0 is the compiler compiling them.

## The problem

D-079 makes the prototype `npkc` the stage-0 bootstrap compiler. **The prototype
does not speak the language we specified.** Verified against
`../nitpick/src/frontend/lexer/lexer.cpp`:

| Construct | Stage 0 | Consequence |
|---|---|---|
| `relay` / `_^` (D-080) | **absent** | error propagation must be hand-written |
| `cstring` (D-049) | **absent** | the kernel-boundary type does not exist yet |
| `comptime` | present | usable |
| turbofish `::<T>` | present | usable |

Everything else needs checking the same way rather than assuming — that check is
the bulk of this subcycle's work.

Without this written down, the failure mode is discovering construct by
construct, mid-implementation, that a file will not compile, and patching around
it inconsistently across the tree.

## Work

**1. Enumerate the delta.** Walk the spec set's constructs against stage 0's
lexer, parser, and type checker. Produce a table with three columns: construct,
stage-0 status, bootstrap spelling. Where a construct is absent, the bootstrap
spelling is the explicit long form.

**2. Write `meta/BOOTSTRAP_SUBSET.md`.** The authority on what our sources may
use until cycle 1.2. It states, for each absent construct, the exact substitute —
notably:

```nitpick
// Full Nitpick (D-080), unavailable under stage 0:
int32:v = relay parse(s);

// Bootstrap spelling — note that it forwards r.error, never a constant:
Result<int32>:r = parse(s);
if (r.is_error) { fail r.error; }
int32:v = raw r;
```

**3. Conformance test.** A `.npk` file exercising every construct the subset
permits, which **stage 0 must compile cleanly**. It is the executable form of the
document: if stage 0 rejects it, the subset is wrong.

**4. A grep-able audit rule for the propagation idiom.** D-080's evidence is that
hand-written propagation gets written wrong — the prototype's own stdlib forwards
the original error code in **0 of 19** sites, substituting `fail 1;`. Since the
whole repository is about to be written in that idiom, a check that every
`if (…is_error) { fail … }` forwards `.error` rather than a literal belongs in
the harness from the start, not after the fact.

## Done when

- `meta/BOOTSTRAP_SUBSET.md` exists and covers every construct in the spec set.
- The conformance file compiles under stage 0.
- The propagation-idiom check runs and passes on an empty tree (it will earn its
  keep from 0.0.3 onward).

## Not in this subcycle

Migrating off the subset. That is **cycle 1.3**, after self-hosting, and it is
listed in the roadmap so this subcycle is understood as temporary scaffolding
with a scheduled removal rather than a permanent constraint.
