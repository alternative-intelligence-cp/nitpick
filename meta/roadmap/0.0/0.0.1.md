# 0.0.1 — Subset 1

**Cycle 0.0 — Foundations.** The subcycle everything else in the bootstrap rests
on.

## Goal

A written, tested definition of **subset 1** — the part of Nitpick the seed will
lower, and therefore the part the real compiler's own source may use until the
backend climbs past it.

## What subset 1 is, and is not

It is **not** a foreign dialect to be escaped later. We write in our own language
from day one (D-085); subset 1 is an honest statement of **what our own backend
can lower yet**, and it shrinks to nothing as the rungs are climbed.

It is bounded from **both** sides, which is the whole difficulty:

- **Large enough** to write a complete compiler frontend in.
- **Small enough** that a throwaway seed can lower it.

Get it too small and the compiler cannot be written; too large and the seed
becomes a second compiler nobody wanted to write.

## The starting proposal

| In | Out |
|---|---|
| integer and char types, `bool` | generics |
| pointers, slices, arrays | traits, `dyn` |
| structs, **tagged enums** | `async` / `await` |
| functions returning `Result<T>` | macros, `comptime` |
| `if` / `while` / `pick` | contracts, `prove`, `limit<Rules>` |
| `pass` / `fail` / `raw` / `relay` | `tbb`, LBIM, `frac`, `tfp`, `dim` |
| allocation | atomics, channels, threads |

**The AST is expressible without generics** because it is tagged enums over
composable structs — `CLAUDE.md` records that as the transferable frontend
technique, and it is exactly what makes this subset viable. That single fact is
what keeps generics out of subset 1 and therefore out of the seed.

**`relay` is in**, though it is nearly free to lower: an error test, an early
return, and the value. Including it means the compiler's own sources are written
the way the language intends from the first line, and it removes the propagation
hazard D-080 documents rather than living with it through the whole bootstrap.

## Work

**1. Fix the boundary.** Walk the frontend's needs — lexer, AST, parser, symbol
tables, diagnostics — and confirm each is writable in the proposal above. Every
place it is not, either widen the subset or record the workaround explicitly. Do
this before writing the seed, because every widening is seed work.

**2. Write `meta/SUBSET_1.md`.** The authority on what our sources may use until
the backend passes it. Constructs, and for each, the lowering the seed owes.

**3. Conformance suite.** A `.npk` set exercising every construct in the subset,
which the seed must compile and which the real compiler must also accept. It is
the executable form of the document and the seed's acceptance test.

**4. A rejection suite.** Programs using constructs **outside** the subset, which
must produce the *backend* diagnostic — *not supported at this rung* — and never
a parse error. This is what proves D-085's central rule holds:

> **The parser never restricts. The backend does.**

That suite matters more than it looks. It is the standing guard against the
failure that ended `nitpick-bootstrap` — a partial grammar re-widened stage by
stage — and it should be written before there is a parser to break, so the
requirement is fixed rather than discovered.

## Done when

- `meta/SUBSET_1.md` exists and is justified against the frontend's actual needs.
- The conformance suite is written (nothing compiles it yet — that is 0.0.2).
- The rejection suite is written, with the diagnostic it expects.

## Not in this subcycle

Building the seed — that is 0.0.2. This subcycle decides *what* the seed must
lower, deliberately before anyone starts writing it.
