# 0.0.2 — The seed generator

**Cycle 0.0 — Foundations.** The largest subcycle in the cycle, and the only one
whose output is deliberately thrown away.

## Goal

A throwaway generator that emits a **subset-1 → LLVM IR** compiler as `.ll` text,
and the committed seed IR it produces.

## What is being built, precisely

Two artifacts with very different lifetimes:

| | Lifetime |
|---|---|
| **the generator** — a small script | needed only to *regenerate* the seed; never to build |
| **the seed IR** it emits — committed `.ll` | the bootstrap's starting point, until stage 1 replaces it |

Committing the IR is what keeps the standing target true: **a machine with only
the LLVM toolchain can build the compiler.** The script is not a build
dependency, and it is invoked **once, ever** — weaker even than D-067's
invoked-never-linked, since `llc` runs at every build.

Nothing from either reaches any artifact, and D-085's fixpoint check is what
demonstrates it.

## Scope discipline

The seed is the one place where "just enough" is the correct engineering
instinct, and the temptation to over-build it should be resisted actively:

- **It compiles subset 1 and nothing else.** Every construct beyond 0.0.1's
  boundary is work on something that gets deleted.
- **No optimisation.** Correct IR, however naive. `opt` and `llc` do the rest, and
  the seed's output only ever has to compile stage 1 once.
- **Diagnostics may be crude.** The seed compiles exactly one program in its life
  — our compiler — and that program is under our control. Good diagnostics are
  0.0.3's job, in the real compiler.
- **No incremental build, no module caching, no parallelism.**

If the seed starts looking like a compiler worth keeping, the subset is too big
and 0.0.1 needs revisiting.

## Work

**1. Lex and parse subset 1.** Enough to build a tagged-enum AST — no more.

**2. Check enough to lower.** Name resolution, types, and `Result` shape. This is
not the real type checker and must not try to be: it exists to catch what would
otherwise produce invalid IR.

**3. Emit IR.** `Result<T>` as `{T, i32}` per D-069, `NIL` zero-sized per D-084,
slices as `{ptr, i64}` per D-070. **The seed must agree with the specified layouts
exactly**, because stage 1's output has to interoperate with the seed's until the
fixpoint closes.

**4. Runtime floor.** The handful of symbols LLVM emits calls to — `memcpy`,
`memset` — as hand-written IR, which D-015 already specifies as the first rung's
approach. Nothing more; syscalls arrive with `nlibc` in cycle 0.8.

**5. Run the suites.** 0.0.1's conformance set must compile. Its rejection set is
**not** the seed's problem — that suite tests the real compiler's parser/backend
split, which does not exist yet.

**6. Commit the emitted IR**, and record the generator's revision alongside it, so
"which generator produced this seed" is answerable later. D-085's fixpoint will
need it.

## Done when

- The generator emits seed IR; `llc` turns it into a working binary.
- That binary compiles 0.0.1's conformance suite.
- The seed IR is committed and reproducible — running the generator twice on the
  same input produces identical text (D-078 applies here too).
- The generator's revision is recorded.

## Not in this subcycle

Any part of the real compiler. Not one line of the frontend that ships is written
here — that begins in 0.1, in Nitpick, compiled by this seed.
