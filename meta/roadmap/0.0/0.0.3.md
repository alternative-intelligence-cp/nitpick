# 0.0.3 — Diagnostics core

**Cycle 0.0 — Foundations.** The first subcycle that writes Nitpick.

## Goal

Source locations, diagnostic records, and a sink that can be pointed at a
capture buffer instead of stderr.

## Why this early

**Diagnostics are how every later cycle is tested.** The lexer in 0.1 is verified
by what it rejects as much as by what it accepts, and a negative test is only
checkable if the diagnostic it produces can be captured and compared.

D-075 made I/O a trait for exactly this reason: writing through `dyn Writer` means
production goes to `stderr` and the harness goes to a memory buffer, one code
path. Building diagnostics last would mean building that capture ability twice.

## Work

**1. `SourceSpan`.** Every AST node carries one (`AST_REFERENCE.md`
"Conventions"). File, byte offset, line, column. Byte offsets over character
counts — source is UTF-8 (`LEXICAL_REFERENCE.md` §1) and the lexer works in
bytes.

**2. The diagnostic record.** Severity, a stable code, a message, a primary span,
and any number of secondary spans with their own notes. Stable codes matter: the
spec set already cites `NITPICK-040`, `NITPICK-019`, `NITPICK-IF-002`, and
`OPAQUE-COPY-001`, and negative tests will assert on them rather than on message
text, which should be free to improve.

**3. The sink.** A minimal writer interface diagnostics render through — *not*
the full `IO_REFERENCE.md` stream library, which needs traits, generics, and
`async` that do not exist under the bootstrap subset. What it must have is the
one property D-075 exists for: **the sink is a parameter, never a global.**

**4. Rendering.** Source line, caret under the primary span, code and message.
Deterministic output — no colour by default, no terminal detection. D-076 already
settled the general form of that rule: behaviour must not depend on whether the
output is a terminal, because the configuration that gets debugged would not be
the one that ships.

**5. Ordering.** Diagnostics sort by span before rendering. Two runs over the
same input must produce byte-identical output, for the same reason builds must
(D-078).

## Done when

- A diagnostic can be constructed, collected, and rendered to a capture buffer.
- Rendering is deterministic across runs.
- The propagation-idiom check from 0.0.1 passes over this subcycle's own sources —
  its first real test, on code written in the bootstrap subset.

## Not in this subcycle

Error recovery, "did you mean" suggestions, multi-file spans, colour. Each is
worth having and none blocks 0.1.
