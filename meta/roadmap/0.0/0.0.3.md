# 0.0.3 — Seed: checker and IR emitter

**Cycle 0.0 — Foundations.** Second of three seed subcycles.

## Goal

Turn 0.0.2's AST into LLVM IR text: enough checking to avoid emitting invalid
IR, then emission.

## The checker is not the type checker

**The seed lowers; stage 1 checks** (`SUBSET_1.md` §2). The seed's checking pass
exists for one reason — to avoid producing IR that `llc` rejects or that is
silently wrong. It does **not** verify `pick` exhaustiveness, `Result` handling
discipline, escape analysis, or definite assignment. All of those are implemented
properly in the compiler, where they are audited.

What it must do:

- resolve names to declarations, across files (`use` is wildcard/relative only)
- compute the type of every expression, enough to pick the right instruction and
  the right `Result<T>` instantiation
- enforce **`fixed`** — no assignment to a `fixed` binding. Cheap, and it guards
  our own source from the first line (D-084-era reasoning: a parsed-and-ignored
  safety annotation is the worse option)
- reject anything outside subset 1 with **`NITPICK-RUNG-001`**, naming the
  construct and the rung that enables it

That last one is what `tests/rejection/` asserts, and it must fire from the
**checker**, never from the parser.

## Layout obligations

The seed must agree with the specified layouts **exactly**, because stage 1's
output has to interoperate with the seed's until the fixpoint closes:

| Type | Lowering |
|---|---|
| `Result<T>` | `{T, i32}` (D-069) — no `is_error` field; `.is_error` is derived as `error != 0` |
| `Result<NIL>` | `{i32}` — `NIL` is zero-sized (D-084) |
| slice `T[]` | `{ptr, i64}` (D-070) |
| `string` | `{ptr, i64, i64}` |
| pointer | one word, opaque `ptr` (D-038) |
| enum | `{i32 tag, i64 payload}` — single-word payloads only (`SUBSET_1.md` §1.2) |
| `T[N]` | `[N x T]`, value type |

## Work

**1. Name resolution and types.** Per above; no more.

**2. Emission.** Straight-line, naive, correct. **No optimisation** — `opt` and
`llc` do that, and the seed's output only ever has to compile the compiler once.

**3. `relay`.** Test `error != 0`, and on the error path construct the enclosing
function's `Result` with the **same code** and return. This is the one construct
where getting it wrong is invisible in testing and corrosive in production, since
a wrong code still looks like a working error path.

**4. `defer`.** Run on every normal exit path — scope end, `return`, `pass`,
`fail`, **`relay`**, `exit` — and **never on a trap** (D-014, D-080).

**5. Determinism.** Identical input produces byte-identical IR: stable ordering of
functions, globals, and temporaries. D-078 requires it and D-085's fixpoint check
is impossible without it.

## Done when

- Every file in `tests/conformance/` emits IR that `llc` accepts.
- Every file in `tests/rejection/` produces `NITPICK-RUNG-001` from the
  **checker**, with no parse error.
- Running the seed twice over the same input produces identical `.ll`.

## Not in this subcycle

No runtime, so nothing runs yet — `llc` accepting the IR is the bar. Linking and
the runtime floor are 0.0.4.
