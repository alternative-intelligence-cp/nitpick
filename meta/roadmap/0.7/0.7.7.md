# 0.7.7 — Places, `pick`, the rung diagnostic, and the suite that tests this compiler

**Cycle 0.7 — IR emission core.** The largest subcycle of the cycle, because its
deliverable is circular in the right way: the rejection suite could not assert
against the real backend until the real backend could lower everything the suite's
files do around their one refused construct.

## What lowers now

- **Places** (`addr_of`): a name's slot, a field through `getelementptr` (auto-deref
  through pointers, D-006), an element of an array/slice/pointer, a pointee
  (`<-p = v`). Assignment routes through places; compound assignment keeps the
  load–op–store shape.
- **Member reads** go through the **value** — `extractvalue` — one shape for every
  base including one with no address (`(raw f()).len`). Index reads are their place
  plus a load, because a dynamic index into an aggregate value does not exist.
- **`Result`'s three members** (D-069): `value` slot 0, `error` slot 1, `is_error`
  **derived** as `error != 0`.
- **Aggregate literals**: struct (one `insertvalue` per field *at the field's
  declared index*, so written order never matters), array, `Result{…}` (omitted
  fields are zero — D-069's derivation made concrete).
- **Enums**: variant refs as tags (declared value or position — the seed's rule),
  payload constructors widening into the uniform `i64` (SUBSET_1 §1.2), and
  **`pick`** as a `switch` over the discriminant with payload narrowing and
  per-arm scopes.
- **The three compiler builtins**: `#size_of` (ask LLVM — `gep null, 1`),
  `#wild_ptr` (`inttoptr`, D-019's one blessed integer→pointer), `#wild_slice`.
- `%tN` discipline extended; every refusal now carries **its construct and its
  span** (`IrVal.what`/`at`), which is what makes the diagnostic possible.

## The rung diagnostic, and the suite switch

`src/backend/ir/emit_codes.npk` holds `NITPICK-RUNG-001` (construct + rung, per
SUBSET_1 §3) and `NITPICK-EMIT-002` (the emitter met a kind nobody classified — a
defect in the *compiler*, listed as internal in `UNTESTED_CODES`).

`src/backend/emit_program.npk` walks the module graph: type headers (each struct's
fields resolved **in its own module's scope** — the first draft used
`graph_at(0)`'s, and module zero is the *prelude*), the runtime declares in one
fixed order, every function, the string table. A refusal is a diagnostic, not a
stop; the IR is discarded whenever any refusal was recorded. An `impl` is
**refused, not dropped** — a rung that silently sheds declared code is a rung whose
output stops meaning the source. Duplicate `%Name`s across modules are refused
(module-qualified mangling is 0.8's decision, and one name for two layouts is a
coin toss about which `llc` believes).

`tools/emit_check.npk` = `check.npk` + the emit stage, buffering the IR so a
refusal after half a module never leaves half a module on stdout.

**The harness now runs two new stages**: `tests/rejection/` through `emit_check`
(all nine files fire `NITPICK-RUNG-001` from the real backend — D-085's promise,
finally kept by the thing it was written about), and `tests/backend/programs/` —
programs **compiled by this compiler, linked, and executed**, exit codes compared.

## What the first real programs found — three Phase A holes

The frontend accepted Phase A as complete; the first programs the backend compiled
found three places it wasn't. All three were invisible because the constructs
appear in no frontend test in the shapes that fail:

1. **Payload-variant construction did not type.** `Ev.Move(5i32)` parses as a
   method call, arrived at "`Ev` is not a function" — the spec's own construction
   syntax (§9.3) had no rule, because every enum fixture either had no payloads or
   only destructured them. `pick` could take a payload apart; nothing could put
   one together.
2. **`pick` bindings were typed UNKNOWN.** `type_ident` had no `SYM_PAT` arm — the
   old comment even said *"which is why `type_ident` has nothing for it yet"* —
   and unknown propagates silently, so `d + "x"` inside an arm type-checked. The
   checker now records the payload type on the pattern's spare slot (the same
   write-back resolution uses for symbols) and `type_ident` reads it. Multi-payload
   and struct-destructure bindings stay unknown until 0.9 lifts them, stated here.
3. **`"a" + "b"` and `tbb + tbb` were type errors.** Both are real Nitpick
   (TYPE_REFERENCE §4 concatenation; D-008 saturating arithmetic) that must
   **type** in front and **rung** in back — the rejection files promising
   `NITPICK-RUNG-001` failed in the wrong stage. The checker types them now; the
   backend refuses them at 0.9. Two stale assertions flipped with the rule.

Also fixed on the way: the taint analysis refused `result_members.npk`'s read of a
failed `Result.value` — the rule working, on this project's own test; the file now
says so instead of reading it. `tests/rejection/nonary_identifiers.npk` **migrated
to `tests/backend/programs/nonary_literals.npk`**: the real lexer has decoded
suffix bases since 0.1, so under the compiler the suite now tests, the file simply
runs — the suite shrank because the compiler grew, which is what §4 of SUBSET_1
says the suite's lifecycle is.

## Done when

- All five programs compile through `emit_check`, assemble, link, and exit 0.
- All nine rejection files fire `NITPICK-RUNG-001` from the real backend.
- The three frontend holes have rules, and the flipped assertions state the new
  behavior with the reasoning attached.
