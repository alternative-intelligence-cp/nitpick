# 0.7.8 — The driver, and subset 1 running under this compiler

**Cycle 0.7 — IR emission core.** The last subcycle.

## The compiler has a `main`

`src/main.npk` exists, and `nitpick.toml`'s `entry = "src/main.npk"` stops being
aspiration: **npkc** reads one root, runs the whole front half, and either reports
diagnostics — codes and spans, one per line — or writes the program's LLVM IR to
stdout. It writes text to fd 1 and nothing else: subset 1 has no process spawning
and the floor has no file creation, so `llc` and `ld.lld` are the build system's to
invoke (BUILD_REFERENCE §4) — which is also the honest shape: the compiler's
output *is* the IR.

## The pipeline moved to `src/driver/`, and the fork ended

0.7.7 created `tools/emit_check.npk` by copying `tools/check.npk` — two 400-line
bodies kept identical by discipline alone, flagged as drift risk in that commit.
`src/driver/pipeline.npk` ends it: `front_run(Front->, root)` is the one sequence
— load, expand, resolve, type-check, analyse — and `check` and `main` are thin
wrappers. `emit_check` is deleted; the harness builds **`src/main.npk` itself** for
the backend stages, so what the suite exercises is the artifact, not a tool that
resembles it.

**The caller owns the tables.** `front_run` fills a `Front` the caller placed
rather than returning one, because the module graph holds a pointer to the intern
table beside it — a returned-by-value `Front` would carry a pointer into the
pipeline's dead frame. Placement first, wiring second. Also: the pipeline never
reports and never exits — it returns 0/1/2 and the tool decides what a diagnostic
looks like; the four early-bail sites that used to `report; exit` now return
through the same contract.

## Subset 1 runs under this compiler — 14 of 14

The conformance suite joined the real-backend sweep: every file is compiled **by
npkc**, assembled, linked, and executed, with the same expectations the seed
meets. That sentence is the cycle's goal ("a program that runs and returns a code,
compiled by this compiler rather than by the seed"), now a test that runs on every
harness invocation — 19 executed programs in all, plus the nine rung rejections.

## What the sweep found before it passed

- **`raw`/`relay` unwrapped by a call-side flag, not by the operand's type** —
  `pass (raw r)` over a Result-typed *local* passed the whole `{T, i32}` through
  as the value, and `llc` refused the insertvalue two lines later. Both now decide
  by the recorded type, with the flag as fallback for the one place the type is
  deliberately unknown (a builtin call).
- **Ranging an array typed as its element.** `int32[]:view = arr[0i64...4i64]` —
  a conformance file — was a type error: `type_index` fell through the integer
  check. It types as the slice now (D-070), and the emitter builds the seed's
  exact `{gep lo, hi-lo}` view.
- **`string`/`cstring`/slice members were half-typed.** Only `.len` had a rule;
  `.ptr` (typed `uint8->` — a code unit is 0..255, and a signed byte would make
  half of every encoding negative) and `.cap` exist now. The compiler's own
  sources read `s.ptr[i]` on every line that walks bytes.
- **The runtime floor was invisible to the resolver.** `is_builtin_name` is
  generated from `BUILTIN_REFERENCE.md`, which documented the library tier and
  never the floor — so `int_to_string`, `write_raw` and six others resolved to
  nothing. The floor is now §2b of the reference, and the list regenerated: the
  compiler's own sources call these on every path.
- **Conformance files carried seed-era laxness**: `tbb32:code = 0i32`,
  `fail 19i32`, `i => int32` where the cast is lossy, `47i8` against a byte, and
  a module pair whose digit-leading filename can never be a module name
  (`09_module_lib.npk` → `module_lib.npk`; a bare use-path is a root search, so
  the import is spelled `./module_lib.npk`). Each file now states the real rule
  it exercises.

## Residual, named

The compiler's own sources still contain `ptr => ptr` casts spelled `=>` where the
real checker requires `=>!` (reinterpretation is an assertion, and the sole opt-out
says so). They compile today because only the seed compiles them; the sweep that
brings `src/` itself under the real checker is 0.8's first act, alongside the
mangling decision the duplicate-`%Name` refusal points at.

## Done when

- `npkc` builds from `src/main.npk` and the harness uses it for every backend
  stage.
- All 14 conformance files and all 5 backend programs compile, link, and run
  right under it; all 9 rejections fire.
- One pipeline body exists, and the tools are wrappers.
