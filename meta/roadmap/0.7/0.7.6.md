# 0.7.6 — Statements and control flow

**Cycle 0.7 — IR emission core.**

## Goal

`src/backend/ir/ir_stmt.npk` — blocks, declarations, assignment, `if`, `while`,
`pass`/`fail`/`exit`, `defer`, `break`/`continue`, `trap`, and `emit_function`,
the per-declaration entry the driver will loop over. Plus `relay`, which is 0.7.5's
last expression and could not exist until this module did.

## The declared cycle

`ir_expr` ↔ `ir_stmt`, the same shape as `type_expr` ↔ `type_stmt` (0.4.2), for
the same reason: a statement contains expressions, and `relay` is an expression
that **exits the function** — which runs the `defer` stack, which emits
statements. The cycle is the honest form of that dependency; a callback would be
the same edge with the name filed off.

The control-flow state (`terminated`, the defer frames, the loop stack) lives on
`FnEmitter`, because the function is the thing an exiting expression and an
exiting statement have in common.

## Two departures from the seed, both closing recorded defects

### `break`/`continue` run the defers of the scopes they exit

The seed's own comment concedes it: *"defers registered INSIDE the loop body do
not run here. That is a gap the real compiler must close."* D-014 makes scope exit
a normal exit path, and a `break` exits every scope between it and the loop. The
loop stack records the **defer depth at entry**; `break` runs every frame deeper
than it, LIFO, before branching. One function emits both `break` and `continue` —
the only difference is which label.

### `pass v` evaluates `v` first, then defers run — D-136, settled this subcycle

The seed runs defers first and evaluates the value second, so a defer that
mutates `x` changes what `pass x` returns — a read whose meaning depends on
cleanup code pages away. The spec was silent; now it is not: **the value you
passed is the value returned**, and `fail`/`exit` follow the same rule. The
divergence is unobservable in the bootstrap (the compiler's defers only release
memory), so the fixpoint is unaffected — which is exactly why it had to be decided
now rather than discovered later. `DECISIONS.md` D-136;
`CONTROL_REFERENCE.md` §4.5 updated.

The test pins it in bytes — `cleanup`'s `pass x` loads `x` **before** the deferred
`x = x + 9i32` — and the smoke run observes it in execution: the function returns
0, where the seed's ordering returns 9.

## The fixture is the real front half

`tests/backend/ir_stmt.npk` lexes, parses, collects, resolves and type-checks its
module — the `type_stmt` fixture's wiring — then calls `emit_function` per
declaration and byte-compares whole functions. First test where the emitted thing
came from **source code** rather than hand-built nodes; it is a rehearsal for the
driver as much as a test.

And the emitted module was assembled, linked against `npkrt.o`, and **run**:
`pipe(4)` relays through `step` to 7, `count(10)` breaks at 3, `cleanup` returns
the pre-defer 0. Exit 0. That is the first execution of code this compiler's
backend emitted.

## Order rules worth naming

- **Slot first, then the initialiser** (`int32:x = a;`): the name binds after the
  initialiser runs, so `int32:x = x;` reads the outer `x`, not the slot being
  created.
- **A deferred body is emitted at each exit that runs it** — cleanup code is
  duplicated per path. That is what naive lowering means; `opt` folds it.
- **A trap runs no defers** (D-014) — the omission is the decision, quoted at the
  emission site.
