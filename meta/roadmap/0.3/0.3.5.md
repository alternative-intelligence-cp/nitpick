# 0.3.5 — Name resolution

**Cycle 0.3 — Modules, symbols, visibility.**

## Goal

Every identifier in every body binds to exactly one symbol, or produces exactly
one diagnostic.

## Work

1. Phase 2 of the two-phase load: walk every function body, every initialiser,
   every contract and invariant.
2. Bind `IdentifierExpr` to a symbol; record the binding on the node so later
   cycles do not repeat the search.
3. Scope entry and exit for blocks, function bodies, `for` bindings, `pick` arm
   destructuring bindings, and `loop`/`till`'s `$`.
4. Member access is **not** resolved here. `p.x` needs `p`'s type, and that is
   cycle 0.4. Resolve `p`; leave `.x` alone.
5. Paths: `Net.Disconnect` in an expression, `math.sqrt` through an alias.

## The check worth building here

**Every `Ident` token in every parsed file resolves to exactly one symbol or to
exactly one diagnostic — no third outcome.**

That is the mechanical completeness question for this cycle, the counterpart to
`check_kinds_reachable` in 0.2. A name that is silently left unbound is the
symbol-table equivalent of an unreachable node kind: not an error at any point,
and invisible until something downstream needs it.

If it holds, it goes in the harness beside the other two.

## Done when

- Every identifier binds or diagnoses, and the harness asserts there is no third
  case.
- An unresolved name names the scope it was looked up in.
- Shadowing works and is not an error where the language permits it.
