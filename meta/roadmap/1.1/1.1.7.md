# 1.1.7 — Reachability and the exhaustive `failsafe` (D-179)

The safety half: a new failure mode anywhere refuses to compile until the
program's one `failsafe` names it.

- The REACHABLE SET, whole-program and conservative (the lock-analysis
  precedent): every constant at any `fail`/`?!` site, plus the entire
  system family, plus everything a spawned child can fail with. No
  flow-sensitive narrowing — the conservative set IS the semantics.
- The RULE: `failsafe` contains a `pick` over its `Error` parameter whose
  NAMED arms cover the set; `(*)` permitted, counts for nothing (the
  defensive floor beneath the proof). New analysis-stage codes, tested from
  both directions — a missing arm refuses, over-naming an unreachable
  constant is examined for whether it should refuse or warn (settle during
  build, record here).
- The exhaustiveness engine is `pick`'s own (0.5.4), fed by the new set.

Done when adding one `fail NewError;` to any module breaks the build at
`failsafe` and naming the arm fixes it, under tests in both directions.

## Outcome

The rule stands exactly as ratified — named coverage of the computed set,
`(*)` permitted and counting for nothing — and the build made it PRECISE
where the plan feared ceremony: the conditional system detectors (division,
indexing, tbb, counted loops, arenas, deadlines; the heap/exit family
unconditional) mean a trivial program owes FOUR floor arms, not twelve, and
the detectors walk USER modules only — a program reaches the prelude's
guard-bearing internals only through machinery its own text must contain.

What the build forced, all now in D-179's amendments: error declarations
are implicitly `pub` (an identity that crosses any boundary a `Result` can
must be nameable where it lands); cross-module references write the
QUALIFIED spelling, which the parser reads as a two-segment destructure —
so the reach matcher compares name pairs, the dead-arm check compares FULL
paths (also removing a latent false positive for same-last-name patterns),
and the backend lowers the pair through the module's scope; and two error
constants sharing a bare name across modules is no longer warned as a
wildcard clash.

The sweep: ~190 test failsafes now carry their picks (three generator
passes plus hand work for the logic-bearing ones); the compiler's own four
entry points name their whole defect roster — main.npk's failsafe
acknowledges all twenty-nine families it can die from, `ast.BoundsId`
beside `DeadlineExceeded`, which is the doctrine applied to ourselves.
The masking lesson cost two rounds: a resolve error anywhere aborts before
the analyses, so "no REACH diagnostics" is not "conforming" — the
generator learned to treat any non-REACH diagnostic as failure. Pinned by
failsafe_reach.npk (refuses twice with the wildcard present) and
failsafe_nopick.npk; the exhaustive-failsafe arc closes with 1.1.7, and
1.1.8's executor inherits a language whose every failure mode is named.
