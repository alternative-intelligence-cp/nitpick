# 1.1.5 — `Error` is a type: declarations, retyping, and the great renaming (D-179)

**Cycle 1.1.** The foundation of the typed-error system, deliberately BEFORE
the executor (now 1.1.8): the executor mints deadline/windup/parking
failures, and built after this change it is built once.

## Stages

- **A — the declaration and the type.** `error:Name;` parses (a new decl
  kind — a language change, ratified with D-179); the `Error` type joins the
  type table as a nominal 4-byte non-number (no arithmetic, no ordering, no
  casts; equality and `pick` only; values exist only by naming a declared
  constant — the `bool`/`char` doctrine applied). The prelude declares the
  SYSTEM family carrying D-142's fixed codes (`HeapIntegrity` −4102,
  `DeadlineExceeded` −4107, …; npkrt.ll's hardcoded values are the
  stability constraint); user constants get deterministic positive codes in
  module-graph order. User code cannot declare into the system domain.
- **B — the retyping.** `Result<T>`'s error half, `fail`'s operand, `?!`'s
  operand and `failsafe`'s parameter all become `Error`. A tbb literal in
  error position becomes a type error — the loud migration edge. The seed
  learns the decl form and the (unchanged-width) lowering.
- **C — the sweep.** Every `fail Ntbb32` / `?! Ntbb32` in `src/`, `lib/`
  and `tests/` flips to a named constant. The compiler's own conventions
  get real names at last (`?! 9tbb32` → `TestAbort`-family, `?! 5tbb32` →
  `ProvenSlice`, `?! 25tbb32` → `Rederivation` — final names chosen in the
  sweep with a naming table recorded here). Sweep tooling per the 1.1.2
  pattern: propose, audit every site, full harness between rounds.

## Done when

`src/` compiles with zero numeric error literals; every test names its
errors; the system family round-trips through npkrt.ll unchanged; full
harness green; fixpoint holds.
