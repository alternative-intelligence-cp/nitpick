# 1.1.12 — The reactor, and the streams over it

**Decision:** D-184 (B-3a closed at stage a). **Gated on:** D-176 (deadlines),
D-177 (coroutines), D-181 (threads).

The executor's waiting story before this subcycle ended at the futex: a task
could wait on time, on a channel, on a lock — never on a DESCRIPTOR. This
subcycle adds the one I/O suspension the rest of the I/O surface is loops
around, then the streams themselves.

## a — the reactor core — DONE (D-184)

**epoll, and only epoll — no timerfd.** The executor already owns a deadline
machine (the sleeper list, the futex wait's absolute timeout); a timerfd
would restate it as a descriptor. Once armed, the idle wait is `epoll_pwait`
whose ms timeout (rounded UP) carries the same deadline the futex wait took.

- `suspend_io(fd, events, abs)` — the inline suspension: register one-shot,
  park exactly as `suspend_until` (same wind-up tail). Prelude
  `io_ready(fd, events, within)` is the `Result` face: `DeadlineExceeded`
  past the deadline; success means readiness was SIGNALLED — re-try the
  syscall, and a retry that still blocks calls it again.
- `io_unwatch(fd)` is **deferred inside `io_ready`**: the registration lives
  exactly as long as the wait. A one-shot left armed past its frame is a
  fire into freed memory — found by review before it found us.
- First `io_ready` creates epoll + eventfd (release-published); the eventfd
  rides the set with payload 0 as the drain marker, and both rousers
  (channel wake, wind-up) write it after their futex protocol. The epoll
  branch re-checks the park word before sleeping — the futex's kernel-side
  expected-0 compare, done by hand; skipping it is a sleep-through-a-wake.
- A ctl failure past creation (EPERM: a regular file; EBADF) dues the task
  NOW — the caller's re-tried syscall reports the errno as an ordinary
  `Result`. Only creating the reactor traps. Files behind `io_ready` read.
- **The task-identity rule** (the find of the rung, not reactor-specific):
  awaits drive children inline, so the frame a nested wait is lowered in is
  NOT the frame the sweep sleeps and wakes — the task root is. The executor
  records `cur_task` (slot 13) at its one resume site, and EVERY waiter
  registration resolves it: channel/lock/condvar/barrier link + unlink, and
  the reactor's payload. Latent until now because every channel test waited
  at task-root level; `nested_wait.npk` (helper-coroutine recv, cross-thread
  sender, stress 40) regresses it.
- `sys` accepts pointer arguments: `ptrtoint` at the trampoline — the one
  place an address becomes a number (`=>!` still refuses ptr→int). The old
  arm `sext`ed every non-i64, which llc rejects; latent, nothing had passed
  a pointer.
- io_uring: **not going in before Astrée** — a decision, not a deferral (an
  SQE owns its buffer past the call's return; a categorically larger
  ownership story, and a second reactor to verify).

Tests: `io_ready_basic.npk` (nonblocking pipe; deadline on silence, then a
writer thread and the byte, stress 40), `nested_wait.npk` (stress 40).

## b — owned descriptors and byte streams — NEXT

An `OwnedFd`-shaped owning builtin whose drop closes; `ByteReader`/
`ByteWriter` as npk structs + impls over `io_ready` retry loops; open/
create/seek; scope-exit close through the managed regime.

## c — the text layer, std streams, buffering

npk source over b.

## d — async methods behind `dyn`

Vtable frame-size slots (sizes appended after the method slots); the caller
allocates the vtable-supplied size, fills the fixed header + params, resume
thunk in the slot. Then `dyn Writer` diagnostics.
