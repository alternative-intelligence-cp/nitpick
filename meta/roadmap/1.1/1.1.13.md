# 1.1.13 — The Bridge (D-149 over D-055): every driver is a supervised child

**The design of record is `meta/roadmap/audit-0.8-close/driver_architecture_plan_v3.md`**
(18/18 poc checks on the deployment kernel). This file stages it and records
what has CHANGED since v3 was written — every prerequisite it listed as
blocking has landed:

| v3 prerequisite | landed as |
|---|---|
| `sys` (variadic, pointers) | 0.9.7; pointer args at 1.1.12a (`ptrtoint` at the trampoline) |
| atomics lowering | D-182 (1.1.10-A) |
| `Duration` + monotonic clock | D-176 (1.1.3) |
| async/await/executors | D-177/D-181 |
| **fd readiness for dispatch's dual watch** | **D-184 (1.1.12a)** — `io_ready`; the pidfd and the ctrl socket are exactly the "both are fds" case v3 anticipated |
| borrows across a leaf await (§15.7) | D-180 |
| owned descriptors, `Path` | D-185 (1.1.12b) |

v3 §15's still-open questions get settled IN this subcycle (D-187):
`#ptr_add<T>` is ELEMENT-scaled (it lowers to gep; byte math is `T = int8`);
`atomic_from_ptr` is **wild-context-only** (aliasing foreign memory is wild
business — the TOS-signed zone — which also disposes of the storability
question: a wild local, used in place); **a `defer` may not `await`**
(cleanup is bounded and synchronous — v3's reap/close split is the blessed
shape, and the drop system is synchronous by construction); fabricated
pointers are tracked by REGISTRIES, not the leak checker (v3 §4.5, adopted).

## a — primitives, spawn, teardown, the registry — UNDERWAY

**Landed:** `#ptr_add<T>` — element-scaled (D-187), gep lowering, `ptr_add.npk`.
`atomic_from_ptr` — D-187 settled as option A (user's call), and it needed
NO grammar change: the turbofish (`::<T>`, D-064) already parses on a
bare-name callee, so `atomic_from_ptr::<int64>(p).load()` works with only
typer + emitter wiring. Fused-only (never stored — TYPE-007), the emitter
dispatches through the pointer. `atomic_alias.npk` / `atomic_alias_rules.npk`.
The two ring primitives are done; **b** is unblocked.

### a (continued) — spawn, teardown, the registry

- `#ptr_add<T>` into BUILTIN_REFERENCE + typing + lowering (gep).
- `atomic_from_ptr<T>` verified lowered (D-182) + the wild-context refusal.
- nlibc constants + helpers (`lib/nbridge.npk`): socketpair, memfd_create +
  the three seals, mmap/munmap, clone(SIGCHLD|CLONE_PIDFD), prctl
  (PDEATHSIG, NO_NEW_PRIVS), execve with a constructed environment, dup3,
  pidfd_send_signal, waitid(P_PIDFD), sendmsg/recvmsg + MSG_NOSIGNAL +
  SCM_RIGHTS (`send_fd`/`recv_fd`, the only place msghdr exists, in wild).
- The allocation-free child path in npkrt (argv/envp prepared pre-clone —
  the npk_thread precedent).
- `Bridge` struct (v3 §4.1; `OwnedFd` where v3 predates it), `spawn_driver`
  (§4.3, all eight steps, seal included), `bridge_reap` (sync, bounded),
  error constants as a D-179 error family (v3's tbb32 codes predate D-179 —
  errors are `error:` declarations now).
- **The driver registry in npkrt**: preallocated 16-entry table, CAS-claimed;
  `npk_driver_kill_all` walked ON THE TRAP PATH by the runtime itself,
  before user `failsafe` runs — safing is mechanism, not policy (D-013), and
  an uncontrolled driver DURING failsafe is the hazard class D-055 exists
  for.

## b — dispatch, the ring, close, stderr

- `io_watch(fd, events, abs)` builtin — REGISTER-ONLY (the reactor's
  existing registration, no park), so a task can watch ctrl AND pidfd and
  park once; `io_ready2` in the prelude over it.
- Ring access (§6.2: wild locals over `#ptr_add` + `atomic_from_ptr`), the
  [UNTRUSTED] validations (§6.2/§7.3) — every driver-written index/length
  bounds-checked with overflow-safe arithmetic before any dereference.
- `dispatch` (§4.4: seq, EXEC_NOTIFY, dual watch, kill-on-protocol,
  poisoning), `bridge_close` (§4.5 ladder), the stderr drain task (§10:
  8 KiB drop-oldest ring, lexical lifetime).

## c — `extern` lowering, the interface hash, the C SDK, conformance

- `DeclExternBlock` lowers to generated stubs over `dispatch` (D-149):
  method order is the kernel_id space; the INTERFACE HASH (FNV over the
  block's signature spellings, D-123's combiner) rides INIT_REQ and a
  mismatch fails the handshake — the wire-level answer to "the driver was
  built against a different interface".
- D-002-era `fails on` contracts on extern fns: refused by name.
- `sdk/npkdrv.h` + a C reference driver as a TEST FIXTURE (clang-built by
  the harness — test tooling, never in the artifact, the valgrind rule),
  grown from the poc; conformance cases: handshake, echo dispatch, protocol
  violation ⇒ kill, hang ⇒ deadline ⇒ ladder, crash ⇒ pidfd ⇒ E_DRIVER_FAULT
  + stderr tail, hostile tail/len ⇒ kill.
