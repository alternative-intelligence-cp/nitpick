# 1.1.1 — The `src/` sweep: every `raw` and `drop` licensed or rewritten

**Cycle 1.1.** The middle third of D-163: the compiler's own sources are
brought under the licence — ~868 clauses, ~1,000 rewritten sites — under the
instrument, the 0.8.0 shape at its scale. `raw` and `drop` still do not refuse;
the instrument's `src/` + `lib/` + `tools/` count reaching zero is the exit
criterion, and 1.1.2 flips the rule after `tests/` follows.

## The worklist (from 1.1.0's instrument; the heuristic's estimate in brackets)

| class | what happens | estimate |
|---|---|---|
| `raw` on a callee that never fails | the callee gains `never fails`; the body check verifies the claim | ~5,500 sites, ~728 functions |
| `drop` on a never-failing `NIL` callee — the intended use | the callee gains `never fails` | ~1,170 sites, ~144 functions (overlap with the above: ~868 total) |
| `drop` on a never-failing callee **with a value** | `discard(raw f());` | ~90 (`lexer_advance` ×42, `te_error` ×31, `lay_field` ×13) |
| `raw` on a callee that **may fail** | rewritten — see below | ~262 |
| `drop` on a callee that **may fail** | rewritten — see below | ~741 (450 `NIL`, 291 with a value) |
| `raw` / `drop` on a builtin | per the `fails` column | ~98 |
| bare statements | `drop` (now licensed) | 2 |

**Resolve transitive may-fail at the root, not the leaves.** `p_expect` ×144
and `p_advance` ×82 are "may fail" only because `p_peek` relays `tokenlist_at`,
which `fail`s on range — after `p_peek` has bounds-checked. One in-range
accessor, or one `?!` on the provably-impossible branch, makes the whole parser
family `never fails`, and 226 `drop p_*` sites become licensed without being
touched. The same shape recurs under the analysis walkers (`assign_expr`,
`exhaust_expr`, `locks_expr` …): find the accessor at the bottom, decide
*there*, and the count collapses. The instrument's per-callee grouping is what
makes this visible; do not work the list top to bottom.

**The rewrite rule for a genuinely may-fail site, in order of preference:**

1. **`relay`** when the enclosing function returns a `Result` and the failure
   should reach the caller — the honest answer for the driver's stage calls
   (`drop check_module(…)` → `relay check_module(…);`) and for accessor
   failures that are internal defects: a defect should surface as a
   diagnostic, not as node 0 or a skipped stage. For a value-returning callee:
   `discard(relay f());` if the value is unused.
2. **`?! <code>`** when the enclosing function cannot return a `Result`
   (`main`, a `never fails` function) or the failure is an invariant violation
   with no caller able to act. The code is a D-141-space internal-defect code,
   not `1`.
3. **An `is_err` branch** when the failure is meaningful and handled here.

Never `? NIL` / `? <zero>` as a mechanical replacement: that is the old
behaviour with the swallow written down, and the point of the sweep is to stop
continuing past failures. The sweep's closing note lists every `? NIL` it did
write and why.

**Each may-fail site is read, not patterned.** Every one is a place the
compiler today continues on a wrong object or past a failed stage; the sweep is
also the audit of whether any of them has been *reached* — a site whose failure
path is live is a bug found, and is logged in the closing note with its repair.

## Order of work

1. The roots: `types.npk`, `ast.npk`, `symbols.npk`, `module_graph.npk`,
   `parser.npk`, `tokens` — the accessors everything else `raw`s and `drop`s.
   Decide each accessor's contract once; the instrument's count should fall by
   thousands here.
2. `src/frontend/parse_*.npk`, the `*_codes.npk`, `resolve*.npk`, `type_*.npk`.
3. `src/frontend/analysis/`, `src/frontend/macro/`.
4. `src/driver/pipeline.npk` — the stage calls become `relay`; this is the one
   place the rewrite changes the compiler's observable behaviour (an internal
   defect in a stage now stops the pipeline with a diagnostic instead of
   reaching the emitter), and it gets its own conformance case.
5. `src/backend/`, `src/main.npk`, `tools/`, `lib/`.
6. The fixpoint, re-proven after each group — the clauses change no byte; the
   rewrites change bytes only where a branch now exists.

## Tests

`tests/conformance/`: a program through the pipeline with a planted internal
defect in a stage now exits through the error path it previously swallowed.
The `selfhost` stage stays green throughout — each group lands compiling.

## Done when

- `check_raw_licensed` reports **zero** for `src/`, `lib/`, `tools/`.
- Every may-fail site is closed with a classified count (root-resolved /
  `relay` / `?!` / handled / `? NIL`-with-reason) and a note of every one whose
  failure path turned out to be live.
- The fixpoint holds; the harness is green on a full run.

## Outcome

**`check_raw_licensed` reports zero for `src/`, `lib/`, `tools/`, and the
prelude** — 14,071 licensed sites on the `src/` root alone, from 8,997 + 118
unlicensed at 1.1.0 — and the fixpoint held byte-identical through the whole
sweep. The plan's instruction to resolve at the ROOTS did the work: the
mechanical phases resolved ~99% of the debt, and the hand-read tail was 57
sites.

### Method: propose mechanically, audit with the checker

- **A fixpoint proposer** marked every function whose extent contains no
  `fail`/`relay`/`return` and no unlicensed site — then the REAL CHECKER
  audited every claim (`TYPE-037`/`041`), round after round. First round: 640
  marks, sites 8,997 → 4,959. Nothing was believed unverified.
- **Family knots** for the mutually-recursive walkers (analysis passes, the
  checker core, the backend emitters, the parser+loader+expander): convert the
  intra-family relays and mark the family in ONE edit; the audit names the
  genuine failers, which get read individually. The checker-core knot marked
  206 functions with exactly two audit lines.
- **`relay` → `raw` sweeps** over marked callees between rounds (~3,300
  conversions; the dead error-branch removed is D-163's zero-cost unwrap).
- End state: **~1,900 marked functions**; a joint driver alternated sweeps and
  proposals to fixpoint.

### The root decisions (each read, none patterned)

- **44 invariant accessors** (`tokenlist_at`, the seven `ast_*` node reads,
  `ast_id_at`, `tt_get`, `symtab_get`, `graph_at`, `intern_get`,
  `diaglist_at`, `impl_at`, `bound_at`, the `ast_set_*`/`exprtypes_set_*`
  writers, …) converted `fail` → `!!!`: an out-of-range index is a DEFECT and
  now stops the world with the table's code. G-4's measured pathology — `raw`
  swallowing the error and continuing on node 0 — is impossible by
  construction.
- **`srcmgr_path`/`srcmgr_text` split two ways**: the may-fail originals stay
  for `diag_line`, whose miss is DATA (a span synthesised outside the manager
  renders `<unknown file>`); `srcmgr_*_proven` trap for the compiler-minted
  ids every other caller passes. One accessor's miss can be two different
  things, and the two now have two names.
- **`slice_proven`** (in `intern.npk`): the bounds-proven slice, trapping
  `5tbb32` — 21 sites, including the generator's operator-matcher template.
  **`?! 25tbb32`** marks the four sites where an analysis re-derives a fact
  the checker established (a failed re-derivation is an internal
  inconsistency, not a program error).
- **`string_concat` and `int_to_string` are `never fails`** by rule 9's
  IR-body audit: both write error 0 on every return path (OOM traps, D-150).
  `string_slice` writes a real −34 and stays may-fail.
- **The seed learned `?!` and `?|`** (checker walk + emitter with the lazy
  default and the caller's-code trap) — D-163's own rewrite rules prescribe
  `?!` in `src/`, so the seed had to compile it; permanent, not scaffolding.

### Live bugs found (the audit half of the sweep)

1. **`npkc -o` with a NUL-bearing path** built a garbage cstring under `raw
   to_cstring` and handed it to `write_file`. Now: refused as an unwritable
   path, exit 2.
2. **`?|` over `Result<NIL>`** emitted `alloca void` — invalid LLVM — in the
   real backend (the arm had never been exercised; both arms produce nothing,
   so the lowering is now just the operand's evaluation).
3. **`?!` over `Result<NIL>`** read `extractvalue …, 1` of a one-slot
   `{ i32 }` — the "value" extract would have READ THE ERROR. `Result<NIL>`'s
   error rides slot 0; the arm now knows.
4. The **stage-call class** (`drop check_module(…)` continuing past a failed
   stage) died wholesale: the stages' internal defects TRAP now, which is
   strictly stronger than the planned `relay` rewrite — a defect cannot even
   be propagated-and-mishandled, it stops the world through `failsafe`.

### Contract changes visible to tests

Four unit tests probed the OLD accessor contract (`Result.is_error` on an
out-of-range read) and one fabricated a `FunctionDecl` with no header window —
honest before only because the failure was swallowed. Each updated to the trap
contract with the reasoning in place; `tests/backend/ir_expr.npk`'s failsafe
now reports `100 + code`, which is how the window fabrication was found.

### The `?| NIL` ledger (every explicit swallow, as the plan requires)

The best-effort diagnostic writers only: `npkc`'s usage/report/error prints
(8 sites), the three `tools/` drivers' equivalents (12) — a broken stderr
cannot be reported on stderr, and the exit code already carries the verdict.
Each site carries the reason in a comment. Nothing else swallows.
