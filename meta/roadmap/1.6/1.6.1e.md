## 0. What 1.6.1e is, and is not

Eleven findings in four classes. **Silent wrong answers** — a macro's free name reading the
call site's local (DEF-144), a `\u{…}` escape typed `char8` and truncated (DEF-145), the
scope-exit join relaying the last-spawned child's error (DEF-146), an expired `timedwait`
returning success (DEF-147). **A memory fault in safe code** — a `shared_arena` destroyed
while a spawned thread holds it (DEF-148). **The compiler's own refusals and stops** — an
un-awaited async METHOD call accepted and emitted as an undefined symbol (DEF-149), three
traps of npkc itself (DEF-150), `--extra-picky=no-wildx` refusing every program at its own
prelude (DEF-151), a unit annotation on `tfp64` accepted and ignored (DEF-152). **The two
tables** — sixteen rows where the compiler departs from the reference safely (DEF-153) and
ninety-four rows where the reference is wrong or stale (DEF-154).

It is NOT: a change to any rule the listener did not find wrong (every fix restores what a
decision or a reference already says, and one question — which child's error a join relays —
is put to the user because no text decides it); a snapshot refresh (nothing in `src/` needs
the new emitter; measured at each step by the emission comparison); a floor byte (DEF-147's
fix is in the emitted wait, not the floor).

## 1. Where it starts (main's chain at `3235308`; every line number is that tree's)

**DEF-144.** `resolve_expr` (resolve.npk 167–185) switches to `module_scope` under a
`HYG_ROOT` node and a statement macro's block takes the module as its parent (318–340): the
RESOLVER binds a body's free name to the module binding correctly, and records the symbol on
the node (`ast_set_expr_a`, 111). The EMITTER does not read it: `emit_ident` (ir_expr.npk

right by accident: `lvl + 0i32` is folded by the constant folder, which reads the resolver's

## 2. The design

### 2.1 DEF-144 — the emitter reads the resolver's binding (step 1)

**The fix.** ONE resolver of an identifier node to its storage, `ident_slot(x, id, n)` in
ir_expr.npk, used by `emit_ident`, `addr_of_place`'s identifier case, `clear_root_flag` and
every other site that resolves an IDENTIFIER NODE through `fnem_lookup_idx` (enumerated at
the step's first act by grep; the parameter-flag lookup in `emit_assign` included). The rule,
by the symbol the resolver recorded (`n.a`): a `SYM_STMT` symbol → the slot declared by that
statement (`fnem_lookup_decl(x.fe, s.origin)`, the by-declaration lookup D-286 added), falling
back to the name only when no slot is registered under the statement; a `SYM_DECL` symbol
whose declaration is a `DeclParamDecl` → the parameter's slot by name (parameters are bound
by name in the prologue and are never shadowed by an expansion's names, which live in a block
of their own); every other `SYM_DECL` (a function, an error constant, a global) →
`emit_decl_value`, before any local is consulted; a `SYM_PAT` symbol → the pattern binding's
slot by name (bound at the arm; a body's block never redeclares it); no symbol (`n.a == 0`: a
bare builtin's name) → the name lookup as today. So a macro body's `lvl` reaches the module's
binding whatever the caller declared, and a caller's `f` of `int32` type no longer shadows
the module function `f()` the body calls (the same class in `emit_call`'s function-value
lookup, DEF-54's corner: a callee identifier whose symbol is a function declaration is a
declared function, whatever local shares its name). The folder's accidental correctness
(`lvl + 0i32` = 7) is not relied on; it is stated in the record.

**Tests.** `tests/backend/programs/macro_hygiene_names.npk`: the listener's four shapes (the
lone identifier, the comparison operand in a statement macro, the two arithmetic controls),
a body calling a module function whose name the caller holds as a local, a body reading a
module binding under a caller local of a DIFFERENT type (an emitter that read the caller's
slot loaded the wrong width), `#caller(lvl)` beside the bare name in one body (the two
differ), and the same shapes inside an `async` function (frame slots) — each its own exit,
both legs. `tests/backend/ir_expr.npk`'s expectations may move by the lookup's text: run
`harness.py --only tests/backend/` before the commit.

### 2.2 DEF-145 — a character literal has a width (step 1)

**The rule** (TYPE_REFERENCE §2.3:280, `ty0280`): a `'\u{…}'` escape is a `char32` literal,
whatever its value, and is refused in a `char8` or `char16` slot as any mismatch is
(TYPE-007); a plain character or a `\x` escape is a `char8` literal as today; a SOURCE
character whose code point exceeds 0xFF (`'😀'`) is a `char32` literal too — the one gap the
reference leaves, decided the safe way here (a code point that does not fit a byte was never
a `char8`; truncating it in silence is DEF-145's own defect) and stated in the reference.
`'é'` (233) stays `char8`, as it has since 1.0.8.

**The fix.** The lexer makes two token kinds, `CharLit` (8) and `CharLit32` (32) — the
escape form or a code point above 0xFF chooses the second; the parser writes the width into
the node's `a` (8 or 32; `ast_add_expr(…, ExprCharLiteral, sp, width, 0, 0, cp)`); the typer,
the folder (`cv_char(tt_char(r.types, width), payload)`), `pattern_const` (ir_stmt.npk 2150:
a `char32` selector's pattern emits the full code point under the selector's width, as it
does today by reading the payload) and the emitter (`i8`/`i32` by the node's type) read the
width; the encoder's `TY_CHAR` terms already carry the type's bits. A `char16` literal has no
spelling (the reference offers none); a numeric with the suffix (`128512char32`) is the other
spelling and stays.

**Tests.** `tests/backend/programs/char_literal_width.npk`: `char32:c = '\u{1F600}'` (0),
`'\u{E9}'` in a `char32` (233), a `char32` `pick` with `\u{}` arms, `'é'` in a `char8` (233),
`'\x41'` (65), the `char32` compare with the numeric spelling; `tests/types/rejection/
char_escape_width.npk`: `'\u{1F641}'` and `'\u{41}'` in a `char8` slot, a `char16` slot —
exactly {TYPE-007}, three sites; the listener's u1 becomes a refusal and u2 runs 0.

### 2.3 DEF-146 — the join relays the FIRST-SPAWNED child's error; S-115 (step 1)

**The question — S-115 (§3).** "First" is undefined. Two readings: the first child error in
SPAWN ORDER (program text; deterministic under every schedule), or the first to OCCUR in time
(needs a stamp the floor does not keep; under the explorer's schedules two runs of one program
would relay different errors). **Recommended: spawn order** — the join relays the error of
the earliest-spawned child that failed. The listener's `j1` expects E1 under either reading.

**The fix under the recommendation.** The walk is LIFO, so "the earliest-spawned failing
child" is the LAST error the walk meets: a child's error OVERWRITES one a previous child of
this walk stored, and never the function's own. One hoisted `i8` alloca per join, `jtook`
(0 before the loop): at `lgot`, with `jerr2 != 0` — if the result slot holds an error and
`jtook` is 0 (the function's own, stored at the seam before the unwind, D-207) → `lhead`
(the body's error wins, as today); else store the child's error, `jtook = 1`, `lhead`. The
join loop pumps the executor synchronously (`npk_run_until`) and never suspends this frame,
so an alloca is right in a coroutine too. `x.fe.bare` (a bare function's join) keeps its
trap path.

**Tests.** `tests/backend/programs/join_first_spawned.npk`: the listener's three (fast then
slow → E1; a single child; slow then fast → E1 too, now by rule), a three-child shape (E1
fails, ok, E3 fails → E1), the body's own error over children's (the body fails E9 after two
failing spawns → E9), thread children (the same through `thread`). Explored: `// stress: 40`
and `// explore: 1000` (the join is a scheduling point).

### 2.4 DEF-147 — an expired `timedwait` is `DeadlineExceeded`, the guard spent (step 1)

**The fix**, in `emit_condvar_wait`: at `reacq`, before `npk_mutex_acquire_wait`, `now =
mono_now(); expired = now >= deadline`; when expired the wait took the deadline path of
phase 0 — `eslot = -4107`, branch to `fin` (which steps off the condvar's list and nulls the
lent guard's slot, as the wind-up path does: the mutex is NOT held, and D-056's amendment
says the guard is SPENT) — no re-acquire. The re-acquire's own −4107 already reaches `fin`
through `eslot`; 1 (parked) keeps its park-and-retry. A signal that lands exactly at the
deadline is late by the deadline's rule. `ctl_t2` (a `recv` deadline) is unchanged.

**Tests.** `tests/backend/programs/condvar_expiry.npk`: no signaller, 200 ms → the error

### 2.5 DEF-148 — a spawn LENDS its sanctioned crossing until the scope's join (step 1)

**The rule.** A `drop f(…)` (or `thread` spawn) that hands a task a `shared_arena<T>->` or a
lock's pointer (D-180's five crossings) LENDS the root binding to the task until the enclosing
block's exit — the join (D-207). Until then the owner may do what the type's concurrency
contract allows — a shared arena's `alloc` and `get` (D-154: a slot is written once, before
its handle escapes), a lock's `acquire`/`read`/`write`/`timedwait`/`signal`/`broadcast`/
`arrive` — and may hand the same borrow to another spawn; it may NOT end the value's life or
identity: `destroy()`, an assignment over the root, a `move` out of it, `$$m`, or `@root` to
a callee whose summary writes what the type's contract does not (a callee that `destroy`s).
Refused as `NITPICK-BORROW-016` at the access, naming the spawn and the block.

**The fix**, in alias.npk: a fifth party kind, `PARTY_LENT` — pushed AFTER `acc_call`'s own
truncation for each such argument of a spawn (the walk learns the spawn as the escape
analysis does: a `drop` of a call whose callee is `async`, or a `thread` call; `callee_is_async`
becomes `pub` in escape.npk), rooted at the argument's place root, holder 0, live until the
enclosing block's `frame_pop`. `conflicts(PARTY_LENT, ACC_WRITE|ACC_EXCLUSIVE)` is true;
`check_access_reported` skips a LENT party when the access is the RECEIVER of a method call
in the type's concurrent set (`acc_call` computes `lent_ok` from the receiver's kind and the
method's name and passes it down), and `acc_call` skips the LENT parties for an argument of
another SPAWN. The escape analysis's mutation summary stops recording a shared arena's
`alloc`/`get` and a lock's concurrent operations as writes of the pointee
(`record_mut_of_place`'s receiver case: the kinds' own sets), so `admit_written(@s)` to a
helper that only allocates is admitted and a helper that destroys is refused. Message: "`s`
is lent to the task spawned at L:C until the end of this block, whose exit joins it (D-180,
D-207): `destroy`, an assignment, a `move` or `$$m` before the join would end a value the task
still holds — destroy it after the block, or join first".

**Tests.** `tests/analysis/rejection/spawn_lent.npk`: `s.destroy()` after a spawn holding
`@s` (BORROW-016), `s = other` (BORROW-016), `move(s)` (BORROW-016), `$$m s` (BORROW-016),
`@s` to a callee that destroys (BORROW-016), a `Mutex` moved while a spawn holds it
(BORROW-016); the controls silent: `s.alloc`/`s.get` by the owner while lent, `@s` to a
second spawn, `@s` to a helper that only allocates, `destroy` after the block, the
listener's a2 and a3. `tests/backend/programs/spawn_lent_ok.npk`: the owner and two tasks
allocating in one arena, destroyed after the join (exit 0 both legs, `// stress: 40`,
`// explore: 1000`).

### 2.7 DEF-150 — the compiler's three stops (step 2)

- **c1, c3 — a mixed macro body.** The first act dumps `macro_body_kind` and each item's id
  at the raise; the fix is the parser's classification (`p_parse_macro`, parse_decl.npk
  1346–1372): a body that mixes declarations and statements is refused at the declaration by
  name — `NITPICK-MACRO-0NN` (the next free code), "a macro body is declarations or statements,
  not both (MACRO_REFERENCE §3)" — because no site accepts both kinds (a struct body takes
  statements, every other site declarations), and `record_site` reads every item by the
  body's one kind. If the dump shows a PURE declaration body reaching the raise (a method
  parsed as a statement, say), the parser's item classification is the defect and the fix
  is there; the reference's two examples (`emit_methods` into an impl, a `comptime` function
  emitted and folded) must run. `tests/backend/programs/macro_emit_decls.npk` (both
  examples), `tests/expansion/rejection/macro_mixed_body.npk`.
- **c2 — the depth bound is the parser's.** `EXPR_DEPTH_MAX = 256` in parse_expr.npk (the
  analyses' `ALIAS_DEPTH`/`BORROW_FUEL` family is 256, and 260 deep refuses by their names
  today; the folder's recursion exhausts the compiler's 8 MiB stack between 450 and 500):
  the expression parser counts its nesting and refuses the 257th level with
  `NITPICK-PARSE-0NN` at the node ("this expression nests deeper than 256 levels; split it
  — no walk of the compiler follows further, MACRO_REFERENCE §5"). An EXPANSION that clones
  deeper than the bound is caught by the same rule applied by the expander after each
  instantiation (`CLONE_FUEL`'s exhaustion becomes a diagnostic if it is silent today —
  measured at the step). The folder's `FOLD_FUEL` stays as a belt.
  `tests/frontend/parse_depth.npk` (256 parses, 257 refuses) and the listener's c2/c4.

refused by `llc` ("duplicate case value"); **DEF-213** — `fold_const` resets the evaluator's depth, so a `comptime
func:` that recurses through a type's array size (`#size_of<int8[comptime(deep())]>()`) is never bounded and the
compiler stops with exit 3 and no message.

**The value.** `CV_ENUM` (6): `type_id` the enum's type, `num` the variant's POSITION among its declaration's
members — the `position` the one tag rule (`variant_tag_of`) takes. Position is identity: DEF-193 made two variants

**What the evaluator gains, and where each lives (`src/frontend/type_resolve.npk`).**
1. `fold_variant` (the `ExprMemberAccessExpr` arm of `fold_expr`): `Enum.Variant` where the base identifier's
   RECORDED symbol is a non-generic `enum` declaration and the member names a payload-less variant.
2. `fold_binary`: `==`/`!=` on two `CV_ENUM` values of one type whose enum carries no payload anywhere (the
   checker's own condition for a built-in `==`, `equatable`); every other operator on one is not a constant.
3. `fold_string_cmp` (the `ExprMethodCallExpr` arm): a method named `cmp` with ONE argument, the receiver and the

**The decisions, each with its reason.**
- **Statements run only inside a `comptime func:` call, so a `pick` EXPRESSION folds only there** (a new counter,
  `TypeResolver.fold_frames`; not `fold_depth`, which a nested `fold_const` resets). An arm is a block of
  statements. Folded where it stands in a run-time body — the emitter asks the folder about every `+ - *` node
  (`emit_const_fold`) — an arm's assignment to a local of that body would be "evaluated" into the resolver's top
  environment and never run: `1i32 + pick (2i32) { (2i32) { acc = 7i32; give 20i32; }, … }` would become the
  constant 21 and `acc` stay 0. So outside a frame a `pick` is not a constant, no existing program's emission can
  move for it, and a constant site that wants one calls a `comptime func:` — the marker that says the compiler may
  run code (D-130: "whether the compiler runs your code is not a thing to discover by accident").
- **An arm of the expression form ends in `give`; a `pass` out of one is not evaluated.** It leaves the FUNCTION
  through an expression, and `fold_expr` answers a value, not a flow: carrying a pending return across every
  expression site is a second control channel whose one missed check hands a caller its callee's value. Declined

- **DEF-211 is fixed here**: `&&`/`||` decide on the left operand where it decides, as the run time's branch does.
