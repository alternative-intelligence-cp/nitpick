## 0. What 1.6.1b is, and is not

A RELAXATION of one accepted refusal, decided by evidence the analysis already computes. D-004
(0.5.0) made a call's result a possible borrow of every `@`/`$$` argument when the result can
carry a pointer — rule A, "`launder` closed" — because the escape analysis never looked into
callees; D-249 (1.5.1b) extended the marking to views. 1.6.1 step 0 (D-325) built per-function
PROVENANCE SUMMARIES at the escape fixpoint — what a result may VIEW (which parameter's bytes,
at which path), what it CARRIES (the pass bit), what a body STORES through each pointer
parameter, what it WRITES — and used them for the view parties (the freeze) and the store
matrix, leaving rule A's `holds` marking as the shape rule it was. So today
`string:r = raw make(@b); pass r;` with `make = string(Box->:b)` building a fresh string is
refused at `pass r` (`NITPICK-BORROW-001`) while the summary knows `make` views nothing of `b`
— the false REJECT the listener met at nitpick-time's cycle 0.4 and nitpick-regex's cycle 0.6,
the other face of DEF-107's false accept.

After this subcycle a call's result holds a borrow of an argument exactly when the callee's
summary says the result may VIEW or CARRY it, or when the callee is unknown (a function value,
a `dyn` method — the shape rule stands). Nothing unsafe is admitted: the summary is what the
freeze and the store matrix already trust. It is NOT: a change to the other rules of D-004
(rule 2's return refusal, rule 3's store refusal, rule B's destinations, the freeze), a change
to the emitter (no program's emission moves), a respelling of any workaround in `src/` or the
libraries (the sweep MEASURES what the relaxation admits; nobody is asked to adopt it), or a
language change needing an advance notice (D-239's rule is for refusals added; this removes
one — the landing notice carries the measurement).

## 1. Where it starts (main at landing 71, `1b4f0c6`'s tree)

- **The seat of rule A** — `src/frontend/analysis/escape.npk`, `escape_call_like` (the one
  call arm: direct calls, method calls, the implicit `@recv` of a pointer-receiver call), its
  last lines:
  ```
      // RULE A.
      if (borrowed == 0i32) { pass false; }
      pass (raw carries_pointer(x, raw exprtypes_get(x.etypes, id), raw CARRY_FUEL()));
  ```
  `borrowed` counts the receiver and the arguments for which `escape_arg` (→ `escape_expr`)
  answered "borrowy": an `@x`/`$$ x` of a FRAME-OWNED root (a local, a pattern binding, a
  by-value parameter — `arg_root_is_local`; a pointer parameter's pointee is not the frame's,
  D-138's refinement) or a value that itself holds a borrow. The verdict is the CALL's: the
  declaration or assignment that receives it marks the binding (`escape_mark`, the `holds`
  bit), and rules 2 and 3 then refuse `pass`/`fail` of it and a store of it into anything that
  outlives the frame.
- **The provenance reader that already exists beside it** — `collect_call_refs(x, call, recv,

  and a value argument its own refs; under the PASS bit (`sum_pass`) an address argument
  contributes a `REF_ADDR` of its place and a value its own refs; a callee with no recorded
  declaration (`call_callee_fn` = 0: a `dyn` method, a function value) is read with EVERY bit
  set (`arg_refs_view` for every position); a builtin METHOD (`call_is_builtin_method`)
  contributes nothing (its result is a scalar or an owned copy). `arg_carries_view` (~3690)
  and `ref_root_is_frame_owned` (~1056) already answer "is this ref rooted at this frame's

## 2. The design

### 2.1 The marking (the one change)

In `escape_call_like`, the two lines above become three, and one helper is added beside
`arg_carries_view`:

```
    // RULE A, BY PROVENANCE (D-326, 1.6.1b): the result holds a borrow of this
    // frame's storage exactly when the callee's summary says it may VIEW or CARRY
    // what a borrowy argument handed it -- the reading the freeze and the store
    // matrix already trust (D-325) -- and by the shape rule alone for a callee the
    // analysis cannot see (a `dyn` method, a function value: every bit set).
    if (borrowed == 0i32) { pass false; }
    if (!(raw carries_pointer(x, raw exprtypes_get(x.etypes, id), raw CARRY_FUEL()))) { pass false; }
    pass (raw call_result_holds(x, id, recv, start, count, depth));
```

```
// DOES THIS CALL'S RESULT HOLD A BORROW OF THIS FRAME'S STORAGE (D-326)? The
// refs the result may carry under the callee's summary (`collect_call_refs`:
// every bit set for an unknown callee, nothing for a builtin method), rooted
// at a frame-owned binding -- a local, a pattern binding, a by-value parameter
// (`ref_root_is_frame_owned`) -- of ANY kind: a direct or laundered VIEW, an
// ADDRESS the result carries, a carried value. A ref rooted at a pointer
// parameter's pointee is the caller's business (D-138), as rule B reads it.
func:call_result_holds = bool(Escape->:x, ExprId:call, ExprId:recv, int32:start,
                              int32:count, int32:depth) never fails {
    List<ViewRef>:refs = raw list_init::<ViewRef>(4i64);
    drop collect_call_refs(x, call, recv, start, count, depth, @refs);
    for (int64:i in 0i64...refs.count) {
        if (raw ref_root_is_frame_owned(x, refs[i])) { pass true; }
    }
    pass false;
};
```

Why ANY kind and not only the view kinds: `arg_carries_view` filters to VIEW_DIRECT/
VIEW_LAUNDERED because it feeds the FREEZE, where an address is D-286's plain party and
freezes nothing; here the question is rule 2's — may the result leave the frame — and a
carried ADDRESS of a local (`pass @b.s` under the PASS bit) or a carried by-value parameter
(REF_PASS, DEF-109) leaves the frame exactly as a view does. `ref_root_is_frame_owned`
answers for every kind.

Why the `carries_pointer` test stays first: `collect_view_refs` filters "a value whose type
holds no pointer carries no view" at every node, so a scalar result yields no refs anyway;
keeping the test in the arm keeps the cost where it was (the common case answers before the
summary is read) and keeps the reading identical to today's for an unknown callee.

What the arm's OTHER readers keep: `borrowed`/`local_borrows` still feed rule B and F-1's
parameter-rooted destinations; `record_dest_refs` and `record_mut_of_call` are untouched; the
freeze (alias.npk) reads the view refs, not `holds`.

### 2.2 What the new reading admits and refuses (each a test in §2.4)

| Shape | Callee's summary | Today | After |
|---|---|---|---|
| `string:r = raw make(@b); pass r;` — `make = string(Box->:b)` builds a fresh string | no VIEW entry, no PASS bit for `b` | BORROW-001 at `pass r` | accepted |
| `pass raw make(@b);` (the temporary form) | the same | BORROW-001 | accepted |
| `string:t = raw take(@sink); pass t;` — `take = string(Sink->:k) { pass string_concat("", string_from_bytes(k.buf.ptr, k.buf.len)); }` (a COPY of a view) | `string_concat` is an owned copy (the reference's `Views` column): no entry | BORROW-001 | accepted |
| `string:v = raw view(@b); pass v;` — `view = string(Box->:b) never fails { pass string_from_bytes(b.s.ptr, b.s.len); }` | VIEW entry (k = 0, path `fs`) | BORROW-001 | BORROW-001 (a laundered view of `b`) |

## 3. Decisions taken at planning (each with its reason)

- **P-1 — The helper reads `collect_call_refs`, not a second summary reader.** One reading
  of the summaries for the freeze, the store matrix and the marking; a second reader would be
  the two-mechanisms shape the blueprint forbids, and the first thing to drift.
- **P-2 — Every ref kind counts, filtered by frame-owned root.** §2.1 says why: rule 2's
  question is "may it leave", and an address or a carried by-value parameter leaves as a view
  does. The freeze's filter to view kinds is the freeze's business.
- **P-3 — The unknown callee keeps the shape rule.** D-326's text; a `dyn` method's or a
  function value's body is not the analysis's to read, and "every bit set" is exactly the old
  marking for it.
- **P-4 — No respelling of `src/`.** The sweep measures; a cleanup of workarounds is not this
  subcycle's deliverable and would move the compiler's own rows for no verification gain.
- **P-5 — One landing.** The change is one predicate and one helper; the tests, the sweep and
  the docs ride with it.
