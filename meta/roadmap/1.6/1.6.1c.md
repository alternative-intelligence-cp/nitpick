## 0. What 1.6.1c is, and is not

D-264 (1.5.2f) made a bare `T` MOVE-ONLY in a generic body — a generic body is checked once
for every type it is instantiated at, and before the rule `T:x = s[i]` at an owning `T`
compiled, linked and ran with two owners of one heap body — naming `.clone()` under `Clone` as
the way to read one out. The prelude's `Clone.clone` is fallible (`Result<Self>`: a clone of
an owning value allocates), so in a `never fails` generic body a clone is `relay`-less and
unusable, and `List<T>` has no by-value get; nitpick-regex answers with its own `Pod` marker
and a `pod_copy`. After this subcycle: the prelude declares the marker trait `Copy` — no
method; a type implements it only if it does not own — implements it for every scalar in the
generated region, derives it for a struct of copyable members, and the bound `T: Copy`
LICENSES a plain copy of a `T` in a generic body where D-264 demands a move; `list_get(l, i)`
on `List<T: Copy>` returns the element by value, `never fails`, the index checked as `l[i]`'s
is. One rule: a copy is a copy; no second clone; no `never fails` clone for owning types (an
allocation can fail). It is NOT: supertraits or a `Self: Copy` licence in a trait's default
body (`Self` stays move-only — a later question, recorded in §3); a change to `Clone` (the
generated `Clone` rows stay; `Copy` types clone by returning themselves as they do today); a
runtime or emitter change (a copy of a `Copy` value is the plain load/store every non-owning
value already gets); a change to the `List` layout or to `l[i]`.

## 2. The design

### 2.1 The trait, its impls, its derive

`src/prelude/prelude.npk`, after `Clone`:
```
// A VALUE THAT IS ITS OWN COPY (D-327, 1.6.1c). A MARKER: no method. A type may
// implement it only if it does not own -- an impl on a type that drops, or whose
// member is not itself `Copy`, is refused (NITPICK-TYPE-087) -- so the bound
// `T: Copy` licenses a plain copy of a `T` in a generic body where D-264 demands
// a move, and `list_get` reads an element out by value. Every scalar implements
// it in the generated region below; a struct or enum of copyable members derives
// it (`#[derive(Copy)]`). A `Copy` type still clones, by returning itself.
pub trait:Copy = { };
```
`gen_tables.py`: every family's tuple gains `"Copy"` (every scalar is its own copy — the
integers, `char`, the twisted kinds, the ternary digits, `frac`, the floats and `flt128`, the
tbb carriers, `bool`, the kernel identifiers, the flag families, `complex` per instance,
`dim256` per distinct vector); `scalar_impl_row` writes `impl:%s:Copy = { };` for kind
`Copy`; `TRAIT_OF_KIND["Copy"] = "Copy"`; `HAND_IMPL_RE`'s alternation gains `Copy` (so a
hand-written `impl:string:Copy` in the prelude would be seen — none exists, none will);
regenerate (`python3 bootstrap/generator/gen_tables.py`, then `--check` clean; the harness's
`check_generated_current` holds it). The region grows by one row per scalar target; each is
an impl with no method, so NOTHING is emitted for it (no function, no vtable) — every
program's plain emission stays byte-identical (§2.5).

The derive (`derive_gen.npk`): `DERIVE_COPY` = 8, `DERIVE_MAX` = 8, `derive_of_name("Copy")`,
the `DERIVE_UNKNOWN` message counts eight and names `Copy`; `dv_reaches_members` true for
`Copy` (a struct's fields, an enum's payloads); `dv_refusal` under `Copy`: DVC_SCALAR, DVC_NAMED
and DVC_PARAM answer "" (the checker decides, §2.2), DVC_POINTER "" (a pointer copies by
address), DVC_SIMD "" (a `simd` copies), DVC_ARRAY "" for an array of scalars (D-258's
`dv_array_of_scalars`, as under `Clone`) and refused otherwise, DVC_STRING refused ("a
`string` owns its bytes: it clones, it does not copy"), DVC_REFUSED refused (the existing
sentence; a `List`, a `dyn`, an `Optional`, a function type, a `cstring`, `any` — a
hand-written impl is the way to say what the checker can judge); the generated text is
`<dv_head>Copy = { };` — `dv_head` puts `: Copy` on exactly the parameters a reached member
mentions, so `#[derive(Copy)] struct:Box<T> = { T:v; }` writes `impl:<T: Copy>:Box<T>:Copy =
{ };` and `Tagged<T> = { int32:id; }` derives `Copy` for every `T`. D-259's re-homing applies:
a refusal reports at the derive's declaration naming the member.

### 2.2 The checker's two rules

**(a) The bound licenses the copy.** `type_owns_for_move(e, ty)`: a `TY_PARAM` owns for the
move-only rule UNLESS its declaration's bound window names the prelude's `Copy`:
```
    if (k == (raw TY_PARAM())) { pass (!(raw param_is_copy(e, ty))); }
```
`param_is_copy`: `type_decl_of(e.types, ty)` is the parameter's declaration index;
`bound_entry_of(e.bounds, that index)` its window; each entry's type id compared with the
prelude's `Copy` trait type — resolved ONCE per typer, the way the prelude's `Ordering` and the
compiler's `Error` are found (the prelude scope's symbol for the interned name `Copy`, then
`tt_trait`'s id for its declaration; record the accessor the executor uses in the record).
`TY_SELF` stays owning (§3, P-3). Every reader of `type_owns_for_move` gets the licence at
once: `require_move_if_owning` (a `T:x = l[i]` under `T: Copy` is a copy, no TYPE-046), the
lending-pick binding rule, the derive generator.

**(b) An impl of `Copy` is refused where a copy would be a second owner** —
`NITPICK-TYPE-087`, `TYPE_COPY_OWNS` in `type_codes.npk`, reported by
`check_one_impl_complete` when `e.trait_id` is the prelude's `Copy`: (1) the target type
DROPS (`type_drops(@r, target, scope, 64)`: a `string`, a `List`, a `dyn`, an owning struct or
enum, an arena, a lock, a channel) — "`X` owns what it holds, so a copy of it would be a
second owner: it cannot implement `Copy` (D-327); write `Clone`"; (2) a field or payload of
the target's declaration whose type is NAMED does not implement `Copy` (`type_implements` over
the substituted member type — for a family target, the pattern's own arguments) — "the field
`f` of `X` is a `P` that does not implement `Copy`, so `X` cannot (D-327): derive or implement
`Copy` for `P` first"; (3) a member whose type is a bare parameter `T` of the impl is not
bounded by `Copy` — "the member `v` of `Box<T>` is a `T` no bound licenses to copy: write
`impl:<T: Copy>:Box<T>:Copy`". A pointer, a `simd`, an array, an `Optional`, a function value
or a `cstring` member passes by kind (none drops). The rule runs where every impl is checked,
so a hand-written impl and a derived one meet one judge; the derive's own refusals (§2.1) are
the conservative subset it can state at the declaration (D-258/D-259).

(2) and (3) exist beside (1) on purpose: a struct of two `int32`s and a `Point` that chose
not to be `Copy` does not drop, yet `Copy` for it would state an intent its member never
made — a marker is a claim about a type's members as much as about its bytes (the reading
`Clone`'s derive already takes, member-wise through the trait, D-258).

**Where the bound is judged for a call**: nothing new — `list_get(l, 0i64)` with
`List<string>` records the instance `list_get<string>`, and `check_arg_bounds` refuses it with
`NITPICK-TYPE-017` ("`string` does not implement `Copy`, which `list_get`'s parameter `T`
requires"); the family impl `impl:<T: Copy>:Box<T>:Copy` is asked at its use (D-256).

### 2.3 `list_get`

In the prelude's checked operations (after `list_pop`):
```
// AN ELEMENT BY VALUE, for a copyable element (D-327, 1.6.1c): the bound is what
// licenses the copy -- D-264 demands a move of any other `T` -- so a `never fails`
// generic body can read a `List<T: Copy>` out with no `Result`. The index is
// checked as `l[i]`'s is (D-314): outside `[0, count)` traps `OutOfBounds`.
pub func:list_get<T: Copy> = T(List<T>->:l, int64:i) never fails {
    if (i < 0i64) { !!! OutOfBounds; }
    if (i >= l.count) { !!! OutOfBounds; }
    pass l.items[i];
};
```
(The spelling of a bounded generic FUNCTION head is TRAITS_REFERENCE §3.1's; confirm against
an existing `func:…<T: …>` in the tree before writing.) The reach analysis follows the call
into the prelude (DEF-86), so a program calling `list_get` names `(OutOfBounds)` — as
`list_pop`'s callers do. The name `list_get` is a prelude export: a program's own
`func:list_get` is refused at module scope (`bind_prelude_into`); the census (§1) found none.

## 3. Decisions taken at planning (each with its reason)

- **P-1 — A marker with no method, not a `Clone` twin.** "A copy is a copy": the licence is
  the bound; a method would be a second spelling of the load/store every non-owning value
  already gets.
- **P-2 — Member-wise, not only drop-wise.** §2.2 (b): the rule mirrors `Clone`'s derive
  (D-258) and keeps a marker a claim about intent, not a bit the checker infers.
- **P-3 — `Self` stays move-only.** A trait's default body copying `Self` would need a
  supertrait `Copy` on the trait (§2.2 exists in the reference); the need has not arisen and
  the rule is one line when it does. Recorded here as the one thing left out, with its owner
  (the compiler seat, on the first report).
- **P-4 — The derive refuses what it cannot judge, the checker judges every impl.** D-258/
  D-259's split: the derive names the member at the declaration; the checker's rule is the one
  judge for hand-written and derived impls alike.
- **P-5 — An ADVANCE notice, with the census.** The name `Copy` is reserved in every program
  by D-239 the moment the prelude declares it; the rule of 1.5.6b step 4 (a reserved name is
  measured across the tree, the libraries and the apps, and told before it lands) applies.
  nitpick-regex's `Pod` retires into the prelude's name when they adopt.
- **P-6 — `list_get` traps, as `l[i]` does.** `never fails` is about the `Result` envelope;
  an index outside the list is `OutOfBounds`, one name for one mistake (D-314).
