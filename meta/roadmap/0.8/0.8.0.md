# 0.8.0 — The measurement, the `use`-path sweep, `enum =>!`

**Cycle 0.8 — `nlibc` core and runtime symbols.**

## The first `npkc src/main.npk`

The compiler had never been fed to itself — the seed builds it, the real frontend
had only ever seen tests. The first run reported **eight findings and then a
wall**: every `use` in `src/` and `tools/` is spelled bare (`"frontend/intern.npk"`),
and MODULE_REFERENCE §is unambiguous — a bare path resolves against the
**dependency roots**; importer-relative requires `./`. The seed resolves
relative-to-importer regardless, which is how 352 wrong spellings lived through
seven cycles.

**The sweep**: every use-path in `src/` and `tools/` now carries its `./` — 352
sites — and the **generator emits the prefix too** (`gen_tables.py` writes five of
those files; the first sweep was silently clobbered by the next regen, which is
the lesson about editing generated files re-learned once more).

## The instrument had to grow a field first

119 findings across ~60 modules, reported as `CODE line:col` — no file. The
format predates the module graph, when every tool took one file and `line:col`
was the whole address. Diagnostics now print **`CODE path:line:col`** (the span
always knew its file; the format finally says it), and the harness's matchers
take the last two colon-fields as the span — expectations still assert code,
line, col, never the path.

One immediate catch: `src/frontend/builtins.npk` had **no imports at all** —
every one of its 47 `string_eq` calls resolved to nothing. The generator now
emits the `use` with the file.

## `enum =>!` reads the tag — settled with the user

The user supplied the original design: `=>` for conversions where **no loss can
occur**, `=>!` to say **"loss may occur and it is fine"** — because intent belongs
in source, never in a blanket flag. Applied to enums:

- `enum =>! intN` **reads the tag** — losing nothing, but treating identity as
  quantity is an assertion, and assertions cost the bang. `enum => intN` stays
  refused.
- `intN => enum` stays **impossible in both spellings**: that direction doesn't
  lose information, it *fabricates* a value that may be no variant at all, which
  would silently break every `pick` the exhaustiveness analysis proved complete.
  (`fd` has the same asymmetry and no exhaustiveness promise — hence
  `int32 =>! fd` is allowed there and confined to `nlibc`.)

The emitter extracts slot 0 first for a payload-carrying enum — "the tag is the
number" holds for both layouts — and `tests/backend/programs/enums_pick.npk`
regained the tag read 0.7.7 had to route around, now exercising declared-value
tags (`Flat.Late =>! int32 == 9`) and the payload-enum tag both, in execution.

## The measured debt, classified — 0.8.1's worklist

78 findings once resolution can see straight, in three classes:

1. **Cross-module privates** — `te_error` and kin, `func:` where `pub func:` is
   needed; the seed's single namespace never enforced visibility. ~60 findings.
2. **Missing imports** — a module using names its `use` list never brought in
   (`QUAL_CONST` in `resolve_type`, `TokenKind` in `type_decl`).
3. **Genuine duplicates** — `round`/`settling` declared twice in one scope of the
   pipeline (pre-existing in `check.npk`'s main, hidden by the seed).

Behind that wall waits the **type-stage debt** the resolve errors currently mask —
the `=>` reinterpret casts, `fail` with integer literals — measurable only once
0.8.1 clears resolution.

## Done when

- Diagnostics carry their file; the harness parses the new format everywhere.
- Every use-path in the tree and in the generator is spec-correct.
- `enum =>!` types, lowers, and runs; both stale directions still refuse.
- The remaining self-check debt is counted and classified, with 0.8.1 owning it.
