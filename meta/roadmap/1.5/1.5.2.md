## 2. What this subcycle builds, in one picture

```
Rules<int32>:r_pos   = { $ > 0i32 };                    define i1 @"npk.m.r_pos"(i32 %a0)   — L-1
Rules<int32>:r_small = { limit<r_pos>, $ < 100i32 };    define i1 @"npk.m.r_small"(i32 %a0): call r_pos, then icmp slt

func:f = int32(limit<r_pos> int32:n) {                  ENTRY: load n; call @r_pos; br … limit.bad → npk_trap(-4111)
    limit<r_small> int32:m = n;                          INIT:  store; load m; call @r_small; br …
    m = m + 1i32;                                        ASSIGN: (overflow guard) store; load; call @r_small; br …
    int32:q = 100i32 / m;                                div-zero DISCHARGED: r_small(m.2) is a hypothesis (L-7)
    pass q;
};
func:main = int32(cstring[]:_~argv) {
    int32:v = f(5i32) ?! E9;                             limit-subsume: (> 5 0) — discharged; step 4: `call @"npk.m.f.body"`
    exit 0i32;
};
```

Rows the walk records for `f`: `limit` at the entry (goal `(> |n.1| 0)`,
hypotheses: the range axiom — `open`, guard retained), `limit` at the init
(goal `(and (> |m.1| 0) (< |m.1| 100))`, hypotheses: `(= |m.1| |n.1|)` and
`(> |n.1| 0)` — `open`: `n = 200` is a counterexample), `limit` at the
assignment (goal over `|m.2|` with `(= |m.2| (+ |m.1| 1))` and `r_small(m.1)`
as hypotheses — `open`: `m = 99`), `div-zero` at the division (goal
`(not (= |m.2| 0))` under `r_small(m.2)` — **discharged**), `div-min`
(discharged: a literal dividend). For `main`: `limit-subsume` at the call
(goal `(> 5 0)`, empty cone — discharged). Every retained guard traps
`LimitViolated` to `failsafe`; every discharged `limit` site is one
`llvm.assume` over the rule's range clauses; the discharged `limit-subsume`
row is, after step 4, the reason `main` calls `@"npk.m.f.body"`.

the site's obligation is recorded BEFORE the rule is asserted on the new
version, so the goal never sits in its own cone):

## 3. Decisions taken at planning (each with its reason; ratify or amend before the step that lands it)

Numbered L-1… so the record and the commit messages can cite them. L-4,
L-5, L-13 and L-18 read the ratified text one way where another reading
exists or add a rule; each is in §9. Everything else follows from
D-220/D-068/D-142 and the tree as measured (§4).

- **L-0 — DEF-14 is fixed first, and the fix is "never named", not
  "never defined".** An escaped name (any local or parameter whose address
  is taken anywhere in the body — `@x`, `$$m x`, `$$i x`, through any place
  path; `collect_escaped` already computes the set) gets NO symbol:
  `bind_define`, `bind_assign` and `invalidate` leave `sym = -1` for it,
  and `enc_expr`'s identifier arm therefore hands every read a FRESH opaque
  term (`term_opaque`, with the type's range axiom). `collect_escaped`
  moves ahead of the parameter loop (`enc_prepare(body)` before
  `enc_param`, in `obl_function`), so an escaped PARAMETER is opaque from
  its first read — today `enc_param` runs first and gives it a stable
  symbol, the same hole one line earlier. Reason: 1.5.0's comment "an
  address-taken local is never defined" was read as "its symbol is never
  given a definition", but a stable symbol IS a fact — "every read of `x`
  is the same value" — and a call handed `@x` breaks it (§4.3: the
  definition `|a.1| = |x.1| + 1` outlived `bump(@x)` and discharged
  `100 / (x - a)`). Fresh-per-read is the reading P-8 meant. What it costs:
  no fact about an escaped local's value ever survives, even before the
  first `@` — flow-sensitivity (escaped from the first address-taking
  onward) is a precision improvement that belongs with 1.5.4's path
  conditions and is decided OUT here. `tests/verify/divz_escaped.npk` pins
  the shape at `div-zero open 1` (§4.3's program), `divz_escaped_param.npk`
  the parameter twin; the compiler's own rows are re-decided and any that
  move are `--record`ed in the same commit with their symbols listed.
- **L-1 — one generated predicate function per `Rules` declaration.**
  `define i1 @"npk.<module>.<name>"(<T> %a0)` — the ordinary mangling
  (`mangled_fn_sym(ctx, decl_index, name)`; a `Rules` name lives in the
  module's one declaration namespace, so the symbol is free), the subject
  the single parameter, the result BARE `i1` (a new `fnem_begin` mode
  beside `fn_is_bare`'s by-name rule: the function is the emitter's own,
  never callable from source, so no envelope). The body: refinements then
  clauses in SOURCE ORDER, short-circuit — each refinement a `call i1` to
  its rule's function, each clause `emit_expr` with `$` bound to the
  subject's slot; the first false clause ends the evaluation with
  `ret i1 false`; all true → `ret i1 true`. Every declaration is emitted
  whether or not it is used (V-6's eager rule for the same reason: a
  defect in a clause is found even before the rule has a user). Reasons:
  (safety) a clause's own guard sites — a division inside `{ $ != 0i32,
  100i32 / $ > 1i32 }` — exist ONCE, in one function instance, with ONE
  row each; inline expansion at every write point would give one clause
  node several sites in one function, and `llctx_elided`, keyed by node id
  per function, would answer one site's elision for all of them;
  (uniformity) the obligation walk treats the rule function like any
  instance (P-3 — `obl_function` with `pnames = [intern("$")]`,
  `ptypes = [subject]`, the body a synthetic block of the clauses), its
  clause obligations count toward the declaring module's `verify`
  expectations (`row_in_module` reads the symbol's module), and `$` is
  the parameter, which is what V-5 says `$` means. D-183: the subject
  arrives by value and is a LENT parameter — no flag, no drop — exactly a
  non-`move` parameter. D-246: each clause is a statement-shaped unit
  under the temporaries protocol, so a pure call's owning result inside a
  clause is dropped when the clause's value is taken.
- **L-2 — `$` inside a rule is the subject's slot, in the emitter.**
  `FnEmitter` gains `rule_slot` (a GEP/alloca text) and `rule_ll` (its
  LLVM type), set by the rule-function emitter and empty otherwise;
  `emit_expr`'s `ExprIterationVarExpr` arm (`ir_expr.npk:1290-1297`)
  reads them FIRST and falls to `fnem_iter_slot` (the counted loop's
  `i64` slot) only when they are empty. Reason: the arm hard-codes
  `load i64` today because a counter is always `i64`; a subject is any
  type, and V-5's "the two constructs cannot nest" is what makes one
  arm serve both without a mode.
- **L-3 — the write points, precisely: the initialiser, every
  assignment to the binding or to any part of it, and the callee's
  entry; the check runs AFTER the write, over the binding's WHOLE
  current value.** One helper, `emit_limit_check(x, root_slot, root_type,
  rule, space, site)`: `load <T>, ptr <slot>`; `call i1 @rule(<T> %v)`;
  `br i1 %ok, label %limit.ok, label %limit.bad`; `limit.bad:` `call void
  @npk_chain_reset(i32 <x_site>)`; `call void @npk_trap(i32 -4111)`;
  `unreachable` — the division guard's shape (`ir_expr.npk:2598-2610`).
  The sites: `emit_vardecl` after its `store` (both slot shapes — alloca
  and coroutine-frame GEP; a declaration WITHOUT an initialiser is not a
  write point: D-225's vacant value is never read, by definite
  assignment); `emit_assign` after the `store` on the `=` path and after
  the `store` on the compound path (the arithmetic's own guards — D-210
  overflow, D-007 division — run first inside `emit_arith_value`, so a
  trap there precedes the limit's); a non-identifier target (`p.x = …`,
  `a[i] = …`, nested) whose ROOT identifier is a limited local — the root
  found by walking `ExprMemberAccessExpr`/`ExprIndexExpr` operands to the
  identifier (never through a `<-` or a pointer/slice/handle-typed base,
  where the storage is not the binding's) — is a write point of the root,
  checked over the whole aggregate; and the entry, for each limited
  parameter, after `fnem_open` (the slots exist in both skeletons: allocas
  for a sync function, frame GEPs at state 0 for a coroutine — `async` and
  `thread` alike, where the check runs once per task at the body's start)
  and after `obl_function` (so the elision answers exist), before
  `emit_block`. `FnEmitter` gains `lrules` beside `lnames`/`lslots` (the
  rule's DeclId per local, 0 for none; `fnem_bind` takes it, the parameter
  loop and `emit_vardecl` set it). Reasons: after-the-write is one shape
  for a scalar and for a field store (a before-the-write check of a field
  store would need the aggregate rebuilt in a temporary); the transient
  between store and trap is unobservable — a trap is a whole-program event
  (D-063) and `failsafe` sees no locals; and "any part of it" is what
  makes a rule over an aggregate mean something.
- **L-4 — a limited binding has no address (TYPE-063; §9 S-28).**
  `@place`, `$$m place` and `$$i place` refuse when the place is rooted at
  a limited local or parameter, and so does a `move`/`pass` out of a
  PROPER sub-place of one (a field or element — S-26's vacate is a write
  no rule can be asked to admit; moving the WHOLE binding is fine, it
  dies). The checker's address-of and borrow arms (`type_expr.npk:3529`,
  `:3541`) and the move-out arms ask one new predicate, `place_limited(e,
  id)`, over `place_is_local`'s walk (`type_stmt.npk:729-773`: the root
  identifier's `Symbol.origin` → its `StmtVarDeclStmt`'s `stmt_decl_limit`
  or its `DeclParamDecl`'s `param_limit`). Reason: a write through an
  alias is a write no write point sees — LIVE-1's exact shape (a `limit`
  that lowered to nothing "told the caller its argument was checked when
  nothing checked it"), and §4.2 measured that all three spellings and a
  store through each are accepted today. The alternative read in §9 —
  admit `@x`/`$$m x` as a DIRECT call argument only, of a call whose
  result holds no address (`type_holds_address`), and make that call a
  write point of `x` whose row is always `open` — keeps `list_push(@xs, v)`
  on a limited list at the price of a second write-point class, a
  result-shape rule, and per-read rule hypotheses for escaped names; a
  by-value rewrite (`xs = grown(move(xs), v)`) covers the case under the
  one rule. `$$i` is refused with the other two because a borrow of
  either kind is a pointer the language cannot tell apart at the write
  (the pointer type carries no mutability), and a limited value passes
  by plain argument freely (D-183 §4). Encoder consequence: a limited
  name is NEVER escaped, so L-7's hypothesis attaches to versions only.
- **L-5 — where a limit has no write point it refuses (TYPE-064; §9
  S-28)**: a trait method's parameter (a signature has no body; the impl's
  own parameters may carry limits, and a `dyn` call reaches the impl's
  checked entry — §4.2: accepted and silently dropped by the impl today);
  a `wild`/`wildx`-qualified binding (its writes are the manual regime's,
  through pointers — accepted today); the parameters and locals of a
  `comptime` function (the frontend folder is a second evaluator, and a
  second implementation of the check is what 1.3.3's compound-assignment
  drift teaches against). A `limit` on a `main`/`failsafe` parameter
  refuses under D-244's arm (TYPE-060: "`main` and `failsafe` carry no
  contract" — nobody but the runtime calls them, and a trap at
  `failsafe`'s own entry re-enters the route). A `stack` binding is
  ordinary (its writes are stores). A `fixed` global cannot carry a limit
  at all (§4.2: the parser has no production — nothing to refuse). A
  `for`/`till` binding cannot either (V-7). A `move` parameter may (its
  entry is a write point; it is then an owning local).
- **L-6 — subjects that encode, and `unencoded` for the rest.** The
  1.5.0 fragment is `intN`/`uintN`/`bool` (`is_int`/`is_bool`). A `limit`
  over any other subject — a struct, an array, a string, a pointer, a
  twisted or float type — records one `unencoded` row per write point
  (P-12's template, `record_unencoded_division`'s shape: empty goal,
  `encoded: false`, the positional canonical text), its guard retained,
  the check still run (D-068). The theories those subjects need are
  unscheduled — §9 S-30.
- **L-7 — the rule is a HYPOTHESIS on every version of a limited
  binding.** `Bind` gains `rule` (the `Rules` DeclId index, 0 for none),
  set at `bind_define` from the declaration's limit node (`stmt_decl_limit`
  → `limit_target`) or the parameter's (`param_limit` → `limit_target`);
  the three version creators — `bind_define`, `bind_assign`, `invalidate`
  — call one `assert_rule(e, bind)` after the new symbol exists. At a
  WRITE POINT the order is: new version and its definition → the site's
  obligation recorded (`record` takes `hyps = e.hyps.count` BEFORE the
  next push, so the goal is never in its own cone — P-17's ordering for
  the quotient's definition, applied here) → the rule pushed. At an
  invalidation (a merge after `if`, a loop's entry and exit, `defer`)
  there is no obligation, only the hypothesis. At `enc_param`: the entry
  obligation, then the hypothesis. Soundness (P-8, TCB §5.4): every
  write to the binding is guarded by exactly this rule (L-3) or its
  guard was discharged under the same hypotheses, so on every execution
  that continues past a write the rule holds — the walk asserts nothing
  the guards do not make true. This is the cross-kind win: a `div-zero`
  whose divisor is limited by `r_pos` discharges, INCLUDING after a loop
  that assigns it (`limit_loop.npk`, §5 step 3).
- **L-8 — the rule's encoding: `enc_rule(e, rule, subject) → Term(Bool)`.**
  The conjunction, in source order, of each refinement's `enc_rule`
  (recursively; fuel 64 — resolve refused cycles) and each clause's
  `enc_expr` under a `subject` term the encoder carries (`Encoder.subject`,
  set around the walk of a rule body; the `ExprIterationVarExpr` arm
  returns it inside a rule and is opaque outside one — a counted loop's
  `$` stays what it is today). A clause the encoder cannot express — a
  `raw f($)` call (1.5.3's uninterpreted functions are its owner; here it
  is opaque), a non-fragment member, anything P-8 declines — becomes an
  opaque Bool `|<rule>.c<i>.<k>|` (P-5's naming; a fresh version per
  instantiation): as a goal conjunct it makes the row `open` (§4.4 f), as
  a hypothesis it asserts nothing usable. The site's canonical text
  therefore CONTAINS the rule's clauses with the version substituted —
  editing a rule changes every dependent row's hash, which is honest: the
  obligation changed.
- **L-9 — the site key gains a SPACE.** `SmtObl.site` stays `int32`;
  `el_sites` gains a parallel `el_spaces` (0 = expression, 1 = statement,
  2 = declaration), `record` takes the space, and `llctx_elided(c, space,
  site, kind)`. Division sites: space 0 (unchanged, the assignment's
  target expression for `/=`). `limit` at an init or an assignment: the
  STATEMENT's id, space 1. The entry check: the parameter's DeclId, space
  2. A `limit-subsume` row: the call expression, space 0. Reason: three
  id spaces meet at one table; a statement and a declaration with equal
  indices would answer one site's elision for the other — the silent
  wrongness P-3's "identical by construction" exists to exclude. 1.5.0 §7
  froze the table as `ExprId → {kind, hash, verdict-bit}`; this is the
  amendment, recorded here and in the record, additive for every existing
  row (every 1.5.0 site is space 0).
- **L-10 — `limit-subsume` rows: one per DIRECT call site of a callee
  with at least one limited parameter.** The callee is the declaration
  the checker recorded (`exprtypes_callee(et, callee-expr)`, the same
  answer `emit_call` lowers by — a free function by symbol, a method by
  its impl); a call through a `dyn` or a function value has no row (its
  entry check covers it — L-3). Goal: the conjunction over the callee's
  limited parameters of `enc_rule(rule_i, arg_i)` with the caller's
  argument terms (an unencodable argument is opaque → the row is `open`),
  each conjunct `:named` for `--explain` so a model names the parameter;
  hypotheses: the caller's cone — a limited-binding argument brings its
  rule (L-7), which is the spec's "one `Rules` implies another at a
  boundary"; symbol: the CALLER's; guard `no`, elision `none` — exactly the
  ratified catalogue — until step 4 (L-13). One row per SITE, not per
  parameter: the bypass is all-or-nothing at a call, and a row must read
  as one verdict with one elision. A variadic collector's `limit` (a
  parameter like any other, L-5) has no call-site row: the call BUILDS
  the array, and the entry check covers it.
- **L-11 — elision of a `limit` row: the guard gone, ONE `llvm.assume`.**
  A discharged site emits `load`, then the conjunction of the rule's RANGE
  CLAUSES — a clause that is a comparison (`< <= > >= == !=`) between `$`
  and an integer literal (either side), or an `&&` of such, with
  refinements expanded — as `icmp`s `and`-chained into one `i1`, and
  `call void @llvm.assume(i1 %c)`; a rule with no range clause assumes
  `i1 true`. No call, no branch, no trap. Reasons: the accounting "one
  assume per discharged guarded row" stays uniform in both runners (L-12);
  the assume is the D-218.9 channel 1.6's leg A reads (its README calls
  them "the `llvm.assume` range rows"); a full re-evaluation would keep
  the cost the discharge exists to remove; a range clause can neither
  call nor trap, so nothing hides in an elided site. Sound because the
  discharge proved the rule on every continuing execution (L-7) and the
  value in register is the value written.
- **L-12 — the elided-IR accounting in both runners, kind-aware.**
  `elided_ir_checks` (`harness.py:2961-2978`, `npkg/verify.npk:301-343`):
  `llvm.assume` count == discharged rows of kinds whose elision emits one
  (`div-zero`, `div-min`, `limit`); per guarded kind, trap count ==
  retained rows (the pair list gains `("-4111", "limit")`); guard-less
  kinds count for nothing. Both renderers (`manifest_of`,
  `manifest_text`) gain the third elision word: `none` when
  `!ok_has_guard(kind)` — neither can spell it today (§4.5). The
  `verify` stage's per-module scoping is unchanged: a rule function's
  symbol is the module's.
- **L-13 — the caller-side bypass (step 4; §9 S-29).** A SYNC function
  with ≥1 limited parameter emits its body under `@"<sym>.body"` and the
  ordinary symbol as the CHECKED ENTRY: the entry checks over the
  arguments, then `%r = tail call <ret> @"<sym>.body"(<args>)`, `ret %r`.
  Every non-call reference — a function value, a vtable slot, a
  `thread`/spawn entry, a derive or bridge stub — names the ordinary
  symbol by construction (those paths never learn of `.body`). A DIRECT
  call whose `limit-subsume` row is discharged calls `.body`; any other
  call, and every call of a coroutine (its parameters arrive in a frame
  the await site builds; its check runs at state 0), calls the checked
  entry. The row's elision reads `elided` when the call names `.body`,
  `retained` otherwise; the catalogue's `limit-subsume` guard column
  becomes `yes (the callee's entry check, at that call)` with a dated
  note. The belt, in both runners: every `.body` occurrence in an
