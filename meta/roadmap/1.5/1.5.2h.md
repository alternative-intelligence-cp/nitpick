# 1.5.2h — A lending `pick` binds views; the selector is frozen while a view is live (D-266) — PLANNED (2026-09-06; execution-grade; ratified the same day)

> Scope: OPEN_DECISIONS S-41 (the question D-264 left), ratified 2026-09-06 as
> **D-266**, and **DEF-24** (found by planning: TYPE-063 does not cover the
> implicit receiver address). Three steps, three commits, each under a FULL
> harness on a cumulative prefix (D-228). A language change: what a lending
> `pick`'s bindings MEAN. Nothing in `src/`, `lib/`, `npkg/` or `tools/`
> binds a payload in a lending `pick` (measured, §4), so the compiler's own
> code changes meaning nowhere and no snapshot refresh is owed.

## 1. Where you are

`main` is the 1.5.2g close (`0ba21ef`): D-265's digest lines, D-264's
move-only `T`. The snapshot is 1.5.1b's close (D-205).

What a `pick` does today. A lending `pick (v)` binds each pattern name to a
COPY of the payload: `bind_payload` (`src/backend/ir/ir_stmt.npk`) spills the
selector VALUE to a temporary alloca, addresses the payload slot, loads it and
stores it into the binding's own slot (`pick_bind_slot`: an alloca in a sync
body, a frame slot at role 7+ordinal on the ARM's statement index in a
coroutine, registered by `scan_pick_binds`). A payload that OWNS is refused
before that (`check_pick_owning_binds`, `src/frontend/type_stmt.npk`, called
from `type_pick_rules` for BOTH spellings since 1.5.2c; TYPE-046 with D-216's
text). The consuming `pick (move(v))` (D-216) binds owned locals with drop
flags and is untouched by this subcycle. A pattern binding is a symbol of its
own kind — `SYM_PAT`, origin the pattern id (`resolve.npk`: `resolve_pattern`
declares enum payload names, `bind_pattern_names` struct-destructure names;
`symtab_declare`'s result is discarded there). Its type is read back from the
pattern's payload window (`type_enum_bindings`, `type_ident`).

The borrow model a view follows. `@x`, `$$i x` and `$$m x` are parsed
(`ExprAddressOfExpr`, `ExprBorrowExpr`), typed as one pointer type with no
mutability (`type_expr.npk`, the pointer family), and tracked by the escape
analysis (rules A/B, BORROW-001/002; `root_symbol`/`root_is_param`/
`escape_yields` in `escape.npk`), the bindings analysis and the suspend walk.
BORROW-005 — a borrow across an `await` — is DEFINED and has NEVER BEEN
EMITTED: the suspend walk makes an address-taken local frame-resident to the
function's end instead (`suspend.npk`, the `ExprBorrowExpr` arm: "the local
stays live to the function's end"), so the crossing is made SAFE rather than
refused. A limited binding refuses `@`, `$$i` and `$$m` (TYPE-063, D-251,
`type_expr.npk`) — and, found by this planning, NOT the implicit address a
method call takes (DEF-24, step 0).

The emitter's identifier read is `emit_ident` (`ir_expr.npk`): the slot's
type from `fnem_local_type_at`, one `load` from `fnem_local_slot_at`. A
place's address is `addr_of` (same file; the identifier arm returns the slot).
A pointer-typed receiver is passed by address at "A POINTER RECEIVER IS
PASSED BY ADDRESS (1.0.9b)" in `ir_expr.npk`'s call emission, and the checker
decides the same at "A POINTER RECEIVER IS TAKEN BY ADDRESS (1.0.9b)" in
`type_members.npk`'s `type_method_call`. Member reads (`emit_member`) read
the BASE VALUE through `emit_expr` and `extractvalue`, so a view's field read
needs nothing beyond `emit_ident`.

### Step 1 — D-266: a lending `pick` binds views; the selector is frozen

**1a. The fact, recorded once (L-1).** `symbols.npk`: `Symbol` gains
`int32:link` — for a `SYM_PAT` symbol the ExprId index of its pick's SELECTOR,
0 for every other symbol; `symtab_declare`'s pattern-site callers keep the
index it returns and call a new `symtab_set_link(tab, sym, link)`. `resolve.npk`:
`resolve_pattern` takes the selector `ExprId` — the statement form passes
`pick_selector(s)` at its arm loop, the expression form (`ExprPickExpr`, two
sites) its selector — and links every name it declares, enum payload and
struct-destructure alike. One predicate in `symbols.npk`,
`sym_is_view(tab, ast, sym)`: `origin_kind == SYM_PAT`, `link != 0`, and the
linked expression's kind is NOT `ExprMoveExpr`. A `SYM_PAT` with `link == 0`
is a defect (the resolver links every pattern) and answers `false`, never a
guess. `root_sym_through_views(…, id, fuel)`: the place's root symbol;
while it is a view, continue from its link's root; the result is what the
freeze and the escape analysis name.

**1b. The checker (`type_stmt.npk`, `type_expr.npk`, `type_members.npk`,
`type_codes.npk`).**

- `check_pick_owning_binds` and its call are DELETED: a lending binding copies
  nothing. Its `_` remark moves to `type_pick_rules`' header. The three cases
  that asserted it flip (1f).
- Two codes in `type_codes.npk`: **TYPE-066 `TYPE_VIEW_READ_ONLY`** (a
  lending `pick`'s binding is a read-only view of the payload in place: it
  cannot be assigned, addressed, borrowed, moved, destroyed or handed to a
  pointer receiver — read it, pass it by value, or consume the value with
  `pick (move(v))`) and **TYPE-067 `TYPE_PICK_FROZEN`** (the selector of a
  lending `pick` is frozen while an arm's view of it is live: no assignment to
  it or any part of it, no `move`, no `@`/`$$i`/`$$m`, no `.destroy()`, no
  pointer-receiver call, no nested `pick (move(…))` over it — write after the
  `pick`, or bind nothing in this arm).
- `place_is_view(e, id)`: `root_symbol` of the place is a view. The FROZEN
  set: `ExprTyper` gains `List<int32>:frozen`; `place_frozen(e, id)`:
  `root_sym_through_views` of the place is in it.
- Where the set is pushed: the statement form's arm loop (`type_stmt.npk`,
  the region after its `type_pick_rules` call) and the expression form's

  `root_sym_through_views(selector)` if nonzero, type the guard and the body,
  pop. An arm that binds nothing pushes nothing (L-3). A selector with no
  root symbol (a temporary) freezes nothing (L-4).

  one report):

  `refuse_move_of_borrowed` (`type_expr.npk`): a view root → TYPE-047 with a
  view's text (the value was lent by the `pick`, not given; `pick (move(v))`

## 3. Decisions taken at planning

- **L-1 — One fact, derived.** "Is this binding a view" is read off the
  selector's spelling through the symbol's link; there is no flag to drift
  from the spelling, and the checker, the analyses and the emitter ask one
  predicate.
- **L-2 — A view has no address, the implicit receiver address included.**
  The language has ONE pointer type and it carries no mutability, so every
  address of a view is a write path into a lent value; a by-value receiver is
  the lend the language already has (D-065). The same site closes DEF-24,
  which is the same question asked of a limited binding.
- **L-3 — The freeze is the view's extent.** The guard and body of an arm
  that binds; an arm that binds nothing lends nothing, so
  `pick (state) { (Idle) { state = Running; } }` stays legal. Measured: no
  arm anywhere writes its selector today, so either scope refuses nothing
  now; the narrower is the borrow rule's own extent.
- **L-4 — The freeze is on the ROOT binding, through views.** `pick (s.kind)`
  freezes `s`; a view's selector's root is the outer selector's root.
  Conservative and one rule. A temporary selector has no root and lives to
  the statement's end (D-246), which contains the arms.
- **L-5 — The slot holds the address; a read loads twice.** Uniform for sync
  and async. Binding the name to the GEP's SSA value would save one load and
  would fail LLVM's dominance check after a suspension in the arm — loudly,
  but only because a frontend rule elsewhere held; a design whose IR
  validity rests on another rule is not chosen to save a load `opt -O2`
  folds.
- **L-6 — A view across an `await` is sound by residency, as `@x` is.** The
  selector's root is extended to the function's end by the suspend walk; a
  temporary selector's spill is a frame slot. BORROW-005 stays defined and
  unemitted, recorded here so its absence is not read as a gap this subcycle
  opened.
- **L-7 — The consuming form is untouched**, byte for byte, in the checker
  and the emitter.
- **L-8 — Struct-destructure bindings are views too.** One rule for both
  pattern kinds; the lending pick over an owning struct binds views of its
  fields.
- **L-9 — A lifted refusal becomes a positive case.** A rejection file loses
  a case only when the case moves into a program.
- **L-10 — DEF-24 is step 0**, before the rule it belongs to is mirrored
  (1.5.2's DEF-14 precedent: a soundness defect found by planning lands
  first, under its own harness).
