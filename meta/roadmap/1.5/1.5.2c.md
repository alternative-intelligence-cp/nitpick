## 2. What this subcycle builds, in one picture

```
enum:Opt<T> = { Some(T); None; };                 // a TEMPLATE, as struct:Box<T> is
Opt<int32>:a = Opt.Some(3i32);                    // the instance from the ANNOTATION
Opt<int32>:n = Opt.None;                          // ...which a payload-less variant needs
Opt<string>:s = Opt.Some(string_concat("a", "b")); // owns; dropped at scope exit
pick (move(s)) { (Opt.Some(v)) { … v: string … }, (Opt.None) { … } }
int64:len = (pick (move(s)) { (Opt.Some(v)) { give v.len; }, (Opt.None) { give 0i64; } });
func:wrap<T> = Opt<T>(T:v) { pass Opt.Some(move(v)); }   // the instance from the RETURN
Opt<int32>:i = Opt.Some(7i32) …                   // or INFERRED from the payload: `Some(T)` against int32

Ordering?:o = a.partial_cmp(b) ?! E9;
pick (o) { (Ordering.Less) { … } }                // REFUSED, TYPE-065: an Optional has no arms
pick (o ?? Ordering.Equal) { (Ordering.Less) { … } }   // the spelling
```

## 3. Decisions taken at planning (each with its reason)

- **L-1 — The `Optional` refusal sits where the frac and complex refusals sit.**
  `type_stmt.npk`'s `StmtPickStmt` arm types the selector and refuses a frac
  (D-198) and a complex (D-199) by kind before the arms are read; the
  `Optional` arm joins them, and `type_pick_expr` (`type_expr.npk`) gains the
  same test on `pickx_selector` — the expression form was admitted the same
  way. TYPE-065 `TYPE_PICK_OPTIONAL` in `type_codes.npk`; one report, the arms
  not walked (their patterns have no selector to be read against). The message
  names both spellings the language has (`??`, `== NIL`). `check_codes_tested`
  wants the case: `tests/types/rejection/pick_optional.npk`, statement and
  expression forms, one TYPE-065 each at the `pick`.
- **L-2 — One binding for every payload read (D-261).** `bind_instance`
  (`type_layout.npk`) becomes `pub` with its comment saying struct OR enum (it
  reads the declaration and the argument window, both kind-agnostic); each of
  the five payload-resolution sites wraps its `resolve_type` in
  `bind_instance(r, enum_type)` / restore: the layout's enum arm
  (`ensure_layout`), `type_enum_bindings`, `check_ctor_args`,
  `variant_payload_slot_at` (which the emitter's construction, `pick`
  binding and drop body all read — one fix, three consumers), and
  `emit_ctor`'s single-payload path, which resolves `vi.payload_ty` by hand
  today and moves onto `variant_payload_slot` so there is ONE payload-type
  rule in the emitter. `variant_info` keeps `payload_ty` as the NODE for the
  callers that read only the tag and count.
- **L-3 — The emitter substitutes the enum type through the specialization at
  its two entries.** `emit_ctor`'s `etid` and `emit_pick`'s `sel_tid` come
  from the recorded type, which inside a generic body is `Opt<T>`; `ll_type`
  substitutes internally for the LLVM text but `variant_payload_slot` reads
  the tid it is handed, so both entries call `subst_emitted_type` when the
  type mentions a parameter (the `type_mentions_param` guard the method-call
  path uses). This is what makes `pick (self)` inside `impl:<T: Eq>:Opt<T>:Eq`
  bind `int32` payloads at `Opt<int32>` — and it is why D-258's generator was
  already written with bare variant patterns and constructors.
- **L-4 — The instance of a constructor or a bare reference: expected, then
  inferred, then refused (D-261).** New `enum_instance_for(e, decl, name, n,
  start, count)` in `type_members.npk`, read by `namespace_member` (the bare
  `Opt.None`) and by the method-call path's constructor branch (`Opt.Some(…)`):
  a non-generic declaration is its bare type as today; for a generic one, the
  expected type wins when it is a TY_ENUM instance of the same declaration;
  otherwise the constructor infers — each payload node resolved under the
  declaration's OWN window (`bind_own_generics`, so `T` is the parameter
  type) and unified against the typed argument by `unify_into` (an argument
  that `takes_type_from_context` skipped, as `infer_from_args` skips it),
  then `all_solved`'s refusal (TYPE_CANNOT_INFER naming the parameter and
  the declaration; the message says to annotate the binding) and
  `make_instance` (`type_generic.npk`, factored from `subst_instance`'s tail:
  `mangle_instance` + `tt_instance` + `inst_record`, so the instance is
  judged by `check_one_instance` like an annotated one). The bare reference
  of a generic enum with no expected instance is TYPE_CANNOT_INFER too:
  `Opt.None` alone names no `T`, and its common spelling
  (`Opt<int32>:o = Opt.None;`) supplies it.
- **L-5 — Patterns are read against the selector, never typed as values.**
  Measured: the checker does not type a value pattern's expression (no
  `pat_value` read in `type_stmt.npk`/`type_expr.npk`; the emitter's
  `pattern_const` and the exhaustiveness pass read them), so `(Opt.None)` in
  pattern position needs no instance and L-4's refusal cannot fire there.
  Nothing to build; recorded so the executor does not add a pattern typing
  that would.
- **L-6 — Payload-less generic enums are `i32` like any other.**
  `enum_has_payload` and `ll_type`'s payload-less shortcut read the
  declaration; `Tag<T> = { A; B; }` is a legal but pointless template, and
  `Tag<int32>` lowers to `i32`. Nothing to build; a test says so.
- **L-7 — What must not move.** `nitpick.obligations` (141 rows: no new
  guard, no new walked kind), the rung count (4), `selfhost` (nothing in
  `src/` declares a generic enum or picks on an `Optional`), the snapshot.
  The test count and the parity count move by the new units only.
- **L-8 — Order.** The refusal first (its own commit: a checker rule with one
  test), generic enums second (the substantive change, one commit — binding,
  instance, emitter, tests — because a partial landing leaves a program that
  types and does not lower, which is the shape this subcycle exists to end),
  the docs last.

## 4. Measurements the plan rests on (2026-09-05, on `4806025`)

- **DEF-19 repro** (eight lines, `.internal/probes_152b/`-style): `func:pc =
  Ordering?(int32:a, int32:b) never fails { if (a < b) { pass Ordering.Less; }
  pass Ordering.Equal; };` and `pick (o) { (Ordering.Less) { exit 0i32; }, (*)
  { exit 3i32; } }` over `Ordering?:o = raw pc(1i32, 2i32);` — `tools/check`
  accepts, `npkc` answers `NITPICK-EMIT-002 …:5:16`. `emit_pick` has no
  `TY_OPTIONAL` arm (`rg TY_OPTIONAL ir_stmt.npk` is empty) and switches on
  the selector as its own discriminant.
- **DEF-20 repro**: `enum:Opt<T> = { Some(T); None; };` + `Opt<int32>:o =
  Opt.Some(3i32);` + a `pick` — TYPE-001 at the payload `T` (2:22, raised by
  the LAYOUT's payload resolution, `type_layout.npk:510`, when the annotation
  `Opt<int32>` asks for its size), TYPE-007 "expected `Opt<int32>`, found
  `Opt`" at the constructor (`namespace_member`/`type_ctor_named` build the
  bare enum with `tt_enum(decl, name, 0, 1)`), TYPE-007 "expected
  `<unresolved>`, found `int32`" at the payload (`check_ctor_args` resolved
  `T` unbound).
- **Every payload-type read in the tree** (`rg variant_payload_start`):
  `type_stmt.npk:498` (`type_enum_bindings`), `type_layout.npk:510` (the
  layout), `type_members.npk:1062` (`check_ctor_args`), `ir_expr.npk:9053`
  (`variant_payload_slot_at`) and `:9113` (`variant_info`'s node), plus the
  generator's text (`derive_gen.npk`, no resolution). Five readers, one
  binding to add.
- **The struct precedent**: `struct_field` binds the instance
  (`bind_instance`) before resolving a field's type; `resolve_named_generic`
  interns an enum instance with `tt_instance(kind = TY_ENUM, …)` exactly as a
  struct's; `subst_instance` substitutes TY_ENUM instances; `type_mentions_
  param` walks TY_ENUM arguments; `emit_instance_header` emits a TY_ENUM
  instance's header; `check_one_instance` judges any instance's bounds. The
  kind was half-carried everywhere but where a payload is read.
- **Inference precedent**: `infer_from_args` + `unify_into` + `all_solved`
  solve a generic call's parameters from its arguments; `unify_into` already
  handles TY_PARAM leaves, the one-operand shapes and instances of one
  declaration (`same_instance_decl` admits TY_ENUM).

## 6. What the executor should know (gotchas, carried and found)

- A full harness is about 75 minutes alone; stdout is block-buffered, judge
  liveness by pid. `cd` EXPLICITLY at the start of every command — 1.5.2b lost
  three commands to a working directory that had drifted to the main tree.
- `quickcheck` rebuilds the checker each run (~1.5 min); `quickemit` rebuilds
  `npkc` when `src/` changed (~4 min) and is cached after.
- A probe's `failsafe` names `HeapOom`, `HeapBadRequest`, `Unreachable`,
  `WildLeak` (and `IntOverflow`, `DivByZero`, `DivOverflow` where arithmetic
  or division appears), or REACH-002 stops it before the rule under test.
- Reserved words that read like locals here: `any`, `on`, `in`, `mod`, `fd`,
  `fails`, `end`, `unit`, `error`, `buffer`, `raw`, `move`, `old`, `pure`,
  `result`, `limit`, `trit`/`nit`, the flag families. 1.5.2b lost a build to
  `any` and a test run to `on`.
- Strings are move-only owners (TYPE-046); an owning payload is bound only by
  a consuming `pick (move(v))` (D-216), which is what `Opt<string>`'s test
  writes.
- Both self-checks share one case set by NAME; nothing here touches them.
- `check_codes_tested` wants a case for TYPE-065 (step 0's file).
- The user's client flags security-attack vocabulary and the column-trimming
  shell command spelled c-u-t; keep both out of prose and commands.
- Stop every background waiter before reporting done.
