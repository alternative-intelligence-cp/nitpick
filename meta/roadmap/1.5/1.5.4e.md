  .with.overflow.vNiW` at `v4i32`, `v8i32`, `v2i64`, `v16i8`, `v8i16`,

## 2. What lands (three steps; each under D-228; the manifest is not expected to move — no new row kind, and the compiler computes in no vector)

### Step 0 — D-284 (and DEF-39): integer lanes trap on overflow; the compound spelling lowers

1. `ir_expr.npk`, `emit_simd_binop`: takes `Span:at` (it used `n` for
   `n.span` only) and the site; `emit_binary` passes `n.span`. For an
   integer element and `+ - *`: the family by `ovf_family_of(op, signed)`,
   the name by `ovf_intrinsic_name(family, "vNiW")`, `%p = call { <N x
   iW>, <N x i1> } @…(<N x iW> a, <N x iW> b)`, the value `extractvalue 0`,
   the bits `extractvalue 1`, `bitcast <N x i1>` to `iN`, `icmp ne iN 0`,
   `br` to `vovf.trap` / `vovf.ok`; the trap block `npk_chain_reset(site)`,
   `npk_trap(i32 -4110)`, `unreachable` — the D-007 any-lane shape. The
   `ins` path stays for everything else. The declaration is noted on the
   context (`LlCtx.vec_decls`, a `List<string>` deduplicated by scan) and
   `emit_all` writes the list after the bodies, beside the site tables.
2. `emit_arith_value`: a `simd` operand type dispatches to
   `emit_simd_binop` first — the compound spelling's one line (DEF-39). The
   compound path's own shift pre-guard is `TY_INT`-gated and stays.
3. `emit_simd_method`, `sum` over integer lanes: every fold step is
   `emit_arith_value(x, OpPlus, elem, acc, e_i, elem, n.span, id.index)`
   — the scalar `+`, guards included; float lanes keep `fadd`.
4. `reach.npk`: the expression and compound `IntOverflow` gates read a
   `simd`'s element kind (as the division gates do since DEF-37); the
   `ExprMethodCallExpr` arm sets `saw_ovf` for `sum` on a `simd` receiver
   with an integer element (`intern_get(x.interns, n.payload =>! int32)`
   is the name, as the emitter reads it).
5. `smt_encode.npk`, `assign_ident`'s `simd` branch: `/=`/`%=` record
   `record_division_lanes` over the binding's current lanes and the
   right-hand side's, `<<=`/`>>=` `record_shift_lanes`, both at
   `target.index`; then the fresh opaque set as now. The non-identifier
   target branch records the same rows over opaque lanes for a `simd`
   place type.
6. Tests. Programs: `simd_ovf_add.npk` (exit 93 through `(IntOverflow)`),
   `simd_ovf_mul.npk` (93), `simd_ovf_sum.npk` (93: lanes that fit, a
   fold that does not), `simd_ovf_edge.npk` (exit 0: `INT_MAX + 0`,
   `INT_MIN - 0`, unsigned `0 - 0`, a sum at the bound, lane values
   checked — no false trap), `simd_compound.npk` (DEF-39: every `op=` on
   integer lanes and `+= -= *= /=` on float lanes, lane values checked,
   exit 0), `simd_compound_trap.npk` (`v /= simd(0i32)`: exit 91 through
   `(DivByZero)` — the compound path carries the guard). Rejection:
   `reach_simd_ovf.npk` (a `simd` `+` and a `.sum()`, no `(IntOverflow)`
   arm: REACH-002). Verify: `simd_compound_rows.npk` (`v /= simd(k)` under
   a `limit` on `k`: `div-zero discharged 1`, `div-min discharged 1`; `v
   <<= simd(3i32)`: `shift-range discharged 1`; the elided build runs — the
   compound rows and their elision, belts included). Every root the built
   checker refuses for a missing `(IntOverflow)` arm gains it.
