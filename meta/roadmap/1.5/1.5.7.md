## 1. Where it starts (measured 2026-09-17 on `c609350`; this machine, five harnesses running beside it)

- **The seam is a TEXT TRANSFORM of the real floor, and its totality is a count.** A scheduling point before every
  atomic step line (`atomicrmw`, `cmpxchg`, `fence`, `load atomic`, `store atomic` — `line_is_step`'s own definition,
  `npkg/floor_model.npk`) and every `@npk_sys6(` CALL routed to the shim: **141 sites = 78 atomic (6 `cmpxchg`, 8
  `atomicrmw`, 39 `load atomic`, 25 `store atomic`) + 63 syscall sites over 27 numbers**, in 63 of the floor's 175
  functions — exactly the census, so "no step escapes" is an equality both runners can hold. Thread lifecycle is four
  hooks: before and after the `npk_clone_raw` call, first in `npk_thread_entry`, before its `ret`.
- **Real clone'd threads under a BATON work with the floor as it is.** One thread runs; the rest sit in a real private
  futex wait inside the shim. `%fs`, the per-thread constants and the clone trampoline stay the real ones.
- **Only what BLOCKS needs virtualizing:** futex WAIT/WAKE (virtual queues, longest-blocked first), `epoll_pwait` (a
  real poll with timeout 0 under the baton; a blocked waiter is re-probed only after another thread stepped — so
  eventfd, pipes and the one-shot registrations stay REAL and deterministic), `clock_gettime` (a VIRTUAL CLOCK: +1 µs
  per read; a jump to the earliest pending deadline when nobody can step). Thread exit: the kernel's CLEARTID write
  and wake are invisible to virtual futexes — a joiner blocked on a word holding the tid of a thread that has ENDED
  does a real wait for the kernel's clear and returns 0. Everything else passes through after its point.
- **EXACT REPLAY:** the same seed gives the same step count and the same schedule hash (`mutex_basic`, seed 1 twice:
  1,314 steps, one hash); different seeds differ. Decisions depend on the seed, slot indices and step counts — never
  on tids, addresses or wall time.
- **RATE:** `mutex_basic`, 300 schedules of ~1,300 steps in 0.83 s (~360/s); the plain build takes 4.97 s for 40 runs.
  Virtual time makes every deadline path instantaneous: a schedule is ~45× CHEAPER than a stress run.
- **THE SWEEP: 35 of the 44 `// stress:` programs explore correctly, 100 seeds each, 0.1–4 s per program.** The other
  9 need fixtures or argv (the six driver programs, `extern_c_driver`, `extern_stub`, `proc_tool`): real CHILD
  PROCESSES, which a virtual clock cannot coexist with (§2.8).
- **The trap route needs VIRTUAL SIGNALS, and they work:** record the handler at `rt_sigaction`; `tgkill` marks the
  target; the target runs the handler in its own context at its next grant, and a virtually BLOCKED target is made
  runnable (a signal interrupts a blocking call). `trap_two_threads`, `windup_thread`, `trap_stops_runner`,
  `failsafe_alloc`: 0 of 30 → 100 of 100.
- **PCT NEEDS A FAIRNESS RULE AND ORDERED PRIORITY BANDS.** A thread that never blocks ("write a byte until another
  thread stops me") starves everyone behind it under strict priorities, and virtual time never advances because it
  never reads the clock: a hang in REAL time. The rule that fixed it: after F consecutive steps while another thread
  could step, the runner drops below everything — and the bands are ordered *initial > change-point > demotion, each
  demotion below every earlier one*. (The first attempt tied the demoted threads and livelocked differently; the dump
  that showed it: two threads at change-point priorities 1 and 2, READY forever behind a spinner whose 700 demotions
  were all still above them.)
- **A LOST WAKEUP IN THIS RUNTIME IS MOSTLY *LATENESS*, WHICH AN EXIT CODE CANNOT SEE — and virtual time hides it
  completely.** Every wait carries a deadline (D-071), so an executor that misses its wake sleeps until the next
  deadline and the program still exits right, late. Planted: `npk_ch_wake_one` stamps the task due and never rouses
  its executor (r6's "absorbed notification", tokio#2057). With a QUIESCENCE ORACLE — *virtual time may jump only
  when no blocked thread's executor holds a task stamped due* — the explorer says `LOST WAKE` at seed 1, 142 steps,
  naming both threads and their deadlines. (§1's last bullet has the comparison numbers.)
- **A MODEL'S CONTROL IS NOT ALWAYS A FLOOR BUG.** `park-unpark`'s `drop-second-sweep` applied to the floor (the second
  `npk_sl_wake_due` of `npk_step` deleted): 0 failures in 1,800 explored schedules and 360 stress runs — and reading
  says why: `npk_sl_earliest` reads the stamp the sweep would have found, so the park's deadline is already past and
  it returns at once. The floor defends that window twice; the model mutates one of the two. So each control is
  MEASURED against the floor, and the ones that are not floor bugs are recorded with their reason (§2.6).
- **THE SPEC'S HYPOTHESES, EXECUTED, WOULD HAVE FOUND E-1's FALSE CLAUSE ON THE FIRST CALL** (two checks written by
  hand into the prototype to measure §2.4's idea; the 35 programs, one schedule each): `npk_small_free` was called
  5,276 times — the clause 1.5.6 wrote (unconditional apartness of the chunk, its neighbours and the partial head) was
  FALSE ON 5,276 OF 5,276 CALLS, and 1.5.6c's `apart-when` clause on none; `npk_rq_push`'s three-way apartness held on
  1,424 of 1,424 calls. Reading found that clause after a year; a checker at the symbol's entry finds it in the first
  millisecond of any program that frees a small block — and it checks the callers no row covers.
- **A shallow planted bug for scale:** `futex-mutex`'s `store-release` (`npk_mx_unlock`'s exchange → a plain store, no
  wake): explorer `DEADLOCK` at seed 1, 268 of 300 seeds, 0.9 s; stress 29 of 40 runs fail (exit 91) in 59 s.
- **THE COMPARISON THAT DECIDES S-81** — the absorbed notification planted (`npk_ch_wake_one` stamps and never
  rouses), the same buggy floor under three instruments (explorer: 100 seeds; stress: 10 plain runs):

  | program | explorer + the oracles | explorer, exit code only | `// stress:` |
  |---|---|---|---|
  | `thread_root_wake` | 100/100 `LOST WAKE`, seed 1, 0.2 s | 100/100 (exit 43: its own `DeadlineExceeded`) | 10/10 bad, 230 s |
  | `channel_threads` | 99/100, seed 1, 0.3 s | 35/100, first at seed 2 | 3/10 bad, 5.5 s |
  | **`nested_wait`** | **100/100, seed 1, 0.2 s** | **0/100** | **0/10 — every run exits right, 1.5 s late** |
  | `channel_cross` | 0/100 | 0/100 | 0/10 (the path is not exercised) |

  `nested_wait` is the case: the bug is there on every schedule and NOTHING but the oracle sees it. On the clean
  floor both oracles are silent over 35 programs × 100 seeds (no false positive), and they turn the shallow control's
  bare `DEADLOCK` into `LOST FUTEX WAKE (a waiter's word changed and nobody woke it)`.

## 2. The design

### 2.1 The explored build is the REAL floor, transformed
`npkg/explore.npk` (and `tools/explored.npk`, the harness's entry to the same functions, snapshot-built as
`tools/floorspec.npk` is — named `explored` at step 0 because a program cannot hold two modules named `explore`,
1.5.2d's `prelude_names` lesson): text in, text out. Before every step line `call void @npkx_point(i32 SITE)`; every
`@npk_sys6(` call becomes `@npkx_sys6(` (same signature); `@npkx_prespawn()` / `@npkx_spawned(i64 tid)` around the
clone call; `@npkx_begin()` first in `@npk_thread_entry`, `@npkx_end()` before its `ret`; the declares appended; a
`sites.txt` (site, function, kind, text) beside it. `module asm`, `@npk_sys6`'s own body and declarations are left
alone. **THE TOTALITY BELT, both runners:** the number of step lines in `runtime/npkrt.ll` (the model belt's
`line_is_step`) equals the number of points plus routed calls in the transformed text, and no step line in the output
lacks its point — `explore-step-escapes`, by name. ONE transformer (as the floor has one translator); the belt is the
second reader, and it is a count.

### 2.2 The shim: `runtime/explore/npkx.ll`, hand-written LLVM IR
Test infrastructure, linked into explored test binaries only, under the floor's own belts (the `undef` ban, D-173
and the stack rule, the zero-dependency scan). NOT Nitpick, by construction and not by taste: the shim needs mutable
module state (D-211 gives a program none), runs INSIDE the floor's critical sections (so it may not allocate, trap
or call the floor), and must not itself be transformed. Contents, each measured in the prototype: 64 slots (state,
tid, priority, futex word, virtual deadline, wake reason, pending signal, executor); `npkx_point`; `npkx_sys6` (futex
WAIT/WAKE/WAIT_BITSET, `epoll_pwait`, `clock_gettime`, `rt_sigaction`, `tgkill`, `exit`, `exit_group`; the rest pass
through after a point); the lifecycle hooks; the scheduler — PCT (depth d, d−1 change points over k steps) with the
three ordered priority bands and the fairness bound F, or a uniform random walk; the virtual clock; xorshift64* from
the seed; an FNV schedule hash; the verdicts (§2.3), each printed with the seed and every slot's state, and ended
with `exit_group(97)`. Parameters by environment (`NPKX_SEED`, `NPKX_POLICY`, `NPKX_D`, `NPKX_K`, `NPKX_FAIR`,
`NPKX_BUDGET`, `NPKX_TRACE`), read once from `/proc/self/environ`.

### 2.3 The verdicts — an exit code is not enough
Per seed: the program's exit equals its `// expect-exit:`; and none of: **`DEADLOCK`** (nobody can step, no deadline
pending, a thread lives); **`LOST-WAKE`** (at quiescence — before virtual time may jump — a blocked thread's executor
holds, on its sleeper list, a frame stamped due: the models' `wake-before-sleep`, `absorbed-notification` and
`spent-marker`, read off the REAL state); **`LOST-FUTEX-WAKE`** (at quiescence a virtual waiter's word no longer
holds the value it waited on: every futex protocol of the floor is "wait while the word is v; whoever changes it
wakes"); **`STEP-BUDGET`** (a livelock the fairness rule did not break). A verdict is a red run by name, with the
replay line (`NPKX_SEED=… NPKX_K=… <binary>`). The quiescence oracles read three offsets of `%npk.exec`/`%npk.hdr`
(sleeper head, `qnext`, `wake_at`): the shim's copy of them is held to the floor's struct types by a belt.

### 2.4 The spec's hypotheses, EXECUTED (1.5.6c's TCB.md §4d, tested instead of argued)
For every section that has rows and a caller assumption (31 today), the transformer emits, at the symbol's entry in
the explored floor, a call of a GENERATED checker (`@"npkx.req.<symbol>"`, IR text written by the tool from the
spec's own S-expressions): each `requires` with no free symbol, each range's address-space bound, and each pair
fact of `(objects …)`/`(views …)` — with `apart-when`'s condition and the null/empty rule exactly as
`objects_facts` states them — evaluated over the ENTRY state (parameters, `load8/16/32/64`, `+ - * mod ite`,
comparisons, the per-thread constants by their own calls). A false one is the verdict **`ASSUMPTION <symbol>:
<clause>`**. A clause the generator cannot evaluate (a free symbol: `npk_small_free`'s sorted-table `requires`) is
LISTED BY NAME in the stage's output and in TCB.md — never skipped in silence. This is what turns §4d's two "NOT
PROVED" columns into "checked at every call of every explored schedule", for untranslated floor callers and emitted
code alike.

### 2.5 Units, markers, the stage
A program opts in with **`// explore: N`** (N seeds; optional `d=…`), or out with **`// explore: no <reason>`**; a
belt in both runners holds every `// stress:` program to one or the other (`explore-unmarked`). `stage = "explore"`
in `nitpick.toml`'s `[[test]]` table (D-238). Per unit: compile, transform the program's IR too (§2.7), `llc`, link
against the explored floor and the shim; a measuring run (seed 0, no change points) gives k; seeds 1…N under PCT;
**the first seed is run TWICE and the two schedule hashes must agree** (`explore-replay-differs`: nondeterminism in
the explored build is a defect of the instrument); one verdict line per unit for `parity`. A seed that ever failed
is committed beside the marker as `// explore-seed: S` and runs first, forever.

### 2.6 Negative controls: the instrument must FIND what is planted
`runtime/explore/controls/<name>.ctl`: a text substitution on `runtime/npkrt.ll` (the exact old lines, the new
lines), a program, the verdict it must produce and within how many seeds. Both runners build the patched floor and
REQUIRE the verdict (`explore-control-blind` otherwise — the models' rule, for the explorer). Landed with the
mechanism: `store-release` (DEADLOCK, `mutex_basic`, seed 1) and `no-rouse` (LOST-WAKE, `thread_root_wake`, seed 1).
Then ALL NINETEEN model controls are walked: each becomes a control, or is recorded in
`runtime/explore/controls/README.md` as NOT A FLOOR BUG with the reason and the measurement (`drop-second-sweep` is
the first: `npk_sl_earliest` sees the stamp) — which is also a finding about the model, recorded in its file.

### 2.7 Program-level atomics
`atomic<T>` lowers inline in the PROGRAM's IR; the same transformer runs over each unit's emitted IR (points before
its atomic lines; its own `@npk_sys6` calls routed). The shim's module is never transformed.

### 2.8 What is NOT explored, and says so (TCB.md, generated where it can be)
Programs with real child processes (a virtual clock cannot coexist with a real child's real time: the nine, each
`// explore: no real child processes`); WEAK MEMORY — the baton serializes, so every atomic is explored as
`seq_cst` and an ordering bug in a `release`/`acquire` pair is invisible here (r6: loom's territory; the models and
D-290's shared-state belt are what speak to it); the clone trampoline and the asm bottom; schedules beyond the
seeds — PCT's guarantee is 1/(n·k^(d−1)) per run for a depth-d bug, which the stage prints per unit from its
measured n and k.

## 5. Decisions taken at planning (each with its reason)
- **X-1 — the explored floor is a TRANSFORM of the real one, never a second floor.** A mock floor that re-implements
  the primitives explores the mock. The transform adds calls and renames one callee; every instruction the artifact
  runs is the instruction explored (at `seq_cst` — X-8).
- **X-2 — the shim is hand-written IR** (S-78). Nitpick cannot express it: no mutable module state (D-211), and code
  that runs inside the allocator's and the scheduler's critical sections may not allocate, trap or call the floor.
- **X-3 — virtualize only what BLOCKS** (futex WAIT/WAKE, `epoll_pwait`, the clock) and the two things the kernel
  does behind the floor's back (CLEARTID at thread exit, signal delivery). Everything else is the real syscall after
  a point: eventfd, pipes and one-shot epoll registrations stay real and are deterministic under the baton. Measured:
  35 programs run unmodified.
- **X-4 — PCT (r6: a per-run guarantee of 1/(n·k^(d−1)) for a depth-d bug), d = 3 by default, with three ORDERED
  priority bands and a fairness bound F = 4,096** (measured: without them two programs hang in real time). A uniform
  random walk stays available by environment for comparison; it is not what the stage runs.
- **X-5 — k comes from a measuring run** (seed 0, no change points) per unit, so the change points fall inside the
  schedule and nobody maintains a number by hand.
- **X-6 — verdicts have NAMES and an exit code is not enough** (S-81): measured — a lost wakeup in this runtime is
  lateness, and virtual time hides lateness completely.
- **X-7 — the replay check is a standing belt, not a debugging aid:** the first seed of every unit runs twice and the
  hashes must agree. A nondeterminism source that creeps into the explored build is found the day it arrives.
- **X-8 — what the baton cannot see is SAID, not implied:** weak-memory behaviour (every atomic is explored as
  `seq_cst`), real child processes, the asm bottom, and everything past the seeds. TCB.md carries the sentence; the
  stage prints PCT's bound per unit from its measured n and k.
- **X-9 — one transformer, and a COUNTING belt as its second reader** in both runners. (1.5.6b's lesson was a model
  with one reader; the answer there was a second implementation because the semantics were rich. Here the property
  that matters — no step escapes — is an equality of two counts.)
- **X-10 — a model's control is MEASURED against the floor before it is a negative control** (`drop-second-sweep` is
  not a floor bug), and what is not one is recorded with its reason: it is a fact about the model.
- **X-11 — a failing seed is kept:** `// explore-seed: S` beside the marker, run first on every run. A schedule that
  found a defect once is the cheapest regression test the project will ever own.
- **X-12 — the explorer COMPLEMENTS `// stress:`** (D-212's words): stress runs the real clock, the real kernel
  scheduler and weak memory on real cores; the explorer runs the interleavings stress never reaches. Neither marker
  implies the other's removal.
- **X-13 (added at step 1, 2026-09-18) — the ADDRESS SPACE is virtual, as time is.** The port of the shim to IR
  found that the C prototype did not replay exactly under machine load: `npk_chunk_new` over-maps 128 KiB and trims
  to 64 KiB alignment, so whether its pre-trim `munmap` happens depends on the alignment of `mmap`'s answer — an
  ADDRESS decided a step count, and with it every later PCT change point and the schedule hash (`channel_owning`
  seed 1: 2,648 steps in one run of eight, 2,649 in the rest, either shim, under a twelve-process load). §1's "exact
  replay" had been measured on one program whose mappings happened to align every time. Both shims now place an
  anonymous private mapping with no hint at a bump pointer (16 TiB, below every randomized mapping and above the
  static image; 64 KiB-aligned so the allocator's trims are the same on every run and every machine) with
  `MAP_FIXED_NOREPLACE`; a collision moves the pointer 1 GiB and retries, deterministically; a hinted, fixed or
  file-backed mapping passes through. The floor has exactly two anonymous `mmap` sites (`npk_hmap`, the `wildx` map),
  both with a null hint. The lesson for X-7: the replay belt (one seed twice, back to back) would not have caught
  this reliably — the two runs would have seen the same alignment more often than not — and a sweep under LOAD did;
  D-303's hash-for-hash measurement is what surfaced it, on the second day of the port.

## 6. What the executor should know
- THE PROTOTYPE IS THE BEHAVIOURAL SPEC of the shim until the IR exists: `meta/roadmap/1.5/tools/explore_prototype/`
  (`transform.py`, `npkx.c`, `build.sh ROOT PROGRAM OUT [FLOOR.ll]`, `sweep.sh ROOT OUT SEEDS`; D-303 — outside every
  gate, built by nothing that ships). Build a unit by hand:
  `npkc prog.npk > prog.ll`, `llc` with the pinned flags, `ld.lld -static prog.o npkrt.explore.o npkx.o`; run with
  `NPKX_SEED=… NPKX_TRACE=1` under `(ulimit -n 1024; …)` and with stdin from `/dev/null`.
- A checker or an oracle that needs one of the floor's `internal` globals gets its ADDRESS as an argument from the
  call the transformer inserts — the inserted call is inside the floor's module and can name it; the shim cannot.
- The spec's integers are mathematical: evaluate a hypothesis in i128 (`2^64` is a spec literal), zero-extending
  parameters and loads; `mod`/`div` on i128 call `__umodti3`/`__udivti3`, which the floor exports. A load whose
  address is below 4096 reads as 0 (the null page is never mapped: a list walked past its null end — `npk_ch_wait_
  unlink`'s nine waiters — must not fault the checker; the spec's own convention is that a null range is no object).
- The three priority bands must stay ORDERED (initial > change-point > demotion, each demotion below the last) — the
  first fairness patch tied the demoted threads and livelocked; the dump format that showed it (every slot's state,
  priority, last site, pending signal) is worth keeping in the IR shim's verdict output.
- A thread the explorer never schedules again after `tgkill` still runs its handler: the target of a virtual signal
  is made runnable if it was virtually blocked, and the handler runs in ITS context at its next grant.
- `printf` with IR text in a shell script dies on `%a`/`%r` having written nothing; a background waiter that
  `pgrep -f`s a pattern its own command line contains waits for itself, and a `pkill -f` kills itself (use a
  character class: `x_dee[p]`). Both cost this planning session a command.
- Real time under exploration is a smell: a run that takes seconds is a thread spinning without reading the clock
  or blocking (the fairness rule's case) — dump it with a small `NPKX_BUDGET`, do not wait for it.
- (Step 0's lessons.) A helper named `site_line` is refused: it is a builtin's name (D-294) — the snapshot, older than
  the rule, compiled `tools/explored.npk` with it and the compiler under test refused `npkg`. A program cannot hold two
  modules of one basename (the `prelude_names` lesson), so the tool is `explored`. The plan's record must be IN the
  tree the harness runs on (D-228): write the record, then launch.
