  a bare `fptosi`/`fptoui`; `emit_simd_cast`'s float→int arm likewise. LLVM: "If the value cannot fit in ty2, the

  if (i > 0i32) { exit 4i32; } exit 5i32;`): **exit 3 at the pinned `-O0`, exit 9 after `opt -O2`** — `main`'s

- **DEF-59, the uncontrolled stack stop.** The floor installs exactly one signal action, SIGUSR1's
  (`npkrt.ll`'s `npk_start`, `rt_sigaction(10, …)`, flags SA_RESTORER alone). A stack overflow is SIGSEGV with the

  8192` ok, `4096` ok, **`2048` exit 139, `1024` exit 139** — the compiler needs between 2 and 4 MiB of the
  kernel's stack, and past it dies uncontrolled. The main thread runs on the KERNEL's stack, so how deep a program
  may recurse is the SHELL's decision today.
- **DEF-60, the stack clash.** `llc -O0 -stack-size-section` over `build/npkc.ll`: 3,192 functions; 456 frames
  above 1 KiB, **151 above 4,096 bytes**, 69 above 8 KiB, 29 above 16 KiB, 2 above 64 KiB — the largest
  `npk.ir_expr.emit_expr_kind` at 120,904 bytes, then `call_builtin` 82,104 and `emit_arith_value` 54,952

- **LLVM's split-stack prologue, under the pinned `llc`** (`"split-stack"` function attribute; both levels):

## 2. The design

### 2.1 Four identities, one refresh (step 0)

`CastRange = 4117`, `StackExhausted = 4118`, `DecreasesViolated = 4119`, `MachineFault = 4120` join the
prelude's system family together, each with its one-line comment, so ONE snapshot refresh carries all four and no
later step needs another for an identity (K-1). Nothing arms them at step 0: each arms with its mechanism — `CastRange`
at step 1, `StackExhausted` at step 2, `MachineFault` at step 3, `DecreasesViolated` at 1.5.8c.

**Every `failsafe` REACH checks names `(StackExhausted)` and `(MachineFault)` from step 0** (K-2) — before they
are reachable, because REACH accepts an arm nothing reaches and because the two will be reachable from EVERY
program: one sweep now instead of two later. Written unqualified (`types/rejection/error_arms.npk` refuses a
qualified system name), exiting what the `(*)` arm exits unless the file gives each identity its own code, in
which case the next two unused codes of that file. The four pre-REACH rejection suites are not swept (their
verdicts are decided before REACH, and an edit moves their expected positions: `release_then_exit.npk`'s
`expect-error-at: 35:5`). `analysis/rejection/failsafe_exit.npk`'s arm above `(*)` is its test case (`exit 0i32 -
1i32`) and is not copied. `conformance/nf_twin` changes identically in both twins (their IR is compared byte for
byte). Each `tests/verify/` file's `failsafe-post discharged N` becomes N+2, and each runner's self-check failsafe
texts gain the two arms with their counts (10 → 12, 9 → 11) in both runners at once.

**The refresh is the bridging variant** (`bootstrap/seed/README.md`, K-3): the prelude gains names that roots the

### 2.2 `CastRange` and the 128-bit conversions (step 1; D-306, DEF-58, DEF-61)

**The guard** (both the scalar arm of `emit_cast` and `emit_simd_cast`'s lanes): the operand widened to `double`
(`fpext`, exact) and tested with ordered compares — `fcmp ord`, then `fcmp ogt d, LO` and `fcmp olt d, HI`:

| bound | signed N-bit target | unsigned N-bit target |
|---|---|---|
| LO | `fcmp ogt d, -2^(N-1) - 1` while that is a `double` (N ≤ 53); `fcmp oge d, -2^(N-1)` while that is (N ≤ 1024 — no `double` lies strictly between the two); past `double`'s range, `fcmp ogt d, -inf` | `fcmp ogt d, -1.0` |
| HI | `fcmp olt d, 2^(N-1)` while that is a `double` (N ≤ 1024); past it, `fcmp olt d, +inf` | `fcmp olt d, 2^N` while that is a `double` (N ≤ 1023); past it, `fcmp olt d, +inf` |

The result is one `i1`; the elision test `llctx_elided(ctx, SITE_EXPR(), site, OK_CAST_RANGE())` is written like
the shift guard's (it answers false until 1.5.8b records rows); otherwise `br i1 ok, label %cr.ok, label %cr.bad`,
the bad block `npk_chain_reset(i32 SITE)`, `npk_trap(i32 -4117)`, `unreachable` — `emit_shift_guard`'s exact shape.
A `simd` operand compares lane-wise at vector type and folds the lanes to one `i1` by the extract chain the other
any-lane guards use (no reduction intrinsic: nothing becomes a libcall). REACH arms `CastRange` where the walk sees
a cast whose source is a float (or a `simd` of floats) and whose target is a plain integer (or a `simd` of them) —
the twisted families' entering casts keep their own ERR-absorbing guards and arm nothing new.

**The conversions** (K-4): at N ≤ 64 the instruction itself (`fptosi`/`fptoui`/`sitofp`/`uitofp`, native on
x86-64 or expanded inline). At N > 64 the emitter lowers BOTH directions by hand, in integer arithmetic, and never
writes an LLVM conversion at a width the target lacks — `opt -O2` proved it will narrow an `i256` route back to an
`i128` libcall, so no route through LLVM's own wide conversion is trusted:
- float → N-bit integer (after the guard, so the truncation fits): `bitcast` the `double` to `i64`; the biased
  exponent `e` and the significand `m` (the implicit bit restored); `k = e − 1075`; `m` zero-extended to `iN`, then
  `shl k` for `k ≥ 0` (the guard bounds `k < N − 53`) or `lshr −k` for `k < 0` (0 when `−k ≥ 64`: every shift
  amount is held below its width, D-277's rule); the sign applied by `sub 0, x`.
- N-bit integer → float: the magnitude (a signed operand's `sub 0, x` under a `select`, computed in the unsigned
  view so `MIN`'s magnitude fits); `lz = ctlz(mag)` (an intrinsic LLVM lowers inline at every width —
  measured at implementation, and the `-O2` leg's zero-dependency scan holds it); zero and
  `bits − lz ≤ 64` take `uitofp i64` directly; otherwise `s = bits − lz − 64`, `t = trunc(mag >> s)` with the
  STICKY bit — `(mag & (2^s − 1)) != 0` — OR'd into `t`'s lowest bit, `uitofp i64 t` (rounds once: `t` carries
  eleven bits past the significand, so the sticky bit decides ties exactly as the full value would), then scaled
  by `2^s` as an exact multiply by a power-of-two constant for `s` within the format's exponent range and as the
  infinity past it (an `s` that puts the value at or above `2^1024` — `2^128` for `flt32` — is infinite under
  round-to-nearest); the sign reapplied. Known-answer vectors from Python's exact rationals over the edges (the
  powers of two, the halfway points either side of each rounding boundary, `MIN`, `MAX`, `2^53 ± 1`,
  `2^64 ± 1`) at `int128`, `uint128` and `int256`, both floats.

### 2.3 The stack (step 2; D-305, DEF-59, DEF-60)

**Emitted code.** Every `define` the compiler writes carries `"split-stack"` after its parameter list — all nine
sites, the prelude's bodies, the drop bodies and the generated helpers included (one rule: every emitted function).
A `define` never runs before the thread's limit word exists: the first emitted call on a thread is `main` (after
`npk_start`'s setup) or a resume function (after `npk_thread_entry`'s).

**The floor** carries `.note.GNU-split-stack` in a `module asm` section, and defines `__morestack` (enters the
trap route as `StackExhausted`, −4118) and `__morestack_non_split` (traps `Unreachable`, −4102: reachable only
through ld.lld's cross-split rewrite, which the note rules out and the closed-world link (D-206) cannot admit).
Both are `module asm` stubs that realign the stack to 16 and call into IR; neither returns. The floor's functions
never carry the attribute: they run before `%fs` exists, inside signal handlers on signal stacks, and inside the
trap route.

**The note is a claim, and a belt holds it** (K-8): "the floor's stack use fits in the reserve" — from
`llc -O0 -stack-size-section` over the floor and its call graph (`floor_shared.npk`'s `floor_calls`, the
harness's `calls_of`), the deepest chain of floor frames, plus one repetition of each trap-route cycle (the
re-entry rule bounds it), plus the 256-byte leaf slack and the 128-byte red zone of an emitted leaf above it, must
be at most a QUARTER of the reserve (16 KiB); a chain that reaches an indirect call stops there (a resume function
is emitted and checks itself; JIT code is `wildx`'s, TCB.md §5). `floor-stack-reserve` in both runners, with a
planted self-check case over a toy floor whose chain is known.

**Every thread's stack is the floor's, one mapping each** (K-6), lowest address first:

| region | size | main thread | spawned thread | failsafe |
|---|---|---|---|---|
| guard (PROT_NONE) | 4 KiB | yes | yes | yes |
| signal stack | 64 KiB | yes | yes | — |
| guard (PROT_NONE) | 4 KiB | yes | yes | — |
| reserve (below the limit word) | 64 KiB | yes | yes | yes |
| usable | — | 8 MiB | 2 MiB (unchanged) | 1 MiB |

`npk_start` maps the main thread's stack and the failsafe stack through `npk_hmap` (so the explorer's virtual
address space places them deterministically), sets both guards with `mprotect`, writes the limit word, registers
the signal stack (`sigaltstack`, 131), installs SIGUSR1 with SA_ONSTACK added, and SWITCHES to the new stack
through a `module asm` trampoline that calls the rest of startup (`npk_start_main`: argv, `main`, `npk_exit`) and
never returns — `argv`, `envp` and `auxv` stay where the kernel put them. `npk_thread_start` maps the larger
mapping, writes the CHILD's limit word and signal-stack base into the child's TLS block BEFORE the clone (K-7), and
`npk_thread_entry` registers the child's signal stack as its first act (a routed step after `npkx_begin` in the
explored build). The kernel checks a signal stack against the machine's minimum (`sigaltstack` fails with ENOMEM
below it): a failure is a startup trap, so the assumption that 64 KiB holds the machine's signal frame is CHECKED
on every machine that runs a program (K-10).

**The TLS block grows to 120 bytes** (K-7): `%npk.tls = type { ptr, ptr, ptr, ptr, i32, i32, ptr, [8 x i64], i64 }`
— the five fields as today, a pad, the signal-stack base at 0x28, reserved words, and the LIMIT at 0x70, where
LLVM's prologue reads it. Spawned blocks come from `npk_alloc_internal(120)` (class 128); the main thread's from
the same raw mapping. The spec's `%npk.tls` rows and the shared-state belt's field lists (`floor.py`,
`floor_shared.npk`) move with it.

**`failsafe` runs on its own stack** (K-9): `npk_trap`'s `call i32 @npk_failsafe(i32 %code)` becomes a call of
`@npk_failsafe_on_stack(i32 %code)`, an IR function whose body calls the `module asm` trampoline
`npk_fs_switch_call`: save the frame and the limit word, load `@npk_fs_stack_top` into `%rsp` and
`@npk_fs_stack_limit` into `%fs:0x70`, call `npk_failsafe`, restore both, return its result. The trampoline sits

### 2.4b Per-slot pools (step 3b; DEF-66) — written 2026-09-19, before the step, from what it measured

**Measured** (step 3's floor; the runners' `nofile` of 1024): a program that spawns and joins threads one after
another, each doing one short `io_ready` wait so that its executor creates its reactor, finishes 505 threads and
dies at 510 with `Unreachable`, the floor's integrity trap for "could not create the reactor". Every dead thread
kept its epoll set and its eventfd, and each also kept its 120-byte TLS block and its executor
(`npk_alloc_internal`, never freed).

**Why freeing at the join was wrong** (DEF-66's record, and one more reason found reading the reactor):
- The stop walk reads a published slot's TLS block without a lock.
- A stale waker holds an executor's address past its thread's exit, reads its eventfd (acquire) and writes to it.
  A closed eventfd's NUMBER can be reused by the next `open`, and the stale write then lands in an unrelated file.
- A wait that expires LEAVES its one-shot registration armed in the epoll set, carrying its frame's address ("a
  late fire dues whatever frame owns the slot then"). An epoll set reused by the next thread in the slot could
  fire an old incarnation's registration and write into a freed frame.

**The design:**
1. **Pools.** `@npk_tls_pool` and `@npk_exec_pool`, 64 entries each, one per registry slot, static and never freed.
   A spawned thread in slot i uses entry i of each. The main thread keeps its raw-mapped block and executor
   (`npk_tls_boot`), whose slot is never retired.
2. **The claim, split.** `npk_reg_reserve` takes a slot, 0 → 1 by `cmpxchg` (acq_rel); `npk_reg_publish(slot,
   tls)` stores the pointer word and then 2 (release). `npk_reg_claim` is the two, for the main thread.
   `npk_thread_start` RESERVES FIRST, so the slot names the pool entries before anything is written. A full
   registry traps −4103 as before. The pointer word is written and read ATOMICALLY (monotonic): a stale walker's
   read may meet the next incarnation's write of the same value.
3. **Rebirth before publish.** `npk_thread_start` rewrites every field of the pooled TLS block — the tid word
   (field 4) by an atomic store, since a stale walker may read it — and of the pooled executor:
   - the owner-only words (0–4, 8–10, 13) by plain stores;
   - the park word (5), which stale wakers set, by an atomic store of 0;
   - `join_ns`/`grace_ns` (6, 7), born before publish;
   - the epoll descriptor (11), left at 0 by the join;
   - the eventfd (12), KEPT.

   No waker of the NEW thread can exist before the publish. A stale waker's rouse after the rebirth is a spurious
   wake, which the clear-then-recheck protocol tolerates.
4. **The join releases what only the thread owned.** Once the kernel has cleared the tid word, it retires the
   slot, unmaps the stack (DEF-65), CLOSES the epoll descriptor and stores 0 over it. The descriptor is owner-only,
   no other thread holds it, and closing it removes every registration still armed in it. The eventfd stays open
   with the pooled executor. At most 64 ever exist, so stale rouses always land on the eventfd they meant.
5. **The reactor's creation, split.** `npk_io_register` creates the epoll set when field 11 is 0, and the eventfd
   only when field 12 is 0, then adds the eventfd to the new set. A reused executor gets a fresh set around its
   kept eventfd.
6. **The evidence.**
   - The spec: the rows for `%npk.tls` 4, `%npk.exec` 5/11/12 and `@npk_thread_reg` restated for rebirth; the pools
     classified.
   - The models: `park-unpark` gains the executor's rebirth and a stale waker, whose rouse after the rebirth must
     reach no bad state. The stop walk's reading of a reused slot is argued in the spec beside the registry row:
     the walk reads only the atomic tid word, and a rebirth's zero is a skipped slot. A reborn thread published
     after the walk's scan parks at its first `npk_step`, which checks the frozen flag before resuming anything.
     *[2026-09-19, at implementation: the `park-unpark` half is NOT done, and here is why. Every bad predicate
     of that model is about a task's OWN wake (wake-before-sleep, absorbed-notification, spent-marker,
     wound-but-asleep). A stale rouse after a rebirth can only ADD a wake, to a task that did not ask for one,
     and no predicate of the model can express harm from that, so the extension would prove what it assumed.
     What can go wrong is memory and ordering: a stale waker writing a freed executor, or a racing plain
     access. Those are what the pools remove, and the spec's rows now state it word by word, each argument
     beside its word. The waker touches only the frame, under the channel lock, and then the executor's park
     word and eventfd. The walk touches only the tid word. The models name the reactor's new blocks, which the
     correspondence belt requires.]*
   - TCB.md's regions; the floor manifest re-recorded.
7. **Tests.**
   - `thread_reactor_reuse`: spawn and join 700 reactor-using threads under the runners' `nofile` → 0. Linked
     against step 3's floor it exits `Unreachable`.
   - `thread_block_reuse`: 5,000 spawned and joined threads without I/O, measured by maximum RSS before and after.
   - A reborn slot's stale waker: an explored program whose waker's rouse can land after a slot's rebirth.

## 5. Decisions taken at planning (each with its reason)

- **K-1 — the four identities are declared together at step 0**, each armed with its own mechanism later. One
  refresh instead of three, and REACH never claims a reachability before the mechanism that makes it true lands.
- **K-2 — the universal arms go in at step 0, everywhere REACH checks.** REACH walks the reachable set, so an arm
  ahead of its identity is accepted; sweeping once instead of at steps 2 and 3 halves the churn of 480 files, and
  the arms' presence changes no verdict until the identities arm. The pre-REACH rejection suites are not touched:
  their verdicts come first and their positions are asserted.
- **K-3 — the bridging refresh at step 0, not at step 2.** Step 2 arms `StackExhausted` for every program, the
  `selfhost` stage then demands the arm in `src/npkc.npk`, and only a snapshot that knows the name can build that
  file — so the refresh must precede step 2, and step 0 is where the names are born.
- **K-4 — above 64 bits, float↔integer conversions are hand-lowered in both directions.** Measured: `opt -O2`
  narrows the `i256` route back to an `i128` libcall. A lowering that depends on what the optimiser declines to do
  is the prototype's lesson (llvm-optimisation-can-remove-guarantees); integer arithmetic has no libcall to become.
- **K-5 — no runner table learns −4117 before its rows exist; `npkg`'s counted codes are derived, not listed.** The

  to compile itself, the conventional default), 2 MiB threads (unchanged), 1 MiB `failsafe` (D-292's region's size),

### Step 3b — per-slot pools (2026-09-19; DEF-66)

- **Measured first** (§2.4b): 700 reactor-using threads spawned and joined in turn died at 510 with `Unreachable`
  under the runners' `nofile` of 1,024, and every thread's block and executor stayed allocated. Under
  `NPK_HEAP_STATS`, 1,600 threads peaked at 371,304 bytes of live heap against 336 for one thread.
- **The floor:**
  - The pools `@npk_tls_pool` and `@npk_exec_pool`, 64 entries each, one per registry slot, static and never freed.
  - The claim is split into `npk_reg_reserve` (0 → 1, `cmpxchg` acq_rel) and `npk_reg_publish` (the pointer word,
    then 2 release). `npk_reg_claim` is the pair, for the main thread. The pointer word is read and written
    atomically (monotonic) everywhere, the stop walk and the retire included.
  - `npk_thread_start` reserves FIRST and rebuilds entry `slot` of each pool field by field. Owner-only words are
    written plainly, and the park word and the tid word atomically. The epoll word stays as the join left it, and
    the eventfd is kept.
  - The join unmaps the stack, closes the epoll set and stores 0, and only then retires the slot. 1b retired first
    and read the mapping afterwards, which with the pools would have been the next thread's.
  - `npk_io_register` creates the epoll set when its word is 0, and the eventfd only when its word is 0 (blocks
    `haveev`, `usekept`, `newev`), then adds the eventfd to the new set.
  - **Found by reading the first cut's readers, fixed:** `npk_park_sleep` decided "armed" (idle-wait in epoll
    rather than on the futex) by the EVENTFD's word. With the eventfd kept across rebirths, a reborn thread that
    had registered no descriptor waited in `epoll_pwait` on descriptor 0, which the kernel refuses at once. It
    spun until its deadline instead of sleeping: 260 `epoll_pwait(0, …)` calls in 20 ms, traced. "Armed" is now the
    epoll SET's word. Every rouse futex-wakes before it pings, so a futex sleeper hears it, and a ping into an
    eventfd no set holds is drained as a spurious wake by the next armed wait (dated notes in `park-unpark`).
- **The spec** (`runtime/npkrt.spec`, the shared section):
  - The executor's owner-only rows say "reborn before the publish, then the owner's alone".
  - The park word's row carries the atomic rebirth. Field 11 is `stated`: closed by the joiner after the kernel's
    clear and before the retire. Field 12 is kept across rebirths.
  - The block's word 4 carries the argument for a stale walk: the earlier tid (ESRCH), the rebirth's 0 (skipped)
    or the new tid (a live thread, which the walk should stop). Words 5 and 9 are classified, and
    `@npk_thread_reg`'s row is restated.
  - `@npk_tls_pool` is classified; `@npk_exec_pool` is a comment, since its address is stored and never handed to a
    call. `@npk_hsec`'s stated reason is corrected: the child's frame is the allocation that precedes every clone.
- **The models:** `reactor-io` and `park-unpark` name `npk_io_register`'s three new blocks (thirteen now), as the
  correspondence belt requires. The rebirth itself is NOT modelled, for the reason §2.4b's dated note gives: every
  bad predicate of `park-unpark` concerns a task's own wake, and a stale rouse can only add one.
- **Tests:**
  - `thread_reactor_reuse`: 700 reactor-using threads, 0 under the runners' limit; `Unreachable` (98) against step
    3's floor.
  - `thread_churn` and `thread_churn_one`: 1,600 and one thread, 0 each, held by `tests/cost/threads.toml`. The

### Step 3c — the standard descriptors, and the reactor's "none" (2026-09-19; DEF-69)

- **Measured first, on step 3b's floor** (OPEN_DECISIONS DEF-69). A program started with stderr closed got
  descriptor 2 for the first data file it opened, and the file then held the floor's `heap:` line after the
  program's data byte. A program that closed its own stdin got an epoll set numbered 0, and every reader of the
  executor's two reactor words took 0 for "no reactor". So a second registration made a second set (traced:
  `epoll_create1` = 0, then 4).
- **The floor:**
  - `npk_std_fds`, called by `npk_start` right after `npk_tls_boot`, because a refusal takes the trap route and
    the trap route reads the TLS block. For each of 0, 1 and 2: `fcntl(fd, F_GETFD)`. An open descriptor is left
    as it is. A closed one (EBADF) is opened onto `/dev/null` with `openat(AT_FDCWD, "/dev/null", O_RDWR, 0)`.
    That returns the lowest free number, which is `fd`, because every lower one is open by then. It is
    read-write and not close-on-exec, since the three are inherited. Any other answer traps −4102 before `main`
    runs: a failed probe other than EBADF, `/dev/null` missing or refused, or no room in the descriptor table.
  - "None" is −1 for both reactor words, at every site:
    - the main executor's initializer;
    - the join, which tests `>= 0` and stores −1;
    - `npk_io_register`, which tests `>= 0` for the set and for the kept eventfd;
    - `npk_park_sleep`, which is armed when the set's word is `>= 0`;
    - `npk_ch_wake_one`, `npk_windup_all` and `npk_io_unwatch`, which skip on a negative word.
    The executor type's comment keeps the old reasoning and says why it was wrong.
  - **The pool entries' −1 is STATIC, not a boot loop.** The DEF-69 entry had said "at boot, before any thread".
    But the eventfd word is atomic everywhere (D-290). Sixty-four atomic stores before `main` would have been
    sixty-four counted steps in every explored run, moving every schedule, which is DEF-67's cause. So
    `@npk_exec_pool` has a static initializer: sixty-four identical entries, every other word 0. It is defined
    below `%npk.exec`, because an initializer needs its named type's body above it (`llvm-as`: "initializer
    with struct type has wrong # elements" while the type was still a forward reference). The startup probe
    still adds three routed calls to every explored run (three `fcntl`s), as step 3's `npk_fault_arm` added
    five `rt_sigaction`s (the four fault signals and SIGPIPE). The controls were re-run over it (below).
- **The table:** the kernel-effect region gains `72 fcntl`, `none`, with the option set `arg2 in 1`. `F_GETFD`
  takes no address, and the option set keeps it that way (`F_GETLK` and its kin write a `struct flock`). No probe
  case: a call with no address argument has no memory to measure. `gen_tables.py` regenerated
  `npkg/floor_kernel.npk`.
- **The spec:**
  - a boundary section for `@npk_std_fds`;
  - `@npk_start`'s boundary names it;
  - the executor's words 11 and 12 say −1 (a static initializer's, and the join's store).
  - Both self-checks' `floor-parse` literal moves to 187 defines, with 95 syscall.
- **Tests:**
  - `std_fds_closed`: the program re-executes itself with descriptor 2 closed (fork, close, execve through

  - `reactor_fd_zero`: the program closes its own stdin, then checks three things:
