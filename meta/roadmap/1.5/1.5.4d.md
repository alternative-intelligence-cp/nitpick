# 1.5.4d — The file-module import's scope and the inline module's error identities (D-274, D-275)

**Planned 2026-09-10 on `1ef034a` by `nitpick-compiler_s4`; D-274 and D-275
were ratified the same day (S-49, S-50). Execution-grade: every decision the
two landings need is settled; the plan proceeds under two readings (R-3, R-4)
recorded for the user to veto, as 1.5.4c proceeded under R-1/R-2. One
question the planning found — S-51, imports inside an inline module — gates
step 0b alone and nothing else waits on it. Scheduled ahead of 1.5.4b, as
1.5.4c was: small, and the module system must not carry a known half-feature
into the theories work.**

## 1. Where it starts

Measured on `1ef034a` with the built checker (`quickcheck`), eight probes in
the planning session's scratchpad, each a whole program with the floor's four
arms:

- **S-49 / D-274.** `mod:plib;` after the header, then `raw plib.f()`:
  `NITPICK-TYPE-019` "module `plib` has no member `f`". The loader loads
  `plib.npk` (`graph_load_imports` → `graph_load_file_module`, module_graph.npk),
  collection declares `plib` as a module symbol and `collect_decl`'s module arm
  opens an EMPTY scope over its zero members (`collect_module`) and sets it as
  the symbol's `inner`; nothing ever connects the symbol to the entry the
  loader found. `module_apply_imports` walks `DeclImportDecl` items only. An
  alias's `inner` is set by `apply_one_import` (D-273 §4) and copied by
  `bind_or_report`/`bind_wildcard` when the symbol is bound elsewhere — a copy
  happens WHEN THE BINDING IS CREATED and never again (`symtab_bind_import`
  returns 0 for a repeat), so a file-module symbol's scope must be right
  BEFORE the import fixed point begins, or a wildcard re-export bound in round
  1 by a module earlier in the graph carries the empty scope forever.
- **S-50 / D-275.** `(hidden.Boom)` written alone for an inline module's
  constant: `NITPICK-REACH-002` "`failsafe` does not name
  `probe_arm_inline.Boom`" — the reach analysis demands the file-qualified
  arm (`reach_settle` matches a two-segment pattern by NAME PAIR against the
  reachable constant's recorded qualifier, which is the FILE's, since
  `reach_module` passes `cur_module` down into an inline module unchanged).
  Written BESIDE the right arm, `(hidden.Boom)` is silent; so are
  `(probe.Nosuch)` — a known file, a constant it never declares — and
  `(nosuch.Boom)`, a first segment naming nothing at all. The emitter's
  `pattern_const` (ir_stmt.npk) hashes the pair with an inline copy of the
  resolver's `error_code_of` and compares the selector against a code no
  constant has; the checker's `type_pick_bindings` types arms over `TY_ENUM`
  and `TY_STRUCT` selectors only, so no rule reads an arm over an `Error`;
  the resolver's `resolve_pattern` binds names and reads none.
- `use hidden.{Boom};` then `(Boom)`, and `use hidden.*;` then `(Boom)`: both
  silent and both satisfy the reach analysis (an error constant is implicitly
  `pub`, D-179 — `collect_decl` sets `SYM_PUB` on every `DeclErrorDecl`). The
  spelling D-275 recommends works today.
- **The pre-scan.** Every qualified arm in the tree — 23 distinct
  `(file.Name)` pairs across `src/`, `tests/`, `lib/`, `npkg/`, `tools/` —
  names a constant its file declares (`error:Name;` in `file.npk`). The
  prelude's 25 constants carry explicit codes except one: `pub error:BadPath;`
  hashes under `prelude` (`PRELUDE_PATH` is `prelude.npk`) and is nameable
  bare or as `(prelude.BadPath)`.
- **Found by planning (S-51).** Two probes outside the ratified scope, both
  silent until a later name fails: a `use "./plib.npk".*;` INSIDE an inline
  module binds nothing (`RESOLVE-002` "cannot find `f`" at the use — the
  import pass never enters an inline module), and a `mod:plib;` inside one
  loads nothing (`TYPE-019` "no member": the loader never enters one either).
  A third probe shows why it matters: an inline module cannot see its own
  FILE's imports (`scope_lookup` stops at the first module scope, and the
  file's `use` bindings live in the file scope), so today an inline module can
  reach nothing but the prelude and its own members, and the one construct
  that could change that is a silent no-op. Recorded as **S-51** in
  OPEN_DECISIONS §2e with the recommendation below.

The sites: `module_graph.npk` (`graph_load_imports`, `graph_load_file_module`,
`graph_collect_all`, `module_apply_imports`, `bind_or_report`, `bind_wildcard`),
`symbols.npk` (`collect_decl`, `SymbolTable`), `resolve.npk` (`error_code_of`,

## 2. What lands

1. **D-274 — the file-module import carries the loaded file's scope.**
   `graph_load_file_module` RECORDS which module entry it loaded for which
   declaration (a `FileModuleLink { decl, loaded }` list on the graph; the
   load already returns the entry's index, deduplicated by `graph_find`), and
   `graph_collect_all` ends with `graph_link_file_modules`: for every
   member-less `mod:name;` past a file's header slot, the symbol collection
   declared for that declaration gets `inner` = the loaded entry's scope.
   That is "set where the alias's is, from the module the loader found for
   it" — one `inner` field, one lookup (`module_symbol_scope`,
   `module_symbol_inner`), no third kind of module symbol — placed at the end
   of collection rather than in the import pass because every scope exists
   there and no import round has copied anything yet (§1's ordering point).
   `collect_decl` still opens the empty scope: it is REPLACED by the link, and
   it stays empty only when the load was refused (RESOLVE-004/-005 already
   reported), and no stage past resolution runs over a program with a
   diagnostic. Every existing reader — `nested_module_scope` in the resolver,
   the checker, the emitter's `emit_nested_module`/`emit_headers_in`, the
   analyses — descends into the declaration's ZERO members and is unaffected.
   `mod:util;` then `util.f()` means what `use "./util.npk" as util;` then
   `util.f()` means; `use util.*;`/`.{f}`/`.f` bind through D-273 §2's binder
   as through any module symbol in scope; a `pub mod:util;` re-exported by
   another file's wildcard import carries the scope across files.
2. **D-275 — the identities, and the arm checked at the arm.** An error
   constant declared inside an inline module is the FILE's (unchanged: the
   resolver hashes `error_code_of(r.module_name, name)` and the reach walk
   passes the file's name down), and a `pick` arm over an `Error` selector is
   CHECKED BY THE CHECKER, in `type_pick_rules` (both spellings, every pick
   over an `Error`, `failsafe`'s included), against the constants the program
   declares:
   - **R-3 (a reading of D-275, recorded for veto).** The qualified arm is
     checked as a PAIR, not the first segment alone: the pair's identity
     (`error_identity(qual, name)`, the one hash) must be the code of a
     constant some loaded file declares, else `NITPICK-RESOLVE-002` at the
     pattern. This implies the decision's first-segment check — a segment
     naming no module is refused because no constant hashes under it — and
     closes the two silent cases the decision's literal text leaves open,
     `(known_file.Nosuch)` and, decisively, `(hidden.Boom)` itself: `hidden`
     IS a module the program knows, and only a pair check refuses it. The
     message names the fix: when a declared constant carries the name, "`Boom`
     is declared in `mod_qualified` — write `(mod_qualified.Boom)`", with a
     note at each such declaration; when the first segment names a module
     symbol in scope whose scope holds an error constant of that name, "or
     `use hidden.{Boom};` and `(Boom)`"; otherwise "no loaded file declares
     `Nosuch`". A library that names another module's identity in a `pick`
     depends on that module and says so with an import (the bare form has
     always required one); the pre-scan found no qualified arm in the tree
     that names an unloaded file, and D-179's "no import needed" stays true
     for every arm `failsafe` is asked to write (a reachable constant's file
     is loaded by construction).
   - **R-4 (the twin spellings, recorded for veto).** Over an `Error`
     selector every arm is one of: `(*)`, a value pattern that is an
     identifier bound to an error constant (`(Boom)`, `(DeadlineExceeded)`),
     or the two-segment bind-free identity `(file.Name)`. Anything else —
     a literal, a global, a range, a struct destructure, a destructure with
     bindings or with one or three-plus segments, an `ERR:` arm — is
     `NITPICK-TYPE-007` at the pattern, "an `Error` arm names an error
     constant — `(Name)` or `(module.Name)` (D-179); an error carries no
     payload to bind". Today each of those reaches the emitter and dies as
     EMIT-002 (`pattern_const`'s `iv_broken`, the "walk hole" answer) — a
     compiler-defect report for a program mistake. One code for the shape
     family, one for the identity; the shape refusal returns before the
     identity is asked (D-240).
   - **One hash, one table.** `error_identity(InternTable->, qual, name)`
     lives in `intern.npk` beside `fnv1a_*`; the resolver's `error_code_of`
     and the emitter's inline copy in `pattern_const` both become calls to it
     (the "SAME function" the 1.4.2b comment promised, made literal). The
     resolver's `ecodes`/`edecls` move onto the `SymbolTable` as
     `error_decls`/`error_quals`/`error_codes` (ALL THREE, ALWAYS; the
     collision refusal RESOLVE-010 reads the table), so the checker — which
     holds the table and not the resolver — can ask `symtab_error_by_code`.
     The reach analysis is unchanged: it demands, it never forbids.
3. **S-51 (only if ratified) — imports mean the same thing inside an inline
   module.** `graph_load_imports`, `module_apply_imports` and
   `graph_link_file_modules` descend into inline modules (an inline module's
   scope through `nested_module_scope`, a file-module import loading relative
   to the FILE), so `use "./x.npk".*;`, `use "./x.npk" as x;`,
   `use "./x.npk".{f};`, `mod:x;` and a logical `use` written inside
   `mod:m = { … }` bind into `m`'s scope under the same rounds and the same
   refusals (R-1's `RESOLVE-002`, `RESOLVE-005`, `RESOLVE-003`, `RESOLVE-007`)
   as at file level. The alternative — refusing an import inside an inline
   module by name — is smaller and would leave an inline module able to
   reach only the prelude and itself, which is the sealed box §1 measured.

Nothing here changes a program that compiles today except R-3/R-4's
refusals of arms that today match nothing or die in the emitter, and
`nitpick.obligations` must not move: no `pick`, no division and no
parameter threaded through a row-bearing function is added in `src/`
(`manifest_check.py` before every harness).

### Step 0 — LANDED (2026-09-10): the loader links the file-module import; the identity table; DEF-32

**What landed (D-274).** `graph_load_file_module` records which entry it
loaded for which declaration (`FileModuleLink { decl, loaded }` on the graph,
pushed for a load that answered an index — the flat and the nested arm alike;
a refused load records nothing), and `graph_collect_all` ends with
