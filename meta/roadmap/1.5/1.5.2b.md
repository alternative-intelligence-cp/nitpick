# 1.5.2b — Derived impls over generic subjects: one rule for every member, the synthesized bound, the prelude's scalar impls, and a family impl's bound enforced — PLANNED (2026-09-05; execution-grade; §9 ratified the same day as D-256…D-259)

> Scope: the README's row — *the prelude implements `Eq`/`Ord`/`PartialOrd`
> for every scalar (generated from the width ladder as the `Hash` impls
> are), a derived impl whose subject is generic carries a synthesized bound,
> and a parameter field compares by the method form; frontend and prelude
> only, no snapshot refresh* — ratified as **D-253** (S-24) on 2026-09-04,
> after 1.5.2 and before 1.5.3. Plus the item OPEN_DECISIONS §6 owes this
> subcycle: `DECL_THREAD` and `DECL_DISCARDED` share one bit, and nothing
> checks the `DECL_*` values are distinct.
>
> **What planning found (§4), in the order it matters.** (1) **A family
> impl's bound is declared and never enforced** (DEF-15): `find_method` and
> `type_implements` match `impl:<T: Ord>:Box<T>:Ord` to `Box<Point>` by
> DECLARATION and never ask whether `Point: Ord` holds; the checker accepts
> the program and the emitter names a method that does not exist —
> `llc` refuses the IR (`use of undefined value '@npk.prelude.Point:Ord.cmp'`).
> Without this fix D-253's synthesized bound is a comment. (2) **The
> no-bound operator story admits programs the compiler cannot compile**
> (DEF-16): `#[derive(Eq)] struct:Box<T>` instantiated with a struct dies
> inside the emitter (`NITPICK-EMIT-002 <derived-1>:3:12`). (3) **The D-250
> class is wider than comparisons** (DEF-17): a derived `Hash` over a NAMED
> field, a derived `Clone` over an OWNING field, and derived `Hash`,
> `ToString` and `Debug` over a generic subject all refuse at a line nobody
> wrote (`<derived-1>`; TYPE-042, TYPE-047, TYPE-019, TYPE-036). (4) **A
> derived `Clone` on a generic subject instantiated with an owner aliases
> it** (DEF-18): `Box<string>.clone()` is `pass self` checked with `T`
> opaque, and the two drops free one body twice — the allocator's instrument
> caught it (exit 95 where 0 was expected). (5) D-250's operator form is
> WRONG for floats: a derived `partial_cmp` over a `flt64` field answers
> `Equal` for `nan` where `NIL` is the answer, and a derived `cmp` over one
> presents a total order the type does not have.
>
> **The one rule this subcycle installs** (L-4, amending D-250's clause 2):
> *a derived body reaches every member through the trait it is deriving —
> a builtin scalar through the PRELUDE's impl, a named type or a parameter
> through its own — and a generic subject's impl carries that trait as a
> bound on exactly the parameters its body reaches.* The prelude implements
> the derivable traits for every scalar it can name, as a GENERATED region
> (L-3), so the rule has something to reach. What no derived body can be
> written for refuses at the user's declaration by name (DERIVE-006, as
> D-250 rule 3), and whatever still reports inside a `<derived-N>` file is
> RE-HOMED to the subject's declaration with the derive named (L-7, closing
> D-250's recorded gap) — with both runners refusing a `<derived-` path as
> a belt.
>

> taken at planning with their reasons (L-1…L-14), the measurements, then
> the record appended as each step lands. Six steps, six commits, each

## 2. What this subcycle builds, in one picture

```
#[derive(Eq, Ord, Clone, Hash)]
struct:Pair<A, B> = { A:a; B:b; int32:n; };
```

The generated text today (`<derived-1>`), and after this subcycle:

```
// today (D-161's no-bound story; D-250's operator form for every builtin)
impl:<A, B>:Pair<A, B>:Eq = { pub func:eq = bool(Pair<A, B>:self, Pair<A, B>:other) {
    if (self.a != other.a) { pass false; }          // `!=` on an opaque A: admitted, and EMIT-002 at Pair<Point, …>
    if (self.b != other.b) { pass false; }
    if (self.n != other.n) { pass false; }
    pass true; }; };
impl:<A, B>:Pair<A, B>:Ord = { … if (self.a < other.a) … };   // TYPE-008 inside <derived-1>
impl:<A, B>:Pair<A, B>:Clone = { pub func:clone = Pair<A, B>(Pair<A, B>:self) { pass self; }; };   // Pair<string, …> aliases
impl:<A, B>:Pair<A, B>:Hash  = { … h = raw fnv_mix(h, raw self.a.hash()); … };                    // TYPE-019 inside <derived-1>

// after (L-4, L-5, L-6): the trait reached through every member, the bound on the parameters the body reaches
impl:<A: Eq, B: Eq>:Pair<A, B>:Eq = { pub func:eq = bool(Pair<A, B>:self, Pair<A, B>:other) {
    if (!(relay self.a.eq(other.a))) { pass false; }   // a parameter: its own `eq`, through the bound
    if (!(relay self.b.eq(other.b))) { pass false; }
    if (!(raw self.n.eq(other.n))) { pass false; }     // a builtin scalar: the PRELUDE's `int32:Eq`, never fails
    pass true; }; };
impl:<A: Ord, B: Ord>:Pair<A, B>:Ord = { pub func:cmp = Ordering(Pair<A, B>:self, Pair<A, B>:other) {
    Ordering:dvo0 = relay self.a.cmp(other.a); if (dvo0 != Ordering.Equal) { pass dvo0; }
    Ordering:dvo1 = relay self.b.cmp(other.b); if (dvo1 != Ordering.Equal) { pass dvo1; }
    Ordering:dvo2 = raw self.n.cmp(other.n);   if (dvo2 != Ordering.Equal) { pass dvo2; }
    pass Ordering.Equal; }; };
impl:<A: Clone, B: Clone>:Pair<A, B>:Clone = { pub func:clone = Pair<A, B>(Pair<A, B>:self) {
    pass Pair{ a: relay self.a.clone(), b: relay self.b.clone(), n: raw self.n.clone() }; }; };   // the BARE literal (1.3.7)
impl:<A: Hash, B: Hash>:Pair<A, B>:Hash = { pub func:hash = uint64(Pair<A, B>:self) {
    uint64:h = raw fnv_offset();
    h = raw fnv_mix(h, relay self.a.hash()); h = raw fnv_mix(h, relay self.b.hash()); h = raw fnv_mix(h, raw self.n.hash());
    pass h; }; };
```

`Pair<int32, Point>` compiles when `Point` derives or implements the four;
`Pair<int32, Point>.cmp` on a `Point` without `Ord` is refused AT THE CALL
naming the derive and the bound (L-1, TYPE-017), never inside the emitter;
`Pair<string, int32>.clone()` owns two bodies (L-6); a `Pair<flt64, int32>`
under `PartialOrd` answers `NIL` for `nan` because the prelude's
`flt64:PartialOrd` does (L-3). The prelude's generated region (L-3), one row
of it:

```
impl:int32:Eq = { func:eq = bool(int32:self, int32:other) never fails { pass (self == other); }; };
impl:int32:Ord = { func:cmp = Ordering(int32:self, int32:other) never fails { if (self < other) { pass Ordering.Less; } if (self > other) { pass Ordering.Greater; } pass Ordering.Equal; }; };
impl:int32:PartialOrd = { func:partial_cmp = Ordering?(int32:self, int32:other) never fails { if (self < other) { pass Ordering.Less; } if (self > other) { pass Ordering.Greater; } pass Ordering.Equal; }; };
impl:int32:Clone = { func:clone = int32(int32:self) never fails { pass self; }; };
impl:flt64:PartialOrd = { func:partial_cmp = Ordering?(flt64:self, flt64:other) never fails { if (!(self == self)) { pass NIL; } if (!(other == other)) { pass NIL; } if (self < other) { pass Ordering.Less; } if (self > other) { pass Ordering.Greater; } pass Ordering.Equal; }; };
```

## 3. Decisions taken at planning (each with its reason; ratify or amend before the step that lands it)

Numbered L-1… so the record and the commit messages can cite them. L-3's
two extra traits, L-4's amendment of D-250, L-6, L-7 and L-8 are §9's;
everything else follows from D-253, D-250, D-107/D-064 and the tree as
measured (§4).

- **L-1 — A family impl applies to an instance only when its bounds hold,
  decided where the impl is USED, never eagerly.** New
  `family_applies(t, bt, ast, types, e, target, fuel)` in `type_trait.npk`:
  the impl's target pattern (`Box<T>`, `Pair<T, U>`, `Pair<T, T>`) is
  unified POSITIONALLY with the instance's arguments — a pattern argument
  that is one of the impl's own parameters (TY_PARAM whose decl lies in the
  impl's generic window) binds the instance's argument, every bound in
  `bound_entry_of(bt, param)` must hold for it by `type_implements` (fuel −1,
  `IMPL_FUEL` as `blanket_applies`), a parameter bound twice must bind ONE
  type (`Pair<int32, int64>` does not match `Pair<T, T>`), a concrete
  pattern argument must be identical, and a nested instance or container
  (pointer, slice, array, optional, result, arena, channel…) unifies
  element-wise by the same walk; anything else is `pattern == instance`.
  `find_method`'s family hit and `type_implements`'s family branch both ask
  it; an impl that does not apply is NOT a candidate. **Not eager**: an
  instantiation is never refused for an impl it does not use (`Box<flt64>`
  under `#[derive(Eq, Ord)]` is fine until someone calls `cmp` — §4.2's
  P4c stays accepted), which is what makes one derive per trait, each with
  its own bound, the right shape rather than one impl with the union of
  bounds. `check_one_instance` (the struct's own bounds, eager, as today)
  is untouched. The emitter's `impl_decl_for`/`note_family_instance` are
  untouched: they mirror `find_method`'s match, and the frontend now admits
  only what applies, so the P4b path (a symbol nobody defined) cannot be
  reached.
- **L-2 — The call site says which bound failed.** `MethodFind` gains
  `unmet_impl`, `unmet_trait`, `unmet_param`, `unmet_need` (the FIRST
  family impl that matched by declaration and failed a bound: its decl, its
  trait, the parameter and the trait it required; 0 otherwise), set in
  `method_none` and every literal construction. `type_members.npk`'s
  no-method branch reports **TYPE-017 (`TYPE_BOUND_UNMET`)** at the call
  when `unmet_impl != 0`: "`Box<Point>` reaches `cmp` only through
  `impl:<T: Ord>:Box<T>:Ord`, and `Point` does not implement `Ord`, which
  its parameter `T` requires" — and when the impl carries `DECL_DERIVED`,
  "…only through the `Ord` that `#[derive(Ord)]` generates for `Box`…". One
  mistake, one report (D-240): TYPE-019 is not also emitted. A bound met
  through `type_implements` elsewhere (a function bound, a `dyn`
  coercion) keeps `bound_unmet`'s existing wording.
- **L-3 — The prelude's scalar impls are a GENERATED region.** D-253's
  words are "generated from the width ladder as the `Hash` impls are"; the
  `Hash` impls are in fact hand-listed, which is exactly why they stop at
  64 bits (`int128`…`uint4096`, `tbb128/256`, `tfp`, `frac`, the ternary
  family, the floats and the flags have none). About 190 one-line impls is
  where a hand list loses a width, so `gen_tables.py` writes them between
  `// --- scalar-impls:begin (GENERATED — do not edit between the markers) ---`
  and `// --- scalar-impls:end ---` in `src/prelude/prelude.npk`, the flags
  region's mechanism (D-230), from the `BuiltinType` production it already
  reads — placed after the hand-written `Hash` impls, before `string`'s
  `Clone`. **Every `BuiltinType` terminal is classified, or the generator
  hard-fails** (the walkers-total shape at the generator): the scalar
  families — `int`/`uint` (all ten widths each), `char` (3), `tfp` (4),
  the ternary four, `frac` (4), `flt32`/`flt64`, `flt128` (storage only,
  D-143), `tbb` (6), `bool`, the kernel identifiers (5), the flag families
  (4), `complex` (its four instances, as `ToString` lists them) — and the
  NON-scalars by name (`string`, `cstring`, `dyn`, `any`, `Result`,
  `Optional`, `Handle`, `arena`, `shared_arena`, `atomic`, `Future`,
  `Channel`, the six sync kinds, `OwnedFd`, `simd`, `array`, `func`,
  `range`, `buffer`, `NIL`, `dim256`, `flt256`, `flt512`). Per family:
  `Eq` (`self == other`) for every scalar but `flt128`; `Ord` and
  `PartialOrd` (three-way by `<`/`>`; `pass Ordering.Less` wraps into
  `Ordering?` by D-099) for the ORDERED kinds exactly as `type_is_ordered`
  says — the ints, chars, `tfp`, the ternary four, `frac` — and
  `PartialOrd` alone for `flt32`/`flt64` with the `nan` clause first
  (`if (!(self == self)) { pass NIL; }`, both operands); NOT `Ord` for
  floats (the prelude's own reason: "a total `cmp` over one would have to
  lie"), not for `tbb` (codes, not sorted), `bool`, the kernel identifiers,
  the flags or `complex` (each refused by `why_not_ordered` today);
  `Clone` (`pass self`) for every scalar including `flt128` **(Q1)**; and
  `Debug` = `pass (raw self.to_string())` for every scalar the prelude
  already gives `ToString` — the generator reads `impl:X:ToString` targets
  out of the prelude text, one authority **(Q1)**. `dim256`: for every
  `unit:` the prelude declares plus the seven compiler-known base units,
  the same four impls on `dim256<Unit>`, IF `impl:dim256<Meters>:Eq`
  resolves as a target (measure first at step 2; if it does not, the units
  are decided OUT here and a `dim256` member compares by OPERATOR as the
  one recorded exception to L-4). A twisted or exact family compares
  through the operator, so its `eq`/`cmp` on an ERR operand TRAPS
  (D-008 §5 as amended at 1.3.2) — the language's rule, inherited, REACH
  arming it as at any operator site. Every body is `never fails` (the
  `Hash` precedent; the trait's declaration stays may-fail). Also
  generated: `src/frontend/scalar_table.npk` —
  `pub func:builtin_scalar_family = int32(TokenKind:k) never fails` (0 for a
  non-scalar; a family code otherwise) — so the derive reader (L-4) and the
  prelude region are two consumers of ONE classification, and
  `gen_tables.py --check` regenerates everything in memory and exits 1
  naming the first file that would change, with a whole-tree
  `check_generated_current` in the harness running it (today "run the
  generator and `git status` clean" is a habit, not a check).
- **L-4 — One rule for every member (amends D-250 clause 2; Q2).** The
  generator classifies a member's SPELLING (it sees type nodes, not types):
  a builtin scalar keyword (by `builtin_scalar_family`) is reached through
  the prelude's impl of the trait being derived, `raw` (the region's bodies
  are `never fails`, and a missing impl — `bool` under `Ord`, a float
  under `Ord`, a wide int under `Hash` — is the checker's "no method",
  re-homed by L-7); a NAMED type or a PARAMETER of the subject through its
  own method, `relay` (the trait declares may-fail); `simd` by `.any()`
  under `Eq` and DERIVE-005 under the rest (D-194, unchanged); a POINTER by
  `!=` under `Eq` (address identity) and by copy under `Clone`, refused by
  name under everything else (DERIVE-006: "a pointer has identity and
  nothing else to derive from"); everything else — the owning builtins
  D-250 lists, `List`, `dyn`, an array or slice, `Optional`, `Result`,
  `cstring`, `any`, `range`, `func`, `NIL`, and `complex` over a parameter
  — refuses by name at the user's declaration (DERIVE-006, one message per
  derive saying what a hand-written impl would have to decide). `string`
  in a FIELD position is a named spelling under Q4 (`relay self.s.eq(…)`,
  `.cmp`, `.hash()`, `.clone()` — the prelude gives `string` all four) and
  stays refused in a PAYLOAD position, because a `pick` cannot bind an
  owning payload (D-216's is the only binding form; D-250 rule 3) — two
  mechanisms, not one meaning varying by context. The rule replaces the
  operator for builtin scalars, which is what puts the float `nan` answer
  and the twisted ERR trap in ONE place (the prelude) instead of in every
  generated body, and makes a derived comparison over a `bool` or a
  kernel identifier under `Ord` a refusal instead of TYPE-008 at a line
  nobody wrote. Cost: a call per member at `-O0`; the `opt -O2` leg
  inlines a one-line `never fails` body, and the `cost` stage measures
  allocations, which do not move. `derive_payload.npk` keeps 121;
  `deriving.npk`, `derive_ord_enum.npk`, `derive_hash.npk`,
  `simd_derive.npk` keep their exits; a payload-less enum's bodies stay
  byte-identical (`self == other`, the tag compare) — they never read a
  member.
- **L-5 — The synthesized bound is exact.** For a derived trait X over a
  generic subject, the head is `impl:<P1: X, P2, …>:Subject<P1, P2, …>:X`
  with `: X` on EXACTLY the parameters that occur in a member the body
  reaches through X: `dv_params_in` walks a member's type node — a named
  node that IS a parameter names it; a named node WITH type arguments
  recurses into them (`Box<T>` as a member needs `Box<T>: Eq`, whose
  derived impl needs `T: Eq` — conservative, and the checker will ask);
  a pointer stops the walk (a pointer compares by address, whatever it
  points at); `simd<T, N>` stops it (lanes compare by operator). A
  parameter no reached member mentions gets no bound (`Tagged<T> = {
  int32:id; }` derives `Eq` for every `T`, as today), and an enum's
  tag-only bodies (`Hash`, D-123) reach no member, so `#[derive(Hash)]
  enum:Opt<T>` stays unbounded. The subject's OWN bounds
  (`struct:Box<T: Writer>`) are not copied onto the impl: the struct's
  instantiation already checks them (`check_one_instance`), and the body
  uses only the derived trait. `Debug`'s bound is `Debug` (Q3): the body
  reaches a named or parameter member through `debug`, so `Box<int32>`
  under `#[derive(Debug)]` needs the generated `int32:Debug` (L-3), and a
  named field must derive or implement `Debug` — the truthful requirement
  and the one-rule reading; today a named field under a derived `Debug`
  renders through its `ToString`, which is the behaviour this changes
  (unpinned by any test).
- **L-6 — A derived `Clone` clones member by member (closes DEF-17's Clone
  half and DEF-18; Q2).** A struct: `pass Subject{ f: <clone of f>, … }`
  — every field listed (a literal that omits one refuses), the BARE
  `Subject{ … }` for a generic subject (1.3.7: `matrix<T>{ … }` does not
  parse; the generator has `bare` beside `tn`) — with `<clone>` by L-4:
  `raw self.f.clone()` for a scalar, `relay self.f.clone()` for a named
  type, a parameter or a `string` field (the prelude's `string:Clone` is
  may-fail: it allocates), `self.f` for a pointer, a `simd` or an array of
  scalars (copies), DERIVE-006 for an array of anything else, an owning
  builtin that is not `string`, and the rest of L-4's refused set. An enum
  with payloads: `pick (self)` per variant rebuilding it —
  `(Tn.V(dv0_0)) { pass Tn.V(relay dv0_0.clone()); }` — an owning payload
  refused as under `Eq` (the pick rule); a payload-less enum keeps `pass
  self` byte for byte. The generic subject's `T: Clone` bound (L-5) is what
  turns `Box<string>.clone()` into a second body instead of a second
  header over one body. A struct with a `string` field derives `Clone`
  after this step (today TYPE-047 inside `<derived-1>`).
- **L-7 — A derived diagnostic is reported at the derive (closes D-250's
  recorded gap; Q5).** The generator emits every line through one seam
  (`dv_line(out, text, member)`) that appends the newline and records
  `(line, subject, member, trait)` into `ModuleGraph.origins`
  (`List<DerivedOrigin>`; the synthetic file id is written over the
  module's entries once `srcmgr_add_synthetic` has issued it; the header
  `mod:derived;` is line 1, so generated lines start at 2). `front_run`
  becomes a wrapper around the pass sequence and, on EVERY return path,
  runs `rehome_derived(@f.g, @f.diags)`: a diagnostic whose span's file is
  a `<derived-N>` synthetic is rewritten in place — its span becomes the
  subject declaration's span (the span DERIVE-006 already uses), its
  message is prefixed "in the `Ord` that `#[derive(Ord)]` generates for
  `Box` (at the field `v`): " (the variant's name for a payload; no member
  for a header line) — its code and severity unchanged, so D-237's set
  equality is unaffected. No diagnostic may then name `<derived-`, and
  BOTH runners' finding parsers refuse one by name as a belt ("reported
  CODE at `<derived-1>:6:12` — a line nobody wrote"), each with a
  self-check case in the DIRECTION of the defect (1.5.2's lesson): the
  parser handed a canned `NITPICK-TYPE-019 <derived-1>:6:12: …` line must
  report, and the same line at `p.npk:6:12` must not — the harness factors
  its inline parse into `parse_findings(stderr)` for that, `npkg` already
  has `findings_of`. Why re-homing and not a wider generator refusal: the
  residue after L-4 is a NAMED USER type that lacks the trait or owns
  (unknowable before collection) and a builtin with no prelude impl under
  this trait — every one of them a checker verdict with a good message,
  which only needs the right span and the derive named; a second table of
  "what the checker will say" in the generator is the two-places-that-
  must-agree shape.
- **L-8 — `string` implements `Eq` and `Ord` in the prelude (Q4).**
  `impl:string:Eq` by `string_eq`; `impl:string:Ord` byte-lexicographic
  (the shorter prefix is `Less`; a loop over `self.ptr[i]`, the `Hash`
  impl's shape), `PartialOrd` the same wrapped. Hand-written beside
  `string:Clone`/`string:Hash`, not generated (they are not a scalar row).
  This is what lets L-4 admit a `string` FIELD; without it `Box<string>`
  under `#[derive(Eq)]` refuses forever, since a program cannot usefully
  supply `string: Eq` itself (coherence across two libraries that both
  try, §8's orphan question).
- **L-9 — Coherence names the earlier impl by a NOTE.** With the prelude
  implementing `int32:Ord`, a program's `impl:int32:Ord` is TYPE-013 as
  today ("already implemented … at line 466") — a line of a file the
  message does not name. `coherence_error` additionally pushes a
  `diag_note` (code TYPE-013, span = the first impl's) reading "the
  earlier implementation", which the walk prints with its FILE
  (`prelude.npk:466:1`); notes are not findings (D-237), so no expectation
  changes. `tests/types/rejection/coherence.npk` gains an `expect-note`.
- **L-10 — No snapshot refresh, no adoption in `src/`.** Nothing in the
  tree derives; the builder's old prelude builds `src/` unchanged; the
  compiler under test carries the new prelude. The family-applies check
  runs over `src/` itself (the harness's `selfhost` builds it with the
  compiler under test): the prelude's `impl:<W: Writer>:TextWriter<W>:Writer`
  and `impl:<BW: Writer>:LineBufWriter<BW>:Writer` are instantiated with
  `ByteWriter` and with `LineBufWriter<ByteWriter>` (a nested check —

### 4.3 DEF-15 — a family impl's bound is declared and never enforced

`impl:<T: Ord>:Box<T>:Ord` is admitted for `Box<Point>` with `Point`
implementing nothing; the checker resolves `a.cmp(b)` through the family
impl by declaration identity, records the callee, and the emitter's
`impl_decl_for` finds no `Point: Ord` impl, qualifies the method by the
TRAIT's module (the prelude's) and emits a call to a symbol nobody
defines. `llc` refuses the module. This is D-064 §1's promise ("a body
correct for the instantiations that happen to exist may still be wrong in
general") broken on the instantiation side: the bound the body was checked
against is not checked against the arguments. The prelude's two bounded
family impls never met an unsatisfying argument, so nothing in the tree
noticed. Fixed at step 1 (L-1, L-2); `family_bound.npk` (types/rejection)
and `family_bound_ok.npk` (programs) pin both directions.

### 4.4 DEF-16 — the no-bound operator story admits programs the emitter cannot lower

D-161 (1.0.4c) wrote the family form with no bound because "the generated
body compares fields with the OPERATOR, so what it requires of `T` is what
the operator requires"; the checker admits `!=` on an opaque `T`
(measured at 1.5.1b step 3b), and the emitter then meets `!=` on a struct
at `Box<Point>` and refuses with EMIT-002 — a defect report against source
nobody wrote. Closed by L-4/L-5: the body reaches `T` through `eq`, the
impl carries `T: Eq`, and `Box<Point>` needs `Point: Eq` at the frontend.

### 4.5 DEF-17 — the D-250 class for `Hash`, `Clone`, `ToString`, `Debug`

`gen_hash_struct` writes `raw self.f.hash()` for every field; a derived
`hash` is may-fail, so a named field under `Hash` is TYPE-042 inside
`<derived-1>` (P8) — `derive_hash.npk` never nests. `gen_clone` is `pass
self`; a struct owning a `string` cannot be returned from a lent parameter,
so `Clone` over an owning field is TYPE-047 inside `<derived-1>` (P9).
`Hash`/`ToString`/`Debug` over a generic subject are TYPE-019/036 inside
`<derived-1>` (P2). Closed by L-4/L-5/L-6.

### 4.6 DEF-18 — a derived `Clone` over a generic subject aliases an owner

`pass self` in `impl:<T>:Box<T>:Clone` is checked with `T` opaque, so
TYPE-046/047 cannot see the string inside `Box<string>`; the specialization
copies the header; both drops free the body. P9c measured it: exit 95
where the arithmetic answer was 0. Closed by L-6 (member-wise clone under
`T: Clone`). Until step 3 lands, the shape is a known hole; no program in
the tree writes it.

### 4.7 The ordered and equatable sets, and D-250's float answers

`type_is_ordered` and `equatable` (§4.1) are the authority for L-3's
family map — the map is written FROM them, and `scalar_traits.npk`
exercises every family so a disagreement is a red test. By construction of
`dv_cmp_stmt` (spelling 0: `if (a < b) { Less } if (a > b) { Greater }`,
then the body's `pass Ordering.Equal`), a derived `partial_cmp` over a
`flt64` field answers `Equal` when either side is `nan`, and a derived
`cmp` presents a total order over a type that has none. L-3's
`flt64:PartialOrd` answers `NIL`, and `flt64` has no `Ord`, so a derived
`Ord` over a float field is refused (re-homed "no method `cmp`") — a
behaviour change for programs that compile today; none in the tree.

### 4.8 What the emitter needs from this plan: nothing

P4 and P12 show a sync method call on a parameter receiver through a
family impl's bound lowering onto a user struct's impl and onto a scalar's
impl; the prelude's impls are ordinary impls on builtin types like `Hash`'s.
The emitter mirrors `find_method`'s match and is reached only for what the
frontend admitted. No backend file changes in this subcycle (the row's
"frontend and prelude only" holds), which is also why no refresh is needed.
