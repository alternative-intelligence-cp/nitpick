## 0. Why this subcycle exists

On 2026-09-03 the library workbench (`nitpick-libs`, planning `nitpick-time`)
reported three compiler defects against the 1.5.0-close compiler, all recorded in
`meta/roadmap/OPEN_DECISIONS.md` §2f with the reporter's numbers, the riders,
and this session's bisection. None was found by any suite in the tree; each came
from building a real library. The user's ruling is that a defect found that way
is fixed in the compiler at once, before planned work, and the real program
becomes the regression case.

| | Reported as | What it is, measured |
|---|---|---|
| **DEF-1** | compile time and memory QUADRATIC in one declaration's size, three axes | three accumulate-by-concatenation loops in `src/backend/` (time), riding a managed-regime defect — **an owning temporary is never dropped** (memory) |
| **DEF-2** | a root file with a mismatched `mod:` header silently merges a sibling; two `@main`, exit 0, `llc` refuses | the loader cannot tell a file's header from an import written first (its own comment says so), and nothing forbids `main` outside the root module |
| **DEF-3** | a `uint8[]` view of a local string is returned out of its frame; exit 0; reads freed memory | the escape analysis knows `@x` and the range-view; it names neither `string_bytes` nor `string_from_bytes` |

The bisection found two facts larger than the report:

- **The compiler compiling itself peaks at 11 516 824 KiB of resident memory**
  (`npkc src/main.npk`, 15.6 MB of output); the frontend alone (`check
  src/main.npk`) at 10 956 716 KiB. Two causes, both by construction: the
  temporaries above, and `List<T>` (`src/frontend/list.npk`, 1.4.7) is a
  `wild` block whose comment says "nothing here drops" — 153 by-value List
  fields and parameters across 28 files, never freed. The compiler is a bump
  allocator that happens to build itself. Four harnesses in parallel do not
  fit a 16 GiB machine (the 1.4.8 UI freeze has a candidate cause).
- **The two probes that settle where the memory goes** (built with the 1.5.1
  worktree's compiler, both exit 0): `t = string_concat(t, "b")` 20 000 times
  peaks at 260 KiB — the overwritten binding frees its old body (D-186's
  fallout, for locals); `t = string_concat(string_concat(t, "b"), "c")`
  20 000 times peaks at 429 740 KiB — the inner result is an unbound
  temporary passed as an argument, and nothing ever frees it. This is
  D-183's "statement-end temporaries" item, recorded at 1.2.4a ("temporaries
  do not drop yet — that cell rides the recorded statement-end-drops debt")
  and never scheduled since.

So the subcycle is five fixes and one instrument, seven commits, each under a
full harness. The order puts the two small refusals the workbench is blocked on
first, the emitter's builders next (that alone makes the reported curves linear
in time and memory), and the two lowering changes last, because they change the
compiler's emission of itself and end with a snapshot refresh.

## 2. Step 0 — The instrument and the baseline (commit 1)

**The fix must be a number, and wall-clock is never a verdict** (the harness
already refuses a z3 wall-clock knob as "a hang net, never a verdict"). The
number is the allocator's, which is deterministic for a given input.

- **`NPK_HEAP_STATS`.** `runtime/npkrt.ll`'s one allocation core

  4767) keeps three words: bytes requested in total, bytes live now, and the

  carries `NPK_HEAP_STATS` (the runtime's `_start` already holds envp for
  `environ()`, 1.4.8 Part A): `heap: allocated=<n> peak_live=<n> count=<n>`.
  Three adds and a compare on the hot path; a debug instrument that stays,
  like `@npk_quarantine` and the 0xAA poisoning. The printed line is data for
  the harness, never a verdict inside the program.
- **The `cost` harness stage** (and its `npkg` twin — D-238: one table, both
  runners), permanent:
  - **The three DEF-1 recipes as generated programs**, parameterised by N,
    regenerated at N and 4N by the stage itself (the workbench's

    `8066e6229c77aed28be7ab471209962a03534b0f`, is the source of the shapes;
    their `big_fixed_array_cost.npk` is checked in as

    `allocated(4N) / allocated(N) ≤ 6` and `peak_live(4N) / peak_live(N) ≤ 6`
    on all three axes — linear is 4 with slack, quadratic is 16. Every

  - **The two probes as programs** — `tests/backend/programs/temp_bound.npk`

## 3. Step 1 — DEF-2: the header and the entry points (D-248, commit 2)

**Mechanism, from the loader's own text** (`src/frontend/module_graph.npk`
~477–489): "THE FILE'S OWN HEADER IS INDISTINGUISHABLE FROM AN IMPORT written
first — both are a member-less `mod:name;` — so the loader cannot say 'your
header is wrong'; what it can do is name that reading when the file is not
found (1.0.8)." `graph_load_imports` loads every member-less `mod:X;` as a
file module; when `X` names an existing sibling, the sibling is a second
module of the program, and if it declares `main` the emitter names both
`@main` (`ir_types.npk:292`, by name alone; `ir_writer.npk:294`;
`ir_func.npk:51`; `type_decl.npk:36` types both as entry points). Measured on
the tree: 525 source files, **240 without a header** (`src/main.npk`, the
three tools, `npkg/main.npk`, `tests/grammar/whole_grammar.npk`, most of
`tests/rejection/`, …); three files whose first `mod:` is not the basename,
all legitimate today (an inline module first in `tests/rejection/inline_mod.npk`
and `tests/modules/rejection/owned_names.npk`; `mod_ambiguous.npk`'s
`mod:twoways;` is the test's subject).

**D-248 (proposed; the recommendation and the alternative in §7):**

1. **The header is mandatory.** Every source file's FIRST declaration is its
   header, `mod:<basename>;` — member-less, naming the file's own basename. A
   file whose first declaration is anything else, or a `mod:` naming another
   module, is refused at that declaration's span (line 1 for a missing
   header): `NITPICK-RESOLVE-012`, one code, two texts — "file `foo.npk` has
   no header: its first declaration must be `mod:foo;`" and "file `foo.npk`
   declares `mod:bar;` first: a file's header names the file — `mod:foo;`;
   an import of `bar` is written after it". The header binds nothing and
   loads nothing (`graph_load_imports` skips item 0 by rule instead of
   loading the file into itself); a LATER member-less `mod:X;` is a
   file-module import exactly as today, and RESOLVE-005's 1.0.8 hint text
   loses its "or your header is wrong" reading, which the loader can now say
   directly. The prelude's constant text carries `mod:prelude;` first (it does
   today; `graph_load_prelude` is unchanged).
2. **`main` and `failsafe` are declared in the ROOT module only** — the file
   the driver was given. A declaration of either in any other module is
   refused at its span: `NITPICK-RESOLVE-013` "`main` is an entry point and
   is declared in the root module; `bar.npk` is a module of this program".
   Checked in `graph_check_owned_names`' position (`module_graph.npk:307`, the
   whole-graph pass 1.4.8c added) since it needs every module loaded and the
   root's index (`graph_load_all`'s `first`). With 1, a mismatched header
   can no longer load a sibling; 2 is the belt for a sibling imported ON
   PURPOSE that happens to be a program — a library cannot smuggle an entry
   point, and the emitter's `@main`/`@npk_failsafe` naming becomes the
   root's by construction (the four by-name sites are left as they are and
   annotated: the rule upstream is what makes them safe).

**The sweep.** 240 files gain a first line. Mechanical, by a script kept in
`meta/roadmap/1.5/tools/` for the record and deleted after: insert
`mod:<basename>;` as line 1, and for every file in a rejection suite shift each
`// expect-error-at: LINE` pin by one — D-237's exact matching then proves the
shift complete, because any missed pin fails by name. `mod_ambiguous.npk` keeps
its `mod:twoways;` as its SECOND declaration (the test's subject is the
two-file ambiguity, not the header). The harness's and `npkg`'s generated
sources — `selfcheck.py`'s and `npkg/selfcheck.npk`'s embedded programs, the
`nf-inert` twins (copies of files that now carry headers), `quickemit`'s
temporaries — get the header their temporary basename requires; an execution
item, found by running them. `tests/modules/README.md` gains the two rows.

**Tests** (all D-237-pinned): `tests/modules/rejection/header_missing.npk`
(a file with no header: RESOLVE-012 at line 1), `header_mismatch.npk` +
its sibling `header_sibling.npk` (the reporter's six-line reproduction — the
mismatched header names the sibling; RESOLVE-012 at the header, and the
sibling is NOT loaded: no second diagnostic, which D-237's exact set proves),
`entry_in_module.npk` + `entry_lib.npk` (a header-correct root importing a
module that declares `main`: RESOLVE-013 at the module's `main`). Accept:
`tests/accept/` gains nothing — every file in the tree is now the positive
case.

## 4. Step 2 — DEF-3: view-makers are borrows (D-249, commit 3)

**Mechanism.** `escape_call_like` (`src/frontend/analysis/escape.npk:1230`)
asks `escape_arg` (1600) whether each argument IS a borrow; `string_bytes(s)`
passes the local `s` by value, which is no borrow, so the call's result is
not borrowy and `escape_return_value` (414; `BORROW_RETURNED` at 429) lets
it out. The result is a `{ptr, len}` into `s`'s heap body, which `s`'s
scope-exit drop frees. `arr[lo...hi]` is known to exactly one walk — the
suspend walk (`suspend.npk:606`, D-191) — and to the escape analysis not at
all; the same hole, one layer over.

**D-249 (proposed):** BUILTIN_REFERENCE's marked regions gain a **`Views`**
column beside `Pure` (1.5.1 step 4's shape, the same generator path in
`bootstrap/generator/gen_tables.py`, which hard-fails on a cell it cannot
read): `—`, or the 1-based index of the argument whose storage the result
aliases. Rows: `string_bytes` 1, `string_from_bytes` 1 (its pointer
argument), every other row `—`. `builtins.npk` gains `builtin_views(name) →
int32` (0 for `—`). The escape analysis treats a call whose callee has a
`Views` index as a borrow ROOTED WHERE THAT ARGUMENT IS ROOTED — as if `@`
had been written at the argument — so D-004 rule 2 (return), the struct-literal
refusal, rule B (a destination among the arguments), the channel-send rule and
the launder-through-a-call rule apply to it unchanged. The range-view
`arr[lo...hi]` gets the same treatment by kind. A user function returning a view
of its own PARAMETER stays legal (`borrows_only_param_rooted`, 507); one
returning a view of a local, or of a local's field, is BORROW-001. Whether a
`wild` operand's view is wild-provenanced is already `wild_provenance`'s
(622) answer and is unchanged.

**Tests.** `tests/analysis/rejection/view_escape.npk`, pinned exactly, carrying
the reporter's CONTRAST (their committed reproduction — hash to be added to §8

BORROW-001 (new), `pass (string_from_bytes(local.ptr, local.len))`

## 6. Steps 4 and 5 — The two leaks (commits 5 and 6)

### Step 4 — Statement-end temporaries (D-246)

**D-246 (proposed):** An owning value that no place takes is a **temporary of
the statement that produced it**. It is dropped when that statement ends, on
every path the statement leaves by — its normal end, `relay`, `pass`, `fail`,
`return` — in reverse order of creation and after the statement's own effect
(a returned value is computed and stored before its statement's temporaries
drop; D-207's seam order — store, unwind, return — gains "drop the statement's
temporaries" between store and unwind). A temporary is **taken**, and not
dropped by its statement, when it is bound by a declaration, assigned into a
place, passed to a `move` parameter, stored into a struct, array or `Result`
literal's slot, sent on a channel, or returned. A temporary passed to a plain
parameter is BORROWED by the callee (D-004) and dropped by the statement after
the call returns; a receiver (`string_concat(a, b).len`) and an operand
(`f() == g()`, `is_err(f())`) likewise; `discard(f())` discards a temporary and
drops it. A trap (`?!`, `!!!`) runs no drops (D-014). In a coroutine, the only
temporary alive across a suspension is an `await`'s own argument (D-178); it
lives in a frame slot and drops when the statement ends after the resume.
`dyn` coercion arguments (D-183's 1.2.4a note) are ordinary temporaries under
this rule.

**Mechanics** (the executor's map; every site read this session):

- `emit_stmt` (`src/backend/ir/ir_stmt.npk:526`) already opens a per-statement
  mark (`irw_stmt_mark`, D-177). A **per-statement temporary list** on the
  function emitter (`x.fe`) opens beside it: entries of `(tid, ll type, ref)`.
- **Registration** happens where an owning value is produced and NOT taken.
  The producer is `emit_call` (`ir_expr.npk:6360`) and its kin (`emit_await`
  6083, method calls, `?|` on a `Result` whose value owns, interpolation,
  `ToString`, the `dyn` coercion). Rather than teaching every producer, the
  rule is applied at the CONSUMERS: `emit_fit` (476) is the one seam every
  value crosses into a slot ("A FIELD IS A SLOT", "AN ELEMENT IS A SLOT",
  the call-argument fit at 6426); the emitter marks a fit as TAKING (a
  declaration's initialiser, an assignment's value, a `move` parameter — the
  signature's move flag, `builtin_sig_param_move` for builtins — a literal
  slot, a send, a return) or BORROWING (a plain parameter, a receiver, an
  operand). A borrowing fit of a non-place owning value registers the
  temporary; a taking fit does not. `type_drops` decides "owning"; a place
  (an identifier, a field of a place, an element of a place) is never a
  temporary — the move analysis already refuses copying one.
- **Emission** at the statement's normal end (`emit_stmt`'s return paths) is
  one `call void @"npk.drop.<tid>"(...)` per entry, reverse order, through the
  generated bodies `emit_drop_bodies` (`emit_program.npk:1225`) already
  produces for every owning type — no new drop shape.
- **Early exits within a statement**: `emit_relay` (7311) is the only
  in-statement return; it drops the statement's temporaries so far before
  the unwind. `emit_pass` (1432), `emit_fail` (1458), `emit_return` (1527)
  drop theirs after storing the result and before `run_scope_drops` (380).
  `?!` and `!!!` trap: nothing.
- **Coroutines**: an owning temporary that is an `await`'s argument is spilled
  to a frame slot (one new frame role, beside D-207's role 41; `emit_await`
  builds the child frame from the argument values, so the spill is the
  caller keeping its own copy of the trio) and dropped from the slot at the
  statement's end after the resume; the suspend walk records nothing new
  because D-178 already guarantees no other temporary crosses.
- **The move analysis** is untouched: temporaries were never places.

**Tests.** `temp_bound.npk`/`temp_nested.npk` (step 0's, now green); a
`dyn` temporary (`report(coerce(x))`); a struct temporary with an owning field;
an `OwnedFd` temporary passed 2 000 times to a borrowing function — EMFILE
proves the drop, the `overwrite_owned.npk` technique; a temporary before a
`relay` that fails on the 10th call (descriptor count again); `discard(f())` of
an owning result; an owning temporary as an `await` argument in a coroutine
with `// stress: 40`; a temporary on both sides of `==`. The checker's

**What changes downstream.** Every program with a borrowed owning temporary
emits differently: `selfhost` (stage 2 == stage 3 must hold with the new
lowering — stage 1 is built by the OLD snapshot and its body still leaks;
stage 2 is the first compiler whose body drops, and it is the one measured),

### Step 5 — `List<T>` owns its elements (D-247)

**D-247 (proposed):** `List<T>` is **compiler-known** and **owning**: it is
declared in the prelude (moved from `src/frontend/list.npk`, its API —
`list_init`, `list_reserve`, `list_push`, `l.items[i]` — unchanged), `type_drops`
answers true for it unconditionally (as for `dyn`), and its generated drop
body drops the `count` elements it holds through `T`'s drop and then frees
the block with `npk_dalloc`. It is therefore move-only under TYPE-046, which
also refuses the aliasing copy today's `wild` block permits (two copies of a
List, one `list_push` that `ralloc`s, one dangling `items`). A struct holding
a List drops it through its own generated body; a List that must outlive its
scope is moved, like any owner. Growth stays `ralloc` on the block; the drop
frees whichever block is current. The precedent is `OwnedFd` (TY 39): a
compiler-known type whose drop does the manual thing on the author's behalf,
by decision.

**Why not the alternatives.** A `buffer`-backed List frees its block but
leaks its owning elements (`List<Root>` carries two strings per element) — a
generated struct drop knows fields, not elements. A user-declared drop hook
is a destructor design the language does not have and should not acquire for
one type. Manual `list_free` + `defer` at 153 holders is the regime the
managed lowering exists to replace, and the compiler's own tables are exactly
the data whose lifetime should follow their pass.

**Mechanics.** The drop generator (`emit_drop_bodies`) gains a List arm keyed
on the prelude declaration (the way `Duration`/`Error` are resolved by name
ahead of lookup, D-179): a loop over `count` calling `T`'s drop on
`items[i]` where `T` drops, then `npk_dalloc(items)` where `cap > 0`.
`type_drops` and the walkers-total instrument (`check_type_walkers_total`)
learn the kind; the escape analysis already treats `wild T->` fields by
provenance. **The sweep**: 153 by-value List fields and parameters, 4
`List<T>->` parameters, 335 `.items[i]` reads (unchanged — reads through the
field are what they were), and every holder struct whose value is copied
between bindings becomes move-only — the checker's own TYPE-046 refusals
enumerate the sites, the same way 1.4.7's adoption found its 26. A List
returned from a factory is `move`d or returned by value (a return takes).
Expected: per-pass tables (a `Resolver`, an `Escape`, an `ExprEmitter`)
die at their scope's end and the compiler's peak falls to its live data.

**Tests.** `tests/backend/programs/list_drop.npk`: a `List<string>` of 10 000
elements built and dropped 100 times in a loop under `NPK_HEAP_STATS`, the
`cost` stage asserting `peak_live` under 2× one list's size; a `List` inside
a struct inside a `List` (nested drops); a moved List (the source refuses
reuse, TYPE-047); `List<OwnedFd>` of 1 000 descriptors dropped — EMFILE
proves the element drops. The compiler's own build ceiling in the `cost`
stage is set here from the measured value.

## 7. Questions for the user — the four decisions (ratify, amend, or refuse)

- **S-19 → D-246, statement-end temporaries.** The rule as §6 step 4 states
  it. Recommendation: ratify as written. The one design choice inside it is
  "taken vs borrowed" being decided at the SLOT (the fit), which is where
  the language already says what a position means; the alternative (a
  temporary is dropped at the END OF THE FUNCTION) is simpler to emit and is
  what the leak becomes if the statement rule is refused — a coroutine's
  frame would then hold every temporary, and the compiler's own memory
  would fall by less.
- **S-20 → D-247, `List<T>` owning and compiler-known.** Recommendation:
  ratify as §6 step 5 states it. The alternative that keeps the language
  smaller — `buffer`-backed, elements leaked — is decided OUT because it
  leaks exactly the strings the compiler's tables hold.
- **S-21 → D-248, the mandatory header and the root-only entry points.**
  Recommendation: ratify BOTH halves. The alternative for the header —
  header optional, identified by NAME (a member-less `mod:` naming the
  basename is the header wherever it stands, anything else is an import) —
  costs no sweep and closes the reported defect through the entry-point rule
  alone, but leaves a mismatched header a silent import of the sibling
  whenever the sibling declares no `main`, and leaves the loader unable to
  say "your header is wrong", which cost a cycle at 1.0.8. Explicit over
  implicit: every file says what it is. The sweep is 240 mechanical lines
  and a pin shift the harness verifies.
- **S-22 → D-249, the `Views` column.** Recommendation: ratify. The
  alternative — a hard-coded pair of names in the escape analysis — is one
  more parallel authority beside the signature table 1.4.2 made the ONE
  authority.

Also for the user, not blocking: whether `NPK_HEAP_STATS` should print on
every exit path (a trap's `failsafe` exit included) — recommended yes, the
line is diagnostic output on fd 2 and the harness ignores it where it did not
ask.
