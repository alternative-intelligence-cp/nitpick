# 1.5.5 — The aliasing half of D-004: `$$i` shares, `$$m` excludes, and the solver relaxes the computed-index refusal (S-60…S-62; DEF-42, DEF-43)

**Planned execution-grade 2026-09-11 on `cb8cbb0` by `nitpick-compiler_s5`.
Three questions are open for the user (§3: S-60 the rules, S-61 the check's
shape and the new obligation kind, S-62 `fixed` has no address); each carries
a recommendation and the steps below are written to the recommendations.
Step 0 (DEF-42, a defect under D-004 rule 3's own text) needs no decision and
may run at once; steps 1–3 run after ratification, under D-228. Nothing else
is decided by the executor.**

## 1. Where it starts (measured 2026-09-11 on `cb8cbb0`; the probes are in the session's scratchpad `p0/`, committed as tests as the steps land)

- **The specification's example does not parse.** VERIFICATION_REFERENCE
  §2.1 (and the prototype text it carries) writes `$$m int32:a = arr[i];` —
  a DECLARATION QUALIFIER. The parser builds `$$i`/`$$m` only as unary
  operators (`parse_expr.npk`: one node kind, `ExprBorrowExpr`, payload 0
  for `$$i` and 1 for `$$m`); the qualifier form is `NITPICK-PARSE-002` at
  the `int32`. 0.5.1's plan recorded exactly this gap ("`borrow_imm` /
  `borrow_mut` DO NOT EXIST AS SPELLINGS … the operators are the only way to
  write a borrow today") and left the aliasing half "not settled here". The
  operator form is the language's: `int32->:a = $$m arr[i];`.
- **Nothing decides aliasing.** With the operator form, two `$$m` of one
  element (`$$m arr[1i64]` twice, both written), and a `$$m x` held while `x`
  is assigned directly and then written through the pointer, are accepted by
  the checker and every analysis, compile, link and run: the probe exits 32
  (9+9 and 7+7 — the second write through both names). What the two
  spellings do today: the checker types both as `T->` (`type_expr.npk`
  ~3841: "a SECOND-CLASS borrow … the distinction is about where the value
  may travel, not about what it is"), refuses a limited root (TYPE-063) and a
  view (TYPE-066); the bindings analysis reads `$$m` as the write that fills
  a caller-owned destination (D-118) and `$$i`/`@` as reads; the escape
  analysis treats both as `@` under rules 1–5; the emitter lowers both to
  the address (`emit_addr_op` → `addr_of`); the encoder marks the root
  escaped (`collect_escaped_expr`) so every later read of it is opaque.
  The mutable/immutable distinction is carried by one AST payload and read
  by one analysis (D-118).
- **The tree's own uses.** Eight code sites of `$$i`/`$$m` in `src/`
  (comments excluded): `npkc.npk` 159 and 169 (`front_run($$m f, root)`,
  `reject_wildx($$m f)` — call arguments, D-118's out-parameter spelling),
  `diagnostics.npk` 121 and 215 (`Diagnostic->:e = $$i list.items[i];`,
  `Diagnostic->:prev = $$i list.items[j - 1i64];` — held), `emit_program.npk`
  2194 and 2228 (`string->:sp2 = $$i w.site_paths.items[i => int64];` —
  held, then `irw_write(w, …)`), `ir_func.npk` 1127 (`pass ($$i
  fe.lflags.items[i => int64]);` — a returned borrow of a parameter-rooted
  place), `ir_expr.npk` 204 (`string->:data = $$i t.v.items[i];` — held).
  `lib/`, `npkg/`: none; `tools/`: one. 1,428 `@` sites in `src/`; six
  pointer locals initialised from a borrow operator. The suites: eleven
  files, all call-argument or refused-elsewhere shapes, plus
  `tests/accept/borrows.npk` 43 (`int32->:q = $$i x;` beside `int32->:p =
  @x;`).
- **DEF-42 — a borrow assigned to an OUTER holder is accepted.** `int32->:p =
  NULL; if (true) { int32:x = 41i32; p = $$m x; } … <-p` passes the checker
  and every analysis and exits 42. D-004 rule 3 says a borrow may not be
  stored "into any aggregate that is not provably shorter-lived", and
  `escape_assign`'s bare-local branch marks the holder and compares no
  scopes ("A BARE LOCAL NAME, and nothing else"). It is benign at run time
  by construction — every local is a function-lifetime alloca (D-173 hoists
  them), and an address-taken local is frame-resident to the function's end
  in a coroutine (the suspend walk's address-taken extension) — so nothing
  dangles today; the rule is unchecked, and the aliasing lifetimes below
  assume a holder never outlives its root.
- **DEF-43 — a write through a pointer to a `fixed` binding.** `fixed
  int32:x = 1i32; int32->:p = $$m x; <-p = 2i32;` is accepted (the
  definite-assignment analysis refuses a second ASSIGNMENT to a `fixed`,
  ASSIGN-002, and sees no store through a pointer); a `fixed` LOCAL is
  silently overwritten, and a `fixed` GLOBAL — an LLVM `constant` in
  read-only memory — kills the process with SIGSEGV (the probe exits −11):
  an UNCONTROLLED crash, the class the language exists to make impossible
  (`failsafe` never runs). Measured over `src/`, `lib/`, `npkg/`, `tools/`
  and `tests/`: 89 `fixed` bindings, none address-taken and none the
  receiver of a pointer-receiver call (one regex hit in `expand.npk` is a
  pointer parameter of the same name), so the rule in §2.8 costs the tree
  nothing.
- **The machinery in place.** `place_root` (`expr_types.npk`) walks a place
  to its root through `.` and `[]` and stops at `<-`; the escape analysis's
  per-statement marking fixpoint with `BORROW-010` on non-settlement;
  `ExprTypes`' sparse statement-keyed marks (`cross`, `odecl`) as the
  channel from an analysis to the emitter; `addr_of` (`ir_expr.npk` 9069)
  the ONE place-address function — 16 call sites, `emit_index` (an element
  read) routes through it, `emit_range_slice` does not; the shift guard
  (`ir_expr.npk` ~2269) and `record_shift` (`smt_encode.npk` ~917) the
  guard-and-row template — one unsigned compare, `npk_chain_reset`,
  `npk_trap(-4115)`, the row's goal the guard's condition, the fact pushed
  after the site; `llctx_elided` answers per (site, kind, space, ctx) and
  ANY matching row discharges — so a guard site records ONE row; the
  runners' tables (`TRAP_OF_KIND`, `Z3_KINDS`, `ASSUME_KINDS`,
  `GUARDLESS_KINDS` in `harness.py`; `trap_of_kind`, `kinds_of_trap`, the
  `assume_kind` disjunction in `npkg/verify.npk`, which reads `ok_has_guard`
  from `smt_kinds.npk` directly); `check_obligation_kinds_agree` diffing
  `smt_kinds.npk`, the catalogue's marked region and `Z3_KINDS`; the
  frontend emitter's binding table looked up BY NAME innermost-first
  (`fnem_lookup_idx`), with inner-block shadowing permitted by the resolver.
  D-218 (7)'s catalogue names no aliasing kind: a new kind is a decision.
- **The prototype's design, for the record** (`BORROW_SPEC_S10.md`, the
  traits-and-borrows RFC, `formal_verification_specs.txt` §5): `$$i` many,
  `$$m` one, "the original variable is frozen while mutably borrowed",
  disjoint FIELDS allowed ("the borrow checker tracks access paths"),
  non-lexical lifetimes by a `LivenessAnalyzer` with loop fixpoints,
  two-phase borrows, closures by reference, and the aliasing verdict
  "without Z3 the borrow checker would conservatively reject this code
  (NITPICK-023); with `--verify` … the code is accepted". D-004 chose
  second-class borrows over that lifetime machinery ("no lifetime variables
  at all; validity is bounded by the callee frame, structurally") and named
  "the existing aliasing rules for `$$i` / `$$m`" as the other half;
  D-068 settled that a safety property never depends on a compiler flag.

## 2. The design (what S-60, S-61 and S-62 ratify; written to the recommendations)

### 2.1 Vocabulary

- A **claim** is a `$$i place` (SHARED: many readers) or `$$m place`
  (EXCLUSIVE: one writer, no other name) expression. `@place` is a **plain
  address**: it claims nothing and says nothing about direction (D-004's
  "a borrow valid for this call"; bindings.npk: "nothing in it that says
  which way the data will travel").
- An **access** is any way source reaches storage under a root: a read of
  the place or a part of it, an assignment or compound assignment to it or
  a part, `@`/`$$i`/`$$m` of it or a part, `move` of it or a part, the
  implicit address a pointer-receiver method or UFCS call takes, a range
  view `r[lo...hi]` (a view is `@r`, D-249), a `pick` selector. A claim is
  itself an access. An access is **write-capable** unless it is a plain
  read: an rvalue read, a by-value argument, `.len` on an array or slice
  (a length, never an element), a `$$i` claim. `@`, `$$m`, `move`, an
  assignment target, a pointer receiver and a range view are write-capable
  — the pointer type carries no mutability, so whatever holds an address
  may write through it.
- A claim's **root** is the identifier at the bottom of its place path
  (`place_root`); its **path** is the steps from the root outward: `.f` (a
  field name) or `[e]` (an index expression, NUMERAL when the folder
  knows its value and COMPUTED otherwise). `a.b[i].c` is root `a`, path
  `.b [i] .c`. A place whose root is not an identifier — a call's result, a
  `<-` at the bottom — has no named root.
- Two paths under one root **overlap** iff, along their common prefix,
  every field step names the same field and every index pair denotes the
  same element; they are **statically disjoint** iff some field step
  differs or some index pair is two unequal numerals; **statically
  overlapping** iff they overlap with every index pair along the common
  prefix two equal numerals (or no index pair at all — one path a prefix
  of the other); **computed** otherwise (at least one pair with a computed
  index, and no static disjointness). A whole-root access has the empty
  path, a prefix of everything.

### 2.2 The lifetime of a claim (lexical; non-lexical lifetimes decided OUT)

- **A whole call argument or receiver** — `f(…, $$m x, …)`, `x.m($$i y)`,
  a builtin's argument — lives from its evaluation to the end of that call.
  It conflicts with every other argument and the receiver of the SAME call,
  in any position (evaluation order is source order; the analysis checks
  every pair, which is conservative and simple).
- **The whole initialiser or assigned value of a pointer local** —
  `T->:p = $$m x;`, `p = $$m x;` with `p` a local of this function — is
  HELD by `p` from `p`'s DECLARATION to the end of the block that declares
  `p`: the holder's whole scope, not the point of the assignment, because a
  loop reaches every statement after the declaration again after the
  assignment. A holder's own uses — `<-p`, `p.f`, `p[i]`, passing `p` —
  are the claim's uses, not accesses of the root. A `defer` body is
  checked against every claim whose holder is declared in an enclosing
  block, at any position: the body runs at the block's exit, after every
  later declaration.
- **A holder is used, not copied.** `q = p`, `T->:q = p`, `Holder{ inner: p
  }` where `p` holds a claim refuse (BORROW-014): the claim's life would
  follow the copy and a single forward walk could not see where. Pass `p`
  down instead. (Zero copies of a claim holder exist in the tree.)
- **Anywhere else a claim expression stands refuses** (BORROW-014): inside
  a struct or array literal, a `pass`/`return`/`give` value, nested inside
  another expression (`$$i a => int32`, `<-($$m x)`, an arithmetic
  operand), assigned to a non-local place (a field, an element, a global),
  an argument of a call whose result can carry a pointer (escape's
  `carries_pointer`) AND is bound or stored — D-117 Rule A's shape, where
  the callee decides what the result points at and no holder's value can
  be compared. The message says: "spell `@` for an address that claims
  nothing". `$$i`/`$$m` are the two spellings that STATE intent; the
  analysis follows exactly the shapes it can honour and refuses the rest by
  name (the D-019/TOS pattern: an opt-out is greppable, never silent).
- A claim of a place with no named root refuses (BORROW-014); a claim of a
  place rooted at a limited binding stays TYPE-063, at a view TYPE-066, at a
  `fixed` binding TYPE-071 (§2.8).

### 2.3 Plain-address holders (the `@` side, tracked where it is spelled)

`T->:h = @place;` and `h = @place;` (a whole-value `@` into a pointer local)
make `h` a **plain-address holder** of that place for `h`'s scope, exactly
as a claim holder; a plain address claims nothing, so two of them never
conflict — but a CLAIM on storage a plain-address holder reaches in scope
is a claim that cannot be honoured (`p` may write through `h` at any time).
A plain address in any other position (a call argument, a struct literal,
a Rule-A call result, a copy of a holder) is NOT tracked: it is exactly as
free as today. The compiler's own context structs (`Escape:esc =
escape_init(@f.g.ast, …)`) are Rule-A holders and stay invisible.

### 2.4 Conflicts (checked at every access whose root is a live party's root)

Let P be a live party (a shared claim, an exclusive claim, or a plain-address
holder; path p) and A an access (read or write-capable; path a) with the
same root:

| P is … | A is a read | A is write-capable |
|---|---|---|
| a shared claim (`$$i`) | no conflict | conflict |
| an exclusive claim (`$$m`) | conflict | conflict |
| a plain-address holder (`@`) | no conflict unless A is a claim | conflict only if A is a claim |

A conflict with **statically disjoint** paths is nothing; with **statically
overlapping** paths it is `NITPICK-BORROW-013` at A, naming P's spelling
and site ("the exclusive claim `$$m arr[1i64]` at 12:17 is live until the
end of its block; end it with a block, or spell `@` for an address that
claims nothing"); with **computed** paths it is a **guard site** (§2.5 —
at step 1, before the guard exists, BORROW-013 with a message that says
the pair is computed). A write-capable access whose root is a SHARED
claim's holder (`<-p = v`, `p.f = v`, `$$m p.f` with `p = $$i x`) is
BORROW-013: shared means readers. Two shared claims coexist; a shared claim
and a read coexist.

**What this checks and what it does not.** Exclusivity is decided among
accesses that spell the SAME ROOT. Two pointer bindings that alias one
storage (`f` and `g` both pointing at a struct) are two roots, and a claim
through one is not seen from the other — a syntactic path analysis cannot
know two names alias, and making every pointer parameter exclusive would
refuse the compiler's own architecture (every walker holds pointers to
shared state). Stated in the reference: a `$$i`/`$$m` claim is a promise
about every access through the root it names; `@` and Rule-A holders stay
outside it, greppably.

### 2.5 The guard (a check in every build — D-068's shape; the departure from the prototype's model, S-61)

At a guard site — an access A whose path is computed against live parties
P₁…Pₙ — the emitter checks at run time that A's storage and every party's
storage are DISJOINT, and traps `BorrowOverlap` (−4116, a new prelude
identity) when they are not; the reach analysis arms `BorrowOverlap`
wherever a guard site exists, so `failsafe` names it. The test is over
BYTE RANGES, not indices: after `addr_of` computes A's address `%q` (the
element or field address, bounds guard included), with `sq` the size of
A's place type and, for each party, `%p` its address and `sp` the size of
its place type,

```
%qe = getelementptr i8, ptr %q, i64 sq        ; one past A's storage
%pe = getelementptr i8, ptr %p, i64 sp
%c1 = icmp ult ptr %p, %qe                     ; p begins before q ends
%c2 = icmp ult ptr %q, %pe                     ; q begins before p ends
%ok = and i1 %c1, %c2                          ; the ranges intersect
… (or over the parties) …
br i1 %ovl, label %alias.trap, label %alias.ok
alias.trap: call void @npk_chain_reset(i32 SITE) / call void @npk_trap(i32 -4116) / unreachable
```

which is exact for every shape the paths can take (an element against an
element, a row against an element of the row, a field of an element
against the element) with no captured indices, no frozen index names and
no frame slot: a held party's address is the value in its HOLDER's slot
(loaded at the site; an alloca or a frame slot alike, through the function
emitter's binding table — looked up by the holder's DECLARING STATEMENT,
which `fnem_bind` gains beside the name, since a nested block may shadow
the name), and a call-duration party's address is the SSA value the same
statement computed (recorded by `emit_addr_op` when the analysis marked the
claim as a party; D-178 keeps an `await` from separating the two). When the
manifest discharged the site's `disjoint` row the compare is not emitted —
the `loop-step` shape, NOT an `llvm.assume` over pointers. A zero-sized
place never intersects anything.

Cost: one compare pair per party at a guard site, and guard sites exist
only where a computed-index access meets a live claim — none in the
compiler's own tree after §2.9's edits.

### 2.6 The obligation (`disjoint`, kind 20 — S-61)

The catalogue row: **`disjoint`** — "two accesses of one root through
computed indices name disjoint storage while a `$$i`/`$$m` claim is live
(D-286): the byte-range compare at the second access, `BorrowOverlap`; a
static overlap is the checker's (BORROW-013) and has no row" — guard `yes`,
rows from 1.5.5. The row at a guard site: for each party, walk the common
prefix of the party's path and the access's; every index pair with a
computed member contributes `(not (= tP tQ))`; a numeral pair that is equal
contributes nothing and an unequal one makes the party disjoint (its
disjunct `true`); the party's goal is the `or` of its disjuncts, the row's
goal the `and` over the parties — a `not` inside a term is the encoder's
`smt_app1("not", …)`, the terms `Term`s. `tQ` is the access's index term at
the site; `tP` is the party's index term CAPTURED WHEN THE CLAIM WAS
ENCODED (a side list on the encoder keyed by the claim's expression id: the
terms of the path's index expressions in order — a term names versioned
symbols, and a version is never reused, so the capture is exact whatever
was assigned since: `$$m arr[i]` held, `i = i + 1`, then `arr[k]` compares
`k` with `i`'s OLD version, which is what the held address denotes). A term
that is not `ok` is opaque and the row `open` — the guard stays, as for any
other kind. The fact is a hypothesis after the site (`hyp_push`, quiet and
proposition rules as `record_shift`'s); ONE row per guard site
(`llctx_elided` matches any row of the site). Both runners: `disjoint` in
`Z3_KINDS`, `-4116` in `TRAP_OF_KIND` and `trap_of_kind`/`kinds_of_trap`;
not an `ASSUME_KINDS` member; `ok_has_guard(20)` true. The verify tests
name `disjoint discharged N` / `disjoint open N`.

Why the guard is exact where the row is indices: the ranges intersect iff
the paths overlap (given in-bounds indices, which the bounds guards before
the site ensure), and the paths overlap iff every index pair along the
common prefix is equal — the row's negation. Discharging the row is
therefore exactly the licence to drop the compare.

### 2.7 DEF-42 — rule 3 for local holders (D-004's text, no new decision)

At an assignment `h = value` where `h` is a local (the bare-name branch of
`escape_assign`) and the value carries a borrow the analysis marks (a
local-rooted `@`/`$$` borrow, or a marked holder copied), the holder's
declaring scope must not be an ANCESTOR of the root's (or of the copied
holder's) declaring scope: if the root's scope walks up to `h`'s scope
before reaching the function's, `h` outlives the storage and the assignment
is `NITPICK-BORROW-002` with its own sentence ("`p` is declared outside the
block that declares `x`, so it outlives the storage the borrow names (D-004
rule 3)"). A declaration-initialised holder is always in scope of its roots
(a root must be in scope at the declaration); a parameter root is in scope
everywhere; a param-rooted borrow is not marked (0.8.1) and its copies pass.

### 2.8 DEF-43 — a `fixed` binding has no address (S-62; `NITPICK-TYPE-071`)

`@`, `$$i`, `$$m`, and the implicit address a pointer-receiver method or
UFCS call takes, of a place rooted at a `fixed` binding — local, parameter,
global — refuse at the checker, beside TYPE-063 (the same reasoning, the
same sites: `type_expr.npk`'s address and borrow arms, `type_members.npk`'s
receiver site): the pointer type carries no mutability, so an address of an
immutable is a write path no rule sees; D-211 made every module binding
`fixed`, so a global's address was a write into read-only memory. Pass a
`fixed` value by value, or declare it plain. A `fixed` binding's field or
element read stays a read.

### 2.9 The tree's edits (measured; every site of §1)

- `diagnostics.npk` `diaglist_sort`: the held `$$i list.items[j - 1i64]`
  is read once (`span_before(cur.span, prev.span)`) and then the same
  element is MOVED OUT (`move(list.items[j - 1i64])`) while the claim is
  live — a real conflict of the kind the rule exists to name; the read
  moves into an inner block that ends before the move (`bool:before = …`).
- `emit_program.npk` 2194, 2228 and `ir_expr.npk` 204: a held `$$i` of an
  element under a pointer parameter (`w`, `t`) that is then PASSED to a
  callee while the claim lives (`irw_write(w, …)` — an access of the whole
  root, write-capable) or is spelled where the root is used only after: the
  two `emit_program` sites spell `@` (no claim is meant: the writer is
  handed on); `ir_expr.npk` 204 keeps `$$i` (the root `t` is not accessed
  while `data` lives). `diagnostics.npk` 121 keeps `$$i` (`list.count` is a
  different field; `i = i + 1` writes no part of `list`).
- `ir_func.npk` 1127: `pass ($$i fe.lflags.items[…]);` — a claim in a
  `pass` value (BORROW-014) — spells `@` (D-117: a parameter-rooted borrow
  may travel up one frame; the claim cannot).
- `npkc.npk` 159, 169: call arguments; nothing else in either call reads
  `f`; unchanged.
- `tests/accept/borrows.npk` `passes_binding_down`: `int32->:q = $$i x;`
  beside a plain-address holder `p` of `x` — a shared claim over storage a
  plain address reaches (BORROW-013 under §2.4) — spells `@` (the case
  tests the escape rule, not a claim).

## 3. Questions for the user (OPEN_DECISIONS §2e S-60…S-62; §2f DEF-42, DEF-43)

**S-60 — the rules of §2.1–2.4 and §2.9's spelling riders**: `$$m`
exclusive, `$$i` shared, `@` a plain address that claims nothing but
counts as a write-capable access; lifetimes lexical (a call argument for
its call, a pointer local's value for the holder's whole scope; NLL and
two-phase borrows decided OUT — D-004's "no lifetime inference" applied to
the aliasing half, and the prototype's `LivenessAnalyzer` is the machinery
D-004 declined); a claim stands only as a whole call argument or a pointer
local's whole value, a holder is used and not copied, every other position
refuses by name (BORROW-014); a claim on storage a plain-address holder
reaches refuses (BORROW-013); the same-root limit stated; the qualifier
spellings `borrow_imm`/`borrow_mut` STRUCK from AST_REFERENCE (the
operators are the spelling, and §2.1's example is rewritten in it).
**Recommendation: ratify as written.** Alternatives costed: non-lexical
lifetimes (last-use) need a liveness analysis with loop back-edges — the
shape the suspend walk found two holes in (D-191, 1.3.8) — for a gain of
fewer braces; exclusivity for `@` refuses the compiler's own pipeline
(1,428 sites, every context struct).

**S-61 — the check's shape and the new kind**: the computed-index conflict
is a RUNTIME GUARD in every build (`BorrowOverlap`, −4116; the byte-range
compare of §2.5) that the verified build ELIDES when the `disjoint` row
(kind 20, §2.6) is discharged — D-068's shape, the `limit`/`shift-range`
precedent — and NOT the prototype's model, where the plain build refuses
the pair and only `--verify` accepts it. **Recommendation: the guard.**
D-068's three reasons apply verbatim (a safety property never depends on a
flag; the literal reading makes the shipped binary the odd one; a reader of
`$$m arr[i]` could not tell whether the program compiles without knowing
the build); the guard is one compare pair at sites the tree does not have;
an `open` row keeps its guard exactly as an `open` `limit` does. The
alternative — a compile-time refusal the verified build lifts — makes
program VALIDITY depend on the flag, which the language has not done
anywhere (a `prove` is the reverse: the verified build is the stricter
one). The README's 1.5.5 row ("the conservative refusal Z3 then relaxes")
is read as the static half (BORROW-013 stays a refusal) plus this.
Also under S-61: the kind's name `disjoint`, the identity's name
`BorrowOverlap`, and the elision as removal without an `llvm.assume` (the
`loop-step` precedent; an assume over pointer inequalities buys the
optimiser nothing the belt needs).

**S-62 — DEF-43's rule**: a `fixed` binding has no address (TYPE-071,
§2.8). **Recommendation: ratify.** It costs the tree nothing (89 `fixed`
bindings, none address-taken), and the alternative — tracking every
pointer to a `fixed` through every call — needs a read-only pointer type
the language decided against. The uncontrolled crash is fixed by the
refusal alone.

DEF-42 (§2.7) is a defect under D-004 rule 3's text and lands at step 0
without a decision.

## 4. What lands (four steps; each a cumulative prefix under a full harness, D-228)

### Step 0 — DEF-42: rule 3 for local holders (no decision needed)

1. `escape.npk`, `escape_assign`, the bare-local branch: before
   `escape_mark`, collect the value's borrow ROOT SYMBOLS and copied
   HOLDERS (a walk shaped like `borrows_all_rooted_at`: `@`/`$$` operands
   through `place_root`; an identifier that `escape_binding` says holds;
