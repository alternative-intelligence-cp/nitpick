## 1. Where it starts (measured 2026-09-17 on `b7d60dc`; kernel 7.0.0-30; the pinned `llc`/`ld.lld` flags)

- **The kernel-effect table** is `tx_syscall` (`npkg/floor_smt.npk` ~3089–3147): per syscall NUMBER, whether the
  kernel writes user memory, through which argument, and how much. VERIFICATION_REFERENCE §9.2 restates it in prose
  by hand, and ends: "the table is the reviewer's to read against the kernel's documentation" — unchecked by design;
  TCB.md §5's eighth acceptance asks a reader to ACCEPT it. Measured through the RAW syscalls with sentinel-filled
  buffers, two sentinels so a written byte equal to one is still seen (`probes/kernel_effects_probe.py`):

  | row | the row's claim | the kernel, measured | verdict |
  |---|---|---|---|
  | `read` 0 | `[buf, buf+result)` | 5 of 64 → `[0,5)`; EOF → nothing; EBADF → nothing | agrees |
  | `getrandom` 318 | `[buf, buf+result)` | 8 → `[0,8)`; 100 → `[0,100)` | agrees |
  | `clock_gettime` 228 | 16 bytes | success `[0,16)`; EINVAL → nothing | agrees (over on failure; harmless) |
  | `epoll_pwait` 281 | `12·result` | one ready → `[0,12)`, events @+0, data @+4; none ready → nothing | agrees — the packed layout is right |
  | `sched_getaffinity` 204 | `arg2` (the REQUESTED length) | returns 8, writes `[0,8)` of 128; all 960 sentinel bits of the tail survive | **over-approximates — and hid DEF-52** |
  | `rt_sigaction` 13 | `arg4` (the sigset size, 8) at `oldact` | writes `[0,32)` to a non-null `oldact`; 32 on untouched | **WRONG, the unsound direction**; latent: the floor's one call (`npkrt.ll:251`) passes `oldact = 0` |

  No recorded verdict rests on either wrong row. The rows that claim NO memory effect hold FOR THE OPTIONS THE FLOOR
  PASSES (`prctl` 1 and 38 — `PR_SET_PDEATHSIG`, `PR_SET_NO_NEW_PRIVS`; `arch_prctl` 4098 — `ARCH_SET_FS`; `futex`
  128/129/9/137 — wait, wake, wait-bitset; `mmap` flags 34 — private anonymous, no `MAP_FIXED`; `epoll_ctl` 1/2/3),
  but the table is keyed by NUMBER alone: `ARCH_GET_FS`, `PR_GET_NAME` and `PR_GET_PDEATHSIG` WRITE user memory, and
  a floor edit that used one would be modelled as writing nothing — silently, the unsound direction again.
- **DEF-52** (OPEN_DECISIONS §2f): `npk_hardware_concurrency` hands the kernel an `alloca [16 x i64]` it never
  zeroes and popcounts all sixteen words; the raw syscall writes `result` bytes and nothing zero-fills the rest (that
  is glibc's wrapper). Reproduced deterministically (`probes/hwconc.ll`, the `runtime/tests/frames.ll` shape: dirty
  8 KiB of stack with `0xFF`, ask the floor, compare with the truth from a zeroed mask): **exit 1, 3 of 3, the floor
  answering 1008 on this 48-thread machine (48 + 960)**; on a scratch copy of the floor with the mask zeroed first,
  exit 0, 3 of 3, answering 48. Unreachable from a program today: `emit_program.npk:968` DECLARES the symbol in every
  module and no builtin row reaches it — which is why nothing ever executed it (S-72).
- **DEF-53, found by auditing the defect's class.** The floor has 15 `alloca`s; all 15 were read
  (`.internal/handoff_s7/ALLOCA_AUDIT.md`, the table this plan commits into the execution record). (A) written before
  read: one failure, DEF-52. (B) EIGHT of the fifteen sit OUTSIDE their function's entry block, and an `alloca`
  outside the entry block is dynamic — it moves the stack pointer each time it executes and nothing returns the space
  before the function does. Measured (`probes/loopalloca.ll`: `alloca i64` in a loop body, 4,000,000 iterations):
  **SIGSEGV at `llc -O0` AND at `llc -O2`**. Two of the eight are inside loops: `npk_windup_all`'s `%onew` (16 bytes
  of stack per pinged task — and the function runs when a join's deadline has EXPIRED, the degraded state) and
  `npk_thread_join`'s `%ts` (16 bytes per return of its futex wait). A child thread's stack is 2 MiB: 131,072
  iterations from the guard page, then SIGSEGV inside the runtime with no `failsafe` — the uncontrolled stop. Remote
  in count, exact in kind. One more is bounded at 16 a call (`npk_park_sleep`'s `%tmp8`), five execute once a call.
- **The rule already exists — for the emitter.** D-173 (SETTLED, 1.0.9a: "allocas are hoisted to the entry block")
  was written when the seed-built compiler segfaulted on exactly this, and `check_allocas_hoisted` (harness) /
  `ir_allocas_hoisted` (`npkg/irscan.npk`) have held it over EVERY emitted module since: `build/npkc.ll` holds 60,776
  allocas and ZERO outside an entry block. The belt was never pointed at `runtime/npkrt.ll`. Pointed there, UNCHANGED,
  it reports the same eight on `b7d60dc`'s floor and none on the fixed one. **DEF-53 is D-173 not extended to the
  floor** — a rule written for one spelling of a construct and owed to the other, the house lesson again.
- **`llvm.memset` under the artifact's flags**: at the pinned `-O0` EVERY `llvm.memset` — 8 bytes included — lowers to
  a CALL of the floor's own byte-loop `@memset`; at `-O2` to inline stores (`z8` 1, `z16` 2, `z128` 9, `z192` 13).
  `npk_mono_now` and `npk_sl_wake_due` run at every executor step, so a rule that memsets EVERY alloca taxes the hot
  path to zero storage the floor already fully stores. The rule of §2.2 is written from this number.
- **E-3, by reading** (`npk_park_sleep`'s nine epoll blocks against `park-unpark.model:57`): (1) the floor's `epoll`
  block returns WITHOUT draining the eventfd when the park word is set, and the step clears `evr` on that path too —
  the model explores fewer wakes than reality: sound for its four safety predicates, not what the blocks do; (2) the
  eventfd is registered level-triggered (`npk_io_register`: `events = 1`, no `EPOLLET`), so the collapsed window
  between the word's load and `epoll_pwait` is sound as argued; (3) **the step NAMES the `due` block (a descriptor's
  event stamps its frame due) and models nothing of it** — no I/O-readiness variable exists, `arm` likewise names all
  ten blocks of `npk_io_register` for one bit — so no predicate can speak about the I/O wake path. The correspondence
  belt is green because a block is named; it cannot see that nothing is said.
- **Builtin names are a resolver fallback** (`resolve.npk` ~133: a name is looked up in scope first, and only an
  unbound one is excused by `is_builtin_name`). Measured: a program declaring `func:mono_now = int64() never fails {
  pass 7i64; }` and calling `raw mono_now()` exits **7**; one declaring `func:read_file = int64(int64:x)` (the
  builtin is `string → Result<string>`) and calling `raw read_file(41i64)` exits **42** — checker and emitter both
  follow the BINDING. So adding a builtin breaks no program, and shadowing one is consistent, not a defect. Blast
  radius of refusing it, over BUILTIN_REFERENCE's 65 names: **0 module-level functions in `src/`, `lib/`, `npkg/`,
  `tools/`, `tests/`, and 0 in `nitpick-libs`** (the regex's nine hits are trait METHODS `read`/`write` — a per-type
  namespace — and one grammar fixture).

## 2. The design

### 2.1 DEF-52 — the mask is defined before the kernel sees it
`npk_hardware_concurrency`'s entry block gains `call void @llvm.memset.p0.i64(ptr %mask, i8 0, i64 128, i1 false)`
before the syscall (the floor already uses the intrinsic at three sites and declares it). `llvm.memset` and not
`npk_zero`: the translator reads the intrinsic as a POINTWISE DEFINITION of the memory after — exact, nothing to
instantiate — where `npk_zero`'s loop invariant over a free offset would need one `(inst j k)` per byte to say that
sixteen loaded words are zero. A cold path; the call's cost is nothing against the syscall beside it.

### 2.2 The stack rule (DEF-53, and DEF-52's class with it)
**Every `alloca` of the floor sits in its define's ENTRY block (D-173, extended to the floor), and is FULLY DEFINED
there before any other use — by `store`s that cover every byte of it, or by one `llvm.memset` of its whole size (the
new half, DEF-52's class).** One rule with no exceptions to remember (blueprint facet 1); both halves syntactic, so
belts hold them; and the first half is NOT a second mechanism — it is D-173's own check, run over one more file.
Applied per alloca (the audit's numbering):

| # | function · alloca | today | becomes |
|---|---|---|---|
| 1 | `npk_start` · `%act [4 x i64]` | entry, four stores | unchanged — already conforms |
| 2 | `npk_ch_wake_one` · `%one i64` | `ping` | hoisted; `store i64 1` hoisted with it (a constant) |
| 3 | `npk_thread_join` · `%ts [2 x i64]` | `wait`, in the loop | hoisted; `%sec`/`%rem` and their two stores hoisted with it (`%dl` is a parameter — the loop stops recomputing them) |
| 4 | `npk_hardware_concurrency` · `%mask [16 x i64]` | entry, undefined | §2.1's memset |
| 5 | `npk_sl_wake_due` · `%cs ptr` | entry, one store | unchanged — already conforms (HOT: no memset) |
| 6 | `npk_windup_all` · `%onew i64` | `pingw`, in the loop | hoisted; `store i64 1` hoisted with it |
| 7 | `npk_park_sleep` · `%ts [2 x i64]` | `futex` | hoisted; `%sec`/`%rem` and the stores hoisted (`%at` is a parameter) |

**The belts.** FIRST HALF: one line in each runner — `check_allocas_hoisted(floor_text, "runtime/npkrt.ll")` beside
the floor's `undef` ban in `harness.py`, `ir_allocas_hoisted(...)` beside `ir_no_undef` in `npkg/build.npk`. Nothing
new is written. SECOND HALF, new: `floor.check_stack` (harness, `check_floor_stack_current` with the floor's other
whole-tree belts) and `npkg/floor_stack.npk` (`floor_stack_current`, run by `npkg verify` before a solver is spawned
and by `tools/floorspec.npk`'s default mode), one answer in both — measured byte-identical on `b7d60dc`'s floor. For
every define: between an alloca and its first use that is not a defining line, the entry block's stores through
constant-offset `getelementptr`s of it (or through the alloca itself) and its whole-size memsets COVER `[0, sizeof)`,
else `alloca-not-defined`. A defining line is one of exactly four forms (the alloca; a `getelementptr` of the ALLOCA
ITSELF at a constant offset, `[N x T], ptr %a, i64 0, i64 K` or `i8, ptr %a, i64 K`; a `store` of an `iN` or a `ptr`
through it or through such an offset; the whole-size memset intrinsic); any other line naming one is a USE. It looks
only at the entry block because D-173 says that is where every alloca is. Self-check cases in both runners, each with
its control: `alloca-not-defined` (a floor copy whose mask loses its memset), and `floor-alloca-not-entry` (a floor
copy with an alloca moved into a loop — proving the floor is now REACHED by D-173's check, which is the defect).
**THE GATE** (D-280's, as 1.5.6 held it): every floor row discharged today stays discharged — #12 and #14 change
functions that HAVE rows (`npk_mono_now`, `npk_hs_put_dec`); a row that regresses is a stop sign, investigated, never
weakened. Hashes move (the SMT text does), so `runtime/npkrt.obligations` is re-recorded in the step (D-040).

### 2.3 The kernel-effect table becomes ONE authority, held to the kernel
- **The authority** is a marked region in VERIFICATION_REFERENCE §9.2, `<!-- BEGIN kernel-effects -->` — one row per
  (number, option): `| nr | name | option: arg = values | effect | buffer arg | length | condition | count bound |`,
  the length one of `result`, `result*12`, a numeral, and the condition one of `result >= 0`, `result > 0`,
  `arg3 != 0 and result = 0`. D-201's pattern exactly: a reference document's marked region parsed STRICTLY
  (`gen_tables.py` hard-fails on a row it cannot read), generated consumers, `--check` held by
  `check_generated_current`.
- **Generated consumer 1**: `npkg/floor_kernel.npk` — `ke_known(nr)`, `ke_effect(nr)`, `ke_buf_arg(nr)`,
  `ke_len_kind(nr)`/`ke_len_num(nr)`, `ke_cond(nr)`, `ke_bound_arg(nr)`, `ke_option_arg(nr)`,
  `ke_option_ok(nr, v)`. `tx_syscall` reads them and keeps no list of its own. **An option-dependent row demands a
  NUMERAL option inside the row's set**, else the translator refuses by name (`a syscall option the kernel-effect
  table has no row for`) exactly as it refuses a number without a row today. The two wrong rows are corrected AT THE
  AUTHORITY: 204 writes `result` bytes at `arg3` when `result > 0`; 13 writes 32 bytes at `arg3` when `arg3 != 0` and
  `result = 0`.
- **Generated consumer 2, the instrument**: `tests/backend/programs/kernel_effects.npk`, an ordinary program both
  runners already run (no new stage, nothing for `mkpara.py` to learn). Hand-written probes — a sentinel-filled
  `wild` buffer, the raw `sys(...)`, the changed span read back byte by byte (`lib/nfs.npk`'s `#ptr_add` + `<-`
  idiom), two sentinels — against a GENERATED region of claims (`// BEGIN generated: kernel-effects`, the prelude's
  `scalar-impls` precedent): for every write-region row the measured span must EQUAL the claimed one on the success
  path and be EMPTY on the failure path. Equality, not containment: an over-approximating row is sound and is what
  hid DEF-52. One exit code per row, so a red run names the row. The probe runs on the kernel the suite runs on —
  which is the claim: the table is held to THIS kernel on every run, in both runners, instead of accepted.
- **What no probe reaches is said in words** (TCB.md §5, S-74): `exit`/`exit_group` (the path ends), `clone`/`execve`
  (asm, never translated), the rows' FAILURE paths beyond the ones probed, and that "no memory effect" is a statement
  about BYTES, not mappings — a load after `munmap` is modelled as the old bytes, so a use-after-unmap is outside the
  model by construction.
- **`npk_hardware_concurrency` gets rows.** `llvm.ctpop.i64` joins the translator's vocabulary as the uninterpreted
  function `ctpop64` with `0 <= ctpop64(x) <= 64` and `ctpop64(0) = 0` (sound: both hold of every popcount; nothing
  else is assumed). Its section: `(loop loop (unroll 16 exact))`, `(ensures (>= result 1))`, `(ensures (<= result
  1024))`, and the BITING row `(ensures (=> (= z 0) (= result 1)))` — refuted on today's floor (the kernel wrote
  nothing, the garbage sums to anything), discharged on the fixed one. The pre-fix refutation is measured and
  recorded as the row's negative control. If the biting row exhausts the budget it becomes a `(residue "…")` sentence
  by D-288's rule and `runtime/tests/hwconc.ll` alone holds the fix; the record says which.

### 2.4 E-3 — the faithful step, and the I/O wake path modelled
- `park-unpark`'s `epwait`: `(evr (ite (= pw 1) evr 0))` — the early-out keeps the eventfd readable, as the block
  does. More wakes is the safe direction: every row must stay `unsat` and every control `sat`; re-recorded.
- **A seventh model, `reactor-io`** (r6's rule: model the primitive, never grow the big model — `park-unpark`'s
  largest row already sits at 12.9M of the 20M budget), of `npk_io_register` (entry create mkev addev arm mod ck1
  duenow out), `npk_park_sleep` (epoll epgo deliver dloop done1 drain due dnext out), `npk_io_unwatch` (entry del
  out), `npk_step` (the sweep that runs a due task): one executor, one task, one descriptor and the kernel.
  State: `reg` (0 none, 1 armed one-shot, 2 fired-and-disarmed), `ready` (the descriptor readable), `wa`
  (0/1/deadline as in `park-unpark`), `alive` (the frame not yet freed), `watched` (the deferred `io_unwatch` has not
  run), `parked`, `epc`. Bad predicates: **stamp-after-free** (a `due` store into a frame with `alive = 0` — the
  hazard `npk_io_unwatch`'s own comment names), **event-consumed-task-asleep** (the one-shot fired and disarmed, the
  task not due and the executor parked with no deadline sooner), **declined-but-asleep** (the kernel refused the
  watch — EPERM, EBADF — and the task is not due: `duenow`'s reason to exist). Controls, each `sat`: drop the `due`
  stamp; free the frame before the unwatch; drop `duenow`. Depth and preemption bound the SMALLEST that decide with a
  margin, measured in the step as 1.5.6's were. `TCB.md`'s `modelled (…)` dispositions regenerate.

### 2.6 A program may not declare a builtin's name (S-73)
D-239 already says it for the type namespace: a name the compiler or the prelude owns cannot be declared by a
program. The builtin table's names are the compiler's, in the FUNCTION namespace: a module-level `func:` (any
modifier) whose name is a builtin's is `NITPICK-RESOLVE-001` at the declaration, naming the builtin. Methods are
exempt — `Writer.write` is a per-type namespace, reached through a receiver, and can never be mistaken for the bare
call. An import cannot bring one in, because its declaration was refused where it was written. One predicate
(`is_builtin_name`, the generated table) read by the loader's owned-names check; `tests/modules/rejection/
owned_builtin_names.npk` (a plain function, a `pub` one, an `async` one, one inside an inline module; a METHOD of the
same name accepted). **This IS the library listener's class — a new refusal — so `nitpick-libs_s4` is told, with the
code and the measured zero sites in its own tree, BEFORE the step lands.**

### 2.7 A callable binding may not take a builtin's name (S-76 → D-296; added 2026-09-17)
Measured at step 4: `func int64() never fails:path_exists = eight;` makes `raw path_exists()` call the local. The
rule is decided by the binding's TYPE, in the CHECKER, at every site that types a binding — a local
(`check_var_decl`), a parameter (`check_function`: a function's, a method's, a bodiless signature's — one rule), a
`for` binding (`check_for`), a pattern's bindings (`type_enum_bindings`, `type_struct_bindings`, both reached through
`type_pick_rules`, the one function both `pick` spellings call). NOT by the annotation's spelling: a pattern binding
has none. One helper, `check_callable_name(e, name, type, what, span)`: `type_is_func` and `is_builtin_name` →
`NITPICK-RESOLVE-001` (the loader's code, reported by the checker as D-275's RESOLVE-002 is). Exempt: a binding of
any other type; a function-typed FIELD; methods. A struct pattern binds its field by name, so destructuring a
function-typed field named after a builtin is refused — stated in the decision and in the message.
`tests/types/rejection/callable_builtin_names.npk`: one refusal per site (both `pick` spellings, both pattern kinds)
and the accepted shapes in the same file, the library listener's negative case among them (a function-typed field
named `open`, declared and called through its receiver in both call spellings). The listener gets the forecast with
its code BEFORE any of it is written (sent as F4).

### 2.8 The function-value corner: DEF-54, DEF-55, DEF-56 (found writing §2.7's test; added 2026-09-17)
Three places where a rule written for one shape of a function value was never given to its twin (OPEN_DECISIONS §2f
has each in full):
- **DEF-54** (`emit_call`, `ir_expr.npk`): the callee decision is inverted to `emit_pipe`'s — DIRECT only for a
  symbol that is a declared function (`SYM_DECL` + `DeclFunctionDecl`), INDIRECT for everything else that is a
  symbol. A pattern-bound function value is then loaded through its view and called. Test, a PROGRAM (both runners,
  both legs): `tests/backend/programs/fn_value_pattern.npk` — an enum payload and a struct field, the statement and
  the expression form of `pick`, the lending and the consuming form, each called and its answer summed into the exit
  code.
- **DEF-55** (`unwrap_licence_of`, `type_expr.npk`): the `MethodCallExpr` branch falls back to the recorded callee
  FUNCTION TYPE when no method declaration was recorded, exactly as the `CallExpr` branch does — `raw o.f(x)` and
  `raw (o.f)(x)` get one answer; `drop` shares the function. Test: both spellings in one accepted unit, and the
  may-fail field still refused in both (the control).
- **DEF-56** (`same_after_self`, `type_trait.npk`): a function-type case — two function types agree when their
  returns agree (through `same_return`, so `Self` in a callback's signature substitutes), their parameter counts
  are equal, their parameters agree pairwise by the same walk, and their `never fails` bits are EQUAL (an impl may

## 5. Decisions taken at planning (numbered so the record and the commit messages can cite them)

- **L-1 — `llvm.memset`, not `npk_zero`, defines the mask** (§2.1): a pointwise definition to the translator.
