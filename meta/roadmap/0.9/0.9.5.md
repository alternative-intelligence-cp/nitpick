# 0.9.5 — `tbb` arithmetic and the cast sentinel checks

**Cycle 0.9.** The Twisted Balanced Binary types — the fail-operational arithmetic
the robotics path depends on (SAFETY_ARCHITECTURE). This is the most safety-dense
lowering in the cycle, and it closes the third of the four Theme-A rung holes (the
int⇄tbb cast that currently forges taint silently).

## What lowers

- **`tbb8/16/32/64/128/256`** arithmetic with **saturation to ERR** on overflow
  (the sentinel is the most-negative value; out-of-range results land there
  naturally), and **sticky ERR propagation**: any operation on an ERR operand yields
  ERR, overriding mathematical identities (`ERR * 0 = ERR`, `ERR - ERR = ERR`) —
  because an identity that erased ERR would defeat stickiness (D-008 §1, TYPE_REF §6).
- **Overflow-checked add/sub/mul** via `llvm.sadd/ssub/smul.with.overflow.iN` (which
  lower natively at 128/256 per D-011, so no libcall) — the checked forms that feed
  saturation.
- **Division/modulo by zero yields ERR** (not a trap — the tbb path degrades where
  the plain-int path traps, D-007; this is the fail-operational distinction).
- **Comparison or branching on ERR traps to `failsafe`** — `bool` has two values and
  cannot represent ERR, so the total rule cannot apply at control flow; ERR flows
  through data and stops at branches (D-008 §5). `is_err(x)` tests without trapping;
  a `pick` with an explicit `ERR:` arm matches it.
- **`pick` over a `tbb` selector requires an explicit `ERR:` arm** (D-008 §5.1,
  D-120) — `(*)` may not absorb ERR, or a tainted value steers a branch. The
  exhaustiveness analysis already enforces this (0.5.4); confirm the backend lowers
  the ERR arm.
- **Bitwise operators are rejected on `tbb`** — they can fabricate the sentinel
  (`~127i8 = -128`) or destroy it (`ERR & 0 = 0`). The checker refuses them; confirm
  no backend path emits them.

## The cast sentinel checks — closing Theme-A hole 3 (type-sys #2)

D-008 §6 and `OP_REFERENCE` require every int⇄tbb cast to carry a **sentinel/forge
check**: the ERR bit pattern differs at every width, so a straight bit-copy is
wrong (sign-extending `tbb8` ERR yields a *valid* `tbb32` value; truncating can
*fabricate* ERR). `type_cast.npk:162-163` claims "the backend must emit it and 0.7
lowers" — but same-width `int32 => tbb32` / `tbb32 => int32` hit the **no-op fast
path** (`ir_expr.npk:582-584`), so **taints can be forged or laundered today**,
unmarked as deferred. This is the third live rung hole.

Fix: **write the full tbb cast matrix** (`=>` / `=>!` × `tbbM` / `intN` / `fltN`,
each cell's trap-or-saturate result) and emit the sentinel check at every cast that
crosses the tbb boundary, including same-width — the same-width case is exactly the
one the fast path wrongly skipped. `int => tbb`: an input equal to the target's ERR
sentinel is either refused (`=>`) or saturated/trapped (`=>!`, decide per the
matrix). `tbb => int`: an ERR input has no valid integer image — trap or a defined
result, per the matrix. Also resolve the incoherent `=>!` "preserves ERR state"
text (meaningless when the target has no ERR state).

## The tbb-ordering contradiction (type-sys #3, resolve here)

D-008 §5 defines runtime ordering semantics for `a < b` on tbb (trap on ERR);
**D-093 rules ordering is int/float/char only** and the implementation enforces a
**compile-time refusal** of `<` on tbb. The reference docs still show the dead
D-008 reading. Resolve in favor of the implementation + D-093: **`<` on tbb is a
compile error**; the runtime ERR-trap applies to **equality** only; and state the
sanctioned magnitude-compare idiom (cast-to-int-then-compare traps on ERR — confirm
that is intended, or provide `tbb_cmp`). Annotate D-008 §5 as narrowed by D-093 in
the doc-sync pass.

## Tests

`tests/backend/programs/tbb.npk`: saturating add reaching ERR; ERR propagating
through a multiply-by-zero (asserting ERR, not 0); div-by-zero yielding ERR;
`is_err` testing without trapping; a `pick` with an `ERR:` arm; a branch on an ERR
value trapping with the tbb-branch failsafe code; a same-width `int32 =>! tbb32` of
the ERR bit pattern (asserting the sentinel check fires, not the old no-op).

## Done when

`tbb` arithmetic saturates and propagates correctly; ERR traps at control flow and
is testable via `is_err`/`pick ERR:`; the cast sentinel check fires at every tbb-
crossing cast including same-width (Theme-A hole 3 closed, verified by
`check_kinds_lowered_or_refused`); the cast matrix is written; the tbb-ordering
contradiction is resolved toward D-093 and the docs queued for correction.
