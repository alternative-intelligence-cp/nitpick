# 0.9.6 — The remaining scalars and forms

**Cycle 0.9.** The type-system tail: character widths, ranges, function values,
enum-tag casts, and the ternary — plus the fourth Theme-A rung hole (inline-`mod`
members shed by `emit_all`). Each is small; grouped because none is a subcycle's
worth alone and together they finish "every type lowers or refuses."

## What lowers

- **`char16`/`char32`** as `i16`/`i32` with the semantic-type operation set (compare
  and index, no arithmetic — the checker enforces it; confirm the backend agrees).
- **Range values `range<T>`** — **decision needed (type-sys #10):** `types.npk:372`
  lays out `{T lo, T hi}` with **no slot for the inclusive/exclusive bound** and no
  normalization rule, yet the backend lowers range values here. Decide: add a third
  field (a bound flag), or normalize at construction (store an exclusive `...` as
  `hi−1`, with the float/char edge cases stated). **Proposed: normalize to a
  half-open `[lo, hi)` at construction** (store exclusive; an inclusive `..` stores
  `hi+1`), which keeps the value two words and makes `for` iteration a single
  convention — but state the char/float edges (a `char32` range at the max codepoint,
  a float range where `hi+1` is meaningless → floats may not form ranges, confirm).
  Write the chosen layout in TYPE_REFERENCE and `tt_range` together.
- **Function values** (`func RetType(Params)`) as plain code addresses, one machine
  word, no environment (closures removed, D-018) — indirect `call` through the value.
  This is the first rung that needs indirect calls; D-087's parser support (0.2.8)
  has been waiting for it.
- **Enum-tag casts (D-140)** — `enum =>! intN` reads the tag; `enum => intN` stays
  refused (identity-as-quantity is an assertion); `intN => enum` stays impossible in
  both spellings (it fabricates a value that may be no variant, breaking `pick`
  exhaustiveness). **Audit note (type-sys #11):** these are absent from both
  reference docs — copy D-140's rules into `OP_REFERENCE §7` / `TYPE_REFERENCE §9.3`
  in the doc-sync pass, and state the width semantics of `enum =>! int8` (tag
  truncation).
- **Ternary `is (cond) : a : b`** — **decision needed (type-sys #20, safety):** it
  lowers to `select i1`, which **evaluates both arms**, so `is (b != 0) : a/b : 0`
  still divides by zero. Specify **branch-based lazy evaluation** (only the taken arm
  runs), not `select`, before lowering — and confirm the mandatory-parens spelling
  (`is (cond)`, the parser's form) against `OP_REFERENCE`'s unparenthesized example.

## Theme-A hole 4 — `emit_all` sheds inline-`mod` members (grammar #14d)

`emit_all` (`src/backend/emit_program.npk:206-243`) neither descends into a nested
`DeclModuleDecl`'s members nor refuses them — inline-`mod` code is **silently shed**
from emission, the exact failure the file's own comment forbids and D-115 requires
walks to avoid (`collect_impls` already complies). Add the nested-`mod` branch:
recurse into its members (matching `collect_impls`) so their functions emit, or
rung-refuse inline `mod` at emission if recursion is deferred — but not silence.
`check_kinds_lowered_or_refused` (0.9.1) flags this until closed.

## Tests

Programs exercising each: a `char32` compared and indexed; a `for` over a range
(proving the bound normalization); an indirect call through a function value; an
`enum =>! int32` reading the tag and the refused `=> ` / `intN =>` directions; a
ternary whose untaken arm would trap, proving lazy evaluation; an inline `mod`
whose function is called from `main`, proving `emit_all` no longer sheds it.

## Done when

Every remaining scalar and form lowers or refuses; the range-layout and ternary-
evaluation decisions are recorded and implemented; the inline-`mod` hole is closed
(Theme-A hole 4); `check_kinds_lowered_or_refused` reports **zero** kinds in the
third outcome — the invariant this cycle set out to establish.
