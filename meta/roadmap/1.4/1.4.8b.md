## Step 2 — D-238: the suites declared

### 2a. The schema

`[[test]]` entries carry `name`, `stage` (default `compile`), `kind`
(`compile` stage only: `positive`/`negative`/`diagnostic`), `paths` (an
array; `path` its one-element shorthand), `recursive` (default false). The
stages and what each demands are D-238's list: `parse`, `resolve`, `check`,
`accept`, `program`, `fixture`, `runtime`. `nitpick.toml` gains the entries
in the harness's run order, after the four existing ones:

- `grammar` — `parse`, recursive — `paths`: the harness's list, ONCE: the
  four targets' directories, `tests/grammar`, `tests/modules`, `tests/types`,
  `tests/analysis`, `tests/expansion`, `tests/derive`, `src/prelude`,
  `tests/accept`, `tests/backend`, `src`, `tools`, `lib`, `npkg`. The
  hardcoded sweep parsed six files twice (its three lists were concatenated,
  not united); the table sweeps each file once — a deliberate change, and
  the one place the before/after verdict lists may legitimately differ (the
  duplicates collapse). Record the six.
- `modules` — `resolve`, recursive, `tests/modules/rejection`.
- `types`, `analysis`, `expansion`, `derive` — `check`, recursive, their
  `rejection` directories.
- `fixtures` — `fixture`, `tests/backend/fixtures` (a `.c` file under a
  fixture path is built with the system C compiler `-O1 -Wall` as today: test
  tooling outside the TCB, D-149).
- `programs` — `program`, `paths = ["tests/backend/programs", "tests/conformance"]`.
- `runtime` — `runtime`, `runtime/tests`.
- `accept` — `accept`, recursive, `tests/accept`.

Membership stays with the stage (D-238): `resolve`/`check` skip a file with
no `expect-error` (a fixture another file imports); `compile`/`program` skip
a file some other file in the same suite imports (`imported_by_others`,
computed per suite as today).

## What bit the 1.4.8 executor (not in the memory files)

- `fails` and `end` are keywords (`never fails`; `end`) — each cost a build.
  The parser's error lands lines away from the name.
- D-004's conservative rule: a call handed `@local` yields a borrow-tainted
  value whenever its result type can hold a pointer, and such a value can
  neither be returned nor stored in a field. Pass read-only containers BY
  VALUE; consume what must leave a frame (`move T:p`); never build a struct
  from a value a `@local` call produced.
- Build `npkg` with `python3 bootstrap/harness/quickemit.py --keep npkg/main.npk`
  (`.internal/quickemit/p_main_npk`); run it from the tree root. `npkg test
  --only SUBSTR` iterates like the harness's, and both rebuild the compiler
  first (~3 min).
- The harness's stdout is block-buffered when redirected: a log shows nothing
  until the run ends. Watch `/tmp/npk-harness-*` for progress.
- `check_codes_centralised` scans `src/` and `tools/` only; a diagnostic code
  spelled in a test program or in `npkg/selfcheck.npk`'s case sources is not
  its business.
- Two runners writing into one `build/` cannot run concurrently in one tree;
  the harness uses its own tmp and may run beside `npkg test`.
