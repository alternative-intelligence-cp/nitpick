## Questions this batch raised, and where they went

- **D-230's seven families are not all bitmasks.** `whence`, `fcmd` and
  `advice` are enumerations — exactly one value per call, never combined with
  `|` — and the language already spells the first as the prelude enum `Whence`
  (1.1.12b), mapped to the kernel's numbers by a `pick` in the seek wrapper. A
  `whence` flags type would be a second mechanism for one job, and `F_GETFL |
  F_SETFL` would be admitted and meaningless, which is the error class D-044
  exists to close. **Put to the user** with the recommendation: `TY_FLAGS`
  carries the four bitmask families (`oflags`, `prot`, `mflags`, `fmode`);
  `whence` stays the enum it is; `fcmd` and `advice` become prelude enums of the
  same shape.
- **D-093's `range<T>` spelling is not resolvable** ("there is no type named
  `range`") though the decision says a range is a value of that type. A
  dormant decided spelling — raised as **S-8** in OPEN_DECISIONS §2e.
- **Typed flag constants as `fixed` module bindings** need the constant
  evaluator to fold `int32 =>! flags` in an initialiser (TYPE-035 refuses a
  cast today); the alternative is the never-fails-function idiom `src/` uses
  for every constant it has. Decided with step 5.
