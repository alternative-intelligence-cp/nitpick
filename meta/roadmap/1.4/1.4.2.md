## Step 0 — the reference normalized, the generator extended (LANDED)

**Full harness green**: 60 suites, 173 real-backend programs (each through
`opt -O2`), fixpoint byte-identical.

### What landed

1. **Every builtin row's Signature cell is one parseable syntax**, specified in
   the reference itself (a new blockquote before §1): `params → type`, the arrow
   U+2192, `->` inside a type being the pointer suffix, an optional `name:`
   suffix and `move` prefix, `()` for none. §3's `sys` table gained the
   Signature column it lacked. `dalloc`'s return is spelled `NIL` rather than
   `void`; `aalloc`'s parameters are parenthesised like every other multi-
   parameter row; `mutex` and `rwlock` were documented `()` and take the
   element's initial value, which is what their arms have always demanded.
2. **The return states the LANGUAGE type.** `Result<T>` appears exactly where
   the Fails column says may-fail, and never on a `never fails` row — so
   `string_concat` reads `(string, string) → string`, which is what D-201 §4
   makes it. The generator refuses a row where the two columns disagree, which
   turns the redundancy into a diff.
3. **`gen_tables.py` parses the rows strictly** (hard-fail on anything it
   cannot read) and emits, beside the existing `is_builtin_name` and
   `builtin_never_fails`: `builtin_sig_special`, `builtin_sig_count`,
   `builtin_sig_param`, `builtin_sig_param_move`, `builtin_sig_ret`. The nine
   irregulars are a generator-side list cross-checked against a `**SPECIAL**`
   marker in each row, so neither list can drift. The name scrape is now ROWS
   ONLY — the two prose regexes that also scavenged `` `name(…)` `` spans are
   gone, verified to change no name (54 before and after).
4. **`src/backend/ir/ir_runtime.npk` is GENERATED** from the same rows. The
   LLVM ABI is DERIVED from the language signature; the reference's rows carry
   an `**ABI:**` note only where the symbol departs, with a five-token
   vocabulary — `inline` (no floor symbol at all: 18 rows), ``sym=`…` ``,
   ``ret=`…` ``, ``args=`…` ``, and `envelope` (a never-fails builtin whose
   symbol still answers `{ T, i32 }`: `string_concat`, `int_to_string`,
   `buffer_new`). The nine emitter-only symbols — the arena and shared-arena
   accessors and `exit`, which are not builtins and have no language type —
   live in a new §2d region (`<!-- rtsyms:begin -->`) that feeds this table
   alone.
5. **`check_runtime_sigs_agree` now diffs the SPEC against `npkrt.ll`**, which
   is what D-201 §5 asked for. Its seed leg is unchanged and dies at 1.4.6.

### Found

- **The instrument's derived-inner cross-check had never once run.** It read
  `wrapped` out of `body` — a variable leaked from the parse loop above it — so
  every entry was told whichever entry the loop happened to parse LAST, and it
  read that entry by splitting the body on commas, which lands in the middle of
  `{ i32, i32 }`. Both halves are fixed (the flag is parsed per entry, matched
  against its own `", true, "` shape) and the check passes; with the old file's
  last entry (`exit`, unwrapped) the guard was simply always false. This is the
  0.6 lesson again: a check that has stopped checking looks exactly like a check
  that passes.
- **All 45 runtime entries derive byte-identically to the hand-written table** —
  symbol, return, wrapped flag, inner, and arguments — which is the validation
  that the derivation is right rather than merely plausible. The declare block's
  ORDER changed (sorted, where the hand table had five late additions appended
  out of order); nothing pins it and both fixpoint stages agree.

### Departure from D-201's literal text, recorded

D-201 §1 says `read`/`write`'s untyped word `ptr` becomes `wild int8->`. It is
`wild any->` instead, and `mcpy`/`mmov`/`memset`/`string_from_bytes`/
`driver_clone_exec` are given the same spelling. The reason is in the tree: the
prelude's `read(self.src.value, dest.ptr, dest.len)` passes a `uint8->` (a
slice's `.ptr` is a pointer to its element) while `nbridge` passes an `int8->`,
so a signature naming one of them refuses the other. `wild any->` is the
reference's OWN spelling for this — `ralloc` and `dalloc` have carried it since
the allocator was written — and it says the true thing about the floor: it takes
an ADDRESS and a byte count, and what the bytes are a pointer to is not its
business. No language rule changes; the acceptance is a named arm of the builtin
argument check (`builtin_arg_fits`), not a loosening of `fits`.
