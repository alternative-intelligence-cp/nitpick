## Step 0 — the reference normalized, the generator extended (LANDED)

**Full harness green**: 60 suites, 173 real-backend programs (each through
`opt -O2`), fixpoint byte-identical.

### What landed

1. **Every builtin row's Signature cell is one parseable syntax**, specified in
   the reference itself (a new blockquote before §1): `params → type`, the arrow
   U+2192, `->` inside a type being the pointer suffix, an optional `name:`
   suffix and `move` prefix, `()` for none. §3's `sys` table gained the
   Signature column it lacked. `dalloc`'s return is spelled `NIL` rather than
   `void`; `aalloc`'s parameters are parenthesised like every other multi-
   parameter row; `mutex` and `rwlock` were documented `()` and take the
   element's initial value, which is what their arms have always demanded.
2. **The return states the LANGUAGE type.** `Result<T>` appears exactly where
   the Fails column says may-fail, and never on a `never fails` row — so
   `string_concat` reads `(string, string) → string`, which is what D-201 §4
   makes it. The generator refuses a row where the two columns disagree, which
   turns the redundancy into a diff.
3. **`gen_tables.py` parses the rows strictly** (hard-fail on anything it
   cannot read) and emits, beside the existing `is_builtin_name` and
   `builtin_never_fails`: `builtin_sig_special`, `builtin_sig_count`,
   `builtin_sig_param`, `builtin_sig_param_move`, `builtin_sig_ret`. The nine
   irregulars are a generator-side list cross-checked against a `**SPECIAL**`
   marker in each row, so neither list can drift. The name scrape is now ROWS
   ONLY — the two prose regexes that also scavenged `` `name(…)` `` spans are
   gone, verified to change no name (54 before and after).
4. **`src/backend/ir/ir_runtime.npk` is GENERATED** from the same rows. The
   LLVM ABI is DERIVED from the language signature; the reference's rows carry
   an `**ABI:**` note only where the symbol departs, with a five-token
   vocabulary — `inline` (no floor symbol at all: 18 rows), ``sym=`…` ``,
   ``ret=`…` ``, ``args=`…` ``, and `envelope` (a never-fails builtin whose
   symbol still answers `{ T, i32 }`: `string_concat`, `int_to_string`,
   `buffer_new`). The nine emitter-only symbols — the arena and shared-arena
   accessors and `exit`, which are not builtins and have no language type —
   live in a new §2d region (`<!-- rtsyms:begin -->`) that feeds this table
   alone.
5. **`check_runtime_sigs_agree` now diffs the SPEC against `npkrt.ll`**, which
   is what D-201 §5 asked for. Its seed leg is unchanged and dies at 1.4.6.

### Found

- **The instrument's derived-inner cross-check had never once run.** It read
  `wrapped` out of `body` — a variable leaked from the parse loop above it — so
  every entry was told whichever entry the loop happened to parse LAST, and it
  read that entry by splitting the body on commas, which lands in the middle of
  `{ i32, i32 }`. Both halves are fixed (the flag is parsed per entry, matched
  against its own `", true, "` shape) and the check passes; with the old file's
  last entry (`exit`, unwrapped) the guard was simply always false. This is the
  0.6 lesson again: a check that has stopped checking looks exactly like a check
  that passes.
- **All 45 runtime entries derive byte-identically to the hand-written table** —
  symbol, return, wrapped flag, inner, and arguments — which is the validation
  that the derivation is right rather than merely plausible. The declare block's
  ORDER changed (sorted, where the hand table had five late additions appended
  out of order); nothing pins it and both fixpoint stages agree.

### Departure from D-201's literal text, recorded

D-201 §1 says `read`/`write`'s untyped word `ptr` becomes `wild int8->`. It is
`wild any->` instead, and `mcpy`/`mmov`/`memset`/`string_from_bytes`/
`driver_clone_exec` are given the same spelling. The reason is in the tree: the
prelude's `read(self.src.value, dest.ptr, dest.len)` passes a `uint8->` (a
slice's `.ptr` is a pointer to its element) while `nbridge` passes an `int8->`,
so a signature naming one of them refuses the other. `wild any->` is the
reference's OWN spelling for this — `ralloc` and `dalloc` have carried it since
the allocator was written — and it says the true thing about the floor: it takes
an ADDRESS and a byte count, and what the bytes are a pointer to is not its
business. No language rule changes; the acceptance is a named arm of the builtin
argument check (`builtin_arg_fits`), not a loosening of `fits`.

## Step 1 — the typing lands, under the transitional rule (LANDED)

**Full harness green.**

### What landed

1. **`type_call`'s callee==0 fall-through is gone.** After the nine specials'
   arms, a bare-name builtin is typed from the generated table:
   `type_builtin_regular` checks arity, per-argument `fits`, the `move` a
   consuming parameter demands, and refuses `..^` into a builtin's fixed
   registers — `check_args`'s rules, over the table instead of over a declared
   function's window. `check_args` itself cannot serve: it reads a func TYPE and
   wraps its answer unconditionally, and a never-fails builtin's call is the
   bare value.
2. **`builtin_text_type` interns the table's type texts** — a flat table of the
   fourteen texts the rows use, not a parser, so a text it does not have fails
   loudly rather than resolving to something close by. The new instrument
   `check_builtin_sig_texts` diffs it against the generated table both ways on
   every full run, which turns "a builtin written with a type nobody taught the
   resolver" from a first-call-site refusal into a build failure.
3. **`NITPICK-TYPE-054`** for a builtin's own call rules (arity, the spread, and
   the two internal disagreements). A wrong argument TYPE rides TYPE-002 like
   every other slot — one rule for every call is the point of typing these from
   a table at all.
4. **Four bespoke arms retired**: `string_bytes`, `buffer_new`, `own_fd` and
   `release_fd` are not irregular — each has an ordinary signature — so keeping
   them would leave exactly the parallel authority P-3 exists to collapse.
   `own_fd` got STRICTER on the way past: its arm admitted any kernel
   identifier, and owning a `pid` closes nothing.
5. **The transitional rule** (D-201 §7a, step 1 only): `raw`/`drop`/`relay` over
   a never-fails builtin call is the identity, so the typing lands as its own
   commit and the tree-wide re-spell follows as another.
6. **The parameter is now the expectation** at a builtin's argument, so an
   unsuffixed literal reads its width from the signature. Before this the OUTER
   expectation reached them — `wild int8->:p = alloc(8)` offered a POINTER as
   the context for a byte count.

### Found — five latent unchecked pointer reinterpretations in `src/`

The typed floor immediately refused five sites that had never been checked
because the callee's type was UNKNOWN:

- `ast.npk:264` and `:507` — `ralloc(…) => wild int32->`. `ralloc` answers in
  BYTES, and reinterpreting what a pointer points at is `=>!`, not `=>`. The
  line two above each of them already spelled it `=>!`; these two had been
  silently exempt.
- `numeric.npk:383`, `:384`, `:459` — `wild uint8->:x = alloc(…)` and
  `wild uint64->:limbs = alloc(80i64)`, the same assertion with no spelling at
  all.

Each is now written `=>!` — the TOS acknowledgement the language demands
everywhere the checker can see the types.

Also found and corrected in the tests: twelve `string_concat(…) ?! E` sites
escalating an error that cannot occur, and the JIT-page bindings in
`wildx_jit.npk` / `moves.npk`, which declare `wildx uint8->` over
`wildx_alloc`'s bytes.

### Two instruments earned their keep on the first run

- **`check_builtin_sig_texts` caught its author.** The wildx signature change
  below was made in the reference and not in `builtin_text_type`, and the check
  named it exactly — "the generated signature table uses the type text
  `wildx any->` and `builtin_text_type` cannot intern it". Without it the first
  symptom would have been four unrelated-looking `NITPICK-TYPE-007`s in
  `tests/analysis/rejection/wildx.npk`, which is what the same run also
  reported.
- **`check_slot_sites_agree` demanded the new `fits` site's partner.**
  `builtin_arg_fits` is registered against `call_builtin` with the reason
  written down: nothing is built for a regular builtin's argument and nothing
  can be, because `builtin_text_type`'s closed table has no `dyn` and no
  `Optional` arm — the two things `fits` admits that a value's own type does not
  say — and `check_builtin_sig_texts` fails the build if a row ever uses one.
  The pairing is written anyway, so the day such a type appears the slot has an
  owner.

### The wildx family takes an ADDRESS

`wildx_seal`, `wildx_call` and `wildx_free` are documented `wildx any->` rather
than `wildx int8->`, for the reason `dalloc` has carried `wild any->` since the
allocator was written: they take a page's address, and what the bytes are a
pointer to is not their business. Naming `int8->` there would refuse the
`uint8->` every JIT page in the tree is spelled as, and add three casts per site
to say nothing.

### Retired: `sys_args.npk`'s `unknown_arg`

The rule it tested — an argument whose type the checker cannot resolve, refused
with "bind it to a typed name first" — no longer fires for a builtin, because
every builtin has a signature now. The case is removed with a note in its place,
and `tests/accept/builtin_sigs.npk` asserts the positive fact:
`sys(39i64, string_byte_length(s))` types and is accepted. That new accept file
is the counterweight the suite exists to be — the bare-value rule, the may-fail
envelope surviving, the nested typed argument, and both pointer spellings
reaching a `wild any->` parameter.
