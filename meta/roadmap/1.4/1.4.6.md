# 1.4.6 — The switch (D-203, D-205) — PLANNED (execution-grade)

> The builder moves from the regenerated Python seed to committed stage
> IR; the seed retires; `npkrt.ll` re-homes. After this subcycle the
> Python generator never builds again (it remains the table/seed
> REGENERATION tool only).

## The work, in order

1. **Take the snapshot**: run the fixpoint; the stage-1 self-emission
   (the byte-stable `.ll`) is written to `bootstrap/seed/stage1.ll`
   (~11 MB text; committed — remove/adjust any `.gitignore` rule that
   would catch it; the carve-out comment at `.gitignore:17-19` already
   anticipates this). Beside it `bootstrap/seed/STAMP`:

   ```
   source-commit: <git rev-parse HEAD at emission>
   toolchain: llvm 20.1.2
   sha256: <sha256 of stage1.ll>
   ```

2. **The harness builds from the snapshot**: `build_tool`'s
   seed-compile of `src/main.npk` is replaced by: `llc` over
   `bootstrap/seed/stage1.ll` + link with npkrt.o → the BUILDER binary;
   the builder compiles current `src/` → stage 1; the fixpoint stage
   compares stage-1's self-emission against stage-2's (the
   builder-is-stale-tolerant comparison D-202 specifies — both compared
   emissions come from CURRENT-source compilers). `quickemit`/
   `quickcheck` follow the same path.
3. **The seed-coupled instruments re-base**: `check_ll_types_agree`
   RETIRES (two emitters → one; record the retirement in its place in
   the whole-suite block with a comment naming D-205);
   `check_runtime_sigs_agree` drops its `emit.RUNTIME` leg (two-way:
   npkrt.ll ↔ the D-201-generated table). The rejection/conformance
   suites' per-test compiles still go through... — DECISION already
   embedded in D-205: the suites compile with the BUILDER (snapshot)
   binary now; the seed's Python `compile_files` path is unused by the
   harness. `selfcheck.py`'s cases run through the same builder path.
4. **`npkrt.ll` re-homes to top-level `runtime/`** (with
   `runtime/tests/`); every path referencing `bootstrap/runtime/`
   updates (harness constants, quickemit/quickcheck, LAYOUT, BUILD
   docs, the npkrt header comment loses THROWAWAY — D-203's text).
5. **LAYOUT.md §5** was amended at 1.4.0 with the survival map — verify
   it matches what happened; sweep stragglers.
6. **The snapshot-refresh ritual** documents itself: a short
   `bootstrap/seed/README.md` — refreshed at cycle closes with the
   push; the exact three commands to regenerate and verify (llc, link,
   fixpoint, sha256); the C-13/D-205 rule that a NEW language feature
   enters `src/` only after a refresh.
7. **The repro stage's snapshot assertions** (1.4.5's guarded leg) arm.

## The trust story (why this is sound — for the record, not new work)

The from-scratch audit path for any historical state: check out the
pre-switch commit, regenerate the seed with the generator, build
forward. Post-switch, the committed IR + STAMP is the reproducible
root; diverse double-compilation remains the Thompson mitigation D-085
records. The generator and `bootstrap/harness/` SURVIVE (regeneration
tool; the runner until `npkg` parity under SWITCH.md).
