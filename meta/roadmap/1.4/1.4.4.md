# 1.4.4 — D-207 lands: per-scope joins — **PARTIAL: item 6 (D-215) LANDED; items 1–5 OPEN**

> `join_head` becomes per-scope, threaded through the 1.2 scope-exit
> machinery that already owns drop flags. Order at every scope exit:
> **join that scope's tasks (relaying the first child error, D-163 rule
> 4) → reclaim that scope's channels → release that scope's shared
> arenas** — joined-before-freed, always.

## The work

1. **The frame layout**: today one `join_head` list per frame. Give each
   SCOPE its own list head (the drop-flag machinery already knows scope
   extents — ride the same structure; a scope's head lives beside its
   drop flags, frame-resident in async bodies exactly as flags are).
   `spawn` links the child onto the CURRENT scope's head, not the
   frame's.
2. **Scope exit emission**: the exit walk (sync and async, plus the
   wind-up unwind and the early exits — `pass`/`fail`/`relay`, the
   D-014 rule that a TRAP runs neither still holds) performs
   join-then-reclaim-then-release for that scope before its drops... —
   careful, the precise order against DROPS: the 1.2 order is
   drops-at-exit; joins must run BEFORE the drops of anything a child
   could still reference (the sanctioned crossings are borrows of the
   sync primitives — which are drop-carrying). Order: joins first, then
   ALL drops (which now include channel reclaim and shared-arena
   release as their kinds' drops). Verify against D-062/D-080's stated
   exit order and write the order into the emitted-IR comment.
3. **Channel reclaim moves from function-exit to scope-exit** (the
   D-183 1.2.5 creation-site finalizer re-homed): `channel()` inside a
   LOOP now works — per-iteration reclaim at the body's exit. Lift the
   C-22 refusal (find it by its row name in the refusal string).
4. **`TY_SHARED_ARENA` leaves the excuse tables**: `type_drops` answers
   true; `emit_one_drop` gains its arm (joined-before-freed is
   guaranteed by 2's order); the harness excuse rows for
   `type_drops`/`emit_one_drop` are REMOVED in the same commit (the
   walkers-total instrument will refuse a half-done change — that is it
   working).
5. **The `dyn`-element refusal stays** (permanent by D-207) — no code
   change, but the refusal message may now cite D-207 rather than the
   C-22 row name.
6. **S-4 WAS ratified (D-215)** — implement here: the dyn coercion site
   asks `type_contains_channel(concrete)` and refuses a true answer
   with a new TYPE code + rejection case (an endpoint-holding struct
   erased to `dyn Trait`); the `type_contains_channel` DYN comment in
   types.npk updates to cite D-215 instead of the residual — the
   walker's `false` for DYN becomes exact, not documented-approximate.

## Item 6 — D-215, the `dyn` coercion refusal (LANDED, full harness green)

A concrete type whose `type_contains_channel` answers true refuses at any `dyn`
coercion, `NITPICK-TYPE-056`. `types.npk`'s DYN arm now says its `false` is
EXACT rather than a documented residual, and cites D-215 for why.

**Where the diagnostic lives, and why it is not at `fits`.** `fits` is a
predicate with no `Span` and twenty-one callers; threading one through all of
them to carry a message was not worth it. `fits` answers `false`, and the
MISMATCH REPORTERS explain — `te_mismatch_at` and `te_assign_mismatch` both
have the span and both already specialise by reason (the
never-fails-into-may-fail case is the precedent sitting directly above the new
arm). One consequence to know: a coercion refused for this reason produces
TYPE-056 and not the generic mismatch, in either position.

`tests/types/rejection/dyn_channel.npk` covers the declaration position, the
argument position, and — the counterweight — a type holding no endpoint, which
erases exactly as it always did.
